`@godcreator/gwb-docsite` 是 gwb 工作台的插件，在这个仓的 `plugins/docsite/`。它自己不定义任何格式——身份、评论、feed 的文件格式与协议正本都在[能力包与组合包](/)里——只做三件事：管理站点的开发服务进程、把本 home 的身份交给站点、给 agent（命令）与别的插件（服务 `gwbDocsite`）出入口。用基础包搭的站都由它托管：会话、终端自己启动的开发服务没有身份码，站点只读；会话一停站点就没了，几个会话还会占用同一个端口。

## 与站点的契约（v1）

插件升级后要能托管按旧约定运行的站点；确实不再支持的版本会明确报错、写明站点要升到哪版。契约改破坏性条目时升 v2，随插件发版附升级说明。

| 条目 | 内容 | 正本在哪 |
| --- | --- | --- |
| 启动方式 | 插件在站点目录跑 `pnpm dev` | 站点 `package.json` |
| 传身份 | 环境变量 `DOCSITE_IDENTITY_CODE`＝本 home 的身份码；不经插件启动的站点只读 | 常量名从 `@godcreator/docsite-identity/server` 的 `identityCodeEnvName` 取 |
| 推送口令 | 环境变量与请求头的名字、端点前缀 | `@godcreator/docsite-feed` |
| 地址 | 站点 `scripts.dev` 写死 `--port`，只绑本机 | 站点 `package.json` |
| 人员列表 | `people.json` 的读写与校验只经 identity 包的函数 | `@godcreator/docsite-identity` |
| 评论目录 | `comments/` 的读写只经 comments 包的函数；写入经站点 action（站点自己校验） | `@godcreator/docsite-comments` |
| 功能包列表 | `package.json` 的 `docsite.features`，见[功能包](/features) | gwb-docsite 的建站器（校验）与 `@godcreator/docsite-kit/feature`（类型） |
| 版本核对 | 启动站点前读站点装的 `@godcreator/docsite-kit` 版本，低于插件支持的最低版就拒绝并写明要升到哪版 | 插件里的常量 `MIN_KIT_VERSION`（当前 0.2.0，契约 v1 对应的最低版本） |

## 托管的站点

登记表持久化在工作台设置 `sites` 里（站点目录的列表，`docsite.site.add` 登记）；工作台每次启动时对登记表逐个 start（异步，不阻塞加载）。内存里每个站一份状态：

| 状态 | 意思 |
| --- | --- |
| `running` | 进程在，url 可用 |
| `stopped` | 没有进程 |
| `failed` | 进程退出了或没能启动，`error` 记退出码与最后几行输出 |

进程崩了只标 failed、记下原因，不自动重启：工作台是交互环境，人或 agent 看到 failed 再 start，比无声重启掩盖问题好。操作 start / stop / add / remove / init 全部幂等。保留的防护：站点目录路径归一（大小写、斜杠不同的写法算同一个站）、spawn 带超时、子进程随插件卸载清理。

## 命令

| 命令 | 做什么 |
| --- | --- |
| `docsite.identity` | 本 home 的身份码 |
| `docsite.site.init` | 一条命令从空目录建站（给目录、端口、站名：组装骨架与功能包模板 → 一次写盘 → 一次装依赖 → 启动一遍检查能运行）；骨架建完归站点，已有站点再调就拒绝，见[建站](/skeleton#建站) |
| `docsite.site.add` / `remove` | 登记进设置 `sites` 并启动（remove 从设置里去掉，在运行就停掉） |
| `docsite.site.start` / `stop` | 启动 / 停掉站点的开发服务；start 只做版本核对与目录有效性，已在运行就回现状 |
| `docsite.site.list` | 托管着的站点与状态：每个站 `{ dir, state, url, expectedUrl, error }` |
| `docsite.people.join` | 把本 home 的码加进站点的 `people.json`，之后写的评论署这个人 |
| `docsite.comments` | 列出评论，可按页面、和谁有关筛；读文件，不要站点在运行 |
| `docsite.comment.create` / `reply` | 写评论，经运行中的开发服务的页面接口，和网页同一套规则；agent 以自己的名义写时给 `as` |
| `docsite.comment.resolve` / `reopen` | 还不支持（评论模型没有已解决状态），调了直接报错 |

每条命令的参数与回执写在它的 usage 里（MCP 入口 `search {"prefix":"docsite."}`），agent 怎么用写在随包发布的说明书 `docsite` 里。

## 服务 gwbDocsite

别的插件注入这个服务管理自己的站点（协作站的 gwb-collab），不各管各的站点进程：

| 方法 | 做什么 |
| --- | --- |
| `identityCode()` | 本 home 的身份码 |
| `start(dir)` / `stop(dir)` / `status(dir)` | 启动（幂等，报错写明原因）、停止（没在运行报错）、此刻的样子 `{ dir, state, url, expectedUrl, error }`：`url` 是运行时的实际地址，`expectedUrl` 是按 `scripts.dev` 的 `--port` 预期的地址，没运行时给人看站点在哪 |
| `onStatus(listener)` | 某个站的状态变了（启动、停止、出错）时调用 |
| `push(dir, channel, data)` | 往站点的[推送通道](/dev-plugin#收-gwb-插件推来的数据)推一份数据；站点没运行就报错 |
| `join(dir, person)` | 把本 home 的码加进 `people.json` |
| `init(dir, { features?, port, title })` | 和命令 `docsite.site.init` 一样，多了给功能包与版本范围的 `features`（协作站的 gwb-collab 用它把 `@godcreator/collab-site` 装进站点，docfirst 的建站命令用它装 `@godcreator/docfirst-site`） |

## 不做的事

- 打开浏览器窗口给人看站：归 VS Code 插件（`docsite.site.list` 回的 url 交给它打开）
- 只读发布（`react-router-serve`）：待定，需求出现再设计
- 页面怎么显示、站点里的代码：归站点
- 不提交、不碰 git：站点目录里的改动由各站自己的流程提交
