评论的做法照 Notion：打开右下角的批注模式，在正文里选中一段文字，或者点一个元素（一张卡片、一个代码块、一张图片、列表里的一项），就能发起评论；
平时选中文字不弹按钮，方便复制。
被批的文字标黄，原文末尾插着评论数按钮；被批的图片、代码块、表格、组件画框，评论数按钮在它右上角。点按钮弹出这串评论。
右下角的「评论」按钮打开右侧栏，列出这一页全部评论。

评论存成文件，放在站点目录的 `comments/` 里，和页面分开，页面的源文件一个字都不改。
[写一页说明](/writing)、[fumadocs 组件](/writing/components)、[TSX 页面](/page-types/tsx-page)和[文档站基础包](/)几页上有示例评论，可以对照着看。

## 在页面上看评论

- **标黄与评论数**：没解决的评论串，被批的文字标黄并画下划线，原文末尾插着评论数按钮，跟着文字一起排版、换行。
  批的是段落、列表项、表格单元格、加粗这类文字元素时，同样标黄
- **画框**：批的是图片、公式、代码块、表格、组件时画框；块级的评论数按钮在它右上角，行内的（如行内公式）插在它后面
- **弹出卡片**：点评论数按钮或点标黄的文字，在原文下方弹出这串评论；同一时间只开一张，点别处就关上。
  同一个元素上有几串评论时共用一个评论数按钮，数字是这几串的评论总数，卡片里依次列出这几串
- **长评论串**：卡片先只显示发起的那条和「展开 N 条回复」，点开才看全部；卡片有最大高度，超出了在卡片里滚动
- **右侧栏**：右下角「评论」按钮打开，分「未解决」「已解决」两栏。点一条找得到原文的评论，正文滚到原文、弹出卡片；
  被批的内容收在没选中的标签页、收起的折叠块或文件夹里时，这条写着「在收起的「npm」里」，点它先替你点开再滚过去（见[被批的内容收起来了](#被批的内容收起来了)）；
  整页评论、已解决的、原文找不到了的，在右侧栏里展开看。宽屏时右侧栏和本页目录那一列一样宽、在同一个位置，
  打开时盖住目录，正文的位置和宽度不变，本页目录改成标题上方的下拉条；窄屏时右侧栏盖在页面上

插进正文的评论数按钮是评论自己放进去的：只在原文结尾处切开那一个文字节点，撤掉时拼回原来那个节点；
取页面文字时跳过这些按钮里的字，选区带上了按钮也不会把数字记进原文。

正文变了就重新找一遍位置：正文的大小变了，正文里的字、元素变了（切换标签页、代码块在浏览器里着色），
或者内容开合了（元素的 `hidden`、`open`、`aria-expanded`、`aria-selected` 变了，如展开折叠块），都会重新找。

## 写评论

只在本机的开发服务（`pnpm dev`）里能写。发布出去的站只读：能看评论，没有输入框、「批注」和「解决」按钮。

### 谁在写评论

每个站自己配人员，不取机器上的信息（git 的 `user.name` 常常不是本人，也和别人对不上）。
站点目录里的 `people.json`（进 git）列出参与的人；「我是谁」由本机的**身份码**认出：

- 每个 gwb home 的设置里有一串身份码（`docsite` 分区的 `identity-code`），基础插件 gwb-docsite 第一次加载时生成。隔离 home 各有各的码，所以各是一个人；换电脑时把旧的码填进新电脑的设置
- gwb-docsite 启动开发服务时把码放进环境变量 `DOCSITE_IDENTITY_CODE`，站点按码在 `people.json` 里找到人
- 把自己加进一个站：`docsite.people.join`，把本 home 的码加进人员列表里自己那一项的 `codes`

| 字段 | 写什么 |
| --- | --- |
| `id` | 评论的 `author`、`resolvedBy` 记的名字：字母、数字、`_`、`-` |
| `name` | 页面上显示的名字 |
| `codes` | 这个人用过的身份码；同一个码只能是一个人的 |
| `gitea` | Gitea 账号，协作站核对权限用；普通站点不写 |
| `agent` | `true` 是 agent：没有码，经接口写评论时用 `as` 说明自己是谁 |

```json title="people.json"
[
  { "id": "zhou", "name": "小周", "codes": ["k3v9q2x7m1ab"] },
  { "id": "claude", "name": "Claude", "agent": true }
]
```

码不是秘密：它进 git，挡不住组里的人冒用别人的码。

评论文件的 `author`、`resolvedBy` 存 `id`，页面上显示 `name`：改名只改 `people.json`，旧评论跟着变。
网页上没有「换成别人」的地方。侧栏底部那一栏左边显示这个人的头像（名字第一个字，底色由 `id` 算出，改名不变色）和名字；
不是经 gwb-docsite 启动的开发服务、码不在 `people.json` 里时站点只读，那里写「只读」，鼠标停上去看原因。

开发服务直接报错、写明怎么改的几种情况：没有 `people.json` 或写错了（码重复、agent 写了码等）；
评论的 `author`、`resolvedBy` 不在 `people.json` 里。`people.json` 每次都重新读，改了不用重启开发服务。

### 全部评论页

`/comments` 是全部评论页：全站的评论串按最近活动排，可以筛未解决、已解决、全部，筛某一页，筛「和我有关」（我发起的、回复过的、@ 了我的）。
挂在页面上的评论点了去那一页（地址带 `?comment=<评论串>`），那一页找好位置后打开它，收起的内容先替你点开。

**不挂在页面上的评论**在这一页顶上发起，frontmatter 不写 `page`，只出现在这一页，就在这里展开、回复。

**@ 某人**：正文里写 `@<id>`（`people.json` 里的 id），他的「和我有关」里就有这一串。
写评论时打 `@` 就在输入框下面弹出人员名单，接着打的字按 id 或名字筛（id 以它开头的排前面）；上下键选，Enter 或 Tab 填进 `@<id>`，Esc 只关名单，鼠标点名字也行。

### 怎么写

| 想做什么 | 怎么做 |
| --- | --- |
| 批一段文字 | 右下角「批注」打开批注模式，在正文里选中它，选区上方浮出「评论」按钮；可以跨段落、跨列表项，也能批标题 |
| 批一个元素 | 打开批注模式，鼠标下的元素画虚线框、标出它是什么，点一下就批它；Esc 或再点「批注」退出 |
| 批整页 | 右侧栏顶上的「评论整页」 |
| 回复 | 卡片底部的回复框 |
| 编辑、删除 | 鼠标移到自己写的那条上，名字后面出现「编辑」「删除」；删发起的那条就是删整串 |
| 标为已解决、重新打开 | 卡片顶上的按钮，谁都能点 |

批注模式里点到的就是鼠标下面那个元素，有三个例外：公式整个算一个（KaTeX 渲染出来是几十层 span），SVG 图整张算一个，
代码块整块算一个（里面是一个个着色的词）。要批一整张卡片、一整个提示框，点它里面文字以外的地方，比如边距。
模式里点链接不跳转，点组件也不触发组件自己的操作；拖选文字照样是批那段文字。
里面一个字也没有、也没有图片的元素（如空的占位块）在页面文字里没有位置，点了会提示只能评论整页。

输入框里写的是 MDX：纯文字、Markdown（`**加粗**`、`` `代码` ``）都行，也能写组件。fumadocs 默认的组件直接写，如 `<Callout>`；
要画个图、做个小控件，就在评论里现写一个组件再用：

```mdx
export const Dot = ({ color }) => <svg width="12" height="12"><circle cx="6" cy="6" r="6" fill={color} /></svg>

两种状态用 <Dot color="green" /> 和 <Dot color="red" /> 区分，比文字醒目。
```

保存前开发服务先把它按 MDX 编译一遍，编译不过就不存，卡片里写着第几行第几列哪里错。
所以要写字面的 `<` 或 `{`，写成 `\<`、`\{`，或者放进反引号里。编译过了、显示时才出错的（如用了没定义的组件），
只在这条评论的位置写出错的原话，页面和别的评论照常显示。

粘贴图片会存进这个评论串的文件夹，并在光标处插入图片引用。
Ctrl+Enter（Mac 上 ⌘+Enter）发送，Esc 取消。正在写的新评论点到别处不会丢，要点「取消」才关。

发出去以后，开发服务看到 `comments/` 里的文件变了，整页刷新：滚动位置不变，刚才那串评论自动重新打开。
不刷新只换评论这条路试过，走不通：编译好的 MDX 正文模块也引用了列出评论的模块，Vite 的热更新绕一圈后还是整页刷新。

### agent 发起评论

agent 没有浏览器，拿不到页面文字，调评论接口时只说批这一页上第几处的哪段文字，再用 `as` 说明自己是 `people.json` 里哪个 agent：

```text
POST /api/comments
op=create  page=/page-types/tsx-page  body=评论正文  as=claude
anchor={"quote":"export default function Page()","occurrence":1}
```

开发服务向自己请求这一页，从渲染出的 HTML 里按同样的规则算出页面文字当快照（`pageTextOfHtml`），在里面找第 `occurrence` 处 `quote`（从 1 数），
后面和网页上发起的一样写文件。找不到时接口回原话，如「这一页的文字里没有第 2 处「useState(0)」，一共有 1 处」。
回复、解决、编辑自己的评论也带 `as`。`as` 只给 agent 用：写了人的 `id` 时拒绝，人的身份只按本机的身份码认。
不给 `page` 是发起一条不挂在页面上的评论，这时不带 `anchor`。agent 一般不直接调这个接口，而是用 gwb-docsite 的 `docsite.comment.*` 命令，它们经这个接口写。

只在浏览器里渲染的内容，服务端渲染出的 HTML 里没有或不一样，算出的文字就和浏览器里差几个字。
比如 TSX 页面里的代码块在浏览器里才着色，服务端那一版没有换行符。这种差别和页面改过一样，由打开页面时的差异推算吸收：
批的那段没有跨着这些字就准确落上，跨着就标「原文改过」。

## 文件

一个评论串一个文件夹，网页上发起的评论文件夹名是「日期-六位随机字母数字」：

```text
comments/
└── 2026-10-10-heading-levels/
    ├── index.mdx            ← 发起的那条
    ├── snapshot.txt         ← 发起评论那一刻整页的文字
    ├── reply-indent.mdx     ← 一条回复
    ├── toc-sketch.svg       ← 评论里的图片
    └── indent-preview.tsx   ← 评论里的组件
```

评论文件一律是 `.mdx`，网页上写的、agent 写的都一样；写成 `.md` 时开发服务报错，让你改扩展名。
组件比较大、要单独一个文件时，放进评论串的文件夹，评论里 import 它：

```mdx title="comments/2026-10-10-heading-levels/reply-indent.mdx"
---
author: claude
createdAt: 2026-10-10T15:31:00+08:00
---

import { IndentPreview } from './indent-preview'

可以试试不同的缩进，拖动看效果：

<IndentPreview />
```

`index.mdx` 是发起的那条，写它批的是哪一页、批的是什么：

```mdx title="comments/2026-10-10-heading-levels/index.mdx"
---
author: zhou
createdAt: 2026-10-10T15:20:00+08:00
page: /writing
quote: 四级标题用来给一小节里的几段起名字
range: [718, 735]
status: open
---

四级标题在本页目录里缩进得太深了，像下面这样只缩一层行不行？

![本页目录只缩一层的草图](./toc-sketch.svg)
```

| 字段 | 写什么 |
| --- | --- |
| `author` | 谁写的：`people.json` 里的 `id` |
| `createdAt` | 什么时候写的，如 `2026-10-10T15:20:00+08:00` |
| `page` | 被批页面的地址，以 `/` 开头；不写就是不挂在页面上的评论 |
| `status` | `open` 或 `resolved` |
| `quote` | 批一段文字：原文，等于快照里 `range` 那一段 |
| `element` | 批一个元素：它是哪类，见下表 |
| `range` | 批的是快照里的第几个字到第几个字，写成 `[开始, 结束]`，从 0 数，不含结束那个字；批元素时是这个元素里第一个字到最后一个字 |
| `openers` | 被批的内容在几层能收起的内容里时，打开每一层要点的按钮在快照里的位置，由外到里，如 `[[658, 663], [686, 693]]`；没有就不写 |
| `resolvedBy`、`resolvedAt` | 谁（`people.json` 里的 `id`）、什么时候标的已解决 |

`quote` 与 `element` 只能写一个，写了就要写 `range` 与 `page`；都不写就是批整页（或不挂在页面上），没有快照。同一文件夹里其余的 `.mdx` 每个是一条回复，只写 `author` 与 `createdAt`。

| `element` | 哪些元素 | 页面上怎么标 |
| --- | --- | --- |
| `text` | 段落、列表项、标题、表格单元格、引用，以及按行内显示的加粗、链接、行内代码 | 标黄 |
| `image` | 图片、SVG、画布、视频，以及里面只有这些、没有字的元素 | 画框 |
| `formula` | KaTeX 公式 | 画框 |
| `code` | 代码块 | 画框 |
| `table` | 表格 | 画框 |
| `component` | 其余的元素：提示框、卡片（链接被做成块的也算）、标签页、TSX 组件 | 画框 |

打开页面时，推算出位置以后，从那段文字往外找同一类的元素；文字正好是这一段的几层元素里取最外层。

### 页面文字

快照和位置都在「页面文字」里数。页面文字从正文容器（带 `commentScopeProps` 的那个）开始，按先后顺序把文字接起来：

- 图片、SVG、画布、视频、iframe、KaTeX 公式整个记成一个 `U+FFFC` 字符，里面的东西不算
- 只给读屏软件看、屏幕上不显示的字（带 `sr-only` 的，如标题旁边的「复制这一节的链接」）不算：换了界面语言，快照也不受影响
- 评论自己放进页面的东西（带 `data-comment-ui` 的）不算

规则写在基础包的 `page-text-rules.ts` 里，浏览器（走 DOM）和服务端（解析 HTML）用同一份。
页面文字只有此刻页面上有的内容：没选中的标签页、收起的文件夹，里面的内容不在页面上，也就不在页面文字里。

### 怎么找到批的是哪里

打开页面时，网页取出现在的页面文字，和快照逐字对比差异，把 `range` 推算到现在的位置：

- 被批的那段没改过，前后插了、删了别的段落：准确落到新位置。同样的文字在页面上出现好几次也不会认错，差异是按前后顺序对齐的
- 被批的那段里改了几个字，但开头和结尾的字还在：照样挂在改后的那段上，标「原文改过」，卡片和右侧栏里写着当时批的原文
- 开头或结尾的字被改掉、整段重写、整段挪到了别处：找不到

快照读出来时换行统一成 `\n`：git 在 Windows 上取出文件可能把换行改成 `\r\n`，位置就会差。
快照缺了、`range` 或 `openers` 超出快照、`quote` 和快照里那一段不一样时，开发服务报错。

### 被批的内容收起来了

组件收起内容有两种做法，评论都认得：

| 组件 | 收起时内容在哪 | 评论怎么认出来 |
| --- | --- | --- |
| fumadocs 的标签页、文件夹，大多数自己写的展开块 | 从页面上拿掉了 | 发起时记下的 `openers` |
| fumadocs 的折叠块、`<details>` | 还在页面上，带 `hidden="until-found"` 藏着 | 找得到位置，但浏览器的 `checkVisibility()` 说看不见 |

**发起时**，从被批的地方往外一层层看，每遇到一块能收起的内容，就记下打开它的那个按钮在页面文字里的位置，存进 `openers`。
按钮按 ARIA 认（ARIA 是给读屏软件看的一套属性，组件库一般都会写）：

- 内容块的 `aria-labelledby` 指着的标签或按钮：标签页的 `role="tabpanel"` 指标签，折叠块的 `role="region"` 指按钮
- `aria-controls` 指着内容块 `id` 的按钮，按钮上要有 `aria-expanded` 或 `role="tab"`：文件夹展开着时就是这样
- `<details>` 里的 `<summary>`

按钮的字本来就显示在页面上，快照里有，所以 `openers` 和 `range` 一样只记位置，打开页面时一样拿快照对比推算。
不同的是按钮上的字常随开合变（▸ 变 ▾）、会被改名，所以不要求首尾都对得上：按钮里有一个字没改过就按它找，
但单个字可能碰巧对到别处的同一个字上，找到的按钮上的字还要和当时的大半相同（最长的相同一段至少占短的那个一半），
「site」改名「my-site」认得，「content」碰巧对到「pnpm」里的「n」不算。

**打开页面时**，被批的内容找不到或看不见，就由外到里看这些按钮：第一个收着的（`aria-expanded="false"`、`aria-selected="false"`、`<details>` 没打开）就是现在要点的，
右侧栏写「在收起的「按钮上的字」里」。内容还在页面上、只是藏着的，不用记下的 `openers`，直接从页面上它外面那几层找按钮。
某一层的按钮找不到了，或者每层都开着内容还是找不到，才写「原文找不到了」。

**点这条评论时**，替你点那个按钮，和你自己点一样，组件不用改。内容露出来后正文变了、重新找位置，下一层还收着就再点下一层，
找到了就滚过去、弹出卡片。点开一层后 5 秒还没露出新东西就停下，提示「点开了收起的内容，还是找不到被批的地方」。

没按 ARIA 写的组件（按钮只是一个能点的 `div`，没有 `aria-expanded`）认不出按钮：发起时记不下 `openers`，收起来以后就是「原文找不到了」。
自己写能收起的组件时，按钮带上 `aria-expanded` 与指着内容块 `id` 的 `aria-controls`，评论就认得。

### 原文找不到了

找不到不算错：评论照样在右侧栏里，标红写着「原文找不到了」和原来批的东西，不去猜位置。

有一种情况注定找不到：同样的一句话连着出现几次，删掉其中一次，单看文字分不出删的是哪一次。
差异算法认定删的是其中一处，批在那一处的评论就找不到了，批在其余几处的照样能找到。

## 写错了会怎样

开发服务直接报错，写明是哪个文件、哪里不对，一次列出全部：

- 缺字段、字段写错，或者写了表里没有的字段
- 回复里写了 `page`、`quote` 这类只有发起的那条才有的字段
- `quote` 和 `element` 都写了，或者写了其中一个却没写 `range`；写了 `openers` 却没写 `range`
- 评论文件不是 `.mdx`
- 文件没放在评论串自己的文件夹里，或者文件夹里只有回复、没有发起的那条
- `page` 写的页面不存在
- `author`、`resolvedBy` 不在 `people.json` 里

网页上的操作出错（页面不存在、编辑别人写的评论、文件名不对、评论按 MDX 编译不过）时，接口回原话，显示在卡片里。

## 在骨架里接上

`app/lib/collections.ts` 里列出评论文件，`schema` 用基础包的 `commentFrontmatterSchema`：

```ts title="app/lib/collections.ts"
export const comments = defineCollections({ type: 'doc', dir: 'comments', async: true, schema: commentFrontmatterSchema })
```

`app/lib/source.ts` 用 `commentThreadsOf` 把文件分成评论串，再用 `assertCommentPagesExist` 检查批的页面在不在。

本机身份由基础包的 `siteIdentity()` 给：开发服务里按环境变量的身份码在 `people.json` 里找到的人，只读时 `person` 是 `null`、`reason` 写原因；
`siteCommenter()` 只取其中的人。布局路由的 `loader` 返回 `siteIdentity()`，传给 `themeSwitchWithIdentity` 显示在侧栏底部；内容页的 `loader` 返回 `siteCommenter()`，传给 `PageComments`。
`app/lib/commenter.server.ts` 的 `pageCommentData(allThreads, pageThreads)` 用 `sitePeople()` 读出 `people.json`、
用 `assertCommentAuthorsKnown` 核对全站评论的作者都在里面，再调用 `commentSnapshotsOf` 读出这一页各评论串的 `snapshot.txt`；
内容页路由的 `loader` 返回这两样，传给 `PageComments` 的 `people` 与 `snapshots`。
发布出去的站也在运行时读这些文件，`comments/` 与 `people.json` 要跟着站点一起发布。

`app/routes/comments.ts` 是评论接口：`action` 调用 `commentRequestResponse` 写文件（传入 `siteCommenter()` 与 `sitePeople()`），`loader` 调用 `commentSourceResponse` 取原文给编辑用。
接口只改 `comments/` 里的文件，不碰 git。agent 用 `{ quote, occurrence }` 发起评论时，接口默认向开发服务自己请求那一页的 HTML；
`commentRequestResponse` 的 `pageHtmlOf` 选项可以换成别的取法，测试里就传了假的。

`app/routes/page.tsx` 用 `commentThreadsByPage` 按页面地址取出这一页的评论串，正文外面套 `PageComments`；正文的容器要带上 `commentScopeProps`，评论在它里面取页面文字：

```tsx title="app/routes/page.tsx"
<DocsPage toc={toc}>
  <PageComments page={url} threads={threads} snapshots={snapshots} commenter={commenter} renderBody={renderCommentBody}>
    <DocsBody {...commentScopeProps}>{children}</DocsBody>
  </PageComments>
</DocsPage>
```

`renderCommentBody` 用 `use(entry.load())` 取出编译好的正文再渲染。不用 fumadocs-mdx 给的 `entry.body`：
它加载完以后不再调用 `use()`，React 会报 `conditional use of use()`。全站的评论串与 `renderCommentBody` 放在 `app/lib/comment-threads.tsx`，内容页与全部评论页共用。

`app/routes/all-comments.tsx` 是全部评论页，挂在 `/comments`：`loader` 返回人员列表、写评论的人、页面标题，
和「和我有关」的评论串（`readCommentThreads` 从文件读出正文，`commentThreadIdsAbout` 找我发起的、回复过的、@ 了我的），页面渲染 `AllComments`。

不经开发服务读评论用 `./server` 的 `readCommentThreads(评论目录)`；`siteProblems(站点目录)` 查人员列表、评论文件的格式、作者、快照，
提交前在站点目录跑一次 `pnpm build`：全部页面与评论的 MDX 都走同一编译链，编不过的会带文件名报错。
每个编不过的文件回一句「路径 第几行第几列：原话」，写错的公式也算；要几秒，只在提交前查，打开站点前不查。
