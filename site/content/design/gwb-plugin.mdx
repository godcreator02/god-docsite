重写 `@godcreator/gwb-docsite` 的设计。需求见[站点生命周期需求](/design/site-lifecycle)（L-10 只读发布这轮不做），原则见[设计原则](/design/principles)的原则六（约定向后兼容）、七（能不能写只看身份）、九（错了就报错）。

## 定位

插件是**能力包的组合层与契约的持有者**：身份、评论、feed 的文件格式与协议正本都在能力包（docsite-identity、docsite-comments、docsite-feed）与组合包（docsite-kit 的模板与初始化）里，插件自己不定义任何格式，只做三件事——管理站点的开发服务进程、把本 home 的身份交给站点、给 agent（命令）与别的插件（服务）出入口。

## 与站点的契约（v1）

插件升级后要能托管按旧约定运行的站点（原则六）；确实不再支持的版本要明确报错说升到哪。契约条目：

| 条目 | 内容 | 正本在哪 |
| --- | --- | --- |
| 启动方式 | 插件在站点目录跑 `pnpm dev` | 站点 `package.json` |
| 传身份 | 环境变量 `DOCSITE_IDENTITY_CODE`＝本 home 的身份码；不经插件启动的站点只读 | 常量名从 `@godcreator/docsite-identity/server` 的 `identityCodeEnvName` 取 |
| 推送口令 | 环境变量与请求头的名字、端点前缀 | `@godcreator/docsite-feed` |
| 地址 | 站点 `scripts.dev` 写死 `--port`，只绑本机 | 站点 `package.json` |
| 人员列表 | `people.json` 的读写与校验只经 identity 包的函数 | `@godcreator/docsite-identity` |
| 评论目录 | `comments/` 的读写只经 comments 包的函数；写入经站点 action（站点自己校验） | `@godcreator/docsite-comments` |
| 功能包列表 | `package.json` 的 `docsite.features` | `@godcreator/docsite-kit/init` |
| 版本核对 | 启动站点前读站点装的 `@godcreator/docsite-kit` 版本，低于插件支持的最低版就拒绝并写明要升到哪版 | 插件里的常量 `MIN_KIT_VERSION` |

契约改破坏性条目时升 v2，随插件发版附升级说明。

## 站点状态机

登记表持久化在工作台设置里（`sites`：站点目录列表）；内存里每个站一份状态：

```
running（进程在，url 可用）
stopped（没有进程）
failed（进程退出了，error 记退出码与最后几行输出）
```

操作四个，全部幂等：

- **start**：spawn `pnpm dev`（带两个环境变量），从输出解析出本机地址后转 running；进程退出转 failed。已在 running 就直接返回现状
- **stop**：结束进程，转 stopped。没在运行就报错
- **add**：登记并 start。remove：stop（如果在跑）并除名
- **init**：不在跑先 stop；从零建站或更新骨架（见命令面），结束时按登记与否决定要不要 start

工作台启动时对登记表逐个 start（L-06，异步、不阻塞加载）。

### 删掉的防护与理由

| 删掉 | 理由 |
| --- | --- |
| 意外退出自动重启 | 工作台是交互环境：崩了标 failed、记下原因，人或 agent 看到再 start，比无声重启掩盖问题好 |
| 5 分钟 3 次失败上限 | 它是自动重启的护栏，重启删了它没存在理由 |
| 启动前的人员/评论文件检查 | 新格局下写入经站点 action、读取经能力包函数，校验在使用时发生 |
| 同站操作排队 | 操作幂等，重复 spawn 被端口占用自然挡住 |
| whileStopped | 退化为 stop → 做事 → start，init 内部自己做 |
| 推送的补投队列（站点没运行先记下、启动后补推） | 没运行就明确报错（原则九）；协作站真需要时序保证再加 |

保留的防护：站点目录路径归一（大小写、斜杠不同的写法算同一个站）、spawn 带超时、子进程随插件卸载清理。

## 命令面

| 命令 | 变化 |
| --- | --- |
| `docsite.identity` | 不变：回本 home 身份码 |
| `docsite.site.list` | 不变：站点与状态、地址 |
| `docsite.site.add` / `remove` | 语义不变（remove 顺带 stop） |
| `docsite.site.start` / `stop` | start 去掉启动前检查那一长串，只做版本核对与目录有效性 |
| `docsite.site.init` | **一条命令从零建站**（L-01）：给目录、端口、站名——装基础包 → 照模板写骨架 → 装全部依赖 → 起服务检查；两段装依赖收进命令里，不再要求调用方自己装。已是站点时做骨架更新 |
| `docsite.people.join` | 不变 |
| `docsite.comments` / `comment.create` / `comment.reply` | 不变（已按新评论模型） |
| `docsite.comment.resolve` / `reopen` | 维持明确拒绝（评论模型还没有 resolved 状态） |

## 服务面（给别的插件注入的 `gwbDocsite`）

精简后：`identityCode`、`status(dir)`、`start(dir)`、`stop(dir)`、`onStatus(listener)`、`push(dir, channel, data)`（站点没运行报错）、`join(dir, person)`、`init(dir, options)`。删掉 `keep` / `forget` / `open` / `whileStopped`（`open` 打开窗口归 VS Code 插件；`keep`/`forget` 与 add/remove 是同一件事，统一成后者）。
