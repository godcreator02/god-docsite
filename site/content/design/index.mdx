## 三层

| 层 | 是什么 | 在哪 |
| --- | --- | --- |
| 基础包 `@godcreator/docsite-kit` | 页面、评论、人员列表、全部评论页、推送通道的站点一侧 | 本仓 `packages/docsite-kit` |
| 基础插件 `@godcreator/gwb-docsite` | 身份码、托管站点的开发服务、把数据推给站点、agent 用的评论命令、说明书 `docsite` | 本仓 `plugins/docsite` |
| 功能：协作站 | 网站包 `@godcreator/collab-site` 改成基础包的功能包（任务、甘特图、日历与日志、通知提示栏、记录链接）；`gwb-collab` 只管 git、Gitea、任务与通知，站点交给基础插件 | 协作站仓 |

基础插件和基础包放在同一个仓：人员列表、评论文件的格式只有基础包一份实现，插件打包时把它带进去，两边一起发版。

## 身份码

- 每个 gwb home 的设置里有一项 `docsite` 分区的 `identity-code`：插件第一次加载时生成 12 个小写字母数字，之后不变；隔离 home 各自生成，所以各是一个不同的人。换电脑时把旧的码填进新电脑的设置
- 码不是秘密：它写进站点的人员列表、进 git。挡不住组里的人冒用别人的码，课题组内部互相信任，这一轮不做签名
- 站点目录的 `people.json` 每项 `{ id, name, codes?, gitea?, agent? }`：
  - `id` 是评论作者、任务负责人记的那个名字，只用字母、数字、`_`、`-`
  - `codes` 是这个人用过的身份码（换电脑、隔离 home 就多一个），同一个码只能出现在一个人身上
  - `gitea` 是这个人的 Gitea 账号，协作站核对权限时用；普通站点不写
  - `agent: true` 的是 agent，没有码；经命令写评论时用 `as` 说明自己是谁
- 基础插件启动开发服务时把本 home 的码放进环境变量 `DOCSITE_IDENTITY_CODE`；站点里 `siteCommenter()` 按码在人员列表里找到人。没有码（不是经插件启动的）、码不在人员列表里时站点只读，侧栏底部写明原因
- `me.json` 不再用
- 把自己加进一个站：`docsite.people.join { dir, id, name, gitea? }`，人员列表里有这个 `id` 就把本 home 的码加进它的 `codes`，没有就新加一项。协作站里由 `gwb-collab` 在打开项目时按令牌的 Gitea 账号自动做

## 推送通道

插件往站点推数据（协作站的通知、项目负责人），照协作站原来那套做法，改成基础包里通用的一份：

- 启动时插件另给环境变量 `DOCSITE_FEED_TOKEN`（随机串）
- 推送：`POST /__docsite/feed/<频道>`，请求头 `x-docsite-token`，正文是 JSON；开发服务按频道只留最新一份，再经 Vite 的 WebSocket 发事件 `docsite:feed` 给浏览器
- 站点一侧：浏览器里 `useSiteFeed(频道)` 取最新一份、之后跟着变；服务端（路由的 `loader`、`action`）用 `siteFeedOf(频道)` 取
- 插件记着每个站每个频道的最新一份，站点重启后补推

## 全部评论页

基础包加一个页面组件 `AllComments`，骨架里挂在 `/comments`：全站评论按最近活动排，筛选状态（未解决、已解决、全部）、页面、「和我有关」（我发起的、回复了我的、@ 了我的）。点一条去那一页并打开它（地址 `/<页>?comment=<评论串>`）。

另外两处补上：

- **不挂在页面上的评论**：frontmatter 不写 `page` 的评论串只出现在全部评论页上，在那里发起
- **@**：评论正文里写 `@<id>`（人员列表里的 id）就是 @ 了那个人，`mentionsOf(正文, 人员列表)` 取出来

## 基础插件 gwb-docsite

服务 `gwbDocsite`（别的插件 `ctx.inject` 取用）：

| 方法 | 做什么 |
| --- | --- |
| `identityCode()` | 本 home 的身份码 |
| `keep(dir)` / `forget(dir)` | 托管、不再托管一个站：开发服务常驻，意外退出 5 分钟内 3 次就停下、记下原因 |
| `start(dir)` / `stop(dir)` / `status(dir)` / `list()` | 人为启停、查状态 `{ dir, url, running, error }` |
| `whileStopped(dir, fn)` | 先停、做完 `fn`（比如装依赖）再启动 |
| `push(dir, channel, data)` | 推数据，站点没在运行就只记下，启动后补推 |
| `join(dir, person)` | 把本 home 的码加进人员列表 |
| `onStatus(listener)` | 站点状态变了通知调用方 |

命令：`docsite.identity`、`docsite.site.list` / `add` / `remove` / `start` / `stop` / `open`、`docsite.people.join`、`docsite.comments`（列评论，读文件，不要站点在运行）、`docsite.comment.create` / `reply` / `resolve` / `reopen`（经运行中的开发服务的评论接口写，和网页同一套规则；`as` 给 agent 用）。设置：`identity-code`、`sites`（托管着的站点目录）、`site-window`（打开用 Chrome 应用窗口还是默认浏览器）。

站点用 `site/package.json` 的 `dev` 脚本启动，端口从脚本里的 `--port` 读。发布服务（`react-router-serve`）这一轮不做。

## 协作站新形态

- 协作仓 `site/` 是一个基础包的站：`content/` 页面、`comments/` 评论、`people.json` 人员列表、`journal/<YYYY-MM-DD>.mdx` 日志、骨架 `app/`；`collab/records/` 只剩任务与模块
- 网站包 `@godcreator/collab-site` 导出：任务页（人员、甘特图、看板）、记录页、日历页与日志页、通知提示栏、`RecordLink`、服务端读写任务模块的函数、骨架模板 `template/`
- `gwb-collab`：
  - 身份：本 home 的码在 `site/people.json` 里对应的人；那一项的 `gitea` 要和令牌的账号一致。不再用 `git config collab.person`
  - 站点：交给 `gwbDocsite.keep`，通知与负责人经 `push(dir, 'collab', SiteFeed)` 推
  - `collab.comments` 去掉（用 `docsite.comments`）；`collab.inbox` 与「找我的」通知改读 `site/comments/`
  - 提交前检查：站点的类型检查加基础包的站点检查（人员列表、评论文件）
- 合并检查包：只有负责人能改的内容里加 `site/people.json`
- 站点协议号加到 8：旧形态的项目新版插件不认，不能用就不能用

## 迁移

内容一律改成基础包的写法；有写法对不上的，直接改那个文件的内容，不为旧写法往基础包或协作站里加兼容规则：

- `<PageLink id>` 改成普通的 Markdown 链接 `[标题](/页)`；协作站只留 `<RecordLink id>`（日志引用任务要用）
- `repo:` 链接、旧网站包 `page-components` 里的东西，按基础包已有的写法改写，没有对应的就改成普通文字或代码

迁移脚本 `collab-site` 仓里 `scripts/migrate-site.mjs <协作仓>` 只做搬文件与机械改写：

- `site/pages/<页>/page.mdx` → `site/content/<页>.mdx`（`export const meta` 换成 frontmatter 的 `title`），`page.tsx` → `<页>.page.tsx`，同文件夹的其余文件 → `site/content/<页>/`，`./X` 引用跟着改；页面地址不变
- `_folder.json` → `meta.json`（`order` → `pages`，根下分组加 `"root": true`，图标换成 lucide 名字）
- `pages/calendar/<日期>/page.mdx` → `site/journal/<日期>.mdx`
- 评论与回复记录 → `site/comments/<评论 id>/`：有 `quote` 的按迁移后页面的文字算快照与位置，算不出的改成批整页，正文前写一行原来批的是哪句；回复压平成一串；`mentions` 写成正文里的 `@id`
- `collab/people.json` → `site/people.json`（`gitea` 就是原来的 id）

先拿 SST 项目（chb-dab-sst）在单独的 worktree 里迁移、在隔离 home 里验；MMC 不动。
