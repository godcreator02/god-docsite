包 `@godcreator/collab-site`，源码在 `packages/collab-site/src/`。协作仓 `site/` 的骨架由基础包的模板写，这个包是接在骨架上的功能包，交出什么见下面「交给基础包的东西」。
协作仓的 `site/` 是一个用文档站基础包 `@godcreator/docsite-kit` 搭的站：页面（MDX、TSX、HTML 三种）、侧栏、搜索、评论与全部评论页、按身份码认人、推送通道、
托管开发服务，都是基础包与基础插件 gwb-docsite 做的，怎么用看基础包的自述站（单元 `oz47p-docsite-kit` 仓 `docsite-kit` 的 `site/`）。
这个包只加协作站自己的东西；记录与通知长什么样、写入合不合规则在 [数据模型包](/collab/collab-model)，合并请求能不能合进 main 在 [合并检查包](/collab/collab-merge-check)。

## 逐条接缝

| 接缝 | 两端 | 送什么 | 改了会让哪边出问题 |
| --- | --- | --- | --- |
| 1 推数据、2 服务端读、3 界面收推送 | gwb-collab → 基础包的推送通道 → 服务端函数与界面 | 频道 `collab` 上整份 `SiteFeed`：通知列表与项目负责人 | 形状由数据模型包定，一改就加站点协议号（见下面「站点协议号」）；频道名两边都从数据模型包的 `siteFeedChannel` 取 |
| 2 身份与人员 | 基础包 → 服务端函数 | 本机身份码在 `site/people.json` 里认出的人、人员列表 | 不是 gwb-docsite 启动的站、码不在人员列表里，只读：写任务回 403 |
| 4 读写记录 | 服务端函数 ↔ `collab/records/` | 记录文件，经数据模型包的写入规则 | 格式只有数据模型包这一份实现，网站与插件写下的是同样的文件 |
| 5 日志页文件、6 读日志页 | `site/journal/` → 日志页 → 服务端函数；模板里的 `journal` 集合也读同一批文件 | 有日志的日子、每天的原文、引用某条记录的段落 | 文件名规矩改了，站点检查（14）跟着改 |
| 7 交给路由、8 交给界面 | 服务端函数 → 布局数据 `./site-server` 与路由模块 `src/routes/` → 界面 | `CollabSiteData`、日志里的进展 | 形状在 `site-data.ts`，只在这个包里用，改了不用加站点协议号；路由模块与路由表都在包里，不复制进协作仓 |
| 9 写任务、10 交给服务端写 | 界面 → `POST /api/collab` → 服务端函数 | `{ action, record }`，回成功的结果或带原话的错误 | 同上，地址与 action 在 `site-data.ts` |
| 11 MDX 组件 | 界面 → `./site` 的 `mdxComponents` → 基础包骨架的 MDX 组件表 | `{ RecordLink }` | 加了组件，MDX 页面、日志页、评论正文里就能直接写 |
| 12 查站点、13、14 | 站点检查 → gwb-collab；基础包的检查与日志页文件名检查 → 站点检查 | 每条一句给人看的话 | gwb-collab 托管前、提交审核前都调它，查漏了的问题会让站点打不开 |

站点只收不发：浏览器与服务端函数都不向插件发请求；gwb-collab 也只调这个包的站点检查，推数据、托管站点经 gwb-docsite。

## 交给基础包的东西

协作仓 `site/` 的骨架（`app/` 与 `site/` 根下的配置文件）由基础包的模板写：gwb-collab 的 `collab.site.init` 交给 gwb-docsite 初始化新站点、或照装好的新版模板重写已有站点的骨架（见 [站点](/collab/notices-site)）。
`site/package.json` 的 `docsite.features` 列着这个包，初始化照它生成 `app/site/`，骨架只经那几个文件引入功能包，这个包不改骨架里任何一个文件。
`app/` 每次初始化整个重写，不放自己的文件；页面放在 `content/`、评论放在 `comments/`、人员列表是 `people.json`，这些照基础包，初始化不碰已有的；协作站多的是 `journal/`（日志页，见 [网站内部](/collab/collab/collab-site) 的「日历与日志」）。
基础包这边的约定见它自述站的「项目骨架」「功能包」两页。

| 出口 | 交出什么 |
| --- | --- |
| `./routes` | 路由表：`api/collab` 写任务与模块、`api/repo-links` 与 `api/project-file/*` 检查与打开 `repo:` 链接，都放在整站布局外面；`tasks`、`tasks/:recordId`、`calendar`、`calendar/:date`，除了日历都能写评论；首页 `/` 跳到 `/tasks`。路由模块在 `src/routes/`，不复制进协作仓，路由表指向包里构建出的 `dist/routes/` |
| `./site` | 侧栏那一排的「任务」「日历」，排在基础包的「评论」前面；MDX 组件 `RecordLink`；链接种类 `linkKinds`（任务、日志、`repo:` 链接的卡片）；包住整个布局的 `CollabDataProvider`；每一页正文上面的 `NotificationBar` |
| `./site-server` | 整站布局的 loader 调的 `layoutData`：拿基础包交来的站里每一页调 `collabSiteData`，读出的协作数据交给 `CollabDataProvider` |

## 站点协议号

插件推给站点的数据由插件这一边生成，站点由协作仓 `site/package.json` 装的那一版功能包读。两边版本不一样、对推来的数据理解不同时，站点照样能打开，只是通知与负责人对不上。
所以数据模型包的 `siteProtocol` 编了一个号，这个包 `package.json` 的 `collabSiteProtocol` 写同一个数：

这个号一加，每个项目都要负责人改一次 `site/package.json`，插件也要一起发版。所以只有推给站点的数据（`site-feed.ts` 与通知的字段）改了、记录格式有破坏性改动时才加；
`site-data.ts`（服务端函数与界面之间的约定，只在这个包里）改了不用加。

## 站点检查

`collabSiteProblems(siteDir)` 是基础包的 `siteProblems`（人员列表、评论文件的格式与作者、评论快照）加上日志页的文件名，每条一句给人看的话。
只查文件，很快，gwb-collab 托管站点前也调它。`collabSiteMdxProblems(siteDir)` 用站点自己装的基础包编译 `content/`、`comments/`、`journal/` 里的 MDX，写错的公式也算；
要几秒，只在提交审核前调。

## 依赖

数据模型包 `@godcreator/collab-model` 是普通依赖，随功能包一起装；任务与模块的内容按 Markdown 显示，另依赖 `react-markdown` 与 `remark-gfm`。
基础包、fumadocs 的界面包 `@fumadocs/base-ui`、React、React Router、图标库 `lucide-react` 由站点装（peer）：功能包和基础包、站点要用同一份 React、React Router 与 fumadocs，上下文才对得上。
不依赖合并检查包；gwb-collab 反过来依赖它。

## 不做的事

- **不运行 git、不连 Gitea、不算通知**：本机身份由基础包按身份码认，通知与项目负责人由 gwb-collab 推来，提交审核、自动同步在 gwb-collab，自动合并在 NAS 上的执行器。理由见 [AGit 与 gwb 分工](/trajectory/2026-09-25-agit-lanes-and-gwb)、[git 状态交给插件追踪](/trajectory/2026-09-30-git-status-in-plugin)
- **不做页面、侧栏、搜索、评论、身份，不启动站点**：都用基础包与 gwb-docsite 的，功能包不另加页面规则。理由见 [搬到文档站基础包](/trajectory/2026-10-11-collab-site-on-docsite-kit)
- **不写站点骨架**：骨架只由基础包的模板与 gwb-docsite 的初始化写，功能包只交出出口和日志页的集合。理由见 [协作站按功能包约定接上](/trajectory/2026-10-11-collab-site-as-feature-package)
- **不定数据格式、不查合并请求**：分别在数据模型包与合并检查包
- **不让网页指定作者**：新记录的作者是本机身份
- **网页上不写日志**：日志页由 AI 写进 `journal/`、提交审核，网页只看
- **不自动处理冲突、不替人纠错**：读不出的文件、校验不过的记录如实列出，由人配合 AI 解决

## 页面与路由（原「页面怎么写」）

协作仓 `site/` 里的页面照文档站基础包写：放在 `content/` 下，MDX、TSX（`名字.page.tsx`）、HTML 三种都行，每个文件夹的 `meta.json` 写标题和顺序。
怎么写、能用哪些组件、评论怎么存，看基础包自述站（单元 `oz47p-docsite-kit` 仓 `docsite-kit` 的 `site/`）的「写一页说明」「三种页面」「评论」几页。协作站多出来的只有下面几条。

## 不能用的地址

`tasks`、`calendar`、`comments`、`api` 是站点自己的路由，`content/` 下第一层不能用这几个名字，占用了开发服务直接报错，一次列出全部冲突的文件。
`comments`、`api` 是基础包骨架留下的，`tasks`、`calendar` 是协作站路由的第一段：骨架把各功能包路由的第一段都算进去。

## 引用任务

MDX 页面、日志页、评论正文里不用 `import`，直接写 `<RecordLink id="记录 id" />` 引用一条任务或一个模块，显示它当前的标题与状态。
TSX 页面要用就从 `@godcreator/collab-site/ui` 引入，页面要放在站点里（`CollabDataProvider` 下面）才取得到数据。显示什么、删了以后怎样见 [网站内部](/collab/collab/collab-site) 的「RecordLink 与日志里的进展」。

## 正文里的链接

站里的链接都显示成带图标的小卡片（基础包的规矩，见基础包自述站的「写一页说明」）。协作站另外认三种，链接文字空着时显示目标现在的名字：

| 写法 | 显示 |
| --- | --- |
| `[](/tasks/<记录 id>)` | 和 `RecordLink` 一样：任务带状态、模块带截止日的记号 |
| `[](/calendar/2026-10-11)` | 那一天的日志；还没写日志的日子画成虚线 |
| `[说明](repo:<仓>/<路径>)` | 项目文件夹里别的仓的文件，见 [网站内部](/collab/collab/collab-site) 的「repo: 链接」 |

## 日志页不放在 content/

某一天的日志写在站点目录的 `journal/<YYYY-MM-DD>.mdx`，一天一篇，不放进 `content/`；文件名、日历怎么显示见 [网站内部](/collab/collab/collab-site) 的「日历与日志」。

## 移动、改名页面

页面的地址就是它相对 `content/` 的路径，移动、改名以后地址就变。两样东西记着页面的地址：

- **评论**：评论串的 `page` 要改成新地址，不然开发服务直接报错，整个站点打不开（基础包的规矩）
- **任务链接的页面**：任务的 `page` 字段不改，任务那一页上显示「找不到的页面」，不报错；能改这个字段的人在任务那一页上重新选一页。能选的页面是基础包骨架交给布局数据的站里每一页

## 网站内部（原「网站内部」）

功能包分两侧：服务端函数（`src/server/`，在站点的服务端运行，由布局数据 `./site-server` 与 `src/routes/` 里路由模块的 loader、action 调）和界面（`src/ui/`，在浏览器里运行）。

## 数据怎么到页面上

基础包骨架里整站布局的 loader 每次都调功能包 `./site-server` 的 `layoutData`，读一份协作数据：从 `collab/records/` 算出任务与模块，加上人员列表、本机身份、gwb-collab 推来的通知与项目负责人、有日志的日子，
以及骨架交进来的站里每一页（任务链接页面时从里面选）。`./site` 的 `Provider` 用 `CollabDataProvider` 包住整个布局，把它交给下面所有页面，任务页、日历、通知栏、`RecordLink` 都经 `useCollabData` 取同一份：

{/* ref file="../packages/collab-site/src/feature/site-server.ts" lines="4-7" hash="df4a9f5b8b56" blob="01369d4f3b2b" */}

{/* ref file="../packages/collab-site/src/server/index.ts" lines="26-42" hash="9f76ec3c5a99" blob="dedd98507f38" */}

gwb-collab 不往站点发请求，它把通知与项目负责人推进基础包推送通道的频道 `collab`（推送通道怎么工作见基础包自述站的「开发服务插件」页）。
浏览器里推来新的一份，`CollabDataProvider` 先用上它的通知与负责人，再让布局的 loader 重新读一遍。gwb-collab 每次检查完协作仓就推一次，
所以 AI 直接改的、自动同步进来的任务与模块，也在这时出现在页面上：

{/* ref file="../packages/collab-site/src/ui/collab-data.tsx" lines="10-22" hash="f27a56d9d902" blob="1f1f384c53dc" */}

还没推来时通知与负责人为 `null`：通知栏不出现，谁的头像都不标负责人，删任务与模块的请求按「没有负责人」处理。不是 gwb-docsite 启动的站一直是这样。

## 写任务与模块

网页上新建、修改、删除任务与模块，都发 `POST /api/collab`，请求体是 `{ action, record }`。功能包的路由模块 `src/routes/collab.ts` 原样交给 `collabRecordResponse`，
它带上本机身份交给数据模型包的写入规则，通过了才写 `collab/records/` 里的文件，不运行 git：

{/* ref file="../packages/collab-site/src/server/index.ts" lines="64-91" hash="2a8b55bdad0a" blob="dedd98507f38" */}

| 回什么 | 什么时候 |
| --- | --- |
| 200 | 写好了；新建回新记录的 id，删除回删掉的文件 |
| 400 | 请求体不是 JSON、`action` 认不出、多了字段 |
| 403 | 只读：站点不是 gwb-docsite 启动的，或本机身份码不在 `people.json` 里；正文是基础包给的原因 |
| 405 | 不是 POST |
| 422 | 写入规则拒绝，正文是它的原话（比如改了别人任务里不许改的字段、模块下还有任务时删模块） |

{/* ref file="../packages/collab-site/test/server.test.ts" lines="68-86" hash="8d1edcf8c447" blob="76b5b01be85d" */}

界面这边由 `useCollabWriter` 发请求：被拒时把原话抛给表单显示，写好了等布局的 loader 重新读完才返回，所以接着跳到新建的那一页时它已经在了。
页面上显示的永远是 loader 读出的文件，不是网页自己记的改动。

## 任务页与任务那一页

`/tasks` 从上到下三块：人员卡片（`people.json` 里的人，agent 不列）写每人没做完、过期的任务数和负责的模块；甘特图只画模块，每个模块一行，只在截止日画一个记号；
看板放具体的小任务。点人员卡片看板只显示他负责的任务，点甘特图上的模块只显示它的任务，两个筛选同时生效。能写时新建任务、模块在弹窗里只填最少的几项，建好就打开它那一页。

## 日历与日志

日历 `/calendar` 是月历（`?month=YYYY-MM` 看别的月），一周从周一开始；有日志的日子画一个点，模块截止的那天画和甘特图同一套的记号，点任何一天进 `/calendar/<日期>`。

某一天的日志是站点目录里的 `journal/<日期>.mdx`，全项目一天一篇，由 AI 写进文件、提交审核，网页上不能写，不记是谁写的。
功能包模板复制进站点的 `journal` 集合把它编译成页面，路由模块 `src/routes/journal.tsx` 显示它，顶上一条 `JournalDayBar`：回到那一月的日历、前后有日志的日子、当天截止的模块。那一天没有日志时显示「这一天还没有日志」，今天以后的日子写「还没到这一天」。
日志页和别的 MDX 页一样能写 fumadocs 的组件与 `RecordLink`，但不进侧栏的页面树。

`journal/` 里只能放 `<真实日期>.mdx`，不合规矩的文件站点检查报错，布局的 loader 读有日志的日子时也直接报错：

### RecordLink 与日志里的进展

MDX 页面（内容页、日志页、评论正文）不用 `import` 就能写 `<RecordLink id="记录 id" />` 引用一条任务或一个模块：显示记录当前的标题，任务带状态、模块带截止日的记号，点了进它那一页。
指向的记录后来删了写「已删除的记录」，不报错，以前的日志照样打得开：

每条任务、每个模块那一页的最下面是「日志里的进展」，就是日志引用它的反向链接。记录页的 loader 读全部日志页的原文，`journalMentionsOf` 按空行分段，

## 页面上的评论

任务页、任务与模块各自那一页、日志页能和内容页一样写评论：路由表里这几条标了 `comments: true`，基础包的评论接口与启动检查就认这些地址。
路由的 loader 用 `routeCommentData` 取评论数据，页面用 `RouteComments` 包住正文。只认地址的样子，删了任务，批它那一页的评论照样留着。

## repo: 链接

正文里写 `repo:<仓>/<路径>` 链接项目文件夹（协作仓的上一级）里别的仓的文件，文本文件可以带 `#L<行号>`，PDF 可以带 `#page=<页>`。
卡片显示出来时问 `POST /api/repo-links` 能不能打开，点了按回答打开：PDF、图片、网页、视频经 `/api/project-file/` 在浏览器的新标签页里看，
文本文件在开着项目文件夹的 VS Code 窗口里打开并跳到那一行，别的用系统默认程序打开。
本机没克隆那个仓画成灰色，文件不在、路径写错画成红色，原因写在鼠标停上去的提示里。只读的站点（没有本机身份）不碰项目文件夹，链接一律是灰色：

## 通知栏

顶部正中的通知栏列出 gwb-collab 推来的通知，每条的短句、原文、点了去哪都由数据模型包的 [通知模型](/collab/collab-model) 按 `kind` 算，网站自己不拼句子。
按组分三段：协作仓、别的仓、找我的，各一种颜色；别的仓一个仓一行。收起时只写各组几条，没有通知（或还没推来）时整个不显示：

{/* ref file="../packages/collab-site/src/ui/notification-bar.tsx" lines="161-168" hash="71b7dae09823" blob="1ed0c7fdd4cc" */}

插件按此刻的状态算，处理好了就不再推，通知栏里随即消失，没有「已读」。点短句按通知的去处走：任务通知去那条任务那一页；@我与回复我的去评论所在的那一页并打开那串评论
（地址带 `?comment=<评论串>`，不属于任何页面的去全部评论页）；合并请求与 issue 开 Gitea 的网页；没有去处的只显示。理由见 [提示栏取代通知](/trajectory/2026-10-03-notice-bar-replaces-notifications)。

{/* ref file="../packages/collab-site/src/ui/notification-bar.tsx" lines="83-101" hash="8701b3f535c6" blob="1ed0c7fdd4cc" */}

网页上没有提交、同步、交给 AI 的按钮：要交给 AI，就在 gwb 的协作窗格里点那个项目一行上的「交给 AI 处理」，通知栏展开后顶上写着这一句。

## 不做的事

- **不运行 git、不算通知**：通知与项目负责人都是插件推来的，网站只显示
- **不向插件发请求**：交给 AI 在协作窗格里，网页只收推来的数据
- **不检查绕过写入接口的改动**：AI 或别的程序直接改的文件照样读出来显示，读不出的列进问题，校验留给提交审核
- **页面、评论不归这里**：内容页怎么写、评论怎么存照基础包，见 [页面怎么写](/collab/collab/collab-site)
