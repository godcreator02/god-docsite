## 怎么跑

仓根是 pnpm 包工作区：`packages/` 是平台包与功能包，`plugins/` 是两个 gwb 插件，`docs-site/` 是本站，`full-test/` 是全功能测试仓，`demo/` 是本地验收用的演示协作仓（内容是一个真实项目的快照，看实际用起来的样子；不进仓，只在维护者本机上有），`tests/` 是全仓级的检查（端到端检查在 `tests/e2e/`，建站器比对是 `tests/scaffold-check.mjs`，依赖方向与分层的规则是 `tests/dependency-rules.cjs`；各包自己的测试在各包里）。

- `pnpm install` 之后 `pnpm build` 按依赖序构建全部包、插件与站；站点与插件用的都是各包的构建产物，改了包要先构建
- 站点的开发服务交给 gwb-docsite 托管（`docsite.site.add {"dir":"<站点目录>"}`），不在会话里自己 `pnpm dev`；端口不写在站里，启动时挑，地址看 `docsite.site.list` 的 `url`
- 平台模板写出的站点文件只改 `packages/god-docsite/template/`，功能的接线文件只改各功能包的 `template/`；本站与 full-test 的 `app/` 由建站器写出

## 测试分级

慢的测试只有显式命令才跑，默认的 `pnpm test` / `pnpm check` 只跑快的一级：

| 级别 | 内容 | 怎么跑 |
| --- | --- | --- |
| 快 | 各包的单元测试 | 默认：各包 `pnpm test` / `pnpm check`，仓根 `pnpm test` / `pnpm check`。仓根 `pnpm check` 一分钟左右，其中测试半分钟 |
| 慢 | 各包里的 `*.slow.test.ts` | 只有显式 `pnpm test:slow`：包里跑本包的，仓根逐个包跑，近三分钟 |
| 全仓·快 | `pnpm test:deps`、`pnpm test:scaffold` | 显式命令，各几秒钟 |
| 全仓·慢 | `pnpm test:e2e`、`pnpm test:pack` | 显式命令 |
| 行为假设 | `plugins/collab` 的 `tests/verified/` | `pnpm test:verified`：升 git 或关键依赖、动了被测的模块、有人明确要求时才跑 |

慢的标准：真建站、装依赖、构建、启动服务的；或者单独运行这个文件时，vitest 报告里它的耗时（不含启动与 import）超过 2 秒，多是每条测试都建临时 git 仓、调几十次 git 的。
慢的文件名写成 `*.slow.test.ts`：包里的 `vitest.config.ts` 排除它们，`vitest.slow.config.ts` 只收它们，`test:slow` 用的就是后者。
现在有慢测试的包是 code-pin、collab、docfirst、gwb-docsite、gwb-collab；给别的包加第一个慢测试时，同时加 `vitest.slow.config.ts` 与 `test:slow`。

## 检查节奏

跑什么检查只看改到了什么，不看改了多少、升哪一位版本号；改代码、交回、合并、推送、发版都照这张表，没改到的东西不查：

| 改到了什么 | 跑什么 |
| --- | --- |
| 某个包的代码 | 那个包的 `pnpm --filter <包> check`（先 typecheck 再 test，有 lint 的再 lint） |
| 碰到了慢测试测的代码 | 再跑那个包的 `pnpm --filter <包> test:slow` |
| 上游包的类型或导出 | 先构建上游，再跑受影响的下游包 |
| 包里会显示在站点上的行为（组件、路由、样式） | 先 `pnpm build`，再 `pnpm test:e2e --skip-build`，一分半 |
| 包的 `package.json` 的 `exports`、`files`、依赖 | `pnpm test:pack`：把包打成 tarball 装进测试站的副本，查漏打包的文件、写错的出口，近三分钟 |
| 包之间或包内 `core/`、`node/`、`site/`、`cli/` 之间的 import | 先 `pnpm build`，再仓根 `pnpm test:deps`：按 `tests/dependency-rules.cjs` 查依赖方向、分层与环，没有豁免清单，报出来的都要改掉 |
| 平台模板或功能包的模板 | `pnpm test:scaffold`：比对测试站、本站和建站器生成的是否一致，几秒钟 |
| 插件 | 插件的 `check`，碰到慢测试再跑 `test:slow`；再用 `devkit.dev` 装进隔离 home 看一眼。测试站不加载插件，`test:pack` 也不打包插件，这两项对插件查不出东西 |
| 升 git，或 gwb-collab 的 `src/organization/setup/`、`src/other-repos/fetch/` | `plugins/collab` 里 `pnpm test:verified` |
| 本站的页面或被钉的代码 | 在 `docs-site/` 里 `pnpm doc`（就是 `docfirst check`），按说明书 [docs-site](/docs/outputs/skills/docs-site) 处理黄灯 |
| 升大家共用的依赖（fumadocs、react-router、vite、catalog 里的版本） | 仓根 `pnpm verify`：`pnpm build` → `pnpm check` → `pnpm test:slow` → `pnpm test:deps` → `pnpm test:scaffold` → `pnpm test:e2e`，五六分钟；再 `pnpm test:pack`。只有这时哪个包都可能坏 |

本站自己的检查在 `docs-site/` 里跑：`pnpm doc`、`pnpm typecheck`、`pnpm test`、`pnpm build`。

端到端检查 `pnpm test:e2e` 直接在测试站 `full-test/site` 上启动 dev 与 build + start 各跑一轮浏览器检查，一分钟左右。dev 一轮写评论、任务和页面，只写本次运行新建的，跑完删掉；start 跑的是只读的发布版，那一轮核对写不进去。最后核对测试站的 `git status` 和跑之前一样。

## 提交

- 一个提交一件事，提交信息用中文
- 同一个仓常有别的会话在改：新文件用 `git add <自己的路径…>`，提交一律 `git commit --only <自己的路径…>`
- 代码、文档、轨迹卡放进同一个提交；改了被钉的代码，同一个提交里处理它引起的黄灯
- 改了生成物的正本（`content/docs/outputs/` 下）就在 `docs-site/` 里 `pnpm doc:render`，正本与生成物放进同一个提交

## 发版

只用工作台命令 `devkit.release`。升哪一位、发版的每一步，每次都先读说明书 gwb-release，包按依赖序发。

发版前的检查照上面「检查节奏」那张表，看这次要发的改动改到了什么。`devkit.release` 发之前自己会构建，并照 `files` 核对产物、查产物里相对 import 指向的文件都在、插件的 peer 与样式合不合规矩，所以从干净的工作树发时检出后只装依赖，不另跑检查。发了协作相关的包或插件之后，照 [协作站双人回归](/maintain/collab-regression) 走一遍。

包发到 npmjs，本机不直接发——从本机到 npmjs 走六步，每处做什么、传什么、卡在哪一步会怎样：

<ReleaseFlow />

- **过渡期同时发 Gitea**：各 home 还从 Gitea 装 `@godcreator` 的包。本机 `~/.npmrc` 里 `@godcreator` 的范围行指向 Gitea，`devkit.release` 照这一行先把同样的包发一份到 Gitea（同号已在那里就跳过），再走 npmjs 那一段，不用另加参数
- **新加一个包**：npmjs 上要先有这个包才能登记谁能发它，命令要在有终端的地方运行（npm 在那里才给出网页批准链接并等着）：
  - 发一个 `0.0.1-stage` 占位版（npmjs 不收 `0.0.0-stage`）：`npm publish <目录> --auth-type=web --access public --tag stage --registry https://registry.npmjs.org/ --@godcreator:registry=https://registry.npmjs.org/`，在浏览器里批准。
    `~/.npmrc` 里 `@godcreator` 的范围行指向 Gitea，它比 `--registry` 优先，不带最后那个参数就发到 Gitea 去了
  - 登记：`npx npm@12 trust github <包名> --repository=godcreator02/god-docsite --file=publish.yml --allow-publish --yes --registry=https://registry.npmjs.org/`。npm 11 发的登记请求 npmjs 回 400，`--allow-publish` 是 npm 12 要求的权限参数
  - 批准页勾上「5 分钟内不再验证」，一批包只验证一次；登记后两天内要正式发一次，不然登记作废
- **工作区不干净时发版**：`devkit.release` 只从干净的工作区发。别的会话有没提交的改动时，用 `git worktree add --detach <仓外目录> <已推送的提交>` 检出一份、`pnpm install --frozen-lockfile`，从那里发，发完删掉
- 演示站 `demo/` 不进仓（见轨迹卡 [演示站改成本地验收站](/trajectory/2026-10-16-demo-local-only)），公开仓里只有测试站与本站
