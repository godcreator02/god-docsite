title: Next docfirst 站迁到平台
description: 用 Next 与 @godcreator/docfirst-workflow 建的旧文档站，怎么换成 god-docsite + docfirst：骨架从哪来、每类差异怎么改、怎么验收、遇到过的问题

没有升级命令：旧站与平台站的路由、页面 loader、功能包接线全都不同，逐个文件把 Next 改成 React Router 不划算。
做法是在空目录用 `docfirst.create` 生成一套新站，把建站器负责的文件整份换进旧站，`content/` 的正文留着，再逐类处理差异。
第一个这样迁过来的是 gwb-vscode 的 `docs-site`（Next 16 + docfirst-workflow 0.5.2，14 个 mdx、一个讲解组件）；
第二个是 gwb-windows-backup 的 `docs-site`（docfirst-workflow 0.5.2 + docfirst-explainer 0.1.1，29 个 mdx、六个用讲解组件包画的组件），讲解组件包怎么换出自这一次。
之后 gwb-gitea、gwb-unit-folder、gwb-nas-suite、gwb-mineru、gwb-agents 五个站照这页迁过，组件样式写在全站 CSS 里、组件没有数据文件这几条出自它们；
再之后 lceda-studio、gwb-block-note、gwb-cgm-alert、gwb-qq-bot、codedoc_fpga_customperiph、gwb-ui-plugins、gwb-base-plugins 七个站由 ZCode 照这页迁、Claude 复查提交，
生成正本里的组件、正文里的 `fumadocs-ui` import、没有轨迹卡的旧站、仓根脚本用 `--filter` 这几条出自它们；
页数上百的 gwb-kernel、gwb-lifecycle-plugins、gwb-paper-fetch 也照这页迁过，仓根 `allowBuilds`、卡的 frontmatter 写法、跨区共用组件这几条出自它们。

开始前站点要停着，`git status` 里没有别人在 `docs-site/` 下未提交的改动。
站是仓根 pnpm 工作区的成员时（仓根 `pnpm-workspace.yaml` 的 `packages` 里列着 `docs-site`），先从那里去掉：平台站自带 `pnpm-workspace.yaml`，留在里面就是工作区里嵌套工作区。
去掉后在仓根 `pnpm install`，锁文件里站的那一份依赖跟着删掉，一起提交。
仓根 `package.json` 的脚本用 `pnpm --filter <站的包名> …` 调站里命令的（gwb-base-plugins 的 `doc`、`doc:confirm`、`doc:render`），站移出工作区后 filter 找不到它，改成 `pnpm -C docs-site run …`；
为了排除站写的 `--filter=!<站的包名>`（gwb-kernel 的 `build`）一起去掉。
仓根 `pnpm-workspace.yaml` 的 `allowBuilds` 不要跟着站一起删：注释写着「文档站带进来的」也先在锁文件里查清是谁带的，gwb-lifecycle-plugins 的 `esbuild`、`@parcel/watcher` 实际是插件的依赖带的，
删了仓根 install 报 `Ignored build scripts` 退出码 1，pnpm 还往 `pnpm-workspace.yaml` 里写一段占位设置，要整段改回。
仓根锁文件除了删掉站的那份依赖，别的条目会重新排版；核对新增的条目旧锁文件里都有，就没有版本变化。

## 1. 生成骨架

```text
docfirst.create {"dir":"D:\\gwb-docfirst-migrate\\<仓名>\\docs-site","title":"<站名>"}
```

- 上一级目录要先建好；站名用旧站 `src/lib/shared.ts` 里的 `appName`，没有这个文件的（gwb-unit-folder）在 `src/lib/tree.ts` 的 `zoneTree()` 里
- 放在 D 盘的空目录里，不放系统临时目录：在临时目录里 vite 报 `pluginutils` 没有 `createFilter`，服务起不来
- 回执的 `features` 列出装好的功能（code-pin、comments、explainer、trajectory）；骨架留着，下一步从它复制

## 2. 换进建站器负责的文件

从骨架复制到旧站的 `docs-site/`：

| 复制 | 说明 |
| --- | --- |
| `app/` 整个目录 | 路由、布局、首页、各功能的接线文件 |
| `vite.config.ts`、`react-router.config.ts`、`source.config.ts`、`tsconfig.json` | 构建与类型检查 |
| `.gitignore`、`pnpm-workspace.yaml`、`pnpm-lock.yaml` | 安装设置与锁文件 |
| `docsite.json`、`people.json`、`glossary.json`、`comments/.gitkeep` | 身份文件是 `{ "kind": "docs", "format": 1 }`，没有它 `docsite.site.*` 拒绝托管 |
| `package.json` 的 `type`、`scripts`、`dependencies`、`devDependencies` | `name`、`version`、`description` 留旧站的；旧站的 `"docfirst": "docfirst"` 脚本骨架没有，不用留，`pnpm exec docfirst …` 照样能用 |

骨架的 `content/start.mdx`、`content/future/overview.mdx`、`content/docs/outputs/` 下的正本与 `trajectory/2026-01-01-site-born.md` 不复制：旧站有自己的生成正本、未来区与根卡。

再删掉旧站的 Next 文件：`src/app/`、`src/lib/`、`src/proxy.ts`、`src/components/mdx.tsx` 与 `registry.ts`、`next.config.mjs`、`postcss.config.mjs`、
`scripts/verify-roster.mjs`、create-fumadocs 留在站目录里的 `README.md`。`registry.ts` 与 `verify-roster.mjs` 是核对组件名册两边一致用的，
新站的组件由页面自己 import，名册只剩 `docfirst.config.mjs` 一处。已跟踪的文件用 `git mv` / `git rm`，挪动的历史留得住。
站里别的脚本只测 Next 那套文件的（codedoc 的 `scripts/verify-markdown.mjs` 测的是 `src/lib/` 里的文件），随 Next 文件一起删。

构建产物与旧依赖也删掉：`.next/`、`.source/`、`out/`（旧命令行写出的各页机读文本 `*.mdx.ai.md`）、`node_modules/`、`next-env.d.ts`、`tsconfig.tsbuildinfo`，然后 `pnpm install`。
新的 `.gitignore` 不再忽略 `.next/`，不删它就出现在 `git status` 里；仓根 `.gitignore` 里专给旧站产物写的规则（`docs-site/.next/` 这类）一起删掉。
`next dev` 在站目录里写过 `AGENTS.md`、`CLAUDE.md` 的（旧 `.gitignore` 忽略、没有跟踪），换了 `.gitignore` 后会露出来，一起删。

站里还有这几样的，照下面处理：

- **`.ledger.json`**：记录还写在这个文件里时用的记录簿。旧站在 docfirst-workflow 0.5.x 上 `pnpm doc` 全绿、页面里的 `ref` 记号都带着 `hash` 与 `blob`，就说明记录早已写进记号，这个文件没人读了，`git rm`（plecs-studio 是这样）。
  记号还没带记录的站不能照这页迁：新 docfirst 不认没有记录的正式记号，也没有把记录簿写进记号的命令，停下来问人
- **站目录自己的 `.npmrc`**（plecs-studio 的写着旧的本机源与 `auto-install-peers`）：删掉。pnpm 不读项目级 `.npmrc` 里的安装设置，骨架的 `pnpm-workspace.yaml` 已经写好
- **`public/`**：照留。平台站的开发服务把它放在站点根上（实测过），构建时 Vite 默认把它复制进产物，页面里写的绝对地址（anpc-lcl 的 `/figures/…`、plecs-studio 轨迹卡里的 `/trajectory/<目录>/x.png`）不用改，
  `/trajectory/` 底下的文件也不会被卡页路由拦住。新加的图仍放进页面的同名文件夹
- **`content/` 下的空目录**（plecs-studio 的 `spec/`、`feedback/`，git 不跟踪）：删掉，不然侧栏会多出空的一项

## 3. 每类差异怎么改

### 分区与侧栏

旧站每个区一个 Next 布局（`/docs`、`/future` 各一个侧栏）；新站只有一棵页面树，顶上的下拉框切换各区：

- `content/meta.json` 写站名与 `pages`，如 `{ "title": "gwb-vscode", "pages": ["docs", "future"] }`
- 每个区的 `meta.json` 加 `title` 与 `"root": true`
- 地址不变：`content/docs/x.mdx` 还是 `/docs/x`，站内链接不用改
- 旧站给某个区单独写了 Next 布局的（plecs-studio 的 `sweep/`），新站里它只是 `content/` 下又一个目录：`meta.json` 加 `title` 与 `"root": true`，目录名加进 `content/meta.json` 的 `pages`
- 旧站自己写的、平台没有对应的页面（plecs-studio 的轨迹卡目录 `/trajectory/browse`，按日期列卡、按关键词与领域筛），迁过来就没有了：新站里这个地址被卡页路由接走、回 404。
  删掉还是在站点 `app/routes/` 里照新平台重写，问人定；删掉的记进迁移卡
- 旧 `next.config.mjs` 里的历史跳转（gwb-base-plugins 的 `/docs/roadmap` → `/future/roadmap` 等）新站没有对应，删了以后旧地址回 404。先查站内有没有链接指向它们，有就改链接；跳转本身不补，记进这个站的迁移卡
- `content/` 根上不放 `index` 页。首页是 `app/routes/home.tsx`；旧站多是把 `/` 跳到 `/docs`，新站首页写站名、一句介绍和去文档的链接：骨架首页里那句「这是站点的首页，写在 app/routes/home.tsx 里。」换成这个站的介绍

### 轨迹卡

`content/trajectory/` 整个挪到站点根 `trajectory/`，删掉里面的 `meta.json`：那是旧站给星轨盘入口排侧栏用的，新站的入口由 trajectory 功能放在侧栏站名下。
卡的地址还是 `/trajectory/<卡身份>`，正文里的卡链接不用改。
旧站一张卡都没有的（codedoc_fpga_customperiph），照说明书 `trajectory` 的卡格式新写一张根卡，`born-at` 取建站那次提交的时间，再写迁移卡。
旧卡的 frontmatter 值里有「冒号加空格」的（gwb-lifecycle-plugins 一张卡的 `title`、`label` 含 `catalog: `），新 docfirst 读成嵌套映射报 `Nested mappings are not allowed`：
只给这几个值加引号，正文不动。卡里链到旧跳转地址的链接（gwb-kernel 约 30 处）照旧留着，卡只增不改，在迁移卡里记一句。

### 讲解组件

新的 docfirst 只核对现状区里与站点 `app/components/` 下的组件源码，站目录下 `src/components/` 里还有文件就直接报错，不会悄悄少核对一批钉码：

{/* ref file="../packages/docfirst/src/project.ts" lines="76-84" hash="cc64e38b44df" blob="f6eb46f4a4d7" */}

先按每个组件被哪几页用到分好去处，再挪：

- 只给一页用的组件挪进那一页的同名文件夹：gwb-vscode 首页 `content/docs/index.mdx` 用的接缝图挪进 `content/docs/index/`，在侧栏里不会多出一组；
  gwb-windows-backup 的 `windows-backup/health.mdx` 用的选情况组件挪进 `windows-backup/health/`
- 同一组里几页共用的放进组里 `_` 开头的文件夹：gwb-windows-backup 的接缝图 `SeamMap` 由 `docs/index.mdx` 与 `docs/windows-backup/index.mdx` 共用，
  和两张图共用的图标、几个组件共用的样式一起放进 `content/docs/_shared/`。跨组共用的才放站点 `app/components/`，放之前先问人：
  gwb-paper-fetch 的 `icons.tsx`、`file-tree.tsx`、`paper.css` 被 docs 与 paper-data 两区的组件共用，问过人后放进了 `app/components/`。交给 ZCode 批量迁时它没法停下来问，回报里要单列出来，提交前由派任务的一方问
- 页面开头加 import，路径相对页面：`import { VscodeSeams } from './index/vscode-seams'`、`import { SeamMap } from '../_shared/seam-map/seam-map'`。旧站靠全局组件表，页面里不用 import
- 去掉文件头的 `'use client'`：React Router 站没有服务端组件
- 站自己的组件样式：旧站在 `src/app/global.css` 里统一引（gwb-windows-backup 是 `@import '../components/backup.css'`），新站的 `app/app.css` 是骨架的，不再引它们；
  改成每个组件开头 `import` 自己用到的样式文件，几个组件共用的那份放进上面的 `_` 文件夹、各自 import。
  组件的颜色变量与类直接写在 `global.css` 里的（gwb-gitea 的 `--gitea-seam-accent`、gwb-unit-folder 的 `.uf-seams`、gwb-nas-suite 的 `--seam-*`），
  删 `src/app/` 之前先把这几段挪成组件旁的 `.css`：三条验收命令都不会因为它们丢了报错，组件只是悄悄没了颜色
- 用在生成正本里的组件（gwb-qq-bot 的 `qq-bot-plugin-api.mdx` 用 `RegistrationLife`）：正本里写 import 会让 render 拒绝生成。
  组件照样放进正本的同名文件夹，再登记进站点的全局组件表 `app/lib/mdx-components.tsx`，正本不 import 也能写；render 后看生成物逐字没变
- 组件之间借用别的组件的样式文件的（gwb-block-note 的 `comment-edges.tsx` 借 `technical.module.css`），样式跟着它的主人走，借用的一方改成相对路径 import
- 旧站用脚本按目录生成组件汇总表的（plecs-studio 的 `scripts/explain-index.mjs` 生成 `src/components/explain/index.ts` 与 `index.ai.mjs`，再交给全局组件表与 `docfirst.config.mjs`），
  脚本和两份汇总表一起删：页面各自 import 组件，`docfirst.config.mjs` 逐个 import 各组件的 `.ai.mjs` 规则
- 机读规则用 `readFileSync(new URL('./x.data.json', import.meta.url))` 读数据的（anpc-lcl 的 `ring-down.ai.mjs`），数据文件跟组件挪进同一个文件夹，路径不用改
- 站里组件直接 import 的第三方包（anpc-lcl 的 `math.tsx` 用 `katex`）写进站的 `package.json` 依赖：骨架只带了 `rehype-katex`，pnpm 不让代码 import 没声明的包。
  旧站声明了却没有代码在用的包（anpc-lcl 的 `motion`）不带过来
- 组件没有 `.data.mjs`、机读文字直接写在 `docfirst.config.mjs` 里的，规则照抄，只改注释里的组件路径，不用补下面的 `.d.mts`
- 数据文件保持 `.mjs`（`docfirst.config.mjs` 在 Node 里直接 import 它），旁边补一份同名的 `.d.mts` 写出导出的类型。
  旧站的 `tsconfig.json` 开着 `allowJs`，类型是推断出来的；新站不开，不补就报 `TS7016: Could not find a declaration file for module './vscode-seams.data.mjs'`。
  数据文件里写了 JSDoc 的，让 tsc 生成草稿再整理：

  ```text
  pnpm exec tsc --ignoreConfig --allowJs --declaration --emitDeclarationOnly --skipLibCheck --module esnext --moduleResolution bundler --target esnext --types node --rootDir content --outDir <临时目录> <数据文件…>
  ```

  命令行上直接给文件时 TypeScript 6 要 `--ignoreConfig`，不加就报 `TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline`

#### 换讲解组件包

用到 `@godcreator/docfirst-explainer` 的组件换成平台的 `@godcreator/explainer`，只换 import。
`@godcreator/explainer-player` 是 docfirst-explainer 改名前的包名（anpc-lcl 用的 0.1.1），入口与构建产物和 docfirst-explainer 0.1.1 一样，
只差样式里 `.dx-caption` 的 `max-width: 70ch`，新包没有这条，说明文字会铺满整行；下表左列的包名换成 `explainer-player` 照样适用：

| 旧站里写的 | 换成 | 取的是什么 |
| --- | --- | --- |
| `'@godcreator/docfirst-explainer'` | `'@godcreator/explainer/site'` | 三种外壳 `Stepper`、`Timeline`、`CasePicker`，零件 `Pane`、`Pill`、`Dot`、`Terminal`、`CodeLines`、`Diff`，接缝图 `SeamDiagram`、`cap` 与类型 `SeamLayout` |

| `global.css` 里的 `@import '@godcreator/docfirst-explainer/styles.css'` | 删掉 | 站点的 explainer 功能已经把包的样式接进全站 |

### Note 组件与 fumadocs-ui 的 import

旧站的 `src/components/mdx.tsx` 自己定义了 `Note`；新站的组件表里没有它，`fumadocsRoster` 只给它在生成物里的机读规则。
页面里用到 `<Note>` 的，现状页改成 fumadocs 的 `<Callout>`；生成正本里的改成引用块，名册里没有 `Callout` 的机读规则，用了 `pnpm doc` 报红。

正文里 `import { Steps, Step } from 'fumadocs-ui/components/steps'` 这类 import（codedoc 有八页）直接删掉：新站装的是 `@fumadocs/base-ui`，没有 `fumadocs-ui` 这个包名，
import 解析不了；`Steps`、`Step`、`Accordion`、`Accordions`、`ImageZoom` 平台的组件表已经提供，页面不 import 就能写。

### 术语表

旧站把术语表写成数据文件的（gwb-windows-backup 是 `src/glossary.data.mjs`，由 `src/lib/source.ts` 交给术语标注；plecs-studio 是 `src/glossary.ts`，导出 `TermEntry[]`），
转成站点根的 `glossary.json`，每条照抄 `term`、`def`、`href`，`aliases` 没有就不写。
数据文件头注释里的收词判据没地方放了，挪进术语页正文。用这份数据画术语页的组件跟着改：

- 画面 `import glossary from '../../../glossary.json'`（路径相对组件），站内链接的 `next/link` 换成 `fumadocs-core/link`
- 机读规则在 Node 里读同一份，写成 `import glossary from '../../../glossary.json' with { type: 'json' }`

### 生成物

迁完第一次 `pnpm doc` 对生成物报红：新渲染器写出的 Markdown 跟旧的不一样。`pnpm doc:render` 后在仓根 `git diff` 逐处看：

- 列表记号 `*` 变成 `-`、表格空格子 `| |` 变成 `|  |`：读出来一样，直接接受。随包的 SKILL.md 只变了这些时不用为它发插件新版。
  正本本来就写 `-`、表格没有空格子的（gwb-windows-backup），render 后没有这类差异
- 裸写的网址：doc-export 0.1.0 会把它写成 `[网址](网址)`，后面紧跟全角标点时连标点带后文一起写进链接（`http://127.0.0.1:4313），不用` 写出成
  `[http://127.0.0.1:4313），不用](http://127.0.0.1:4313），不用)`）。之后的版本照原文写出；站里装的还是 0.1.0 时，把网址放进反引号，或改写那一句
- 旧站 AGENTS / README 正本里「先 `pnpm build` 再 `pnpm start`（端口 43xx）」「`pnpm dev`，端口 43xx」这类说法都过时了，
  改成开发服务由工作台托管：`docsite.site.add {"dir":"<站目录>"}`，地址看 `docsite.site.list`；正本里说说明书属于 `@godcreator/gwb-docfirst-workflow` 的，改成 `@godcreator/gwb-docsite`
- 未来区 `inbox/` 里要求升级 docfirst-workflow 或 fumadocs 的反馈，迁完站里已经换成骨架带的版本，删掉；别的反馈（如立创行为的）照留

钉着站外文件的页（gwb-ui-plugins 的 `dev.mdx`、gwb-base-plugins 的 `develop.mdx` 钉站的 `package.json`、`docfirst.config.mjs`、仓根 scripts）因为迁移改了这些文件会亮黄灯，
未提交时算红：照说明书 `docs-site` 逐条看，论断还成立就 `pnpm doc:confirm <页> --accept`；不成立的先改正文（gwb-base-plugins 的「工作区是 `plugins/*` 与 `docs-site`」改成文档站不在工作区里）。

## 4. 验收

在站目录依次运行，三条都要退出码 0：

```text
pnpm doc
pnpm typecheck
pnpm build
```

再 `docsite.site.start {"dir":"<站目录>"}`，请求首页、各区首页、一张卡页、`/llms.txt`，都回 200。没有 index 页的区（未来区常常只有 `roadmap.mdx`）请求区的地址是 404，
下拉框点进去去的是它的第一页，验收时请求第一页。有 `public/` 的站，再请求几张页面里用到的图片地址。有讲解组件的页，照 `docs-site` 说明书的「讲解组件截图验收」每个组件截浅色、深色、375 宽各一张逐张看，
动画拖到中段与后段再截；然后 `docsite.site.stop`。要常驻的站改用 `docsite.site.add`。

页面里 import 组件的相对路径算错了层级，`pnpm typecheck` 发现不了（它不解析 mdx 里的 import），要到 `pnpm build` 才报 `UNRESOLVED_IMPORT` / `Module not found`；
同名文件夹本身是路径的一段，`content/docs/x/index.mdx` 到 `content/docs/_shared/` 是 `../_shared`。

开发服务的日志里 `Failed to resolve dependency: @godcreator/code-pin > @types/mdast, present in client 'optimizeDeps.include'` 每个平台站都有，骨架站也有，不影响页面。

## 5. 提交

站的全部改动放进一个提交：删掉的 Next 文件、挪动的卡与组件、复制进来的骨架文件、改过的正本与重新生成的生成物，再加一张这个站自己的轨迹卡，记下这次迁移和没做完的事。
`git add` 新文件、`git commit --only` 列出全部路径，别的会话未提交的文件不收进来。

## 遇到过的问题

- 本机的删除守卫拦下了 shell 里带变量路径的 `Copy-Item -Recurse`、`git rm -f`：复制骨架与删构建产物写成 Node 脚本，路径作参数传入
- 旧 `node_modules/` 里有超过 260 字符的路径，`git status --ignored` 报 `Filename too long`；删掉旧依赖重新安装后就没有了
- 轨迹卡 `git mv` 到站点根以后紧接着 `git rm trajectory/meta.json`，git 报 `the following file has changes staged in the index`：刚挪的文件还在暂存区里，要加 `-f`
- 旧页面 frontmatter 里的 `full: true` 不再生效：平台的页面组件不把它交给 fumadocs 的 `DocsPage`，正文旁边照样有目录栏。
  gwb-windows-backup 两张 1200 宽的接缝图因此在 593 宽的正文里横向滚动，图本身画全了；这是平台包的事，迁移时不改页面
- 旧站 `global.css` 里给 `@theme` 设的字体（如更纱黑体）不在骨架的 `app/app.css` 里，迁过来用的是平台默认字体
- 有的页面是 CRLF 行尾（gwb-base-plugins 的 `mcp.mdx`）：批量给页面插 import 的脚本只认 LF 就会漏掉它，插入时跟着文件自己的行尾
- `pnpm exec docfirst trajectory` 文本输出的卡数不算根卡，新卡写好后数字看着少一张时用 `--json` 看 `cards`
