## 依赖方向：只有一个文件在检查

pnpm 严格的 `node_modules` 只保证没写进依赖的包 import 不到；「该不该写进依赖」没人管，workflow 包里
`marker/`、`reference/`、`mdx/`、`pinning/`、`project/`、`cli/` 之间编译器也不拦——`mdx/` 里写一句 `import "../project/load.ts"` 不会报错，
mdx 格式从此就跟读盘、git 绑在一起。补上这两项的是 `tests/boundary.test.ts`，它是包之间、workflow 目录之间**唯一**的边界检查。

## git 那一侧：真 git 仓，不打桩

这一侧的行为几乎全看 git：blob 取不取得到、`diff -U0` 的 hunk 头长什么样、`status --porcelain` 列出哪些路径。
打桩测的是对 git 的假设，所以这几组都调真 git：

- `tests/git-history.test.ts`：比较器接上 git 版旧内容来源之后的跟随、退回滑窗、取对象的次数
- `tests/reader-tree.test.ts`：目录树按 `.gitignore` 过滤、软链接按真实路径读
- `tests/cli-uncommitted.test.ts`：本仓未提交改动引起的黄灯算红（见[门禁](/docs/pin/gate)）
- `tests/hash-text.test.ts`：自己算的 blob 名跟 `git hash-object` 逐字节相同

`tests/repo.ts` 建的临时仓一律 `core.autocrlf=false`，否则 Windows 上的换行转换会让工作区和 blob 逐字节不同：

## 装配、摆放、命令行

装配的归一（内容根、`outputs` 的两种写法、文档身份）经 `loadProject` 看，在 `tests/project-load.test.ts`。
摆放用 `PlacingHost` 的两个适配器测：`tests/placing-host.test.ts` 的落点是内存里一张表，一个字节不落盘；
`tests/placement.test.ts` 在临时目录建真项目，`loadProject` 之后直接调摆放的方法，不经命令行。
命令行把结果打印成什么、退什么码，在 `tests/cli*.test.ts` 那几份。

轨迹核心的测试是 `tests/trajectory-*.test.ts`，星轨盘相关的几份用 `tests/fixtures/trajectory/` 下的卡片；术语标注在 `tests/glossary.test.ts`，
fumadocs 适配不接 Next 的那一半在 `tests/fumadocs.test.ts`，讲解组件包在 `tests/docs-explain.test.ts`，
各包能装、能出产物、出口解析得到在 `tests/skeleton.test.ts`。

## 插件那组

除了一条慢测试，插件的测试只传入输入看输出，不启动进程、不打开窗口：建站参数与模板（`create.test.ts`）、本机约定怎么改官方脚手架的输出
（`scaffold.test.ts`，对照的是存在 `tests/fixtures` 下的样本）、端口挑选（`ports.test.ts`）、产物与依赖（`artifact.test.ts`）。
真运行官方脚手架的 `scaffold.slow.test.ts` 要联网，只在 `pnpm test:all` 里跑。插件怎么工作见[工作台插件](/docs/plugin)。

## 站也是使用者，也是一组测试

`docs-site/` 就是「装了这几个包的项目」：项目根是站目录，被钉的代码在工作区的 `packages/` 与 `plugins/` 下，
记号写 `../packages/…` 或 `../plugins/…`。仓里因此不另留示例项目。

{/* ref file="docfirst.config.mjs" lines="4-4" hash="8afea51faa05" blob="ef8b98ac9425" */}

站测试 `docs-site/tests/page.test.mjs` 不启动 Next：`register()` 把 fumadocs 的 Node loader 注册进 Node，`import` 一篇 `.mdx`
经过的就是站构建时的那条处理流程。导入时带 `?macro_id=src/lib/source.ts%23docs`，loader 才用上集合的 `mdxOptions` 与 postprocess。
它断言每条引用在页面上都有带状态点和来源标题的元素、组件没有漏成裸标签、机读版里有来源行且组件已压平成文字，
以及这个站自己全绿：

{/* ref file="tests/page.test.mjs" lines="124-132" hash="10ebafcc9456" blob="5ae8125b5dda" */}

所以每一页钉着的源码一改，`docfirst check` 报出来、站测试直接失败，文档跟不上代码就过不了门禁。
允许不钉码的页由 frontmatter 明说：`docfirst: none` 是明说不钉的页，`docfirst: draft` 是还没写完的页，两样都没写就必须至少钉一处：
