## 知道但没解决的

1. **`remarkInclude` 排在 docfirst 的插件前面**，所以被引入的片段里的引用，`check` 看不到（站上能渲染，因为那时
   片段已经并进来了）。两边的结果不一致，靠「别在被引入的片段里写引用」避开。
2. **行内组件规则只能交回行内节点，没有机制检查**。规则作者在行内位置交回一个块级节点，机读版序列化出来的
   md 会是坏的。规则知道「这处是行内」，但没人检查它交回了什么。
3. **取不到确认时的内容就少了 diff。** 记号上的 blob 名是确认时在进程里算的：确认之后、提交之前又改了文件，
   或者仓里按 CRLF 存，这个 blob 就不在对象库里，核对只能在整个文件里找 hash 相同的那段，找不到报「位置不明」、不给 diff。
   这是有意的降级，记在这儿是为了碰到时知道原因。
4. **站上看不到讲解组件的状态。** 组件源码里的引用只在 `check` 与门禁里报，页面上的组件不带状态点：要在服务端算出组件文件的清单
   再传进客户端组件，多一层传递，先不做。

## 自指带来的一条

这一条是这套机制**用自己写自己**才会碰到的，代码没问题，但得知道：

- **有些源码段不能引用**，因为它们的内容会触发站测试的断言。两处实例：造 diff 块那段源码里带着 shiki 的
  增删标记，放进机读版会触发「机读版不该带 diff 标记」；名册默认表那段注释里带着尖括号包住的组件名，
  会触发「组件没被名册转换」。避开的办法是引用邻近的另一段，正文照常写。

不打算「修」——真要解决，得让站测试的断言只看引用块之外的内容，代价比收益大。

## 待办

- **别的站迁到新结构**：新版本不认 `.ledger.json` 记录簿，也不认草稿记号 `@@docfirst … @@`，没有迁移命令。
  还用记录簿的站先用 `@godcreator/docfirst-workflow` 0.3.x 的 `docfirst migrate-ledger` 把记录写进记号再升；草稿记号改写成
  不带记录的正式记号（`check` 逐行指出来）；把 spec / feedback / outputs 三个旧区挪进 `future/` 与现状区，改配置与路由
  （配置里的 `formats` 那一行删掉，配置文件只认 `docfirst.config.mjs`）。站的 `src/components/` 下的代码文件从此进 `check`，只有写了记号的才报状态。
  经各仓站的 `future/inbox/` 通知。
- **各站的 `has` 记号改成行段**：新版本遇到 `has` 记号直接报错，报错里给出这个格式里改成行段的完整写法。
  钉名字、常量、配置值的改钉那一行；钉测试名、想说「有测试守着这件事」的改钉整条测试（从 `test(` / `it(` 钉到结束行）。
  换成行段后第一次 `confirm` 会多出一批黄灯，逐条复核再 `--accept`。
- **钉在大文件上的整文件引用改成钉具体几段**：如 gwb-ui-plugins 的 `openable.ts`、`open-pane.ts`。整文件只留给几十行以内、
  要说「全部就这些」的短文件。
- **接缝图的接口签名钉在源码上**：接缝图数据里每条接缝的 `iface` 是照抄的函数签名，数量多，还没写记号。
- **下游迁完后删掉已删写法的报错**：`has` 记号与以 `@@docfirst` 开头的一行，现在报错时给出改法，下游九十多个页面还用得上。
- **组件里的源码片段构建时从源码读**：现在组件里手抄的片段靠记号核对，变了就黄；改成构建时现读之后，
  记号只需要管讲解文字还对不对。
