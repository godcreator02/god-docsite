要做什么

正文、标题、代码三种字体由每个人自己选，选一次，这台电脑上 gwb 托管的所有站都生效。站点本身不指定字体：没设的人看到的还是现在的系统默认字体。比如自己把三项都设成更纱等宽（Sarasa Mono SC），别人设他们自己装的字体。

设置放在 gwb-docsite 的设置里，在 gwb 设置窗格的下拉框里选，下拉框列出本机装了的字体。gwb-docsite 把三项写成一个文件，启动站点时用环境变量告诉站点文件在哪；站点每次请求读这个文件，把三个 CSS 变量写进页面。平台和各功能包的组件只认这三个变量，所以全部跟着变。改了设置，刷新页面生效。

fumadocs 自己的 CSS 不设字体（@fumadocs/base-ui 16.17.1 里只有代码块用了 font-mono 类），全靠 Tailwind 的基础样式：html 用 --font-sans，code、pre、kbd 用 --font-mono。所以正文和代码只要换这两个变量，fumadocs 的组件就跟着变；标题另加一个变量 --font-heading。

总图

逐条接缝

1

gwb-docsite 声明三项设置 gwb-settings 新增

设置服务的声明 SettingDef 加一个可选字段 options，服务接口加一个方法 watch：

// gwb-base-plugins/plugins/settings/src/registry.ts
interface SettingDef {
  …
  /** 只能配 type: 'string'。界面画成下拉框；settings.set 写入时值必须在清单里 */
  options?: () => Promise<readonly string[]>
}

// gwb-base-plugins/plugins/settings/src/index.ts
interface GwbSettingsApi {
  …
  /** 自己声明过的一项写进文件之后（不管经命令、界面还是 set），回调拿到 get 会回的值；调用方卸载时自动退订 */
  watch(key: string, listener: (value: unknown) => void): () => void
}

options 配在 string 以外的类型上，define 直接报错。watch 只认调用方自己声明过的键，没声明过就报错，跟 set 的规矩一样。

gwb-docsite 在分区 docsite（身份码 identity-code 也在这个分区）声明三项：

键标题没设时
font-body正文字体站点默认（Tailwind 的 --font-sans）
font-heading标题字体跟正文字体一样
font-mono代码字体站点默认（Tailwind 的 --font-mono）

三项都是 type: 'string'，不写 default，options 都是同一个函数：现列本机字体（见字体清单从哪来）。

2

设置窗格与 agent 怎么选 gwb-settings、baseui 新增

  • settings.all 的行，声明里带 options 的加一个字段 hasOptions: true（函数没法交给页面，清单另取）
  • 新命令 settings.options {section, key}（effect 是 read）：调那一项的 options()，回字符串数组。没声明这一项、或声明里没有 options，报错
  • settings.set：声明里有 options 的，先 await options()，值不在清单里就拒绝，报错里写明用 settings.options 查能填什么。列清单放在写入队列外面做，不让列字体的半秒卡住别的写入
  • settings.delete 不查清单：删掉就是回到默认
  • baseui 的设置窗格：hasOptions 的行画成下拉框，窗格打开时调 settings.options 取清单；第一项是「默认（不设置）」，选它调 settings.delete。acceptSetting 收下 hasOptions 这个布尔字段

agent 经 MCP 走同一套：先 settings.options 看清单，再 settings.set，拼错的名字会被拒绝。

3

gwb-docsite 写字体文件 gwb-docsite 新增

文件放在 gwb-docsite 自己的数据目录：join(ctx.gwbData.dir, 'reader-fonts.json')。格式由 gwb-docsite 定，带版本号：

{ "format": 1, "body": "Sarasa Mono SC", "heading": null, "mono": "Sarasa Mono SC" }
  • 每项是字体族名，或 null（没设）
  • 插件启动时按当前设置写一次；三项各 watch 一次，变了就重写
  • 先写同目录的临时文件再改名（原子写入），站点不会读到写了一半的文件
  • 不用 gwbData.writeDoc：这个文件是给站点进程读的，是 gwb-docsite 和站点之间的约定；writeDoc 在磁盘上存成什么样是 gwb-data 内部的事
4

启动站点时交出文件路径 gwb-docsite 新增

docsite.site.start（以及经它启动的 add、open、gwb-collab 托管的协作站）启动开发服务时，在已有的 DOCSITE_IDENTITY_CODE、DOCSITE_FEED_TOKEN 旁边多给一个环境变量：

DOCSITE_READER_FONTS_FILE=<gwb-docsite 数据目录>\reader-fonts.json

不管有没有设字体都给：文件里全是 null 时站点照默认显示。改字体不用重启站点，因为站点每次请求都读文件。

5

站点读文件 平台包新增

平台包 @godcreator/god-docsite/server 导出 readerFontsCss(): string | null：

  • 没有环境变量 DOCSITE_READER_FONTS_FILE：回 null。手动 pnpm dev、发布版、e2e 测试站都是这样，用默认字体
  • 有环境变量：读文件，按修改时间缓存。文件不在、不是 JSON、format 不是 1、某项不是字符串或 null、名字里有 " ' \ ; { } < > 或换行，直接报错并写明文件路径和哪一项不对。不悄悄改用默认字体：文件是 gwb-docsite 写的，格式不对就是 gwb-docsite 的问题，要马上看得到
  • 回的 CSS 只写设了的项，名字后面接上 Tailwind 默认的那串字体做后备（字体里没有的字，比如英文字体里的中文，浏览器逐字往后找）：
:root {
  --font-sans: "Sarasa Mono SC", ui-sans-serif, system-ui, sans-serif, …（Tailwind 默认的其余几项）;
  --font-mono: "Sarasa Mono SC", ui-monospace, SFMono-Regular, …;
}
6

写进页面 平台模板改动

变量要放在根路由：布局路由 routes/layout 不包首页（index('routes/home.tsx')）和功能的独立页面（featureStandaloneRoutes）。平台模板的 app/root.tsx 加一个 loader，Layout 在 <head> 里输出 <style>：

import { readerFontsCss } from '@godcreator/god-docsite/server'

export function loader() {
  return { readerFontsCss: readerFontsCss() }
}

export function Layout({ children }) {
  // 出错页也用 Layout 渲染，那时没有 loader 数据
  const fonts = useRouteLoaderData<typeof loader>('root')?.readerFontsCss
  …
  <head> … {fonts && <style dangerouslySetInnerHTML={{ __html: fonts }} />} </head>
}

根路由的 loader 在站内跳页时不重新运行（React Router 默认只在参数或查询串变了、或提交表单后重新运行），所以改了字体要刷新页面。这是接受的代价。

root.tsx 是站点自己的文件，平台模板改了，已经建好的站不会自动跟上：docs-site 与 full-test 用建站器重新生成，SST 协作站（chb-dab-sst/collab/site）和别的仓的站手动加这几行，平台的说明页写明升级步骤。

7

各包的组件只认三个变量 平台包与功能包

见下一节。

CSS 约定

约定写在平台包的 styles.css（每个站都经 app.css 引入它），功能包不用知道字体是从 gwb 来的：

@theme {
  --font-heading: var(--font-sans);
}
@layer base {
  h1, h2, h3, h4, h5, h6 { font-family: var(--font-heading); }
}
  • @theme 里声明 --font-heading，同时得到 Tailwind 的 font-heading 类。它默认等于 --font-sans，所以只设了正文字体时标题跟着正文走
  • 根路由输出的 <style> 不在任何 @layer 里，比 Tailwind 主题层里的同名变量优先，直接盖掉默认值
  • h1–h6 那条规则让页面标题、正文标题、评论与协作界面里用标题标签写的小标题都用标题字体

各包的组件只写 font-sans、font-heading、font-mono 三个类，或 var(--font-sans) 等三个变量，不写字体名。现在要改的只有一处：

位置现在改成
packages/explainer/styles/explain.css:29--dx-mono: 'Sarasa Mono SC', ui-monospace, 'Cascadia Mono', Consolas, monospace--dx-mono: var(--font-mono)
packages/trajectory/styles/star.css:39var(--font-sans, system-ui, …)不用改，已经跟着变量走
collab 的 font-mono 类Tailwind 类不用改

两处例外，不跟阅读字体：

  • KaTeX 公式用它自己的字体，不动
  • word-report 的报告页照 Word 排版，固定用报告自己的字体：在 packages/word-report/styles/report.css 里给报告正文的容器写定字体，取导出 Word 用的 .dotx 模板里的那几种（实现时从模板读出来写进去）。现在报告页是跟着站点字体走的，这一步把它固定下来

字体清单从哪来

下拉框里的名字必须正好是 Chrome 在 CSS font-family 里认的名字，否则选了也不生效。实验 probes/2610192151_local-font-family-names/ 在本机把六种来源各列一遍，逐个放进 Chrome 155 无头模式量宽度：

来源名字数Chrome 认问题
注册表 Fonts 键的值名262140字重、斜体写在名字里（Sarasa Mono SC Bold）；随应用装的字体（Cascadia）根本不在注册表里
.NET InstalledFontCollection（GDI 族名）203180字重拆成单独的族（Sarasa Mono SC Light），长名截到 31 个字符
字体文件 name 表的族名122118要先从注册表找文件，跟注册表一样漏字体
WPF Fonts.SystemFontFamilies（en-us 名字）136131不认的 5 个里 4 个是 WPF 自己的组合字体 Global User Interface 等，按 Global 开头去掉；剩 1 个是字体本身的问题

用 WPF：一个字体族一项，不拆字重，用户目录里装的更纱、随应用装的 Cascadia 都在。gwb-docsite 用 pwsh 7 运行：

Add-Type -AssemblyName PresentationCore
[System.Windows.Media.Fonts]::SystemFontFamilies |
  % { $_.FamilyNames[[System.Windows.Markup.XmlLanguage]::GetLanguage('en-us')] }

本机列一遍 0.48 秒。不缓存：每次 options() 现列，装了新字体马上能选到。去掉空名字和 Global 开头的，按名字排序、去重。

检查与验收

  • gwb-settings 单元测试：options 配在非 string 上报错；settings.set 收清单外的值被拒、清单内的写入；settings.delete 不查清单；watch 在命令写入、自己 set、delete 后各收到一次，值和 get 一致，卸载后不再收到
  • 平台包单元测试：readerFontsCss 没有环境变量回 null；三项全 null 回 null；只设一项只出那一个变量；格式不对的几种情况各报错
  • 防止再写死字体的检查：仓根 tests/ 加一个脚本，扫描 packages/*/ 的 css 与 tsx：font-family 声明，以及名字里带 font 或 mono 的 CSS 变量定义，值里只许出现 var(…)、inherit 和通用字体名（monospace、sans-serif 这类）。word-report 的 report.css 是唯一合法写字体名的地方，脚本里写明它和理由
  • e2e：base 组加一轮，启动 full-test 的开发服务时给 DOCSITE_READER_FONTS_FILE 指向本次运行新建的临时文件，查正文、标题、代码的计算字体是文件里写的那几个；不给环境变量的那轮保持默认
  • 在隔离 home 里看一遍（devkit.dev）：设置窗格里三个下拉框能选到 Sarasa Mono SC；选完刷新托管的站，正文、标题、代码都变了；选「默认」后刷新回到原样
  • 讲解组件的图：在 docs-site 上把三项都设成更纱后，把用了 --dx-mono 的图逐张看一遍（浅色、深色、375 宽），标签不超出方框

风险与边界

  • 只对 gwb-docsite 托管的开发服务生效。手动 pnpm dev、发布版（build + start）、e2e 不给环境变量时，都是默认字体
  • 字体跟着开发服务走，不跟着看的人走。别人在局域网里打开你的开发服务，看到的是你设的字体；按现在的做法每个人在自己电脑上开自己的开发服务，两者一一对应
  • 讲解组件的图按现在的字宽画的，换成更宽的字体（更纱等宽）标签可能超出方框，验收时逐张看，超出的改图的尺寸
  • 只做了 Windows：列字体靠 WPF。别的系统上 options() 直接报错，写明这个平台还不支持
  • 清单里偶尔有 Chrome 不认的字体（本机 1 个：HYZhongHei），选了它浏览器用后备字体。不另做过滤

已定的决定

  • 字体是每个人自己的阅读设置，不是站点的设置；站点不带字体文件，只用本机装了的字体
  • 做成 gwb-docsite 的设置（用户：「这样一处设置全局生效」），不用站点里的 cookie 或 localStorage
  • gwb 设置窗格加下拉框（用户：「可以增加下拉框功能」）；值必须在清单里，拼错的名字写不进去
  • 环境变量只交一个文件路径，文件放在 gwb-data 给 gwb-docsite 的数据目录里（用户：「就放 gwbdata」），格式由 gwb-docsite 定、带版本号
  • 改了字体刷新页面生效，不推送给已经打开的页面
  • 三个变量的约定写在平台包，不单独开字体功能包
  • 报告页不跟阅读字体，固定用 Word 模板的字体
