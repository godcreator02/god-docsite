讲解组件里有大量照源码抄来的东西：手抄的源码片段和行号、逐字照抄的测试名、命令行的输出格式、接缝图里的函数签名。
页面正文每一句都有引用盯着，组件里这些却不在任何检查范围里，代码改了没人知道。这次让组件的源码也能挂引用：
被钉的代码变了，组件在 `check` 里变黄，改代码的那个提交被拦下，人去复核组件。

同时删掉草稿记号 `@@docfirst … @@`。它当初是给多种文档格式共用的一行普通文字，现在反而成了负担：
它要先作为 markdown 文字穿过解析，挨着写会被并成一段、路径里的 `__main__` 会变成加粗，一旦穿不过去就静默不认。
未确认改用不带记录的正式记号表示，两种载体都一样。

## 两种载体怎么写

| | mdx 页面 | 讲解组件 |
| --- | --- | --- |
| 哪些文件 | 内容根下 `trajectory/`、`future/` 之外的 `.mdx` | 站的 `src/components/` 下的 `.ts`、`.tsx`、`.mjs` |
| 外壳 | 单独一行的 `{/* … */}` | 单独一行的 `/* … */` |
| 新写（未确认） | `{/* ref file="src/a.ts" lines="2-3" */}` | `/* ref file="src/a.ts" lines="2-3" */` |
| 确认之后 | `{/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */}` | `/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */` |
| 另外能做 | 名册检查、按原文渲染生成物、站上换成代码块 | 只认引用、写回 |

两种外壳里面那一截一字不差，由记号写法（workflow `src/marker/`）一处定义。组件里的记号放在它钉住的那段数据正上方；
一个组件文件里任何一处变黄，就是这个组件要复核。

## 写错了一律报错

- 以 `@@docfirst` 开头的一行：草稿写法已经删了，报错并给出正式记号的写法，不让一处引用悄悄变成普通文字
- 外壳里是「一个词 + `key="value"` 属性」的样子、这个词却不是 `ref` / `tree` / `has`：报错，不当成普通注释
- 正式记号的记录只写了一半（有 hash 没 blob）、值不合法：跟现在一样报错到行

## 首批挂钉的组件

| 组件 | 钉什么 |
| --- | --- |
| trajectory-flow | 手抄的星轨盘页面几行、`loadTrajectory` 的定义、`docfirst trajectory` 的输出格式 |
| boundary-rules | 逐字照抄的边界测试名、禁止表 |
| commit-gate、render-flow | 命令行打印的那几种行、渲染拒绝的说法 |
| ref-kinds | 四类引用的记号写法与校验规则 |
| span-follow | 行段跟随的判断顺序 |

接缝图里每条接缝的 `iface` 抄的是函数签名，数量多，第二批再钉。

## 这次不做

- **站上显示组件的状态**：要在服务端算出组件文件的清单再传进客户端组件，多接一层；先只在命令行和门禁里报
- **组件里的源码片段构建时从源码现取**：那样片段就不用手抄了，钉码只管讲解文字还对不对；先做到「变了就黄」，稳定后再做

## 顺序

每一步单独提交，测试全过再走下一步：

1. 删草稿：未确认改成不带记录的正式记号；`@@docfirst` 行与认不出动作词的记号报错；本仓文档、建站模板、说明书里的草稿写法改掉
2. workflow 恢复格式接口，mdx 格式与新的组件格式（`src/code/`）各实现一份，钉码编排按文件挑格式；现状区文件加上 `src/components/` 下的代码文件；边界测试守住组件格式只认识记号写法
3. 首批组件挂钉并确认
4. 钉码核心、workflow 模块页与接缝图、钉码几页、说明书改成现状；写轨迹卡；删掉这张方案页

## 对下游的影响

跟前面几项放进同一个破坏性版本。各站还没确认的草稿记号要改写成不带记录的正式记号（`check` 会逐行指出来）；
站的 `src/components/` 下的代码文件从此进 `check`，只挂了引用的才会报状态，没挂的不受影响。
