**本页回答**：轨迹核心怎么跟 docfirst 的卡格式分开、分开后每块只认识什么、顺带删掉哪些机制、按什么顺序做。

## 验收

- [ ] 轨迹核心的源码与产物里不出现 frontmatter、关系行、里程碑标题、`.md` / `.mdx` 这些 docfirst 卡格式的写法
- [ ] `buildModel` 只收中性输入；`serial.ts`、`RouteCard`、`Trajectory`、`toRuntimeModel` 不存在
- [ ] docfirst 卡格式在 workflow 的 `src/cards/`，边界测试守住它不被轨迹核心 import
- [ ] fumadocs 卡集合与链接改写用 workflow 的解析器，gray-matter 那一份校验删掉
- [ ] 容错改成报错，断掉的关系与指向根卡的关系算病卡，fixture 改用标准链接
- [ ] 下面「一起收掉的」逐条做完；「实测再定的」有截图对比和结论
- [ ] 各站的盘页模板一个字不改就能用上新版本
- [ ] 模块页、接缝图、flow 页改成现状，写轨迹卡，本页删掉

钉码核心只收「目标 + 记录」，记号是 mdx 还是组件源码归 workflow 的两个格式。轨迹核心照同样的办法切：
它只收一份中性数据——盘心，加一组卡；卡文件怎么写、哪些字段必填、一个目录只能有一张根卡，这些 docfirst 的规矩
都在 workflow 的卡格式里。卡格式只有一种，所以不做格式接口，写死。

## 每一块只认识什么

| 模块 | 在哪 | 认识 | 不认识 |
| --- | --- | --- | --- |
| 建模 | 轨迹核心 `src/model/`，出口 `.` | 中性输入、关系边、树、主干、孤星、领域顺序、时间范围 | 卡文件的写法、像素 |
| 布局 | 轨迹核心 `src/layout/` | 半径、角度、空档折叠、同日错开、补间 | DOM |
| 画布 | 轨迹核心 `src/canvas/` | SVG、相机、视觉层、标签避让、色板、节点种类 | React |
| 星轨盘组件 | 轨迹核心 `src/disk/`，出口 `./disk` | React 状态、工具条、侧栏 | 卡文件的写法 |
| docfirst 卡格式 | workflow `src/cards/`，出口 `./cards` | frontmatter、关系行、里程碑区块、卡身份、全部校验、卡里不许钉码 | 盘怎么画 |

轨迹核心里四个目录只许往上游 import（组件 → 画布 → 布局 → 建模），由边界测试的目录禁止表检查，跟 workflow 的目录同一种写法。

## 中性输入

```ts
interface DiskInput {
  /** 盘心：docfirst 里是那张根卡；根卡不是恰好一张时为 null，盘照画、盘心无主 */
  center: { label: string; at: string; milestones: { date: string; name: string; desc: string }[] } | null;
  cards: DiskCard[];
}

interface DiskCard {
  id: string;
  /** YYYY-MM-DD 或 YYYY-MM-DDTHH:mm */
  at: string;
  label: string;
  /** 分组配色；null 归「未分道」 */
  group: string | null;
  /** 节点种类：choice / evidence / derivation / reference / snapshot，其余与 null 画缺省形状 */
  kind: string | null;
  relations: { kind: "supersede" | "pivot"; target: string }[];
}

function buildModel(input: DiskInput): TrajectoryModel;
```

`buildModel` 收到不合格的输入（身份重复、时间写坏、关系种类不认识）直接抛错：卡格式已经把坏卡挡在外面，
走到这里说明卡格式有 bug。关系指向卡集合之外的目标，照旧放进模型的 `broken`，盘上不画那条边。

**建模挪到客户端**。`StarDisk` 的 `data` 就是中性输入，组件自己建模、交给画布；服务端和客户端之间传的就是这份输入，
不另有传输形状。`loadTrajectory` 交回 `{ center, cards, sick }`，站的盘页把它原样交给 `StarDisk`、拿 `sick` 显示报病数，
所以盘页模板不用改。

节点种类是星轨盘自己的一套词，恰好跟 docfirst 的卡体裁同名。只有一个下游，不做种类配置表。

## docfirst 卡格式

从轨迹核心搬过来的：按行解析 frontmatter、关系行、里程碑区块、`CARD_KEYS`、挑卡文件、单卡与整个目录的校验、
病卡的类型 `Problem` / `SickFile`。`scanCardDir(dir)` 交回中性输入与病卡清单；校验不过、画不出来的卡（`born-at` 写坏）
记成病卡、不进中性输入。

新增的校验，全部记成病卡：

- 关系指向的身份不是盘上的卡
- 关系指向根卡（根卡代表整个项目，从项目转向、取代项目都说不通）
- 同一身份 `.md` 与 `.mdx` 两个文件都在
- 里程碑行格式不对、日期写坏

fumadocs 的 `cardSchema` 收到的 `ctx.source` 是卡的原文，改用卡格式的解析器判断是不是卡、取标题；
`remarkTrajectoryLinks` 改用 `cardIdFromHref`。gray-matter 那一份校验与 `stemFromHref` 删掉。

## 一起收掉的

中性输入之后自然没有了的：

- 一张卡的四种形状（`RawCard`、`RouteCard`、`Card`、`ProjectRoot`）与 `Trajectory` 里的两份卡列表；组件为拿种类与里程碑建的
  `routeById` 表，以及 `StageData.typeOf`、`BuildCtx.typeOf` 那一路传参
- `serial.ts` 与它的两条接缝：只为 `supersededIds` 是 `Set` 才存在
- `mtime`：workflow 每张卡 `stat` 一次，没有代码读它
- `status`：一路传到组件，没有代码读它；卡格式照旧不校验这个字段

删掉的死代码与重复：

- `advanceFrame` 与 `FrameState`：视图补间在 `Camera`、悬停补间在各层，这里只剩焦点日与鱼眼强度的补间，收成 `RingsLayout` 的一个方法
- `LAYOUT_PATCH_KEYS` 与 `layoutPatchOf`：没有调用方
- `hubBase`、`innerR`、`hubR` 三个字段关系固定，只存一个
- `NODE_RADIUS` 按形态分两项、值相同，换成一个常量
- `smoothWindow` 与 `smoothstep` 同一个公式
- `chains.ts` 自己算的主干末端集合，跟画布里的 `spineTipIds` 重复
- 设置面板：`settings.ts`、面板、`localStorage` 里的手感参数，连同两套默认值、两套名字、`tune` / `patch` 两种滑杆

改成报错的容错：

- wikilink 形式的关系与卡链接：本机真实的卡没有一条在用，只有 fixture 在用
- frontmatter 单值与列表互相转换、链接目标写在 `<>` 里
- 读卡目录时除「目录不存在」以外的读取失败

日级 `born-at` 是合法写法，不动。

## 实测再定的

防重叠有四层：同日按角度排开、忙的日子加宽环带斜排、每帧算的跨日错开、鱼眼。本机同组同日最挤的是 plecs-studio 38 张、
gwb-lifecycle-plugins 19 张、gwb-kernel 11 张（`probes/2609271010_disk-input-survey/`），在这几个站上逐层关掉截图对比，
多余的删。

扇区一圈装不下时复用角度的那条路径留着：plecs-studio、gwb-kernel、gwb-block-note、collab-site 四个站会走到。

## 顺序

每一步单独提交，测试全过再走下一步：

1. 本页与轨迹卡
2. 删死代码与重复（不改行为，测试一个字不改）
3. 卡格式搬进 workflow `src/cards/`（只搬位置，测试只改 import 路径）
4. 轨迹核心改收中性输入，建模挪到客户端，四个目录与边界测试
5. 容错改成报错，新增的校验，fixture 改写
6. 防重叠实测、删设置面板
7. 模块页、接缝图、flow 页、说明书改成现状；写轨迹卡；本页删掉；发版

## 对下游的影响

`docfirst-trajectory`、`docfirst-workflow`、`docfirst-fumadocs` 三个包都是破坏性改动，发版照 gwb-release 升 x 并给下游投反馈。
各站的盘页不用改。会多红的卡有两张：gwb-ui-plugins 的 `2026-09-12-shell-refactor-round` 的 `parent` 没写成列表，
gwb-paper-fetch 的 `2026-09-17-paper-fetch` 的 `pivots-from` 指向了根卡；发版前在那两个仓里改掉。
