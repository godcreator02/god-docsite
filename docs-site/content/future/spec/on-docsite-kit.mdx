## 验收清单

本仓的 `docs-site/` 迁到基础包上，下面全部做到：

1. [ ] 站点是基础包的项目骨架加功能包 `@godcreator/docfirst-site`，经 `docsite.site.init` 生成，`app/` 里没有站自己写的文件
2. [ ] 地址不变：`/docs/…`、`/maintain/…`、`/future/…` 的每一页，星轨盘 `/trajectory`，卡页 `/trajectory/<卡身份>`，全部返回 200、没有报错页
3. [ ] 钉码投影成带状态点的代码块，目录树引用显示成文件树，术语自动标注
4. [ ] 讲解组件与接缝图正常显示、能交互
5. [ ] 星轨盘能用，点节点能读卡正文
6. [ ] 能在页面上写评论：`people.json` 认出本机身份
7. [ ] `pnpm doc` 全绿；`render` 出的 README、AGENTS、CLAUDE 与三份 SKILL.md 只有这次本来就要改的说法不同
8. [ ] 站的测试与仓根 `pnpm check` 通过
9. [ ] 开发服务由 gwb-docsite 托管（`docsite.site.add`），本站不再登记进 docfirst 插件的 `docfirst.site.*`
10. [ ] 讲 Next 接入的页改写成现状（见「要改写的页」），决定写成轨迹卡，这一页删掉

## 分成几块

| 块 | 在哪 | 做什么 |
| --- | --- | --- |
| 功能包 `@godcreator/docfirst-site` | 本仓新包 `packages/docfirst-site` | 照基础包的功能包接口提供：给内容集合的 remark 插件（钉码投影、术语标注）、MDX 组件（带状态点的 `pre`、`Term`）、轨迹卡集合（放进模板）、星轨盘与卡页两条路由、侧栏入口「轨迹」、样式 |
| 命令行 | 本仓 `docfirst-workflow` | 配置加一项 `trajectory`：轨迹卡目录，相对项目根；不写时仍是内容根下的 `trajectory/`，没迁的 Next 站不用改 |
| 基础包 | 仓 `docsite-kit` | 功能包接口加一项：功能包给内容集合加 remark 插件 |
| 本站 | `docs-site/` | 换成基础包骨架；页面里用到的站内组件改成在页面开头 `import`；轨迹卡搬到 `trajectory/` |

`docfirst-workflow` 的 `./fumadocs` 出口留着，没迁的 Next 站还在用；最后一个 Next 站迁完再删。

## 决定

1. **现状区与未来区留在 `content/`**：`content/docs`、`content/maintain`、`content/future` 各写 `"root": true`，就是基础包侧栏下拉框里的三组，地址前缀与现在一样
2. **轨迹卡搬出 `content/`，放到站点根下的 `trajectory/`**：卡的 frontmatter 和页面不一样（标题由 `label` 派生），星轨盘与卡页是功能包的路由，留在内容集合里会和路由抢地址。做法与协作站的日志页 `journal/` 相同：集合定义放进功能包模板的 `app/lib/`，侧栏里是「轨迹」入口而不是一组页面
3. **remark 插件的配置从 `docfirst.config.mjs` 读**：插件本来就按项目根装配项目（钉码状态要用），术语表的位置与不标注的页也写进这份配置，骨架里不写站自己的代码。术语表从 `src/glossary.ts` 改成配置能直接加载的 `.mjs`
4. **站内组件照基础包的写法 `import`**：组件源码仍在 `src/components/`（命令行按这个目录认现状区的代码文件）；名册 `components` 不变，`render` 照旧按它把组件换成机读文字
5. **基础包没有的不带过去**：每页的机读版路由（`llms.txt`、`llms-full.txt`、`<页>.mdx`）、页头的复制 Markdown 与查看方式按钮、`proxy.ts`。讲它们的页删掉或改写
6. **托管**：本站交给 gwb-docsite。`docfirst.site.*` 与窗格「文档站」留给还没迁的 Next 站，最后一个迁完再删（那时插件升 x）。gwb-docsite 的「闲置到点自动停」放到下一轮
7. **建站命令**：`docfirst.create` 改成调用 `docsite.site.init` 并写上功能包，放到下一轮
