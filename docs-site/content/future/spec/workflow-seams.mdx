**本页回答**：`docfirst-workflow` 现在哪里的接缝不清楚、改成什么样、每一块只认识什么、顺带删掉哪些多余的机制、怎么证明行为没变、按什么顺序做。

## 验收

- [ ] 包里只有 `src/node/` import `node:fs`、`node:fs/promises`、`node:child_process`、`node:os`；`process` 只在 `node/` 与 `cli/` 里出现；边界测试守住
- [ ] 装配拆出配置 `config.ts`；命令行拆成参数、各命令、文案三块
- [ ] 下面「重复的概念归到哪」逐条做完
- [ ] 第 1 到 4 步只挪代码、不改行为：`tests/` 里的断言一个字不改，只有被挪走的文件的 import 路径跟着改；每步全绿
- [ ] 第 5 步用 git worktree 取改动前的提交，新旧两边对本站运行 `docfirst check --json`、`docfirst trajectory --json`、`docfirst render`，输出一致
- [ ] 下面「删掉的多余机制」逐条做完；写进系统临时目录的 hunk 缓存实测过再定去留
- [ ] 出口去掉重复，发 `docfirst-workflow` 0.5.0；插件建站依赖表跟上，下游升级反馈改成 0.5.0
- [ ] 模块页、接缝图、边界规则图改成现状，写轨迹卡，本页与它的接缝图删掉

## 现在哪里不清楚

**碰外部环境的代码散在各处。**`project/load.ts` 直接读写文件、遍历目录、动态加载配置；`project/git.ts` 起子进程、写系统临时目录；
`cards/card-dir.ts` 读卡目录。哪些代码碰磁盘，只能一个文件一个文件地看，没有边界测试守着。

**两个文件什么都管。**`project/load.ts` 同时是配置校验、分区规则、文件遍历与组装；`cli/run.ts` 四百多行，参数解析、
各命令的编排、中文文案与状态符号、打印混在一起。

**同一个概念写了两份以上**，改一处另一处不会跟着变（下面有表）。

**有只剩一个使用者的选项、按构造不会触发的检查、吞掉的错**（下面有表）。

**出口有重复**：`scanCardDir` 同时从 `.` 与 `./cards` 出；`langOf` 从 `./mdx` 出，`./fumadocs` 又再出一次。

## 每一块只认识什么

| 块 | 在哪 | 认识 | 不认识 |
| --- | --- | --- | --- |
| Node 实现 | 新目录 `src/node/` | `node:fs`、`node:child_process`、`node:os`，钉码核心的 `Reader` / `History` 接口 | docfirst 的任何格式：记号、mdx、卡、分区、配置的键 |
| 记号、引用、mdx 格式、组件格式、钉码编排 | `marker/` `reference/` `mdx/` `code/` `pinning/` | 不变 | Node |
| 装配 | `project/` | `node/`、配置的键、分区规则、钉码编排、摆放 | 命令行 |
| 卡格式 | `cards/` | 卡的写法与校验；`card-dir.ts` 用 `node/` 列目录读文件 | 命令行 |
| 命令行 | `cli/` | 装配好的项目、卡格式、星轨盘建模、`node/` 的未提交改动探针、`process` 与 `console` | — |
| fumadocs 适配 | `fumadocs/` | 不变：只按包名用 `.`、`./mdx`、`./cards` | 命令行那一侧的目录 |

方向：`node/` 在最底下，只从钉码核心取类型，包里别的目录都不认识；装配、卡格式、命令行直接 import 它。
不做可以替换的外部环境接口：Node 实现只有一个使用者，测试照旧建临时 git 仓，没有第二种实现要换进来。

## 装配与命令行怎么拆

| 现在 | 拆成 |
| --- | --- |
| `project/git.ts`、`fs-reader.ts`、`history.ts`、`uncommitted.ts` | 挪进 `node/`，`project/index.ts` 照旧再导出 `createReader`、`createGitHistory`、`createUncommittedProbe` |
| `project/load.ts` | `node/` 里的 `files.ts`（列目录、读写文本、目录在不在）与 `config-file.ts`（找配置文件、由 Node 原生加载）；`project/config.ts`：配置的类型、认哪些键、校验、加载、内容根归一；`load.ts`：组装，加上定现状区文档的二十来行（单独成文件要改它列目录的方式，不值得） |
| `cards/card-dir.ts` 的读盘 | `node/files.ts` 的 `readDirFiles(dir, accept)`：列一层、按 `accept` 挑名字、并发读全文，目录不在交回 `null`；`card-dir.ts` 只剩组合 |
| `cli/run.ts` | `args.ts`：命令与开关表、求助、点名页解析；`commands.ts`：check / confirm / render / trajectory 各一个函数；`text.ts`：状态符号、状态文案、每种结果打成哪一行 |

拆的时候只挪代码、改名，逻辑不动；每个函数的名字要说得出它做什么，说不出就说明那几行还不该单独成一块。

## 重复的概念归到哪

| 概念 | 现在在哪 | 归到 |
| --- | --- | --- |
| 状态的中文说法（新鲜、有变动……） | `cli/run.ts:39`、`fumadocs/blocks.ts:24` | 不合并：两处措辞不同（命令行带「等作者复核」），给不同地方用 |
| 卡文件后缀、关系行头、身份去日期前缀 | `cards/scan.ts:17`、`cards/parse.ts:26`、`cards/card.ts:18`，fumadocs `card-collection.ts:49,94,96` 又各写一份 | `cards/`，经 `./cards` 出口给 fumadocs |
| 解析 `git status --porcelain -z` | `project/fs-reader.ts:43`、`project/git.ts:197` | `node/git.ts` 里一个函数 |
| 组件目录 `src/components` | `project/load.ts:95`、`code/index.ts:14` | 组件格式 |
| `PluginFile` 与 `GlossaryFile` | fumadocs `remark-plugin.ts:11`、`glossary-plugin.ts:22` | 只留 `PluginFile` |
| `Project` 类型 | `cli/run.ts:273` 用 `ReturnType` 推 | 直接 import |

frontmatter 按行扫描在 `project/placement.ts:158` 与 `cards/parse.ts:71` 各有一份，对照过口径不同：摆放逐行原样搬点名的字段，
卡格式要解析出值，相同的只有找到 frontmatter 块那几行，装配也不认识卡格式——各留各的。

## 删掉的多余机制

只有一个使用者的选项、按构造不会触发的检查、吞掉的错。这一步会改行为，测试跟着改：

| 在哪 | 是什么 | 改成 |
| --- | --- | --- |
| `project/load.ts:70` | 配置文件认 `.mjs`、`.js`、`.ts` 三种名字 | 只认 `docfirst.config.mjs`：本机 18 个站与建站模板全是这个名字 |
| `fumadocs/glossary-plugin.ts:30,34` | `componentName`、`oncePerPage` 两个选项 | 删掉：没有调用方，组件名写死 `Term`，每页每个词只标第一次 |
| `fumadocs/blocks.ts:37` | 导出的 `TREE_SUFFIX` | 删掉：没有调用方 |
| `fumadocs/remark-plugin.ts:21` | 名册的默认值 `fumadocsRoster`，跟命令行的默认值 `{}` 口径不一 | 删掉默认值：项目上的名册没写就是 `{}`，站与命令行用同一份 |
| `marker/index.ts:171` | `toTarget` 把 `parseFormal` 已经判过的动作词再判一次 | 删掉第二次 |
| `mdx/render.ts:24` | `isRenderRefusal` 按错误名认，理由是「两份产物各有一个类」 | 删掉，摆放直接 `instanceof RenderRefusal`：查过产物，这个类只在一个 chunk 里 |
| `pinning/index.ts:47`、`fumadocs/transform.ts:17` | 「不止一个格式认领」（两种格式按扩展名与目录互斥）、「记号节点没有父节点」这类按构造不会触发的检查 | 删掉 |
| `project/fs-reader.ts:20,59` | 读文件、判断文件类型时把所有错误都当成「文件不在」 | 只有「不存在」当成没有，别的错照原样抛 |
| `fumadocs/host.ts:22`、`glossary-plugin.ts:98` | 拿不到页面路径时用空串继续跑 | 报错 |
| 只在本文件里用的导出（`marker/` 的 `wordOf` 等、`git.ts` 的 `realpathLoose` 等） | 导出了没人用 | 去掉 `export`；测试直接 import 的留着 |

**实测再定**：`project/git.ts:120` 写进系统临时目录的 hunk 缓存，只写了理由、没有单独测过，而且只增不减。
新旧各对本站运行两遍 `docfirst check`（有它、没它），差得不多就删。内存里的 blob 与 hunk 两层缓存有实测（轨迹卡
「check 在进程内记住 git 的回答」），留着。

**留着的**：同一个根只装配一次的项目缓存（站构建时几十个 loader 并发调用）；`PlacingHost`（测试里有内存实现）；
`Placing.check` 的清单参数可选（命令行总会传，测试里几十处不传、让它自己算）；`renderAi` 与 `applyListing` 里「清单里没有它」的报错
（两个都是导出的函数，调用方传进来的清单可能对不上正本，有测试钉着这个报错）；
文档路径认绝对路径、`./` 前缀与反斜杠，命令行认 `--help`、`-h`、`help`（都是命令行上用户输入的等价写法）；
已经删掉的写法（`has` 记号、以 `@@docfirst` 开头的一行）报错时给出改法——下游还有九十多个页面写着 `has`，迁完再删，记进路线图。

## 出口的变化（0.5.0）

| 出口 | 变化 |
| --- | --- |
| `.` | 去掉 `scanCardDir` 与卡的类型（从 `./cards` 取） |
| `./fumadocs` | 不再再导出 `langOf` 与 `TREE_SUFFIX`；类型 `GlossaryFile` 并进 `PluginFile` |
| `./cards` | 加导出卡文件后缀 `CARD_EXT`、关系行头 `EDGE_HEAD`、身份的日期前缀 `ID_DATE_PREFIX` |
| `./mdx` | 不再导出 `isRenderRefusal` |
| bin `docfirst` | 不变 |

站与插件模板都不用 `.` 的 `scanCardDir` 与 `./fumadocs` 的 `langOf`，只有本仓的三份星轨盘测试从 `.` 取 `scanCardDir`，改成从 `./cards` 取。
升 x 是因为删了出口的名字；下游站都还没迁到 0.4，这一版它们直接迁到 0.5。

## 不做的事

- **不做可以替换的外部环境接口**：Node 实现只有一个使用者
- **不做格式接口**：mdx 页面与组件源码两种格式照旧写死在钉码编排的表里
- **fumadocs 适配内部不动**：只收它重复的那几样、删上表里点名的几处
- **命令行照旧直接用星轨盘建模**打印主干：命令行是入口，认识下面所有块
- **不改任何命令的输出与退出码**，配置只少认两种文件名

## 顺序

每一步一个提交：

1. 建 `node/`，把 git、读取器、旧内容来源、未提交探针、列目录读文件、加载配置、文件读写挪进去（只挪代码，测试断言不改）
2. 装配拆出 `config.ts`（只挪代码）
3. 命令行拆成 `args.ts`、`commands.ts`、`text.ts`（只挪代码）
4. 重复的概念归一（只挪代码）
5. worktree 对比：新旧两边对本站运行三条命令，输出一致；顺带实测 hunk 磁盘缓存；证据写进轨迹卡
6. 删掉的多余机制，测试跟着改
7. 边界测试加新规矩；出口去掉重复、改那三份测试，升 0.5.0，插件建站依赖表跟上
8. 模块页、接缝图、边界规则图改成现状，写轨迹卡，删本页与计划图；发版，改下游升级反馈
