# docfirst 重设计

**本页回答**：这次重设计改什么、为什么、按什么顺序做、做到哪了。设计是 2026-09-25 在总控台会话里跟人
逐条讨论定下的，下面只写定论。

## 为什么要改

在 16 个接了 docfirst 的站上量过：

- 确认类提交占全部提交的 15%–20%，大多只是「行号写回」加上重写 `.ledger.json`（确认 15 页时记录簿改了 923 行）
- git 记忆要求「先提交再确认」，一次改动拆成两个提交；全仓一份记录簿，分支合并必然冲突，只能手工挑着合
- 黄灯不拦提交，于是攒着、隔几天由别的会话成批确认，确认的人不是改代码的人
- 反馈区的 hatch 几乎全是空模板，spec 多数站只有导读页，inbox 是单个文件，别的会话有未提交改动时投不进去
- 生成正本走 fumadocs 的 mdx→md 序列化，反引号被转成 `&#x60;`（`AGENTS.md` 里已经有受害）
- `docfirst.attach` 只看文件集合不看内容，会覆盖已改过的正文、删掉自定义的 `layout.tsx`（审查报告 GWB-18）

## 验收

- [x] **记号自带记录，删掉记录簿**：正式记号的属性里带着确认时的记录；`.ledger.json`、`Ledger` 接口、孤儿、
      strays / forget 全部删除
- [x] **确认不要求先提交**：确认时不起 git，blob 名在进程里按工作区内容（换行统一成 LF）算
- [x] **行段与整文件只有一个比较器**：先比段哈希，再用 blob 取旧内容跟 hunk，取不到退回滑窗查找；
      `comparator` 配置项删除
- [x] **`confirm` 拆成两个动作**：默认只做机械写回，签黄灯要点名页并带 `--accept`
- [x] **`check` 拦本仓未提交改动引起的黄灯**
- [x] **分区按约定**：内容根下只有 `trajectory/`、`future/` 两个固定名字，其余目录都是现状、都进 `check`
- [x] **生成正本按原文渲染**：不再经过 fumadocs 编译
- [x] **迁移命令**：`docfirst migrate-ledger` 把旧记录簿写进各记号后删掉记录簿
- [ ] **装配不覆盖改过的文件**（写盘前检查、失败恢复已做；逐个核对是否骨架原样要站点插件配合，未做），并铺新分区的模板（已做）
- [x] 说明书与本站现状区跟上；轨迹卡落下；本站自己迁移完、门禁全绿
- [ ] 发版；别的站的迁移经 feedback 通知各仓

## 方案

### 记号上带什么

正式记号 = 目标属性 + 记录属性，记录属性只在确认过的记号上出现：

| 目标 | 记录属性 | 含义 |
| --- | --- | --- |
| 行段 `ref file lines` | `hash` `blob` | 段哈希（归一化后 sha256 取前 12 位）；确认时整文件的 blob 名（LF 归一后按 git 算法算，取前 12 位） |
| 整文件 `ref file` | `hash` `blob` | 整文件的段哈希；blob 名同上 |
| 目录树 `tree` | `hash` | 名字表的哈希。旧名字表不再存，变了只报黄、给当前表，不给多了少了哪些 |
| 存在性 `exists` / `absent` | `type` | `file` / `dir` / `absent` |
| 名字 `has` | 无 | 正式记号本身就表示确认过 |

例：`{/* ref file="../src/a.ts" lines="10-23" hash="3fa9c2e1b07d" blob="2689fa073ac6" */}`。

没有记录属性的正式记号（人手写的）跟草稿记号一样算未确认；`has` 例外，正式记号即确认。
记录属性写了一半（比如行段只有 `blob` 没有 `hash`）是记号写错了，报错到行。

**blob 为什么在进程里算**：本机的仓对象库里存 LF（`core.autocrlf=input`），把工作区内容换成 LF 后按
git 的 blob 算法算出的名字，就是这份内容提交后的 blob 名。确认因此一个 git 都不用起；代价是：确认之后、
提交之前又改了这个文件，或者仓里的文件本来就存 CRLF，这个 blob 就不会进对象库——核对时取不到旧内容，
退回滑窗查找（有意设计的降级，理由写在比较器的注释里）。

### 行段与整文件的判定

一个比较器，判定层给纯的那一半，环境层注入「按 blob 取旧内容、算 hunk 表」两样：

1. 记号上的行段按段哈希比，一样就是绿，行号不动
2. 当前文件的 blob 名等于记号上的：内容没变，同上
3. 取得到旧 blob：用 hunk 表把旧行段映到今天，段哈希对得上是绿（挪了位置），对不上是黄（带 diff 和旧内容），
   整段删光是红 `vanished`
4. 取不到旧 blob（不在仓里、没提交、浅克隆）：按段哈希在整个文件里滑窗查找，找到是绿，找不到是黄 `unlocated`
5. 文件不在是红 `file-missing`

`blob-missing` 这种红没有了——取不到旧内容不再是错，只是少了 diff。

### confirm

- `docfirst confirm [页…]`：**只做机械写回**，不需要判断——草稿记号换成正式记号并写上记录；绿灯里行段挪了
  位置的，写回今天的行号与记录；然后重新渲染所有挂了 outputs 映射的正本，内容有变才写。黄灯原样不动，
  逐条列出「需复核后 `--accept`」；红灯列出来，退 1。不带页名就是全部页
- `docfirst confirm <页…> --accept`：在上面之外，把点名页里的黄灯按今天的内容重新记。**不带页名报错退 2**
- 每处记号各带各的记录，写回互不牵连，不再「一处钉不住整篇拒」：红的那几处不动，别的照写

### check 拦什么

红照旧拦（退 1）。黄分两种：被钉文件在**文档所在的仓**里、且有未提交的改动（工作区或暂存区跟 HEAD 不一样，
或者未跟踪），这个黄是这次改动引起的，**算红**，提示在同一个提交里复核并 `--accept`；其他黄
（已经提交的代码引起的、被钉文件在别的仓里）只报告。每个仓一次 `git status --porcelain` 就够。
`--json` 报告里这种黄带 `blocking: true`。

### 分区

配置新增 `content`（默认 `"content"`），是各区的上一级目录。`content/trajectory/` 是轨迹卡目录，
`content/future/` 是未来区，这两个名字固定；`content/` 下别的目录一律是现状区，都进 `check`，数量和名字由站自己定。
配置项 `docs`、`trajectory`、`comparator`、`ledger` 删除；配置里出现不认识的键一律报错（写明哪个键、
该怎么改），不静默忽略。

未来区收下原来的 spec 与 inbox：`future/roadmap.mdx`、在途方案 `future/spec/<名字>.mdx`、
别的仓投来的反馈 `future/inbox/<日期>-<来源>-<标题>.mdx`（一条一个文件，并发投递互不冲突，
总控台的中转站随之撤掉）。hatch 删除。生成正本放在现状区里，由 `outputs` 映射认出来。

### 生成正本的渲染

fumadocs 格式的 `renderAi` 改成按原文处理：去掉 frontmatter（映射要求保留的字段照旧由摆放模块加回），
每个正式记号换成一个代码块（标题是 `路径:起-止`，内容是今天的那几行；目录树是名字表），其余文字逐字节不动。
正本里出现 JSX 组件或别的 mdx 表达式就报错，不静默丢。站上各页的机读版（`docfirstMarkdownOptions`）不受影响。

### 装配（插件 `docfirst.attach`）

- 要覆盖或删除的每个文件，先跟站点插件那份骨架模板的原样比，有一个不一样就一个字不写，报错并列出这些文件
- 模板改成新分区：`content/docs/`（入口页、术语表、生成正本 `content/docs/outputs/`）、`content/trajectory/`、
  `content/future/`（roadmap）；删掉 spec、feedback、outputs 三区的路由与骨架页
- 骨架页只规定每页都成立的写法（第一句「本页回答」），不规定小标题——docfirst 要能用在任何项目上

### 迁移

`docfirst migrate-ledger`：读 `.ledger.json`，逐篇逐处把记录写进记号（git 记录取 `hash` 与 `blob` 的前 12 位，
hash 记录只写 `hash`，目录树算名字表的哈希，存在性写 `type`），行段按记录里的行号写。记录簿里没有对应记号的
（孤儿）直接丢；记号在、记录不在的保持未确认。全部写完删掉记录簿，打印一句配置里还要手工删改哪些键。
各站迁完后这条命令在下一个版本删掉。

## 顺序

1. 主包：判定层 → 环境层 → 格式 → 命令行，测试随改随跟（一个子代理，串行）
2. 插件：装配防覆盖与新模板（另一个子代理，跟 1 并行，互不碰文件）
3. 本站迁移：跑 `migrate-ledger`、挪区、改配置与路由
4. 说明书 `docfirst-docs` 等随新写法重写；现状区里讲记录簿、git 记忆、六区的页跟上；落轨迹卡
5. 读 `gwb-release` 定版本号并发版；给各站投 feedback
