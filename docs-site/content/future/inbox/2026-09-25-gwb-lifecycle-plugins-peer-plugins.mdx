插件运行时用到的别的插件，从 devDependencies 挪到 peerDependencies，范围写 `^x.y.z`，下限写开发、验证时用的那一版；同一个仓里的插件写 `workspace:^`，发版时换成 `^<版本号>`。「用到」指：经 `ctx.inject` 用它的服务、经命令总线 `@godcreator/gwb-commands` 登记命令、用外壳 `@godcreator/gwb-shell` 注册窗格或样式令牌、import 它的类型。只用 `ctx.inject([...], fn)` 局部注入、缺了只少一部分功能的，在 `peerDependenciesMeta` 里标 `optional: true`；只按命令名调它的命令的不用写。写进 peer 的插件不再另写 dev：插件仓里 pnpm 会把 peer 装进 `node_modules`，类型从那里取。

- peer 里只许三类：按值 import 的 `cordis`、内核包 `@godcreator/gwb-kernel-desktop`、别的插件（清单 `keywords` 含 `gwb-plugin`）。库、接口定义包、构建工具照旧写 dev 或 `dependencies`
- 清单字段 `gwb.requires` 已删：插件管理不再报它，发版检查也不再查
- 发版检查（devkit 0.18.15 起）：peer 里每个 `@godcreator` 插件的范围要是 `^x.y.z`，并且和源上 `latest` 在同一条线（0.x 比次版本号，≥1 比主版本号），不在同一条线就拒；peer 里有这三类以外的包也拒
- home 里关掉了 pnpm 自动补装 peer：插件管理、`devkit.home.new`、`devkit.dev` 在 home 里运行 pnpm 时都带环境变量 `pnpm_config_auto_install_peers=false`。peer 里的插件 home 里没装，不会被顺带装上，由 `plugin-manager.list` 每个包的 `unmetPeers`（`{ pkg, range, installed? }`）报出来，只报告、不拦加载；在隔离 home 里验证时，peer 里的插件要自己装上
- 升级一个插件时，peer 写了它的插件会被 pnpm 装进新目录，插件管理在同一次升级里把它们一起重新加载（回执里的 `dependents`）

本仓要改的：

- `@godcreator/gwb-docfirst-workflow` 的 peer 已经写了命令总线与说明书（说明书标了 `optional: true`），符合上面的写法；只剩 dev 里重复写的命令总线、说明书两项删掉

随适配内核 0.6 那一轮一起改、一起发，版本号照说明书 `gwb-release` 升。规矩正本是 devkit 文档站的规则页「用到的插件写 peer」与说明书 `gwb-release`（`run skill.read {"name":"gwb-release"}`）。
