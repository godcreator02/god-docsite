# 愿景

**本页回答**：`god-live-doc` 做成了是什么样、为什么值得做。这一区常改，现状区一字不写未来。

## 做成了是什么样

一个仓的文档站上，**没有一句关于代码的话是死的**。每一句对代码的论断背后都有一条引用钉着真源码：
代码改了，那句话旁边当场变色；引用指向空气，门禁当场拦人。文档不再需要靠人定期通读来发现它在撒谎，
撒谎会被机器抓住。

配套的另一半是**历史不被改写**：一次方向了断落一张卡，卡只增不改，谁取代了谁、谁是从哪条路转过来的
看得见。现状文档因此可以放心地只写现状——它不用背历史的包袱，因为历史有地方去。

两件事合起来是同一个目标：**让 agent 读到的文档跟代码是同一份事实**。一等读者是干活的 agent，
人是看呈现面的监督者。

## 为什么值得做

写文档的成本从来不在第一次写，在于**第二次以后没人愿意维护**。一段手抄的代码副本，写下的那一刻是对的，
三个月后是错的，而且没人知道它错了。把副本换成引用，维护成本从「定期重读全站」降到「门禁红了才看」。

这套机制不承诺文档写得好——它只承诺**文档说的假话会被发现**。写得好不好归写的人，见随
`@godcreator02/live-doc-cli` 发的 skill「livedoc-docs」。
