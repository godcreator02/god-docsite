# 明确不做

**本页回答**：哪些能力想过、决定不做，为什么。**「不做」也是决定**——推翻其中一条要落一张
[轨迹卡](/trajectory)，不是悄悄开始做。

## 机制上不做的

- **不自动修复**。代码改了，工具报黄，等人来看；它不会替你把文档里的话改对。判断改得对不对
  需要意图，机器没有。
- **不猜作者意图**。别家比较器记的记录一律当「未确认」重新确认；行映射跟内容对不上时报黄让人复核，
  不把红判成绿；hash 记忆找不到那段就说「位置不明」，不拿旧行号上的东西冒充。
- **不做全文正则**。记号靠语法树或逐行扫认，写在围栏里、句子里的同样文字一律不算。

## 五类之外不做的

五类引用（行段、整文件、目录树、存在性、名字）把「文件系统这根轴」填满了。轴外面的几样：

<Tabs>
  <Tab title="跑出来的数">
    「86 条测试」「23 个路由」不是文件的话，是命令输出的话。靠约定：跑出来的数字不进散文，要写就钉
    产生它的东西（钉 tests 目录树，让读者自己数）。真要做是「探针」一类，跑命令记输出哈希，
    成本和风险都不是现在的事。
  </Tab>
  <Tab title="行内记号">
    文内链接指向的那篇还在不在、句子里的反引号——本质是 exists / has，缺的是行内记号：三个格式包
    各要加一套识别，fumadocs 那头走的也不是 pre 组件。押后，块级先用着。
  </Tab>
  <Tab title="目录的内容">
    目录树只看名字。「这个目录下任何内容变了」就是 git 树哈希，改一行就黄，没有文档需要这种话，不做。
  </Tab>
  <Tab title="符号级别的存在">
    `has` 是纯文本匹配，不上语言服务：`save` 会命中别处的 `save(notes)`，得写 `export function save`。
    要更准得接语言服务，那是另一件事。
  </Tab>
</Tabs>

图、外部网址钉不住；git 历史不会变，不用钉。

## 形态上不做的

- **不做「代码根 / 命名根」配置项**，所以引用路径一律相对项目根，站里写的就是 `../packages/…`，
  标题栏上也这么显示。要更好看得先给配置加一项，那是接口变更。
- **文件改名不追**。改了名就是缺失，重钉。追改名要靠内容相似度猜，猜错比报错更糟。
- **绝对路径不认**。仓外路径在别的机器上会红，机器相关的路径该留在本地配置。
- **不出第二份给人看的产物**。fumadocs 那份人看的就是站本身，md 与 html 也没有第二种人看的形态，
  所以渲染只有一种：出给 agent 读的那份，挂了 `outputs` 的摆到落点。哪天真需要另一种形态，
  那是给格式包接口加一项，是接口变更。
- **不并发确认**。记录簿一个 json，靠「没变不写」躲过并发构建；`confirm` 单线程逐篇跑。
  哪天要并发确认，这条得重做。
