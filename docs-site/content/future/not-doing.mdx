---
title: 明确不做
description: 想过、决定不做的那些，连带为什么
---

**本页回答**：哪些能力想过、决定不做，为什么。**「不做」也是决定**——推翻其中一条要写一张
[轨迹卡](/trajectory)，不是悄悄开始做。

## 机制上不做的

- **不自动修复**。代码改了，工具报黄，等人来看；它不会替你把文档里的话改对。判断改得对不对
  需要意图，机器没有。
- **不替人确认黄灯**。`confirm` 只做机械写回（未确认的记号写上记录、挪了位置的写回新行号）；黄灯要人复核后
  点名页 `--accept`，不能不点名就确认整个仓——同一个仓里别人没复核的黄灯不能替他确认。
- **不猜作者意图**。记号的记录只写了一半、写坏了就报错到行，长成记号却认不出动作词的注释、以 `@@docfirst` 开头的一行也报错，
  不当成普通文字放过去；跟着改动映射过来的那段内容对不上时报黄让人复核，
  不把黄判成绿；取不到确认时的内容、在整个文件里也找不到那段，就说「位置不明」，不拿旧行号上的东西冒充。
- **不做全文正则**。mdx 页面里的记号靠语法树认，写在代码围栏里、句子里的同样文字一律不算；讲解组件的源码不解析
  TypeScript，只认独占一行的块注释，跟代码写在同一行的注释不算。

## 这几种引用之外不做的

行段、整文件、目录树管的是文件里的内容与目录下有哪些东西。「这个路径在不在」「文件里有没有某个名字」不单独钉：
钉写着它的那一行，或写成正文说明。这之外的几样：

<Tabs>
  <Tab title="跑出来的数">
    「86 条测试」「23 个路由」不是文件的话，是命令输出的话。靠约定：跑出来的数字不进散文，要写就钉
    产生它的东西（钉 tests 目录树，让读者自己数）。真要做是「探针」一类，跑命令记输出的哈希，
    成本和风险都不是现在的事。
  </Tab>
  <Tab title="行内记号">
    文内链接指向的那篇还在不在、句子里的反引号——本质是「在不在」与「有没有这个名字」，缺的是行内记号：mdx 格式
    要另加一套识别，fumadocs 那边走的也不是代码块组件。先不做，块级记号先用着。
  </Tab>
  <Tab title="目录的内容">
    目录树只看名字。「这个目录下任何内容变了」就是 git 树哈希，改一行就黄，没有文档需要这种话，不做。
  </Tab>
  <Tab title="名字在不在">
    只看一个字面量在不在的引用不做：它永远不会变黄，测试被改弱、配置值换了都看不出来，
    行段能说的它都说不了。按符号认（导出了没有、签名是什么）得接语言服务，那是另一件事。
    理由见[删掉名字引用](/trajectory/2026-09-27-drop-has-refs)。
  </Tab>
</Tabs>

图、外部网址钉不住；git 历史不会变，不用钉。

## 形态上不做的

- **不做「代码根 / 命名根」配置项**，所以引用路径一律相对项目根，站里写的就是 `../packages/…`，
  标题栏上也这么显示。要更好看得先给配置加一项，那是接口变更。
- **文件改名不追**。改了名就是缺失，重钉。追改名要靠内容相似度猜，猜错比报错更糟。
- **绝对路径不认**。仓外路径在别的机器上会红，机器相关的路径该留在本地配置。
- **不另存记录文件**。确认时的记录只写在各自的记号上，没有全仓共用的记录文件，分支合并不会在那儿冲突。
  理由见 [记录进记号](/trajectory/2026-09-25-records-live-in-markers)。
- **不出第二份给人看的产物**。人看的那份就是站本身，所以渲染只有一种：给 agent 读的那份，按原文渲染，
  只处理 `outputs` 里有映射的生成正本。哪天真需要另一种形态，要在 mdx 格式里另写一种渲染、给摆放加一种落点写法，是接口变更。
- **生成正本里不用 mdx 表达式与名册外组件**。按原文渲染，它们出现就报错，不静默丢掉；名册里的组件换成它自己的机读文字。
  理由见 [按原文渲染](/trajectory/2026-09-25-outputs-render-from-source-text)、[生成正本里的组件换成机读文字](/trajectory/2026-10-08-components-in-outputs)。
