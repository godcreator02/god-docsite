## 仓布局

单元目录只有一张出生证 `unit.json`，不在 git 里；仓根 `god-live-doc/` 是 git 仓，同时是 pnpm 包工作区，
布局照 devkit 的 workspace 仓：插件在 `plugins/`，不是插件的包在 `packages/`，另加 `docs-site/` 这个站。

`plugins/docfirst/` 是工作台插件 `@godcreator/gwb-docfirst-workflow`（两条建站命令与七份说明书，跟四个包互不认识）。
`packages/` 下四个 docfirst 的 npm 包，外加讲解组件的模板包：

`docfirst-pin` 是钉码核心，`docfirst-trajectory` 是轨迹核心，`docfirst-workflow` 是命令行与项目（`src/` 下
format / mdx / project / cli 四个目录），`docfirst-fumadocs` 是 fumadocs 适配，各包管什么见[系统地图](/docs/system-map)。
`docs-explain` 是文档站讲解组件的外壳与零件（分步、动画、选情况三种模板），普通 fumadocs 站也用它，跟四个 docfirst 包互不认识。
站也是工作区成员，是本仓有意的例外：devkit 的建仓模板不收文档站，
这个站却要用 `workspace:*` 装工作区里的包、钉工作区里的真源码，理由见轨迹卡
[插件挪到 plugins/docfirst](/trajectory/2026-09-25-plugin-to-plugins-dir)。
仓根的 `tests/` 是工作区级测试，`tests/fixtures/trajectory/` 是星轨盘的诗名 fixture。

站用这套机制写自己的文档，内容在 `content/` 下分三个区：`docs/` 是现状区（生成正本在 `docs/outputs/`），
`trajectory/` 是轨迹卡，`future/` 是未来区（路线图、在途方案 `spec/`、别的仓投来的反馈 `inbox/`）：

## 提交规矩

按步骤拆，一个提交一件事。提交信息中文，末尾带会话里给的 `Co-Authored-By` 与 `Claude-Session` 两行。
改了被钉的代码，就在同一个提交里处理它引起的黄灯：`docfirst confirm` 做机械写回，逐条复核剩下的黄灯，
论断还成立就 `docfirst confirm <页…> --accept` 点名接受。细节照 skill「docfirst-docs」。

## 发布：devkit.release

四个 npm 包与插件都用工作台命令 `devkit.release` 发布；升哪一位、发版的每一步、发完升级 default，
照 skill「gwb-release」。发到哪个源由各包 `package.json` 的 `publishConfig.registry` 决定，五个包都写的是团队源。

`packages` 只列这次升了版本号的包（源上已有的版本号会被拒），按依赖顺序给：两个核心在前，workflow 其次，
fumadocs 适配最后——包里 `workspace:*` 的依赖发出去写成 `^<工作区里那个包的版本号>`：

```text
devkit.release {"dir":"<仓根>","packages":["packages/docfirst-pin","packages/docfirst-trajectory","packages/docfirst-workflow","packages/docfirst-fumadocs"]}
devkit.release {"dir":"<仓根>","packages":["plugins/docfirst"]}
```

第二行是插件单独发。插件发之前在隔离 home 里用 `docfirst.create` 与 `docfirst.create-plain` 各新建一个站验一遍，
隔离 home 里验证的步骤在 skill「gwb-devkit」。改了官方脚手架的版本或本机约定，先在 `plugins/docfirst/` 里跑 `pnpm test:all`：
它比 `pnpm test` 多一条慢测试，真的运行官方脚手架、跟样本比较（要联网）。

`docfirst-workflow` 与 `docfirst-fumadocs` 升版本号时**跟着改 `plugins/docfirst/src/deps.ts` 那张表**——建站时写进站的依赖版本就取自它，
插件的 `tests/create.test.ts` 里有一条检查它是精确号、跟工作区各包的版本对得上，忘了改测试当场失败。

**两边各发各的，没有先后。**插件对四个包零依赖：它不打包这些包、`package.json` 的各类依赖里也没有它们，所以先发哪个
都不影响另一个；只是表里的版本号改了，插件得再发一版，之后新建的站才装到新包。
