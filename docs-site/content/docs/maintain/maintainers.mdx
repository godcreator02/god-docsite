## 提交规矩

按步骤拆，一个提交一件事。提交信息中文，末尾带会话里给的 `Co-Authored-By` 与 `Claude-Session` 两行。
confirm、render 与提交的先后照 skill「docfirst-docs」。

## 发布：devkit.release

三个包都用工作台命令 `devkit.release` 发到 gitea 个人源；升哪一位、发版的每一步、发完升级 default，
照 skill「gwb-release」。

两个 npm 包一次发，`packages` 按依赖顺序给，轨迹包在前——主包里 `workspace:*` 那条依赖发出去写成 `^<工作区里轨迹包的版本号>`：

```text
devkit.release {"dir":"<仓根>","packages":["packages/docfirst-trajectory","packages/docfirst-workflow"]}
devkit.release {"dir":"<仓根>","packages":["packages/gwb-docfirst-workflow"]}
```

第二行是插件单独发。插件发之前在隔离 home 里新建一个站验一遍（`docs-site.create` 接 `docfirst.attach`），
隔离 home 里验证的步骤在 skill「gwb-devkit」。

两个包升版本号时**跟着改 `packages/gwb-docfirst-workflow/src/deps.ts` 那张表**——装六区时往目标站补的依赖版本就取自它，
插件的 `tests/attach.test.ts` 里有一条检查它是精确号、跟工作区各包的版本对得上，忘了改当场红。

**两边各发各的，没有先后。**插件对包零依赖：它不打包那个包、`package.json` 的各类依赖里也没有它，所以先发哪个
都不影响另一个；只是表里的版本号改了，插件得再发一版，之后新装六区的站才装到新包。
