## 提交规矩

按步骤拆，一个提交一件事。文档章节和它带来的记录簿改动放在同一个提交里——记录簿就是那一章的记忆，
分开提交等于让中间那个提交自相矛盾。挂了 outputs 映射的文档（README、AGENTS.md、五份 skill）动的是 mdx 源：
`docfirst render` 重摆之后，mdx 源、生成物、记录簿同一个提交。提交信息中文，末尾带会话里给的 `Co-Authored-By` 与 `Claude-Session` 两行。

## 发布：devkit.release

三个包都走工作台命令 `devkit.release`，发到 gitea 个人源（scope 路由住用户级 `~/.npmrc`，仓里不配
`.npmrc`）。号在仓里抬、提交之后再调：它先守仓根 git 树干净（有未提交改动就一个都不发），再仓根
`pnpm build`、照 `files` 白名单验产物、同号已在源上就拒，最后 staging 发 `latest`。同一个版本号永不重发。

两个 npm 包一趟发，`packages` 按依赖序给，轨迹包在前——主包里 `workspace:*` 那条依赖发出去写成 `>=` 范围：

```text
devkit.release {"dir":"<仓根>","packages":["packages/docfirst-trajectory","packages/docfirst-workflow"]}
devkit.release {"dir":"<仓根>","packages":["packages/gwb-docfirst-workflow"]}
```

第二行是插件单发。插件发之前在隔离 home 里铺一个新站验（`docs-site.create` 接 `docfirst.attach`），
发完去升 default——外循环正本在 skill「gwb-devkit」。

两个包抬版本号时**跟着改 `packages/gwb-docfirst-workflow/src/deps.ts` 那张表**——铺六区往目标站补的就是它，
插件的 `tests/attach.test.ts` 里有一条守着它是精确号、跟工作区各包的版本对得上，忘了抬当场红。

**两边各发各的，没有先后。**插件对包零依赖：它不打包那个包、三档依赖面里也没有它，所以先发哪个
都不影响另一个；只是表抬了号，插件得再发一版，新铺的站才装到新包。
