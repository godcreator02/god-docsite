# 测试与边界

这一章回答：这套东西一共几摊测试，各守什么规矩，为什么边界测试要去读依赖图，以及文档本身怎么防漂。

## 三摊，各自跑

| 在哪儿 | 怎么跑 |
| --- | --- |
| 工作区根 | `pnpm test`（先 build，再 `node --test tests/*.test.ts`） |
| `docs-site/`（这个站） | `pnpm test` |
| `packages/gwb-live-doc/`（[工作台件](/docs/modules/plugin)） | `pnpm check`（typecheck + oxlint + vitest） |

件那一摊用 vitest，是 `node --test` 唯一的例外——它照 devkit 建出来的件骨架长，不为一个件把骨架
掰弯；工作区根的 `test` 脚本因此不去收它。**铺六区那摊的账整个在件里**，件对包零依赖那条红线
也是件自己守，都归 [工作台件](/docs/modules/plugin) 那一页；工作区这摊一个字都不管它们。

## 记号与比较器：各守一条硬账

- **记号**：`parse(marker(t))` 认回 `t`（两个适配器、五类目标一起过）；草稿记号哨兵不齐的、
  写在句子里的、写在围栏里的、动作词不认识的，一律不认；写回幂等——确认过的文档再确认一次，
  一个字不变。
- **五类目标**：目录树名字多了少了黄带 diff、目录没了红；存在性没了红、类型变了红、断言不在却出现了红；
  名字找不到红；整文件末尾追加也黄。
- **比较器**：git 版与 hash 版在同一串改动下状态一致；git 版的行段跟随、`vanished`、`blob-missing`、
  未提交拒确认，各一条；hash 版的滑窗（挪了跟上、改了位置不明、撞车取最近、并列不猜）各一条；
  auto 版按位置分派——忽略走 hash、仓外走 hash、另一个仓走 git（脏了拒、挪了跟、改了给 diff）、
  未跟踪拒、没提交过的仓拒、软链接按真实路径算，各一条。

## 站测试：不起 Next，走同一条链

`register()` 把 fumadocs 的 Node loader 挂进 Node，`import` 一篇 `.mdx` 走的就是站构建那条链——
不用起服务器，也不是另写一条模拟。断言四样：每条引用在页面上都有一个带 `data-dot` 和来源标题的 `pre`、
组件由 React 表画出来（没有裸标签漏出去）、`_markdown` 里有来源行且组件被压平、以及**这个站自己全绿**。

<Note>
  站测试**不跟命令行比状态**：算状态的是同一个 service，比出来只能相等，比了也证明不了什么。
  跨调用方的比对留给起站抓 `.md` 路由，跟 `render` 落在 `out/` 的那份产物逐字节对。
</Note>

## 文档防漂：这个站自己就是测试

每一章都钉着本仓源码的真实行段。源码改了，那一章的状态点变色，`pnpm livedoc check` 报出来，
站测试那条「全是绿的」直接失败——**文档跟不上代码就过不了门禁**。

哪些文章允许没有引用，由 frontmatter 明说，测试按这个态度放行：

{/* ref file="tests/page.test.mjs" lines="50-51" */}

`livedoc: none` 是导读页（明说不钉），`livedoc: draft` 是还没写的章。两样都没写的，就必须至少钉一处。

门禁怎么跑、提交怎么拆，见 [维护者手册](/docs/maintain/maintainers)。
