包 `@godcreator/gwb-docfirst-workflow`，在 `plugins/docfirst/`，源码在 `src/`，入口 `src/index.ts`，说明书在 `skills/`。
它是 god 工作台（gwb）的插件，不发成 npm 库。

建站经 gwb-docsite 的服务 `gwbDocsite`：地基骨架、功能包起始物、装依赖、探活都归它，这个插件只做 docfirst 特有的两件事——
认站名与选端口，再把功能包交出去。站的托管（`docsite.site.*`）也归 gwb-docsite。docfirst 经[站的功能包](/docs/site)接进站。

## 功能

**包的使用者是仓，插件的使用者是 agent。** 要在仓里发生的核对、确认、渲染归 npm 包，agent `cd` 到站目录里运行站装的
`docfirst` 命令行；只在 agent 手上发生一次的建站归插件。判据的来历见[包给仓、插件给人](/trajectory/2026-09-10-package-serves-repo-plugin-serves-agent)：

scope、仓目录名；端口不给就在站目录的祖父目录里查重、从 4310 起选；然后把功能包交给 `gwbDocsite.init`：

交给哪个版本写在 `src/deps.ts` 那张表里（精确号，`tests/create.test.ts` 盯着它与工作区版本一致）；起始物
（`docfirst.config.mjs`、README / AGENTS / CLAUDE 的 outputs 正本、轨迹与未来两区起始页、docfirst 系脚本）由功能包的
模板带进站。骨架写完就归站点，没有照新模板重写它的命令。

插件没有任何文件启动子进程：装依赖与探活在建站服务里发生，插件不转发 `docfirst` 命令行（`tests/artifact.test.ts` 检查）。

## 零依赖

插件对本仓 `packages/` 下的包零依赖——三档依赖都没有，源码里也不 import（同一条测试检查）。`deps.ts` 里出现包名只是
「写进别人 package.json 的字符串」：装出来的站要跑 docfirst、要渲染，站当然该装这个包。
