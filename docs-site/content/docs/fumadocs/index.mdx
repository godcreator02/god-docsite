包 `@godcreator/docfirst-workflow` 里给 fumadocs 站用的那部分，源码在 `packages/docfirst-workflow/src/fumadocs/`。出口 `./fumadocs`（`src/fumadocs/index.ts`），另有 `./fumadocs/roster`、`./fumadocs/pre`、
`./fumadocs/term`、`./fumadocs/trajectory`，样式表 `./fumadocs/light.css`、`./fumadocs/term.css`、`./fumadocs/trajectory.css`。

调用方有三个：建在文档站基础包上的站经[站的功能包](/docs/site)用其中的 remark 插件与样式表；`docfirst.config.mjs` 展开名册规则；
其余出口给工作台插件建出、还没迁到文档站基础包的 Next 站。本仓的文档站是第一种。

### 两种站都用的

**钉码投影** `remarkDocfirstHost` 是异步插件：每篇 `await loadProject(root)`，第一篇时用项目上的钉码编排、文档身份与名册建出 `remarkDocfirst`，之后复用。
站的 remark 链上没有命令行替它装配，root 就是项目根：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/host.ts" lines="18-32" hash="5004e01206ce" blob="d3d30563fce4" */}

`remarkDocfirst` 对每篇依次认引用、算清单、换节点、按名册标上机读文字，每一步交给谁见上图：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/remark-plugin.ts" lines="26-32" hash="ac17d35141a4" blob="0723b1e3439d" */}

引用在页面上是两种节点：行段与整文件是代码块，状态点的颜色写在 meta 的 `data-dot` 里；目录树是 fumadocs 的 `Files`，容器自己带 `data-dot`。
怎么把颜色画出来归站：站的功能包把代码块包进一层带 `data-dot` 的 div，Next 站靠 meta 白名单与 `DocfirstPre`：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/blocks.ts" lines="4-6" hash="58d79505821f" blob="19f00626cf69" */}

黄「有变动」时旧行和新行显示在同一个代码块里，块里夹着已经不存在的旧行，所以不带行号；红「缺失」显示确认时那段；
取不到旧内容、全文也找不到的黄不显示代码。目录树：

这个 `<img>` 不是作者写的组件。`remarkDocfirstHost` 先给它挂上机读文字 `![说明](/p2/x.png)`，按名册标机读文字时就跳过它；

## 不做的事

- **不认识站的路由框架**：这个目录里没有一处 import Next 或 React Router，卡页地址由调用方传 `hrefBase`，项目根由调用方传 `root`。
- **不认记号、不判状态**：认记号与标上机读文字用 workflow 的 `./mdx`，核对经项目上的钉码编排，状态由[钉码核心](/docs/pin)算，这里只把清单换成树上的节点。
- **不管讲解组件源码里的引用**：remark 插件只处理 mdx 页面；组件源码里写的引用由命令行的 `check` 核对，站上不显示组件的状态。
- **不管生成物**：生成正本的渲染与写到哪归 [workflow](/docs/workflow)。
- **不分区**：哪篇是现状区、哪篇是轨迹卡由调用方判断，站的功能包按项目的内容根与轨迹卡目录分。
- **不把宿主、本仓别的包与本包的命令行代码打包进产物**：只按包名 import；`./fumadocs/pre` 的 `"use client"` 在产物第一行，别的出口不带：
