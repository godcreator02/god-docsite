文档对代码说的话只有三种：内容、形状、有没有；说的对象是文件或目录。五类引用把这张表填满：

| | 文件 | 目录 |
| --- | --- | --- |
| 内容 | 行段 `ref 文件:起-止`、整文件 `ref 文件` | 不钉：目录的内容改任何一行都算变，没有哪句话需要这样钉 |
| 形状 | 名字 `has 文件 "字面量"` | 目录树 `tree 目录` |
| 有没有 | `exists 路径`、断言不在 `absent 路径` | 同左 |

行段和整文件会黄，是因为记号上记了内容的 `hash`；目录树只记名字表的 `hash`，旧名字表不存，所以只知道「变了」、说不出多了哪个；
存在性和名字不记内容，只有对得上和对不上，没有黄。

## 一句话该用哪一类

| 你想说的话 | 用哪一类 | 为什么不用别的 |
| --- | --- | --- |
| 「这段代码是这么写的」，或者钉住注释里写的理由 | 行段 | `has` 看不见内容的改动；整文件别处一改就黄 |
| 「整个文件就是这些」（小配置、小脚本） | 整文件 | 行段看不见末尾追加的行 |
| 「这里有哪些东西」 | 目录树 | 行段钉不住目录；`exists` 一次只说一个路径 |
| 「有 / 不该有某个文件」：边界与禁止事项 | `exists` / `absent` | 目录树会连带报出同目录别的文件的变化 |
| 「里面写着某个名字」：导出名、契约条目、测试名 | 名字 `has` | 行段那行改个空格就黄；名字改了该是红，不是黄 |

几条容易挑错的：

- **`has` 是逐行的纯文本包含**，区分大小写，不管在第几行、出现几次。写 `export function hashSpan`，不写光秃秃的 `hashSpan`：
  后者也会命中别处的调用：导出删了、调用还在，它照样是绿。

{/* ref file="../packages/docfirst-pin/src/compare.ts" lines="58-62" hash="beccefc10c11" blob="29bf0bfed8b4" */}

- **目录树按 `.gitignore` 过滤**：`dist/`、`node_modules/` 不进名字表，也不往里走。`glob` 只认 `*` 和 `?`，匹配的是名字不是路径。

{/* ref file="../packages/docfirst-workflow/src/project/fs-reader.ts" lines="4-5" hash="e234123a7860" blob="2c9427f15c3d" */}

- **整文件别钉随发版变的文件**：`package.json` 带着 `version`，每发一次版就黄一次，跟文档那句话毫无关系。
  这种黄多了，人会不读就直接 `--accept`。
- **跑出来的数不钉**：「几条测试」「几个路由」是命令的输出，不是哪个文件里写着的，不写进正文。
