文档里钉一处码，是在一句话下面单独写一行记号，指向源码里的几行。`confirm` 在记号上写下两个值：`hash` 是被钉那几行（去掉行尾空白）的
sha256 前 12 位，`blob` 是整个文件当时的 git blob 名前 12 位。之后每次 `check` 都拿今天的代码去比，给出四种状态之一：

{/* ref file="../packages/docfirst-pin/src/types.ts" lines="94-95" hash="d2a2e323f0a3" blob="5973fadd9101" */}

| 状态点 | 状态 | 什么意思 | `check` 算不算红 |
| --- | --- | --- | --- |
| 绿 | 新鲜 | 被钉的内容跟确认时一样，位置变了也算 | 不算 |
| 黄 | 有变动 | 内容变了，等人读一遍那句话再确认 | 不算；本仓未提交的改动引起的算，见[什么算红](/docs/pinning/gate) |
| 红 | 缺失 | 被钉的东西不在了 | 算 |
| 空心 | 未确认 | 记号上还没有确认时写的记录 | 不算 |

记录只写在记号自己身上，没有另外的记录文件。同一篇里两处记号指向同一段，也各带各的记录、各自写回；
一处是红，只是那一处不动，别的照写。删掉记号，它的记录也就没了。

`confirm` 对每一处做什么只看它此刻的状态：未确认的记上记录；绿的行段挪了位置就写回新行号；黄的只有带 `--accept`
