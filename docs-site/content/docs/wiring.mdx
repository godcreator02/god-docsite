# 插件之间怎么连

**本页回答**：本仓插件提供哪些服务、命令与事件；注入了哪些服务、是必需还是局部注入、peer 怎么写；按名字调用了别家哪些命令、用了哪些约定通道。

本仓只有一个插件；两个 npm 包 `@godcreator/docfirst-workflow`、`@godcreator/docfirst-trajectory` 不是插件，不在这一页。

## @godcreator/gwb-docfirst-workflow

### 提供

| 类别 | 名字 | 说明 |
| --- | --- | --- |
| 命令 | `docfirst.attach` | 给一个刚生成的 fumadocs 骨架装上 docfirst 的三个区，见[装配](/docs/modules/site) |
| 说明书 | `docfirst`、`docfirst-docs`、`trajectory`、`spec-grill`、`parallel-by-module`、`docs-governance` | 插件包 `skills/` 下六份，正本在本站 `content/docs/outputs/skills/` |

不提供服务、事件、窗格，也没有给别的插件按值 import 的导出。

{/* has file="../packages/gwb-docfirst-workflow/src/index.ts" text="export const ATTACH_COMMAND = 'docfirst.attach'" */}

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需 | `^0.5.0` | 登记 `docfirst.attach` | 插件不加载 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入 | `^0.4.5`，`optional: true` | 注册 `skills/` 下的说明书 | 命令照常可用，只是读不到说明书 |

{/* has file="../packages/gwb-docfirst-workflow/package.json" text="gwb-commands&quot;: &quot;^0.5.0&quot;" */}

{/* has file="../packages/gwb-docfirst-workflow/package.json" text="gwb-skills&quot;: &quot;^0.4.5&quot;" */}

peer 里另有内核包 `@godcreator/gwb-kernel-desktop`（`GwbContext` 从它的包根 `import type`），范围写验证时那个内核的版本。
构建产物里没有按值 import 的包，所以 peer 里没有 `cordis`。本仓 `pnpm-workspace.yaml` 关了 `autoInstallPeers`，
所以 peer 里的三个包在 dev 里再各写一份，否则装不进 `node_modules`、类型检查找不到。

{/* has file="../packages/gwb-docfirst-workflow/package.json" text="gwb-kernel-desktop&quot;: &quot;^0.7.2&quot;" */}

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 读写文件 | 目标站目录 | `docfirst.attach` 的 `dir` | 往站里写装配文件；站的骨架由站点插件 `@godcreator/gwb-docs-site` 的 `docs-site.create` 生成，两个插件之间不互相调用，由人或 agent 先后调两条命令 |

不按名字调用别家的命令，不推、不收事件，不起子进程，不联网。
