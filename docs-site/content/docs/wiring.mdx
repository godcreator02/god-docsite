**本页回答**：本仓插件提供哪些服务、命令与事件；注入了哪些服务、是必需还是局部注入、peer 怎么写；按名字调用了别的插件哪些命令、用了哪些约定通道。

本仓只有一个插件，在 `plugins/docfirst/`；`packages/` 下四个 npm 包 `@godcreator/docfirst-pin`、`@godcreator/docfirst-trajectory`、`@godcreator/docfirst-workflow`、`@godcreator/docfirst-fumadocs` 不是插件，不在这一页，它们也不认识任何 gwb 插件。

## @godcreator/gwb-docfirst-workflow

### 提供

| 类别 | 名字 | 说明 |
| --- | --- | --- |
| 命令 | `docfirst.create` | 建一个接好 docfirst 三个区的文档站，见[建站](/docs/modules/site) |
| 命令 | `docfirst.create-plain` | 建一个不接 docfirst 的普通 fumadocs 站，见[建站](/docs/modules/site) |
| 说明书 | `docfirst`、`docfirst-docs`、`docs-site`、`trajectory`、`spec-grill`、`parallel-by-module`、`docs-governance` | 插件包 `skills/` 下七份，正本在本站 `content/docs/outputs/skills/` |

不提供服务、事件、窗格，也没有给别的插件按值 import 的导出。

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需 | `^0.5.0` | 登记两条建站命令；按名字调 `settings.get` | 插件不加载 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入 | `^0.4.5`，`optional: true` | 注册 `skills/` 下的说明书 | 命令照常可用，只是读不到说明书 |

{/* has file="../plugins/docfirst/src/index.ts" text="export const inject = ['gwbCommands']" */}

{/* has file="../plugins/docfirst/src/index.ts" text="ctx.inject(['gwbSkills']" */}

{/* has file="../plugins/docfirst/package.json" text="gwb-commands&quot;: &quot;^0.5.0&quot;" */}

{/* has file="../plugins/docfirst/package.json" text="gwb-skills&quot;: &quot;^0.4.5&quot;" */}

从这两个包的包根只 `import type {}`：为的是让它们的 `declare module 'cordis'` 生效，`ctx.gwbCommands`、`ctx.gwbSkills`
才有类型。构建产物里没有它们的运行时 import。

{/* ref file="../plugins/docfirst/src/index.ts" lines="2-4" hash="dfb1db0d7f65" blob="a9aa2f4c2ca3" */}

peer 里另有内核包 `@godcreator/gwb-kernel-desktop`（`GwbContext` 从它的包根 `import type`），范围写验证时那个内核的版本。
构建产物里没有按值 import 的包，所以 peer 里没有 `cordis`。本仓 `pnpm-workspace.yaml` 关了 `autoInstallPeers`，
所以 peer 里的三个包在 dev 里再各写一份，否则装不进 `node_modules`、类型检查找不到。

{/* has file="../plugins/docfirst/package.json" text="gwb-kernel-desktop&quot;: &quot;^0.7.2&quot;" */}

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 命令 | `@godcreator/gwb-settings` | `settings.get` | 建站时读容器根，决定端口在哪个目录里查重 |
| 设置 | `@godcreator/gwb-unit-folder` | 分区 `unit-folder`、键 `units-root` | 容器根的路径。读不到、没配或站不在它里面时只查站目录的祖父目录，原因写进回执 |

{/* has file="../plugins/docfirst/src/index.ts" text="cli.run('settings.get', UNITS_ROOT_SETTING)" */}

{/* has file="../plugins/docfirst/src/index.ts" text="section: 'unit-folder', key: 'units-root'" */}

两个对方都不是必需注入：`settings.get` 调不成，或单元文件夹插件没装、这个键没配，建站都照常，只是查重范围小一些。
不发出、不监听事件。唯一的子进程是运行官方脚手架（`pnpm dlx create-fumadocs-app`，带超时，要联网），见[建站](/docs/modules/site)。
