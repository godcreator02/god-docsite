# 文档站的操作

这份只讲**对站执行什么命令**。页面内容怎么写、钉码钉哪种话看同一个插件的说明书 `docs-writing`；轨迹卡看 `trajectory`。

站约定放在 `<仓>/docs-site/`，下面的命令都在站目录里运行。站建在平台包 `@godcreator/god-docsite` 上（fumadocs + React Router + Vite）；
docfirst 站另装功能包 `@godcreator/code-pin`、`@godcreator/trajectory`、`@godcreator/explainer`，命令行 `@godcreator/docfirst` 装在 devDependencies。
**核对、确认、生成在站目录里自己运行 `pnpm doc` 系列脚本**，插件不转发命令行。

## 建站

```
docfirst.create  {"dir":"<仓>/docs-site","audience":"shared"}    接好 docfirst 的站：现状、轨迹、未来三个区，钉码与生成物
```

- `dir`：站目录的绝对路径，**要不存在或是空目录**，上一级（仓目录）必须已经存在
- `audience`：必给，写这个站给谁看。别人也会 clone 下来看写 `shared`（代码仓的文档站多是这种），只有自己在本机看写 `personal`；拿不准就问人
- `title`：站名，不给就依次用仓根 `package.json` 的 `title`、包名去掉 scope、仓的目录名
- 只认这三个参数，多给一个就拒绝

它先建基础站（同 `docsite.site.init`：复制平台模板、装依赖、启动服务检查），再把 `@godcreator/docfirst` 的起始物（`docfirst.config.mjs`、`content/docs/outputs/` 下
README / AGENTS / CLAUDE 的正本、未来区起始页、第一张轨迹卡）复制到站点根（已有的文件不覆盖），往 `package.json` 写脚本 `doc`、`doc:confirm`、`doc:render`，
最后逐个加功能包 code-pin、trajectory、explainer。中途失败时前面做完的不回退，报错写明是哪一步失败。

仓根已经有 `README.md` / `AGENTS.md` / `CLAUDE.md` 时，第一次 `pnpm doc:render` 会**覆盖**它们：先把原有内容移进 `content/docs/outputs/` 下对应的 mdx 正本，再 render。

不要 docfirst 的站直接用这两条命令：

```
docsite.site.init    {"dir":…,"title":"站名","audience":"personal"}           dir 要不存在或是空目录；title、audience 必给
docsite.feature.add  {"dir":…,"package":"@godcreator/trajectory","version":"^0.1.0"}   加一个功能包
```

`docsite.feature.add` 在站点目录里 `pnpm add` 这个包，把它 `template/` 里站点还没有的文件补进 `app/features/<功能>/`（已有的不覆盖），重写 `app/features/` 下的汇总文件，
再启动服务检查。可以对同一站点重复运行，只补缺的；站点在运行时拒绝，先 `docsite.site.stop`。`version` 不给就用 gwb-docsite 旁边装着的那一版，没装就拒绝。

## 改站的结构

- **加一个分区**（`content/notes/` → `/notes`）：建目录，`meta.json` 写 `title`、`"root": true` 与 `pages`，再把目录名加进 `content/meta.json` 的 `pages`。`content/` 下除 `future/` 外的目录自动算现状区，不用登记
- **侧栏顺序**写在各目录的 `meta.json`：`{ "pages": ["index", "...", "glossary"] }`，`"..."` 是其余按文件名排
- **`app/` 由建站器写出**：`app/features/` 下文件名带 `generated` 的汇总文件每次加功能都重写，不手改
- **页面用到的文件放哪**：只给一页用的组件、数据、样式、图片放进和页面同名的文件夹（`push.mdx` 配 `push/`），页面开头按相对路径 `import`（`./push/auto-merge`）；
  同一组里几页共用的放进组里 `_` 开头的文件夹；跨组共用的放内容根下的 `_components/`（`content/_components/`），页面里按前缀 `@components/…` import，**放之前先问人**。这些文件夹里不放页面与 `meta.json`，组文件夹里只放页面、`meta.json` 与这几种文件夹，放错了构建直接报错，开发服务在页面顶上正中的问题按钮里列出来。
  写法与例子看 gwb-docsite 的说明书 `docsite`「写页面」
- **用组件**：fumadocs 自带的组件（`Callout`、`Cards`、`Tabs`、`Steps`、`Files` 等）与平台的 `Term` 不用 import。
  生成正本里用到的组件才要在 `docfirst.config.mjs` 的 `components` 给一条机读规则，名册外的组件 `pnpm doc` 报红、render 拒绝渲染
- **术语表**是站点根的 `glossary.json`（每条 `term` / `aliases` / `def` / `href`），不标术语的页写在 `app/lib/mdx-plugins.ts`
- **图片**放进页面的同名文件夹，Markdown 图片 `![说明](./push/x.png)` 不用登记；**公式**模板已经接好（remark-math + rehype-katex），直接写
- **代码块要行号**就在开头写 `lineNumbers`（`lineNumbers=N` 从 N 起），没写的不带。没写语言的块写成 ` ```text lineNumbers `：开头第一个词是语言名
- 站用到的包都写进站自己的 `package.json`：pnpm 不让代码 import 没声明的依赖

## 托管与查看

开发服务由 gwb-docsite 托管，不在会话里自己 `pnpm dev`；改了页面，开发服务自己刷新。下面每条只收 `dir`（站点目录的绝对路径），`list` 不收参数：

```
docsite.site.add     {"dir":…}    登记为常驻并启动（插件每次加载时也会启动登记着的站：工作台启动、插件升级都算）
docsite.site.start   {"dir":…}    启动；人为停了、启动失败修好之后也用它
docsite.site.stop    {"dir":…}    停掉
docsite.site.list    {}           各站的站名、state（running / stopped / failed）、url（只在运行时有）、error、是否常驻与谁登记的
docsite.site.remove  {"dir":…}    停掉并不再托管
```

人在工作台的「站点」窗格里看同一张表，能打开、启停。

- 端口不写在站里（`scripts.dev` 写了 `--port` 就拒绝启动）：先试这个站上次用的，被占了由平台的 vite 插件在 10000–49151 里随机挑；地址以 `docsite.site.list` 的 `url` 为准。启动前核对站点的 `node_modules` 里装着 `@godcreator/god-docsite`
- **页面打开是「Error」、白屏，或开发服务退出了**：开发服务的输出进 gwb 日志，日志名 `gwb-docsite-dev`，每条开头是站点目录。stderr（Vite 与服务端渲染的报错）记 warn，`logger.query {"name":"gwb-docsite-dev","minLevel":"warn","limit":50}` 就能看到；stdout 记 debug，默认不写进 gwb.log，要看完整输出就在环境变量 `GWB_DEBUG` 里加上 `gwb-docsite-dev` 再启动工作台
- **改了构建页面时 remark 插件会调用到的包**（code-pin、trajectory、god-docsite 的术语标注）：在改过的包里 `pnpm build`，再 `docsite.site.stop`、`docsite.site.start`
- 给人看就在 VS Code 的内置浏览器里打开 `docsite.site.list` 回的地址（读说明书 `vscode`）；只是自己验证，没托管的站 `docsite.site.start`，验完 `docsite.site.stop`
- `pnpm build` 是 `react-router build`，只作提交前的检查；agent 读 `content/` 下的 mdx 正本，不解析 HTML

### 验收一页

- 每个按钮点一下、每种情况都试一遍，深浅主题各看一次，把窗口拉窄看一次。预览把窗口缩放过时按坐标点会点偏，改用元素引用
- docfirst 站再运行 `pnpm doc`；页面是生成正本的，看一眼生成物里组件变成的文字读得懂

**讲解组件截图验收**：预览面板被隐藏时截图是空白的（页面宽度是 0、逐帧回调不运行），改用 Playwright 驱动本机 Edge 截图。
Playwright 从 academic-deck 仓里取，不另装；脚本放临时目录，用 `node <脚本> <页面地址> <截图目录>` 运行，再逐张看图：

```js
import { createRequire } from 'node:module';
const { chromium } = createRequire('D:/unitfolders/e0k6i-academic-deck/package.json')('playwright');

const [url, out] = process.argv.slice(2);
const views = {
  light: { viewport: { width: 1280, height: 900 }, colorScheme: 'light' },
  dark: { viewport: { width: 1280, height: 900 }, colorScheme: 'dark' },
  narrow: { viewport: { width: 375, height: 812 }, colorScheme: 'light' },
};
const browser = await chromium.launch({ channel: 'msedge' });
for (const [view, options] of Object.entries(views)) {
  const page = await browser.newPage(options);
  await page.goto(url, { waitUntil: 'networkidle' });
  const components = page.locator('.dx:not(.dx .dx)');   // 只取最外层的讲解组件
  for (let i = 0; i < (await components.count()); i++) {
    await components.nth(i).screenshot({ path: `${out}/dx-${i}-${view}.png` });
  }
  await page.close();
}
await browser.close();
```

- 每个组件截浅色、深色、375 宽各一张
- 动画在宽屏和 375 宽下都把时间拖到设计说明里写的关键时刻再截：起始帧画面上还没东西，看不出会不会重叠。
  动画外壳的时间条是 `aria-label="时间"` 的滑块、值以秒计，`components.nth(i).locator('input[aria-label="时间"]').fill('<秒数>')` 拖到那一刻，截图文件名带上秒数
- 对照设计说明的验收标准逐条看图。发现问题逐条写清：哪个组件、哪张图、哪里出了问题、要改成什么，发回给实现方，改完重截

## docfirst 站：核对、确认、生成

```
pnpm doc                                        核对（docfirst check）。有红时退出码 1——那是核对结果，不是命令失败
pnpm doc --json                                 整份机读报告，一行 JSON，退出码同上
pnpm doc:confirm                                机械写回：未确认的记号写上记录、挪了位置的写回新行号、重新生成生成物
pnpm doc:confirm content/docs/a.mdx --accept    复核过后，接受点名页里的黄灯；必须点名页
pnpm doc:render                                 只重新生成生成物
pnpm exec docfirst trajectory                   列出轨迹卡在星轨盘上的树与主干（可带 --json）
```

开关写错、`check` 或 `render` 带了页名，命令行报错、退出码 2，什么都不动。

**读 `--json` 报告**：`docs[].items[]` 里 `status` 是 `changed`（内容变了）或 `missing`（目标不在了）的就是待处理，带 `blocking: true` 的黄灯算红；
`line` 是记号在文档里第几行，`lines` 是被引的那段今天在源文件里的位置，`diff` 是变了的那几行；`unconfirmed` 不算对不上。
`doc` 也可能是讲解组件的源码：现状区里的 `.ts`、`.tsx`、`.mjs`（项目根下还有 `src/components/`、或站点 `app/components/` 下有带钉码标记的文件时 docfirst 直接报错，组件要挪进内容根）。生成正本还有 `outputs[]`，轨迹卡的问题在顶层 `trajectory[]`。

### 改了被钉的代码：同一个提交里处理黄灯

1. 改代码，先运行不带文档的检查（类型、测试）
2. 在站目录运行 `pnpm doc`：钉住的文件在本仓有未提交改动、内容又变了的黄灯**算红**
3. `pnpm doc:confirm`：机械写回，黄灯原样留着、逐条列出
4. 逐条看剩下的黄灯：论断还成立就 `pnpm doc:confirm <页…> --accept`；不成立先改正文再确认（怎么改看 `docs-writing`）
5. 代码、文档、记号上的新记录放进同一个提交

`--accept` 只点名自己复核过的页，别人还没复核的黄灯不替别人接受。确认不要求先提交。

### 生成物

README、AGENTS.md、CLAUDE.md、插件里的 SKILL.md 是生成物：`docfirst.config.mjs` 的 `outputs` 把 mdx 正本对到生成位置。
**改正本，不改生成物**，改完 `pnpm doc:render`，正本与生成物放进同一个提交；两边对不上 `pnpm doc` 报红。
SKILL.md 要在映射里写对象形式 `{ to, frontmatter: ["name", "description"] }`，否则生成出去没有 frontmatter，永远不会被读到。

## 给别的仓写反馈

在 A 仓工作时发现 B 仓的问题，在 B 仓在 gitea 上的仓里开一条 issue，不往 B 仓里写文件：仓的位置看它 `package.json` 的 `repository.url`
或在仓里 `git remote get-url gitea`，经 `gitea.http {"method":"POST","path":"/repos/<owner>/<仓名>/issues","body":{"title":…,"body":…}}` 开，
回执 `status: 201` 才算开好。正文最后一行写 `来源：<哪个仓 / 哪次会话>`。B 仓在 gitea 上没有仓的，告诉人。

## 安装或构建失败

- 发布不满一天的包 pnpm 拒绝安装（`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`）：把版本退回上一个；只在本机临时验证可以在当前终端设 `$env:pnpm_config_minimum_release_age='0'`
- 安装设置写 `pnpm-workspace.yaml`，项目级 `.npmrc` 里的安装设置 pnpm 不读
- 页面报「DocsPage 要在 DocsLayout 下」：装出了两份 `@fumadocs/base-ui`，常见原因是 fumadocs-core 的可选 peer `zod` 解析成两个版本；在 `pnpm-workspace.yaml` 的 `overrides` 里把 `zod` 定成一个版本再装
