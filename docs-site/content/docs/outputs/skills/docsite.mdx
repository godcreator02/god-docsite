# 平台建的站（gwb-docsite）

站点建在平台包 `@godcreator/god-docsite` 上（fumadocs + React Router + Vite）：`content/` 放页面，`comments/` 放评论，`people.json` 列出人员，
`docsite.json` 是身份文件（站点类别与布局代号），`app/features/<功能名>/` 是各功能包的接线文件。基础站自带身份（`@godcreator/identity`）与评论（`@godcreator/comments`）。
每条命令的参数与回执以 usage 为准（`search {"prefix":"docsite."}`）；`dir` 一律是站点目录的绝对路径。

## 始终照做

- 开发服务由工作台托管，不在会话里自己 `pnpm dev`：会话一停站点就没了，几个会话还会抢同一个端口；自己启动的拿不到身份码，站点只读
- 要看页面，把 `docsite.site.list` 回的 `url` 交给 VS Code 插件打开（说明书 `vscode`）
- 这些命令只写站点目录里的文件，不碰 git；提交由各站自己的流程做（协作站是 `collab.submit`）
- 评论只经网页或 `docsite.comment.*` 写，不自己写评论文件

## 建站与加功能

```text
docsite.site.init    {"dir":…,"title":"站名"}
docsite.feature.add  {"dir":…,"package":"@godcreator/trajectory","version":"^0.1.0"}
```

- `docsite.site.init`：`dir` 要不存在或是空目录，`title`（写进 `content/meta.json`）必给；端口不写进站点，启动时挑。
  复制平台包的 `template/`，平台包、身份、评论三个包写成插件旁边装着的那一版的 `^<版本>`，身份文件写 `"kind": "base"`，`pnpm install`，补上评论功能的接线文件，再启动服务检查首页。
  `people.json` 里只有 agent `claude`，人用 `docsite.people.join` 把自己加进来
- `docsite.feature.add`：在站点里 `pnpm add <package>@<version>`，把功能包 `template/` 里站点还没有的文件补进 `app/features/<功能名>/`（已有的不覆盖），
  重写 `app/features/` 下文件名带 `generated` 的汇总文件，再启动服务检查首页。`version` 不给就用 gwb-docsite 旁边装着的那一版，没装就拒绝。
  可以重复运行，只补缺的；站点在运行时拒绝，先 `docsite.site.stop`
- 启动服务检查时看首页回不回 200：通过后登记为常驻的站保持运行，没登记的停掉；没通过就报错，站点留着运行，报错在浏览器里看，看完 `docsite.site.stop`
- 协作站由 `collab.site.init` 建（说明书 `collab`），docfirst 站由本插件的 `docfirst.create` 建（说明书 `docs-site`），它们自己做完建基础站、加功能这两步，不用再调这两条命令

## 升级已有站点

没有升级命令：平台模板写出的文件写完就归站点，`docsite.site.init` 只建新站，`docsite.feature.add` 不覆盖已有文件。要跟上新版的平台包或功能包时：

1. 站点停着时在站点目录里把包升到要的版本（`pnpm add <包>@^<版本>`；功能包也可以 `docsite.feature.add` 带 `version`，顺带补上新加的接线文件）
2. 由 agent 对照平台包与功能包的 `template/` 逐个判断要改哪些文件：平台包的 `node_modules/@godcreator/god-docsite/template/` 对站点根，
   功能包的 `node_modules/<包名>/template/` 对 `app/features/<功能名>/`。站点自己改过的地方保留，只把模板里新的改动并进去
3. 改动给人过目，再启动检查、按站点自己的流程提交

## 托管与启停

```text
docsite.site.add     {"dir":…}   登记为常驻并启动；插件每次加载时（工作台启动、插件升级）也启动登记着的站
docsite.site.start   {"dir":…}   启动；已在运行或正在启动就回现状
docsite.site.stop    {"dir":…}   停掉；没在运行就拒绝
docsite.site.list    {}          每个站 { dir, state, url, error, title, kind, hosted, by }：state 是 running / stopped / failed，url 只在运行时有，
                                 title 是站名，kind 是类别（base / docs / collab，没有身份文件为 null），hosted 是登记为常驻，by 是谁登记的（docsite.site.add 或插件名）
docsite.site.remove  {"dir":…}   去掉常驻登记，在运行就停掉；没登记过就拒绝
```

- 启动前核对：站点根有身份文件 `docsite.json` 且写对了，`node_modules` 里装着 `@godcreator/god-docsite`，`scripts.dev` 没写 `--port`（写了就拒绝，照报错去掉）
- 身份文件写明站点的类别与布局代号，平台建站时写，只有两项：`{ "kind": "base" | "docs" | "collab", "format": 1 }`。
  没有它的站拒绝托管（旧包 `@godcreator/docsite-kit` 上的站、有身份文件之前建的站）：平台建的站照报错手动补一份，别的站先迁到平台；`format` 不是 `1` 也拒绝，照平台包的 `template/` 升级站点后再改
- 启动时经环境变量交给站点本 home 的身份码 `DOCSITE_IDENTITY_CODE` 与这次的推送令牌 `DOCSITE_FEED_TOKEN`
- `failed` 时 `error` 写着退出码与最后几行输出。进程自己退出了会自动重启：连续崩溃时依次等 2 秒、10 秒、60 秒，`error` 末尾写着几秒后第几次；连续三次重启都没撑过 5 分钟就不再重启，`error` 写着「不再自动重启」，查明原因修好后 `docsite.site.start`。等着重启时 `docsite.site.stop` 取消这次重启
- 常驻的站只记在 gwb-data 的文档 `hosted-sites` 里，不在设置里。协作站也在里面：gwb-collab 在项目加进列表时登记、移出列表时去掉，启停照样用 `docsite.site.start` / `docsite.site.stop`；
  不想要某个协作站就移出项目列表（`collab.project.remove`），单 `docsite.site.remove` 的话 gwb-collab 下次加载又登记回来
- 人在工作台的「站点」窗格里看每个站：站名、类别（协作站、文档站、基础站）、来源（手动、gwb-collab、临时）、状态与端口，能打开、启停，手动登记的还能不再托管

## 我是谁

每个 home 有一串身份码（`docsite.identity` 查，设置 `identity-code`，第一次加载时生成），站点按 `people.json` 里各人的 `codes` 认人。
只有本机由工作台托管的开发服务（`pnpm dev`）能写评论、改任务；`pnpm build` 之后用 `pnpm start` 跑的是发布版，全面只读，环境变量里有身份码也不认。
协作就是各人在自己电脑上改、经 git 同步，不做多人共用一个网站写入。
侧栏底部写「只读」、悬停提示码不在 `people.json` 里时：

```text
docsite.people.join {"dir":…,"id":"<字母数字_->","name":"<显示名>","gitea":"<可选>"}
```

已有这个 `id` 就把码加进它的 `codes`，没有就新加一项；码已在别人名下、`id` 是 agent 时拒绝。只写文件，要别人也看到得提交。
换电脑时把旧电脑的码填进新电脑的设置 `identity-code`，之后启动的开发服务才用新的码。

## 评论

- 读：`docsite.comments {"dir":…,"page"?:…,"about"?:…}`，读文件，不要站点在运行。`page` 是页面在 `content/` 里的路径（如 `writing/collapse-test.mdx`），
  `about` 是人员 id，只列和他有关的（他发起的、正文或回复里 @ 了他的）。评论串在 `comments/<id>/`：`index.mdx` 是发起的那条，回复各一个 `.mdx`
- 写：`docsite.comment.create {"dir":…,"page":…,"body":…,"anchor"?:…,"as"?:…}` 批整页，给 `anchor`（页面元素的 id）批那个元素；
  `docsite.comment.reply {"dir":…,"thread":…,"body":…,"as"?:…}`，`thread` 是 `docsite.comments` 回的 `id`。两条都要站点在运行。
  agent 以自己的名义写时给 `as`（`people.json` 里 `"agent": true` 的 id），不给就署本 home 的人
- 正文是 MDX：字面的 `<`、`{` 写成 `\<`、`\{` 或放进反引号；`@<id>` 是 @ 某人
- 每串评论有状态：`index.mdx` 的 `status` 是 `open` 或 `resolved`，`resolved` 时还有 `resolvedBy`（谁标的）与 `resolvedAt`；`docsite.comments` 每串带着它们。
  `docsite.comment.resolve {"dir":…,"thread":…,"as"?:…}` 标为已解决，`docsite.comment.reopen` 重新打开，要站点在运行；已经是那个状态就拒绝。网页上点开一串评论、鼠标移到发起的那条上，有同样的按钮（对勾是标为已解决，回转箭头是重新打开），发布版没有。
  标了以后这串带来的 @ 与回复不再算待办；替人标之前先问人
- 人让你照某条评论改页面时：先 `docsite.comments` 找到它，改完页面再 `docsite.comment.reply` 说明改了什么

## 写页面

- 页面放在 `content/`：`名字.mdx`（frontmatter 写 `title`、可选 `description`、`icon`）、`名字.page.tsx`（导出 `meta = { title }` 与默认组件）、`名字.html`（`<title>` 是标题）
- 页面用到的文件按用到它的范围放：
  - 只给一页用的组件、数据、样式、图片、被 import 的正文（`_` 开头的 `.mdx`）放进和页面同名的文件夹，里面可以再分子文件夹；
    `waveform.mdx`、`waveform.page.tsx`、`waveform.html` 都配 `waveform/`，页面里写 `./waveform/…`
  - 同一组里几页共用的放进组里 `_` 开头的文件夹（如 `_shared/`）
  - 跨组共用的放内容根下的 `_components/`（`content/_components/`），页面里写 `@components/…`（站点 `tsconfig.json` 的 `paths` 带这个前缀，早建的站没有就补上 `"@components/*": ["./content/_components/*"]`，`include` 里再加 `"**/*.mdx"`：Vite 只给 tsconfig 收进来的文件按 `paths` 解析，`"**/*"` 不收 `.mdx`），**放之前先问人**：多数时候放进上面两处就够了。
    `app/` 是站点代码，页面用的组件不放那里
  - 同名文件夹与 `_` 开头的文件夹里不放页面（不以 `_` 开头的 `.mdx`、`.page.tsx`、`.html`）与 `meta.json`：
    fumadocs 解析 `meta.json` 里的名字时先找文件夹，同名文件夹一旦被认成组，那一页就从侧栏消失。目录说明只认 `meta.json`，别的 `.json` 可以当附件放
  - 组文件夹（有 `meta.json`、里面是页面）只放页面、`meta.json`、同名文件夹、`_` 开头的文件夹与子组，不散放别的文件
  - 放错了 `pnpm build` 直接报错；开发服务不拦，终端与浏览器底部的问题按钮里列出每个文件，照着挪；协作站的 `collab.submit` 也拦下放错的文件
- 有子页面的页写成组：`guide/index.mdx` 是 `/guide`，它的组件放 `guide/index/`
- 例子：

  ```text
  content/research/
  ├─ meta.json        pages: ["survey", "fpga"]，不写同名文件夹
  ├─ survey.mdx       只有文字，没有文件夹
  ├─ fpga.mdx
  ├─ fpga/            fpga.mdx 用的组件、数据、图片
  │  ├─ Comparison.tsx
  │  └─ media/board.png
  └─ _shared/         组里几页共用的
  ```

- 文件夹的 `meta.json` 写 `title`、`pages`（顺序，写文件名去掉扩展名，TSX 页面也去掉 `.page`）、`icon`（lucide 图标名）；写了 `"root": true` 的是侧栏顶上切换下拉框的一项，点了去这一项的首页，没有首页就去它里面的第一页（只放子文件夹也行）；不在任何一项里的页面收成以站名命名的一项
- 首页 `/` 是站点的 `app/routes/home.tsx`（fumadocs 的 `HomeLayout`，没有侧栏），不在 `content/` 里：`content/` 根上不放 `index` 页，放了打开首页报错
- 地址就是 `content/` 下的路径；`/api`、`/comments`、`/llms.txt` 与功能包的页面（如协作站的 `/tasks`、`/calendar`、装了报告功能的 `/reports`）留给站点自己。改了页面，开发服务自己刷新

## 写报告

装了功能包 `@godcreator/word-report` 的站才有报告（`docsite.feature.add` 加上）。

- 报告放在站点根下 `reports/<报告 id>/`，不放进 `content/`；报告 id 只用小写字母、数字和 `-`。正文有两种写法，一个报告目录里只能有一种，新写的报告用 MDX：
  - **MDX**：`index.mdx` 是入口（文件头写 `title`、`language`、`revision`、`date`、`chapters`），各章一个 `.mdx` 放在报告目录根上，文献列表在 `references.mdx`，图片在 `assets/`。
    图、表、编号公式、引用用固定的组件与写法（`<WordFigure>`、`<WordTable>`、` ```math <id> `、`<WordRef to>`、`<WordCite to>`），完整写法见文档站的「写报告」页；只有要被引用的对象才写 id，其余编译器生成
  - **JSON**（`docreport` 格式）：`content.json` 是入口（正文按顺序 `include` 各章），每章在 `chapters/<章>/content.json`，图片在那一章的 `assets/`；字段说明在包里的 `engine/schemas/report-content.schema.json`
  - 只给 Word 用的版式两种都写在 `layout.json`
- 网页上 `/reports` 列出全部报告，`/reports/<报告 id>` 整份报告一页；改了文件刷新就能看到
- 改完在站点目录运行 `pnpm exec report-docx check`，有问题照原话改
- 导出 Word 用 `pnpm exec report-docx export <报告 id>`：要本机装着 Word 与 MathType，引擎目录里要有 `.venv`（没有时命令会说怎么建）；人让导出时才导出

## 服务 gwbDocsite

别的插件 `inject: ['gwbDocsite']` 后调用，`dir` 都是绝对路径，大小写、斜杠不同的写法算同一个站：

| 方法 | 做什么 |
| --- | --- |
| `init(dir, { title, kind })` | 同 `docsite.site.init`，身份文件写给的 `kind`（`base` / `docs` / `collab`）；回 `{ dir, platformDependencies }` |
| `addFeature(dir, { packageName, specifier? })` | 同 `docsite.feature.add`；`specifier` 还可以写 `link:` / `file:` 加绝对路径 |
| `add(dir, { by? })` / `remove(dir)` | 同 `docsite.site.add` / `docsite.site.remove`：登记为常驻再启动（回这个站此刻的状态，起不来报错、登记照留），`by` 写登记的插件名，显示在站点窗格里，不给记成 `docsite.site.add`；去掉登记、在运行就停掉（回 `{ registered }`，`false` 是本来就没登记） |
| `start(dir)` / `stop(dir)` / `status(dir)` | 启停与此刻的状态，形状同 `docsite.site.*`；不改常驻登记 |
| `onStatus(listener)` | 某个站启动、停止、出错时调用 `listener(dir)`，返回撤掉的函数 |
| `push(dir, channel, data)` | 往站点的推送通道推一份 JSON（频道只用字母、数字、`_`、`-`）；站点没在运行就报错 |
| `join(dir, { id, name, gitea? })` | 同 `docsite.people.join`，回 `{ changed }` |
| `identityCode()` | 本 home 的身份码 |
