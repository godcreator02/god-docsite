新建、版本、托管，以及给 agent 的命令。只写要做到什么；原则见[设计原则与总体划分](/design/principles)。

## 新建

| 编号 | 要求 |
| --- | --- |
| L-01 | agent 用一条命令新建站点：给出目录、端口、站名，得到一个依赖已装好、能直接启动的普通 fumadocs + React Router 项目。生成以后站点文件归站点自己 |
| L-02 | 目标目录不是空的就拒绝。新建只写文件，不碰 git |

## 版本

| 编号 | 要求 |
| --- | --- |
| L-03 | 站点在 `package.json` 里固定所用库的版本；库发新版，没升级的站点照旧运行 |
| L-04 | 库里破坏站点用法的改动只随 x 升级，并附升级说明；站点要升级时由 agent 照说明改 |
| L-05 | 插件和站点之间的约定（启动时交给站点的参数、插件调用的站点接口、人员列表与评论文件的格式）写明并带版本号；插件升级后照样能用旧站，碰到不再支持的旧版本就报错，说明站点要升到哪一版 |

## 托管

| 编号 | 要求 |
| --- | --- |
| L-06 | 工作台能启动、停止一个站点；登记过的站点在工作台启动时自动启动 |
| L-07 | 每个站点的地址固定不变，只有本机能访问 |
| L-08 | 启动时把本 home 的身份交给站点；不经工作台启动的站点只读 |
| L-09 | agent 或人改了页面、评论以后，开着的站点马上能看到新内容，不用重新构建 |
| L-10 | 站点在本机或 NAS 上发布成只读的站 **待定**　你以前定过要只读发布；这一轮做不做 |

## 给 agent 的命令

| 编号 | 要求 |
| --- | --- |
| L-11 | 新建、登记、移除、列出（带状态和地址）、启动、停止站点，查本 home 的身份码。评论命令见评论章 |

## 不作为需求的

- 启动失败报出原因、端口被占时报错：属于原则九「错了就报错」，不单列。
- 托管跑开发服务还是构建后的服务：是实现 L-09 的手段，设计时再定。
- 自动重启与失败计数、启动前检查、同一站点的操作排队、路径写法归一、卸载时的清理：现有实现里的防护，不是谁提出的要求。
- 打开站点的方式：不归这个插件，给人看时由 VS Code 插件打开站点地址。
- 给别的插件用的服务、往站点推数据：只有协作站用，下一轮按协作站的需要再定。
- 功能包接进站点的机制：站点自己引用库（原则一、四）。
