**本页回答**：这套东西拆成哪几块、各在哪、块与块之间谁依赖谁、经哪几条接缝连起来、新来的人先读哪块。

## 四个包，一个插件

布局照 devkit 的 workspace 仓：插件在 `plugins/`，不是插件的包在 `packages/`。`plugins/docfirst/` 是工作台插件
`@godcreator/gwb-docfirst-workflow`——它不进 npm 的依赖网，只在桌面工作台里给 agent 提供两条建站命令和几份说明书。
`packages/` 下四个 npm 包：

{/* tree dir="../packages" depth="1" hash="991dd33377ea" */}

两个核心、两个适配。两个核心不读盘、不认文件格式、不认站点框架，要的东西全从接缝上传进来：

| 包 | 管什么 | 先读 |
| --- | --- | --- |
| `@godcreator/docfirst-pin` 钉码核心 | 引用模型、记号语法、比较器、编排服务；只用 `node:crypto` | [钉码核心](/docs/modules/pin) |
| `@godcreator/docfirst-trajectory` 轨迹核心 | 卡片格式与校验、建模、布局、缩略图；`./disk` 是星轨盘画布 `StarDisk` | [轨迹核心](/docs/modules/trajectory) |
| `@godcreator/docfirst-workflow` 命令行与项目 | 命令行 `docfirst`、项目装配（读盘、git、生成物、磁盘读卡）、mdx 格式 | [workflow](/docs/modules/workflow) |
| `@godcreator/docfirst-fumadocs` fumadocs 适配 | remark 插件、机读版、状态点与术语组件、fumadocs 组件的名册规则、卡集合、星轨盘服务端组件 | [fumadocs 适配](/docs/modules/fumadocs) |

**两个适配包的分界看调用链从哪里开始**：从 `docfirst` 命令开始的归 workflow，由 fumadocs 或 Next 调用的归 fumadocs 适配
（mdx 加载器编译页面时调的插件、集合的 schema 与回调、页面渲染时的组件）。两边都要的（`loadProject`、mdx 语法树上认记号）
按依赖方向归 workflow。来由见轨迹卡[按接缝拆四包](/trajectory/2026-09-26-split-by-seams-into-four-packages)。

workflow 包里再分四个目录，各一件事：

{/* tree dir="../packages/docfirst-workflow/src" depth="1" hash="fdc52981e029" */}

`cli/` 是命令行，`project/` 是项目装配，`mdx/` 是 mdx 格式，`format/` 是命令行要的格式接口 `DocFormat`。

包里没有建站：**建一个接好三个区的站**那部分在工作台插件里（[建站](/docs/modules/site)）。
包的使用者是仓，插件的使用者是 agent，判据见轨迹卡
[包给仓、插件给人](/trajectory/2026-09-10-package-serves-repo-plugin-serves-agent)。

## 依赖方向

包与包之间的方向是**单向**的：钉码核心谁都不认识，轨迹核心也谁都不认识，workflow 认识两个核心，fumadocs 适配认识全部三个，
谁都不认识它。表里**列的是禁止的包不是允许的包**——写成允许的话，加一个新包会默默地什么都不许，加错地方反而更难发现：

{/* ref file="../tests/boundary.test.ts" lines="116-128" hash="8b6633b0f4cc" blob="55f573c4c909" */}

钉码核心是这张图的终点，自己零依赖，只用 `node:crypto`。它不读文件、不启动子进程、不认识任何
文档格式——运行要的三样全是外面传进来的：

{/* ref file="../packages/docfirst-pin/src/service.ts" lines="57-61" hash="e6d5208e0ea0" blob="33d8acf46386" */}

格式、读取器、旧内容来源（按 blob 取确认时的内容、算 hunk 表）都是构造参数，所以它的依赖面可以是空的。
轨迹核心的 `.` 入口更进一步，产物里一条 import 都没有，卡片文件由调用方读好传进来。

**包与插件互不认识**：四个 npm 包的三类依赖字段里不许出现工作台插件，也不许出现任何
`@godcreator/gwb-*`——装这些包的人不该连带装上整个桌面工作台生态；反方向，插件对四个 `@godcreator/docfirst-*`
包零依赖，由插件自己的 `tests/artifact.test.ts` 检查。

## 接缝

块与块之间只经下面这些接缝相连。有代码接口的写接口名；标「约定」的没有代码接口，靠文件名、目录名、配置键这类约定对上：

| # | 接缝 | 连接的模块 | 接口 |
| --- | --- | --- | --- |
| 1 | 记号格式 | mdx 格式 ↔ 钉码核心的记号语法 | `Format`：claims / parse / write / marker |
| 2 | 文件与旧内容 | 读盘与 git ↔ 钉码核心的比较与跟随 | `Reader`、`History` |
| 3 | 编排服务 | 项目装配 ↔ 钉码核心的编排服务 | `createService` 交出 check / confirm / resolveRefs，结果是 `Listing` |
| 4 | 卡片记录 | 磁盘读卡 ↔ 轨迹核心 | 卡片文件（name、text、mtime）→ `scanCards` → `buildTrajectory`，交出模型与病卡 |
| 5 | 星轨盘组件 | 星轨盘画布 ↔ fumadocs 适配的星轨盘服务端组件 | `StarDisk`、`star.css` |
| 6 | 项目 | 项目装配 ↔ fumadocs 适配的 remark 插件 | `loadProject`，加 `./mdx` 的语法树认记号、打标记函数 |
| 7 | fumadocs 接线 | fumadocs 适配 ↔ fumadocs 本体 | applyMdxPreset、postprocess、meta 白名单、CodeBlock、Files |
| 8 | 站接入 | fumadocs 适配 ↔ 站的接线代码 | docfirstMdxOptions 等出口、DocfirstPre、Term、样式表；`./roster` 给 docfirst.config.mjs |
| 9 | 项目根（约定） | 项目装配 ↔ docfirst.config.mjs 与 content/ | 配置键；trajectory/、future/ 两个名字固定 |
| 10 | 仓里的文件（约定） | 读盘与 git ↔ 被钉的源码与 git 历史 | 按文件读取；git 取 blob、算差异、查未提交改动 |
| 11 | 生成物（约定） | 生成物写入 ↔ 仓根生成物 | outputs 映射的落点 |
| 12 | 模板（约定） | docfirst 插件 ↔ 站的接线代码 | 模板里写的包名与出口名要跟四个包对得上 |

各接缝两边分别在哪一页：1、2、3 的接口定义在[钉码核心](/docs/modules/pin)，实现一侧在 [mdx 格式](/docs/modules/workflow/mdx)
与[项目装配](/docs/modules/workflow/project)；4 在[项目装配](/docs/modules/workflow/project)与[轨迹核心](/docs/modules/trajectory)；
5 至 8 在 [fumadocs 适配](/docs/modules/fumadocs)；9 至 11 在[项目装配](/docs/modules/workflow/project)；
12 由插件的 `tests/create.test.ts` 检查模板引用的出口都在写进站依赖表的两个包里，见[建站](/docs/modules/site)。

## 三条入口

三种使用者从三个方向进来，前两条走的是同一套判定：

<Tabs>
  <Tab title="命令行">
    `docfirst check / confirm / render / trajectory`，外加一次性的迁移命令 `migrate-ledger`，在 workflow 包里。命令行逐篇把文本交给编排服务，
    把回来的清单译成一行行人读的文字和一个退出码。git hook 与 CI 跑的就是它——**提交那一刻工作台
    不一定在运行**，所以判定与核对必须是 npm 包，不能依赖任何 GUI 应用开着；那些仓也不一定装了 fumadocs，所以命令行不依赖 fumadocs 适配。
  </Tab>
  <Tab title="站构建">
    站的 `src/lib/source.ts` import `@godcreator/docfirst-fumadocs`，接到现状集合上，remark 插件在构建期
    装配一次项目、认引用、算清单、把状态点加到语法树上。人看的那份文档就是站本身。
  </Tab>
  <Tab title="工作台插件">
    `@godcreator/gwb-docfirst-workflow` 经命令总线提供 `docfirst.create` 与 `docfirst.create-plain`（运行官方脚手架、应用本机约定并写盘，
    `docfirst.create` 再在官方输出上增、换、删几份文件），另把七份说明书注册给 agent 读。**它对四个包零依赖**：不 import、不运行它们的命令行——要核对
    就 `cd` 到那个仓里跑包的命令行。
  </Tab>
</Tabs>

前两条入口共用同一份编排服务，这就是「判定只有一处」：站上看到的绿，跟命令行
`check` 退 0 说的是同一件事；第三条根本不做判定，它只建站。

## 边界靠什么检查

包与包之间有 pnpm 严格的 `node_modules` 挡一半——没写进依赖的包 import 不到——但「该不该写进依赖」没人挡；
workflow 包里四个目录之间更是谁都能 import 谁。挡住它们的是一个测试文件：

{/* ref file="../tests/boundary.test.ts" lines="1-28" hash="246706fc960b" blob="55f573c4c909" */}

**它失败的时候，出错的是设计，不是测试。**各类检查分别在哪一页讲，见各模块页的「不做的事」；测试怎么分组见
[测试与边界](/docs/cli/testing)。

方向单向换来的是替换一块只动一处：换一种文档格式，新写一份 `Format` 实现，钉码核心一行不动；
旧内容不从 git 取，实现 `History` 的两个方法；换站的宿主，只换 fumadocs 适配这一个包。

## 站也是使用者

`docs-site/` 就是「装了这几个包的项目」：项目根是站目录，被钉的代码在工作区的 `packages/` 与 `plugins/` 下，
记号写 `../packages/…` 或 `../plugins/…`。

{/* ref file="docfirst.config.mjs" lines="4-6" hash="ec944a1565bb" blob="3271a37f8bd2" */}

所以仓里不另留示例项目——这几个包对外的样子由站自己展示，站上的状态点绿着，就是它们在真源码上
跑通了。

## 每块一页

上面每一块在这一区有自己的一页，四段顺序固定：功能 / 接口 / 依赖 / 不做的事。开头一句写包名、
源码目录与入口文件。写到「错了难改」为止——边界、依赖方向、接口契约、状态机、取舍讲透；
字段清单、内部算法、内部命名是实现者的自由，不写。测试集中在 [测试与边界](/docs/cli/testing)。

## 读序

跟依赖方向反着来：**先 [钉码核心](/docs/modules/pin)**——接口正本、记号语法、比较器、编排服务、四种
状态都在那儿，别的包只认这一份；**再 [workflow](/docs/modules/workflow)**——[项目装配](/docs/modules/workflow/project)
讲装配的全貌、旧内容怎么按 blob 取回、一篇正本怎么渲染到落点，然后是[命令行](/docs/modules/workflow/cli)与
[mdx 格式](/docs/modules/workflow/mdx)。[轨迹核心](/docs/modules/trajectory) 自成一块，[fumadocs 适配](/docs/modules/fumadocs)
是站构建那条入口，[工作台插件](/docs/modules/plugin) 与它的 [建站](/docs/modules/site) 在包外面，各从自己那一页进，
只关心命令行的人整个跳过。

两处边界值得在进代码之前先知道，免得照目录名猜错：

**摆放在 `project/`**，全部在 `placement.ts` 里——一篇 mdx 正本渲染成生成物、加回指定的
frontmatter 字段、写到每个落点、核对盘上那份是不是最新，都在那一份。它在项目装配而不是
钉码核心，是因为要写盘、要调用格式的渲染，钉码核心两样都不做；也不在命令行，是因为放进命令行
别的调用方就只能启动子进程从 stdout 取结果。

**命令行只负责打印**：它拿到摆放的两个方法与编排服务，把回来的清单译成一行行人读的文字和一个退出码，
引用的状态一件都不在那儿算。它另外只问项目装配一件事：被钉的文件在本仓有没有未提交的改动，
有的话那处黄灯算红。
