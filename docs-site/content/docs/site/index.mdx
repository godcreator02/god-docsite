包 `@godcreator/docfirst-site`，源码在 `packages/docfirst-site/src/`，样式在 `styles/`，要复制进站点的文件在 `template/`。
它是文档站基础包 `@godcreator/docsite-kit` 的功能包：基础包给出站点骨架（fumadocs 加 React Router 框架模式与 Vite），功能包按基础包的约定交出几个出口，
骨架读它们，站点就有了 docfirst 要的钉码状态点、术语标注、星轨盘与卡页。钉码、卡格式与 remark 插件本身在 workflow，这个包只把它们接到基础包上。

### 状态点为什么包一层 div

钉码投影把状态点的颜色写在代码块 meta 的 `data-dot` 里，可 fumadocs 的代码块只把白名单里的 meta 放进属性，颜色到不了页面。
所以给每个投影出的代码块包一层带 `data-dot` 的 div，点由样式画在这层 div 上；认投影出的代码块看节点 data 上的 `docfirst` 标记，颜色读不到直接报错。
目录树引用投影成的 `<Files>` 自己带 `data-dot`，不用包：

{/* ref file="../packages/docfirst-site/src/pin-frame.ts" lines="1-33" hash="8c18d85f77af" blob="c6df8d2524bb" */}

## 不做的事

- **不认识钉码核心与讲解组件包**：钉码经 workflow 用；讲解组件归站自己的组件用。谁都不依赖它：

{/* ref file="../tests/boundary.test.ts" lines="144-181" hash="b14536dacdee" blob="03e2140e3c08" */}

- **不写建站模板**：`template/` 下只有基础包初始化时写进站点的轨迹卡集合定义，建一个新站是基础包与 gwb-docsite 的事：

{/* ref file="../tests/boundary.test.ts" lines="580-599" hash="7ae344d3476d" blob="03e2140e3c08" */}

- **不出每页的机读版**：基础包没有 llms 路由与复制 Markdown 的按钮，功能包也不接 workflow 的机读版回调；机读文字只出现在 `docfirst render` 渲染的生成物里。
- **不画状态点组件**：代码块就是 fumadocs 自己的，功能包只包一层 div、由样式画点，不替换 `pre`。
