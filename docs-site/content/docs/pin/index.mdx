## 功能

**核对与确认**是唯一算状态的地方。`check` 只收目标与记录（还没确认的记录是 null）、交回每处的判定；`confirm` 在核对的结果上逐处决定要不要重新记、记成什么，
改文件归 workflow 的钉码编排。结果与传入的顺序一一对应，一处钉不住只是那一处不动：

{/* ref file="../packages/docfirst-pin/src/pinner.ts" lines="1-9" hash="5888e052f3c2" blob="89c8a0c744fd" */}

确认对每一处的结果只有六种。`recorded` 与 `moved` 是机械重记；黄的只在带 `accept` 时才按今天的内容重新记：

{/* ref file="../packages/docfirst-pin/src/pinner.ts" lines="16-25" hash="b775aac011bd" blob="89c8a0c744fd" */}

**比较器** `compare.ts` 是纯函数：每种目标各自怎么判新鲜、确认时记什么。行段按什么顺序判、取不到旧内容时怎么降级，
见[钉码状态](/docs/pin/judge)；每种目标各钉哪种话，见[引用的种类](/docs/pin/targets)；旧内容与 hunk 表怎么从 git 来，
见[行段跟随](/docs/pin/git)。

**归一化**只做三件事：换行统一成 LF、去每行行尾空白、去掉末尾空行。展示和算 `hash` 用同一个函数，记号上的 hash 取前 12 位：

## 依赖

源码只 import 包内文件和 `node:crypto`（算段 hash 与 blob 名），`package.json` 里没有运行时依赖和 peer。
其余两样在创建时传进来，生产实现都在 [workflow](/docs/workflow)。

**读取器 `Reader`** 与**旧内容来源 `History`**：行段、整文件读文件的行，目录树要 `list`，
读取器没提供它时目录树一律判缺失；`oldText` 给 `null` 时比较器改为滑窗查找，少的只是 diff：

## 不做的事

**不碰磁盘，不启动子进程，不知道 git 存在。** 边界测试只许源码 import 包内文件和 `node:crypto`，清单里不许有依赖：

{/* ref file="../tests/boundary.test.ts" lines="169-178" hash="a91ae39e41d4" blob="e450056cc091" */}

**不认识别的包。** 它不依赖任何兄弟包：

{/* ref file="../tests/boundary.test.ts" lines="121-135" hash="2235688de96c" blob="59252de07558" */}

**不接触文档文本。** 记号写成什么样、在文件第几行、写回时怎么改那一行、这个文件是 mdx 页面还是讲解组件的源码，
都归 workflow 的记号写法、两个格式与钉码编排。
边界测试查源码与产物里有没有文档文本那一侧的名字：

{/* ref file="../tests/boundary.test.ts" lines="180-193" hash="bed945d7fee3" blob="20992db5df4e" */}

**不渲染，不知道项目根、配置文件和生成物放哪。** 装配、渲染与摆放在 workflow。

**不存旧内容。** 记号上只有 `hash` 与 `blob`；目录树只记名字表的 hash，变了只能报黄、给出当前的名字表。
理由见[记录进记号](/trajectory/2026-09-25-records-live-in-markers)。

**不决定黄灯拦不拦提交。** 这个包只给状态，哪些黄算红由 check 决定，见[门禁](/docs/pin/gate)。
