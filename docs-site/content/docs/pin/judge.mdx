文档里钉一处码，是在一句话下面单独写一行记号，指向源码里的几行。新写的记号只带目标，`confirm` 在同一行记号上写下两个值：`hash` 是被钉那几行（去掉行尾空白）的
sha256 前 12 位，`blob` 是整个文件当时的 git blob 名前 12 位。之后每次 `check` 都拿今天的代码去比，给出四种状态之一：

{/* ref file="../packages/docfirst-pin/src/types.ts" lines="78-79" hash="d2a2e323f0a3" blob="714c2718e246" */}

| 状态点 | 状态 | 什么意思 | `check` 算不算红 |
| --- | --- | --- | --- |
| 绿 | 新鲜 | 被钉的内容跟确认时一样，位置变了也算 | 不算 |
| 黄 | 有变动 | 内容变了，等人读一遍那句话再确认 | 不算；本仓未提交的改动引起的算，见[什么算红](/docs/pin/gate) |
| 红 | 缺失 | 被钉的东西不在了 | 算 |
| 空心 | 未确认 | 记号上还没有确认时写的记录 | 不算 |

记录只写在记号自己身上，没有另外的记录文件。同一篇里两处记号指向同一段，也各带各的记录、各自写回；
一处是红，只是那一处不动，别的照写。删掉记号，它的记录也就没了。

## 记号写在哪：mdx 页面与讲解组件

讲解组件里也有照源码抄来的东西：手抄的源码片段、逐字照抄的测试名、命令行的输出格式。组件的源码里也能写引用，
被钉的代码变了，组件文件在 `check` 里跟页面一样变黄，本仓未提交的改动引起的黄照样拦提交。两种文件用同一套记号，只有外壳不同：

| | mdx 页面 | 讲解组件 |
| --- | --- | --- |
| 哪些文件 | 内容根下 `trajectory/`、`future/` 之外的 `.mdx` | 站的 `src/components/` 下的 `.ts`、`.tsx`、`.mjs` |
| 外壳 | 单独一行的 `{/* … */}` | 单独一行的 `/* … */` |
| 新写（未确认） | `{/* ref file="src/a.ts" lines="2-3" */}` | `/* ref file="src/a.ts" lines="2-3" */` |
| `confirm` 之后 | `{/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */}` | `/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */` |
| 另外能做 | 名册检查、按原文渲染生成物、站上换成带状态点的代码块 | 只核对与写回，站上不显示 |

组件里的记号必须单独占一行，放在它钉住的那段数据正上方：组件的源码不经语法树，按行认，一行里除了这个注释还有别的代码就不是记号。
一个组件文件里任何一处变黄，就是这个组件要复核。两种外壳里面那一截由记号写法一处定义，写法见[四类引用](/docs/pin/targets)。
