记号上只有 `hash` 和 `blob`，没有代码。今天的内容对不上 `hash` 时，要知道「挪了还是改了」、要给出旧行新行，都得拿回确认时的整个文件。
钉码核心只收旧内容来源 `History`，从哪儿取由使用方实现；本页讲的是 docfirst 的 workflow 那一份（`node/git.ts`）。
下面跟着一次「上面插了两行」的 `check` 走一遍：

## blob 在进程里算，确认不用先提交

`blob` 不问 git：把文件的换行统一成 LF，按 git 算 blob 对象名的办法 `sha1("blob " + 字节数 + "\0" + 内容)` 在进程里算。
仓按 LF 存时，这就是这份内容提交后的 blob 名，所以被钉的文件改没改、提没提交都能确认，确认时一次 git 都不启动。
`tests/hash-text.test.ts` 拿真 git 的 `hash-object` 逐字节核对这个算法。

代价是：确认之后、提交之前又改了这个文件，或者仓按 CRLF 存，记号上的 `blob` 就从没进过对象库，取不回旧文件，只能在整个文件里找。
为什么接受这个代价，见轨迹卡[记录进记号](/trajectory/2026-09-25-records-live-in-markers)。

## 按被钉文件自己的位置找仓

被钉的文件不限于项目自己的仓：另一个单元、上游 clone、工作区里别的仓都能钉。所以去问哪个 git，看的是被钉文件在哪，不是项目根在哪；
记号上也不记仓在哪，每次核对重新找。

{/* ref file="../packages/docfirst-workflow/src/node/git.ts" lines="56-77" hash="f365907d7105" blob="834127e543cf" */}

- **先取真实路径**：pnpm 工作区里 `node_modules/@x/y` 是指向 `packages/y` 的软链，按写的路径会落进被忽略的 `node_modules`。
  文件已经删了就取最近一个还在的上级目录的真实路径再拼回去，仓照样找得到。
- **再往上找最里层的 `.git`**：`.git` 可以是目录，也可以是子模块、worktree 里的文件；子模块算它自己的仓。找到磁盘根都没有，就是不在任何仓里，取不到旧内容。
- **文件从所在目录起找，目录从它自己起找**：文档里写 `tree .` 时目标目录自己就是仓根，先跳一级就出了这个仓，`.gitignore` 过滤随之失效。

取 blob、问 status、列被忽略的路径，git 的工作目录一律是找到的那个仓根。

## 从对象库取旧内容

把记号上的 `blob` 写进 `git cat-file --batch` 的标准输入，「在不在」和「内容是什么」一次问到。输出按头一行给的字节数截取内容，不按行拆。
不在对象库（没提交过、浅克隆、gc 过）、缩写有歧义、认出的不是 blob，都只是「没有旧内容」，交回 `null`，不报错；
取到的按「仓 + blob」记在进程里，一次 `check` 里同一个 blob 只启动一次 git。

## hunk 表：两份内容跑一次 git diff

旧文件和今天的文件写成两个临时文件跑 `git diff --no-index -U0`，不往任何对象库写东西，因为被钉文件可能在别人的仓里。
git diff 有差异时退出码是 1，只有这一种非零退出码被当作正常，别的照原样抛出去。

{/* ref file="../packages/docfirst-workflow/src/node/git.ts" lines="153-187" hash="8debd8fc4e0d" blob="834127e543cf" */}

hunk 表按「旧内容的 blob + 新内容的 blob」缓存两层：进程里一层，系统临时目录下的 `docfirst-cache/hunks/` 一层。
键按内容算，同一对内容的 hunk 表永远不变，不用管失效，所有项目共用；盘上的文件认不出就报错并说是哪个文件。
写到磁盘上是为了那些只挪了位置、没人重新确认的引用：它们一直是绿的，每次 `check` 都要为它们对一次位置。

## 取不到旧内容：在整个文件里找

没有旧文件就没有 hunk 表。这时拿一个跟记号上行数一样高的窗口从头滑到尾，逐个算 `hash`，找等于记号上 `hash` 的那一处；
有几处就取离原行号最近的，两处一样近就不猜，算找不到。

## 未提交的改动

`check` 还要问 git 另一件事：被钉文件在本仓有没有未提交的改动。它决定一处黄灯拦不拦提交，见[提交门禁](/docs/pin/gate)。

## 归一化：站展示什么就 hash 什么

算 `hash` 之前和站上展示之前用的是同一个函数：换行统一成 LF、去掉每行行尾空白、去掉末尾空行。缩进和注释照算，
JSDoc 是契约的一部分，改了就该黄。两处要是不一样，就会出现「页面上看着没变、状态却是黄」。
算 `blob` 和送进 `git diff` 的整个文件也先统一成 LF：对象库里存的是 LF，工作区是不是 CRLF 不该改变判定。
