文档对代码说的话，说的是一个文件里的内容，或者一个目录下有哪些东西。引用有三种：

| 引用 | 说的是 | 记号上记什么 |
| --- | --- | --- |
| 行段 `ref 文件:起-止` | 「这几行代码是这样写的」 | 这几行的 `hash`，加确认时整个文件的 `blob` 名 |
| 整文件 `ref 文件` | 「这个文件就这些，不多不少」 | 整个文件的 `hash` 与 `blob` 名 |
| 目录树 `tree 目录` | 「这个目录下就这些」 | 名字表的 `hash` |

三种目标写成记号各带哪些属性，路径相对项目根：新写的只带目标属性，`confirm` 再添上记录属性。mdx 页面与讲解组件的源码里是同一套属性，
只有外面的注释不同（见[记号的写法](/docs/pin/markers)）：

## 一句话该用哪一种

| 你想说的话 | 用哪一种 | 为什么不用别的 |
| --- | --- | --- |
| 「这段代码做了什么」「这条测试守着什么」「配置里这个值是多少」 | 行段 | 只在这几行真改了时黄；整文件别处一改就黄 |
| 「整个文件就这些」（几十行以内的小配置、小脚本） | 整文件 | 行段钉满全文件时，文件开头或末尾新加的行不会报 |
| 「这个目录下就这些」 | 目录树 | 行段与整文件钉不住目录 |

几条容易挑错的：

- **钉测试，钉整条测试**：从 `test(` / `it(` 那行钉到它结束的那行。只钉测试名那一行，断言删了、条件放宽了照样是绿。
- **钉配置里的值，钉那一行**：值一变就黄，回来看正文那句话还成不成立。
- **整文件只钉短文件**：大文件里任何一处改动都黄，这种黄多了，人会不读就直接 `--accept`。要说大文件里的几件事，分别钉那几段。
- **整文件别钉随发版变的文件**：`package.json` 带着 `version`，每发一次版就黄一次，跟文档那句话毫无关系。
- **目录树按 `.gitignore` 过滤**：`dist/`、`node_modules/` 不进名字表，也不往里走。`glob` 只认 `*` 和 `?`，匹配的是名字不是路径。

- **跑出来的数不钉**：「几条测试」「几个路由」是命令的输出，不是哪个文件里写着的，不写进正文。
