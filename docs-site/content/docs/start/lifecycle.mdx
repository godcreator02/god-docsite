title: 一条引用的一生
description: 写下 → 未确认 → confirm 写上记录 → 挪了位置机械写回 → 代码改了变黄 → 复核后 --accept → 段没了变红
---

**本页回答**：一处引用从写下那一刻起会经过哪些状态，每一步命令行说什么、页面上长什么样、该做什么。

下面每一段的输出，都是在一个临时 git 仓里真跑出来的：项目根有一份 `docfirst.config.mjs`（只写了
`formats`）、一份 `src/greet.ts`、一篇 `content/docs/a.mdx`。

## 一、写下：未确认

文档里单独起一行，前后空行：

```md
@@docfirst ref src/greet.ts:2-3 @@
```

```text
⚪ content/docs/a.mdx  src/greet.ts:2-3  未确认，等作者确认
```

空心黄，退 0。站上那一块照样显示代码（内容是现取的），只是标题后面加了「· 未确认」。

## 二、确认：写上记录

```text
✅ content/docs/a.mdx  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
```

那一行草稿记号换成 mdx 的正式记号，确认时的记录就在它的属性上：

```mdx
{/* ref file="src/greet.ts" lines="2-3" hash="901ac644922d" blob="c12611d97d6e" */}
```

`hash` 是这两行归一化之后的段哈希，`blob` 是确认时整个 `src/greet.ts` 的 git blob 名，各取前 12 位——**没有代码内容**，
内容在 build 时现取。blob 名是在进程里按 git 的算法算的，所以确认**不要求先提交**，被引的文件改没改、提没提交都能确认。
再 `check` 一次就是绿的：

```text
🟢 content/docs/a.mdx  src/greet.ts:2-3  新鲜
```

## 三、代码挪了位置：还是绿，confirm 写回新行号

在函数上面插两行注释，函数整体下移，内容一个字没改：

```text
🟢 content/docs/a.mdx  src/greet.ts:2-3  新鲜
```

还是绿。确认时那份内容已经提交过，能按记号上的 blob 名从 git 里取回来，拿 hunk 表把旧行段映到今天，
段哈希对得上就是新鲜。行里写的仍是记号上的行号；站上那一块的标题写的是今天的位置。

这时跑 `confirm`，它做的是不需要判断的写回：

```text
✅ content/docs/a.mdx  src/greet.ts:2-3  内容没变、挪到了 4-5，已写回新行号
```

```mdx
{/* ref file="src/greet.ts" lines="4-5" hash="901ac644922d" blob="9cc862cd8cfc" */}
```

段哈希没变，行号和 blob 名换成今天的。**记号上的数字不用人维护。**

## 四、代码改了、还没提交：红，拦下这次提交

把 `hello` 改成 `hi`，还没提交：

```text
🔴 content/docs/a.mdx  src/greet.ts:4-5  有变动，是本仓还没提交的改动引起的——在同一个提交里复核，再 docfirst confirm content/docs/a.mdx --accept
```

内容变了是黄；而被钉的文件跟这篇文档在同一个仓里、又有未提交的改动，说明这个黄就是这次改动引起的，`check`
把它算红、退 1，门禁拦下。改代码的人最清楚改了什么、文档里哪句还成立，所以要在同一个提交里处理。
站上这一块把旧行新行放在同一块里（`-` / `+` 用 shiki 的 diff 标记），一眼看出改了什么；`check --json`
里这一条带 `"blocking": true` 和同样的 diff。

这时跑不带 `--accept` 的 `confirm`，黄原样留着，只列出来：

```text
🟡 content/docs/a.mdx  src/greet.ts:4-5  有变动，等作者复核——复核后 docfirst confirm content/docs/a.mdx --accept
```

## 五、复核后 --accept：按今天的内容重新记下

读一遍正文里说这段代码的那几句，还成立就重新记下；不成立先改正文再重新记下。`--accept` 必须点名页：

```text
--accept 要点名页：docfirst confirm <文档路径…> --accept——签黄灯得说清是哪几页，什么都没动
```

```text
·  按页限定：只动 content/docs/a.mdx，别的页不碰
✅ content/docs/a.mdx  src/greet.ts:4-5  已按今天的内容重新记下
```

```mdx
{/* ref file="src/greet.ts" lines="4-5" hash="b2d5d5a29685" blob="fb0e7806bc72" */}
```

代码、文档、记号上的新记录放进同一个提交，`check` 回绿。

## 六、已经提交的改动引起的黄：只报告

改动先提交了、没经过上一步（比如别人提交的，或者被钉的代码在别的仓里），`check` 只报告、退 0：

```text
🟡 content/docs/a.mdx  src/greet.ts:4-5  有变动，等作者复核
```

碰到了照样复核、`--accept`，只是不再拦提交。

确认之后、提交之前又改了文件，确认时那份内容就没进过 git 对象库，取不回来，只能按段哈希在整个文件里找；
找不到就是「位置不明」，站上这一块不放代码，只留一句提示：

```text
🟡 content/docs/a.mdx  src/greet.ts:2-3  有变动，等作者复核（取不到确认时的内容，这段也找不到了，位置不明——重读源码后 --accept）
```

## 七、段没了：红

把函数删掉，或者把文件删掉：

```text
🔴 content/docs/a.mdx  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
🔴 content/docs/a.mdx  src/greet.ts:4-5  缺失，引用指向空气（文件不在了）
```

红退 1。取得到确认时的内容，站上这一块显示的就是**文档写下时那段**，好让人知道原本引的是什么。`confirm`
碰到红的那一处不动，同一篇里别的记号照写：

```text
🔴 content/docs/a.mdx  第 3 行 src/greet.ts:4-5  缺失，引用指向空气（整段已被删光），这处没动
```

改写这处引用，或者连同说它的那句话一起删掉。记录就在记号上，记号删了，记录也就没了，不用另外清理。
