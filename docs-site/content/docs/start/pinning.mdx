钉码就是在文档里一句话的下面写一行记号，指向源码里的几行。确认的时候，记号上写下这几行此刻内容的 `hash`（sha256 前 12 位）与整个文件的 `blob`。
之后每次核对，都重算这几行的 `hash` 跟记号上的比，得出四种状态之一：

{/* ref file="../packages/docfirst-pin/src/types.ts" lines="94-95" hash="d2a2e323f0a3" blob="5973fadd9101" */}

| 状态点 | 状态 | 什么意思 | 退出码 |
| --- | --- | --- | --- |
| 绿 | 新鲜 | 被钉的内容跟确认时一样，位置变了也算 | 0 |
| 黄 | 有变动 | 内容变了，等人读一遍文档里那句话再确认 | 0；本仓未提交的改动引起的按红处理 |
| 红 | 缺失 | 被钉的东西不在了 | 1 |
| 空心 | 未确认 | 记号上还没有确认时写的 `hash` | 0 |

## 除了几行代码，还能钉什么

记号一共五种写法，写在文档里单独一行，`confirm` 时换成正式记号：

{/* ref file="../packages/docfirst-pin/src/marker.ts" lines="163-167" hash="b6a9218b38eb" blob="cd45c0abef46" */}

| 钉的是 | 什么时候变黄 | 什么时候变红 |
| --- | --- | --- |
| 几行代码（行段） | 内容变了；取不到旧文件又找不到这段 | 整段删光、文件不在 |
| 整个文件 | 任何一处变了，末尾追加也算 | 文件不在 |
| 目录下有哪些名字（目录树） | 名字多了或少了，说不出是哪几个 | 目录不在 |
| 某个路径在或不在 | 没有黄 | 该在的不在、该不在的出现了、文件变成了目录 |
| 文件里有某个名字 | 没有黄 | 名字不在了、文件不在 |
