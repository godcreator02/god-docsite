一个项目根下有 `src/greet.ts` 和 `content/docs/a.mdx`。

## 二、项目根放一份配置

命令行和站读的是同一份 `docfirst.config.mjs`。它只认四个键：`formats`（用哪个格式）、`content`（内容根，
不写就是 `content`）、`components`（组件名册）、`outputs`（生成物写到哪），写了别的键当场报错。这个站的配置：

{/* ref file="docfirst.config.mjs" lines="29-50" hash="78f85e416247" blob="fce0d84ad1f9" */}

分区不用配：内容根下 `trajectory/` 是轨迹卡、`future/` 是未来区，这两个名字固定，**其余目录都是现状区**，
里面的文档都进 `check`。`outputs` 把 mdx 正本映射到生成物（README、AGENTS.md 这类），`render` 与 `confirm`
会重新生成它们，`check` 检查生成物跟正本是否一致。

引用里的路径**相对项目根**——这个站的项目根是站目录，源码在工作区的 `packages/` 下，所以记号里写的是
`../packages/…`。站侧还要接几处，见 [站接线手册](/docs/start/wiring)。

## 三、写一行草稿记号

不用记各格式的记号长什么样，也不用跑命令登记。想引哪段代码，就在文档里**单独占一行**写，前后空行：

```md
@@docfirst ref src/greet.ts:2-3 @@
```

头尾的 `@@` 是标记，少一头就是普通文字。写在句子里、围栏里的不算。

## 四、核对

```powershell
pnpm docfirst check
```

新写的引用是空心黄「未确认」，已经确认过、代码没动的是绿：

```text
⚪ content/docs/a.mdx  src/greet.ts:2-3  未确认，等作者确认
```

`check` 只读，什么都不写。有红退 1，黄和白退 0——只有一种黄算红：被钉的代码在本仓有未提交的改动。

## 五、确认

```powershell
pnpm docfirst confirm
```

```text
✅ content/docs/a.mdx  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
```

草稿记号换成 mdx 的正式记号，确认时的记录就写在它的属性上：

```mdx
{/* ref file="src/greet.ts" lines="2-3" hash="901ac644922d" blob="c12611d97d6e" */}
```

`hash` 是那几行的段哈希，`blob` 是确认时整个文件的 git blob 名，各取前 12 位；没有代码内容。记号由 `confirm`
写，不手改。再 `check` 一次就是绿的。

<Note>
  **确认不要求先提交**。改了被钉的代码，就在同一个提交里处理它引起的黄：`check` 会把本仓未提交改动引起的黄算红、
  拦下这次提交；复核过正文后 `docfirst confirm <页…> --accept` 重新记下，代码、文档、记号上的新记录一起提交。
  整个过程见 [一条引用的一生](/docs/start/lifecycle)。
</Note>

## 六、看站

```powershell
pnpm build
pnpm start
```

页面上那一块代码是 `next build` 那一刻从源文件里现取的，标题栏写着来源 `文件:起-止`，
复制按钮左边那个小圆点就是状态。调试用 build + start，**不用 dev**；改了 `src/fumadocs/` 的代码要先删 `.next`
再 build 才看得见。

## 命令一览

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="3-19" hash="5dfc0087023e" blob="7307ed6bcc73" */}

拿不准就先 `docfirst --help`：它只打用法，什么都不改；写错的开关只会报错退 2，不会被当作没写。
**`confirm` 不带路径就是全部页**：它只做不需要判断的写回，黄原样留着；要把复核过的黄重新记下，必须点名页再带 `--accept`，
同一个仓里别人还没复核的黄不会被一起重新记下。

日常用的是 check / confirm / render 三条。`render` 只生成在 `outputs` 里有映射的生成物，别的文档不渲染；
`trajectory` 列轨迹卡的盘与主干，见 [轨迹](/docs/modules/trajectory)；`migrate-ledger` 只给从旧版升级的站用一次。
建站不在命令行上，归工作台插件的 `docfirst.create`，见 [建站](/docs/modules/site)。命令行的完整输出和退出码见
[命令行](/docs/modules/cli)。
