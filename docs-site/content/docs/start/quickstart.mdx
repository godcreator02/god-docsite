# 一分钟上手

**本页回答**：从零到「站上出现一块钉住源码的代码」，一共要做哪几步。全程用的是这个站自己跑出来的输出。

## 二、项目根放一份配置

命令行和站读的是同一份 `livedoc.config.mjs`：挂哪些格式包、文档在哪、用哪个比较器、产物摆到哪、组件名册是什么。

{/* ref file="livedoc.config.mjs" lines="17-35" */}

`comparator` 不写就是 `auto`：被引文件在 git 仓里就用 git 记忆，不在（被忽略的 `node_modules`、仓外目录）就用 hash 记忆。
`outputs` 是产物摆放：挂了映射的文档 render 直接写到指定位置（README、AGENTS.md 这类生成物），
check 顺手守着生成物跟源一致。
`trajectory` 是可选的轨迹卡目录，跟五类引用不是一套账，见 [站接线手册](/docs/start/wiring)。
引用里的路径**相对项目根**——这个站的项目根是站目录，源码在工作区的
`packages/` 下，所以记号里写的是 `../packages/…`。站侧还要接几处，见 [站接线手册](/docs/start/wiring)。

## 三、写一行草稿记号

不用记各格式的记号长什么样，也不用跑什么命令注册。想引哪段代码，就在文档里**单独起一行**写：

```md
@@livedoc ref ../packages/core/src/types.ts:11-16 @@
```

头尾的 `@@` 是哨兵，少一头就是普通文字。写在句子里、围栏里的不算。

## 四、核对

```powershell
pnpm livedoc check
```

新写的引用是空心黄「未确认」，已经确认过、代码没动的是绿：

```text
🟢 content/docs/start/wiring.mdx  livedoc.config.mjs:17-35  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/core/src/types.ts:11-16  未确认，等作者确认
```

`check` 只读，什么都不写。红（缺失、孤儿记录、名册外组件）退 1，黄和白退 0。

## 五、确认

```powershell
pnpm livedoc confirm
```

```text
✅ content/docs/start/requirements.mdx  ../packages/core/src/types.ts:11-16  已确认，草稿记号已换成正式记号
```

这一下做四件事：让比较器出记录、刷记录簿、清孤儿、把草稿记号换成这种格式的正式记号。mdx 里换成
`{/* ref file="…" lines="…" */}`，之后草稿不再出现。再 `check` 一次就全绿了。

<Note>
  **confirm 之前先 commit**。git 记忆只对已提交、且工作区干净的内容钉，引用到别的仓也一样；引用到的源码没提交，
  这一篇整篇拒——记录簿一条不写、文档一个字不改。为什么这么严，见 [git 原理](/docs/principles/git)。
</Note>

## 六、看站

```powershell
pnpm build
pnpm start
```

页面上那一块代码是 `next build` 那一刻从源文件里现拿的，标题栏写着来源 `文件:起-止`，
复制按钮左边那个小圆点就是状态。调试用 build + start，**不用 dev**；改了格式包的代码要先删 `.next`
再 build 才看得见。
