**本页回答**：这套机制是什么、页面上那个小圆点怎么看、这一部分按什么顺序读。

docfirst 把文档里对代码说的话钉在真实源码上：文档只写「引哪个文件哪几行」「这个目录下有哪些东西」
「这个名字还在」，代码在构建那一刻现取；确认时的记录写在记号自己的属性上。代码变了，文档上的状态点变色，
作者复核后才回绿。

这个站本身就是被核对的文档：每一块引用的代码都是从本仓源码里现取的，页面里不存副本。

## 状态点图例

代码块标题栏里、复制按钮左边那个小圆点：

- 绿：新鲜，代码跟确认时一样（挪了位置也算）。
- 实心黄：有变动，代码改了，等作者复核。
- 空心黄：未确认，引用写下了还没确认过。
- 红：缺失，引用指向的段没了、文件没了，或者断言不在的东西出现了。

## 这一部分

按第一次接触的顺序排：

1. [需求](/docs/start/requirements)：文档里的代码为什么会过时，这套机制承诺什么、不承诺什么。
2. [一分钟上手](/docs/start/quickstart)：装、配、写一行草稿记号、核对、确认、看站。
3. [五类引用：一篇手册里怎么用](/docs/start/handbook)：行段、整文件、目录树、存在性、名字，
   拿本仓的判定层从头到尾用一遍。
4. [一条引用的一生](/docs/start/lifecycle)：写下、确认、挪了位置、代码改了变黄、复核后重新记下、段没了变红。
5. [站接线手册](/docs/start/wiring)：把这一套接进自己的 fumadocs 站要改哪几处。

读完就能在自己的项目里用起来。

## 别的部分

- [系统地图](/docs/system-map)：这套东西分成哪几部分、谁依赖谁、先读哪块。
- [模块](/docs/modules/engine)：一模块一页，接口与边界逐条钉住。
- [术语表](/docs/glossary)：这个仓里的词各指什么。
- [路线图](/future/roadmap)：还没做、在等什么前提的事。

每页至少钉一处源码，钉的都是契约：类型定义、接口签名、核心函数体、配置文件。代码一改，那一页的
状态点就变色。
