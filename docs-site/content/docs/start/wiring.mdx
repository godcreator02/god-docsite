# 站接线手册

**本页回答**：当前代码现状下，把 livedoc 接进一个 fumadocs 站要动哪七处、每处写什么。

这个站自己就是消费方：页面上每一块代码都是 `next build` 那一刻从工作区源码里现拿的，页面里不存副本，
块右上角那个小圆点是状态（图例见 [入门](/docs/start)）。所以下面每一处钉的都是这个站自己的文件，
读到的就是正在跑的那一份。

`livedoc init --dir <仓>` 把这一整套铺出来，模板在 `packages/cli/template/docs-site/`。**手接与 init 铺
是同一套形状**，差异只有星轨整页那一处——见第四节末尾。

外加一条自己画的顶栏。**`searchParams.disk` 缺失渲启动器卡阵，有则渲那张盘**——组件切盘 / 回启动器时
`replaceState` 写回这个参数，一个链接因此能直接指到某一张盘：

{/* ref file="src/app/(trajectory-disk)/trajectory/page.tsx" */}

顶栏上只有三样：回文档、报病数、主题切换。搜索、设置、帮助、图例、日期竖轨与盘内的「启动器」钮都归
组件自己贴在容器四角——当前盘是组件的状态、切盘要同步写 URL，住在一处才不必把整个盘态提到页面上。

包照常导出服务端组件 `Trajectory`（读目录、渲一张方形嵌入的盘或启动器、报病列表），留给想把盘摆进一篇
长文档中间的消费方；这个站的名册里不登记它，盘走路由。`hrefBase` 要跟 loader 的 `baseUrl` 和
`remarkTrajectoryLinks` 的 `hrefBase` 是同一个值——三处对不上，节点点开是 404。

**这是这个站跟 `livedoc init` 模板唯一的形状差异**：模板把 `/trajectory` 留给卡集合的导读页，六条路由
都在 `src/app/<区>/[[...slug]]/`，树在根 layout 里合成；这个站把 `/trajectory` 让给了星轨整页，所以卡路由
的 slug 必选、路由分成两组、树搬进 `src/lib/tree.ts`，轨迹区也就没有导读页——区的入口是盘。

## 七、next.config.mjs：外置边界与 turbopack.root

{/* ref file="next.config.mjs" lines="7-23" */}

**`turbopack.root` 抬到工作区根。**这个站的包从同一个 pnpm 工作区拿，`node_modules` 里是指向站外的
软链；Turbopack 只认它 root 以内的文件，root 不抬，`packages/` 就在视野外。用发布版包的项目不必管这条；
卡目录也不必管——它在站自己的 `content/trajectory/` 里，本来就在 root 之内。

**`serverExternalPackages` 里是三个包。**它们只在服务端跑，还要读盘、起 git 子进程，标成外部包让 Node
自己解析。这条边界上有两处不能越：

**发布版包（registry 装的）别把 `format-fumadocs` 外置。**它的 `/pre` 是客户端组件（状态点），外置后
Next 走 Node 单独加载它、跟站打包的 React 分了家，预渲染报 `Cannot read properties of null (reading 'use')`。
工作区软链的装法没这个问题，所以这个站外置了它；发布版只外置 `core` 和 `project` 就够——
`format-fumadocs` 的服务端那半（remark 插件）走 fumadocs-mdx 的 loader，本来就是 Node 直载，不经过
打包器。

**`trajectory` 一律不外置。**它的 `./react` 是客户端组件，`./server` 内部用**包名自引用**去渲它；一外置，
Next 就走 Node 单独加载 `server.mjs`、发现不了 `./react` 产物头一行那句 `"use client"`，`StarDisk` 被当
服务端组件渲染，一命中 hooks 就炸。包内部为这件事也付了代价——`server.tsx` 引 `./react` 走的是包名而不是
相对源路径，为的是让 tsdown 把它当外部依赖、原样留在产物里；写成相对路径会被这一趟构建内联或拆成共享
chunk，`"use client"` 落到一个没人标记的文件上，两头都看不到边界。

两条是同一类：**外置的边界会把客户端指令吃掉**。剩下一项是站根重定向到 `/docs`：六区各有各的基座，
现状区自己有 `index.mdx`。

跑站三件事：改了格式包的代码**先删 `.next` 再 build**——Turbopack 只按 mdx 内容缓存，文档一个字没改它
就不重跑 remark 插件，格式包里的改动看不见；调试用 `build` + `start`，不用 `next dev`，dev 那条链的缓存
和热更新会让「这一版到底跑没跑我的插件」说不清；`start` 脚本钉的端口被别的进程占了就
`pnpm exec next start -p <别的口>`，起来的站验完停掉。

## 附：六区各是什么

- **现状** `content/docs/`：设计现状，只写现状、散文、尽量多钉；进 `check`。
- **轨迹** `content/trajectory/`：卡只增不改，正文冻结历史、不钉活代码；入口是星轨盘 [/trajectory](/trajectory)。
- **交接** `content/spec/`：在途的 spec 与实施方案，做完拆解归梁、删页。
- **未来** `content/future/`：愿景、不做什么、路线图。
- **生成正本** `content/outputs/`：README 这类生成物的 mdx 正本，`render` 摆到落点；进 `check`。
- **反馈** `content/feedback/`：本仓的重复操作候选，加别的仓投来的意见。

六区的目录、路由、loader、侧栏根节一一对应；进 `check` 的只有现状与生成正本两区，另外四区的草稿记号与
卡天然不进门禁。
