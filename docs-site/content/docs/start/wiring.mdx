# 站接线手册

**本页回答**：当前代码现状下，把 docfirst 接进一个 fumadocs 站要动哪七处、每处写什么。

这个站自己就是消费方：页面上每一块代码都是 `next build` 那一刻从工作区源码里取的，页面里不存副本，
块右上角那个小圆点是状态（图例见 [入门](/docs/start)）。所以下面每一处钉的都是这个站自己的文件，
读到的就是正在跑的那一份。

生成骨架归站点插件，接六区是工作台插件那条 `docfirst.attach`（[装配六区](/docs/modules/site)），模板在
`packages/gwb-docfirst-workflow/template/attach/`。**手接与插件装出来的是同一套形状**，差异只有星轨整页那一处
——见第四节末尾。

## 一、装包，与项目根那份 docfirst.config.mjs

`pnpm add -D @godcreator/docfirst-workflow @godcreator/docfirst-trajectory`。`fumadocs` 与 `react` 在包里
只是 peer——用项目里装的那份，包自己不带；只跑命令行、不装 fumadocs 的仓一个都不必装。

命令行和站读的是同一份 `docfirst.config.mjs`，它住项目根（对这个站来说项目根就是站目录）：

{/* ref file="docfirst.config.mjs" lines="34-58" hash="9a474ecbe1a3" blob="97ccb7da232e" */}

这段说明接线要交代的全部事实：用哪个格式、哪几区进 `check`（六区里只有现状与生成正本的论断跟代码对应）、
用哪个比较器、生成物写到哪、轨迹卡目录在哪、组件名册是什么。`comparator` 不写就是 `auto`：按被引文件的位置
挑记忆——在 git 仓里（本仓、别的仓都算）已提交的用 `git`，被忽略的、不在任何仓里的用 `hash`；写死
`git` 或 `hash` 是强制全用一种，分派规则见 [环境层](/docs/modules/host)。

## 二、source.config.ts：六个集合与全局 mdxOptions

站侧的集合全在这一个文件，六区各一个 `defineDocs`（自带 docs + meta 双集合，`meta.json` 的侧栏排序天然
支持）。集合名就是目录的最后一截，格式那一层靠这条约定给命令行 `?collection=`——所以集合要定义在
`source.config.ts` 而不是 loader 那边：fumadocs 的 Node loader 只认这里的集合。

### 轨迹卡集合

轨迹卡不是文档：它们不进 `content/docs`，用自己的集合。两个要点——`schema` 用包里给的 `cardSchema`（把
`label` 派生成 `title`，`born-at` 被 gray-matter 解成 `Date` 时转回字符串），`mdxOptions` 里加上
`remarkTrajectoryLinks`（关系边行渲染成标注，`轨迹卡身份.md` 链接与 wikilink 改写成轨迹卡页路由）。集合级
`mdxOptions` 会把默认插件全去掉，所以用 `applyMdxPreset` 先把默认 preset 加回来：

{/* ref file="source.config.ts" lines="36-47" hash="fa38632d9a71" blob="7d082201893d" */}

### 轨迹卡页与星轨整页

轨迹这一区的 slug 是**必选**的：空 slug 归星轨整页那条路由，所以静态参数里也要把它滤掉。轨迹卡页在标题下
多两行——元信息（`born-at`、`type`、`domain`、`parent` 链到父轨迹卡页）与界面上写着「回到盘」的链接（带上第一个 `parent`
当星轨盘身份）：

{/* ref file="src/app/(zones)/trajectory/[...slug]/page.tsx" lines="6-19" hash="6ff23e4bb903" blob="61131d6d7f84" */}

{/* ref file="src/app/(zones)/trajectory/[...slug]/page.tsx" lines="49-52" hash="06c11836968c" blob="61131d6d7f84" */}

**星轨盘不是 mdx 里的组件，是一条独立的整页路由 `/trajectory`。**它跟轨迹卡页共用一段 URL 前缀，却要两套完全
不同的布局——星轨盘不要侧栏与目录，轨迹卡页要。Next 的路由组把两套分开，组名不进 URL；星轨盘这一组只用最简单的布局：

{/* ref file="src/app/(trajectory-disk)/trajectory/layout.tsx" hash="620a9ec79939" blob="6d970e94605b" */}

星轨盘页自己读轨迹卡目录建模，把模型和 `launcherThumbs` 渲染好的启动器缩略图交给 `mode="page"` 的 `StarDisk`，
外加一条自己画的顶栏。**`searchParams.disk` 缺失时渲染启动器的缩略图网格，有则渲染那张星轨盘**——组件切换星轨盘 / 回启动器时
`replaceState` 写回这个参数，一个链接因此能直接指到某一张星轨盘：

{/* ref file="src/app/(trajectory-disk)/trajectory/page.tsx" hash="c173b7c05951" blob="9eb5e8658512" */}

顶栏上只有三样：回文档、报病数、主题切换。搜索、设置、帮助、图例、日期竖轨与星轨盘内的「启动器」按钮都由
组件自己放在容器四角——当前是哪张星轨盘是组件的状态、切换时要同步写 URL，住在一处才不必把整个星轨盘的状态提到页面上。

包照常导出服务端组件 `Trajectory`（读目录、渲染一张方形嵌入的星轨盘或启动器、报病列表），留给想把星轨盘嵌进一篇
长文档中间的消费方；这个站的名册里不登记它，星轨盘用独立路由。`hrefBase` 要跟 loader 的 `baseUrl` 和
`remarkTrajectoryLinks` 的 `hrefBase` 是同一个值——三处对不上，节点点开是 404。

**这是这个站跟六区模板唯一的形状差异**：模板把 `/trajectory` 留给轨迹卡集合的导读页，六条路由
都在 `src/app/<区>/[[...slug]]/`，树在根 layout 里合成；这个站把 `/trajectory` 让给了星轨整页，所以轨迹卡路由
的 slug 必选、路由分成两组、树搬进 `src/lib/tree.ts`，轨迹区也就没有导读页——区的入口是星轨盘。

## 七、next.config.mjs：外置边界与 turbopack.root

{/* ref file="next.config.mjs" lines="7-28" hash="f4f5ef0d3ed0" blob="2b911bebe3fe" */}

**`turbopack.root` 设到工作区根。**这个站的包从同一个 pnpm 工作区拿，`node_modules` 里是指向站外的
软链；Turbopack 只认它 root 以内的文件，root 不设到工作区根，`packages/` 就不在它能读的范围里。用发布版包的项目不必管这条；
轨迹卡目录也不必管——它在站自己的 `content/trajectory/` 里，本来就在 root 之内。

**`serverExternalPackages` 是空的，那一行本身就记着一个决定。**两个包都**不许**外置：
`@godcreator/docfirst-workflow` 里同时住着服务端那半（读文件、调 git、remark 插件）与两个客户端组件
（`/fumadocs/pre` 状态点、`/fumadocs/term` 术语），而这个字段按包名匹配、没有子路径粒度——整包
一外置，Next 用 Node 单独加载它、跟站打包的 React 不再是同一份，预渲染报
`Cannot read properties of null (reading 'use')`。

**`docfirst-trajectory` 同理，还多一层。**它的 `./react` 是客户端组件，`./server` 内部用**包名自引用**
去渲染它；一外置，Next 就用 Node 单独加载 `server.mjs`、发现不了 `./react` 产物头一行那句
`"use client"`，`StarDisk` 被当服务端组件渲染，一用到 hooks 就报错。包内部为这件事也付了代价——
`server.tsx` 引 `./react` 用的是包名而不是相对源路径，为的是让 tsdown 把它当外部依赖、原样留在
产物里；写成相对路径会在这次构建里被内联或拆成共享 chunk，`"use client"` 落到一个没人标记的文件上，
两头都看不到边界。

两条是同一类：**外置的边界会让客户端指令丢失**。不外置的代价只是 Turbopack 多打包一遍服务端那半，
那半只在构建期跑、进不了客户端束。剩下一项是站根重定向到 `/docs`：六区各有各的 URL 前缀，
现状区自己有 `index.mdx`。

运行站要注意三件事：改了 `src/fumadocs/` 的代码**先删 `.next` 再 build**——Turbopack 只按 mdx 内容缓存，
文档一个字没改它就不重跑 remark 插件，那一层里的改动看不见；调试用 `build` + `start`，不用 `next dev`，dev 那条链的缓存
和热更新会让「这一版到底跑没跑我的插件」说不清；`start` 脚本写死的端口被别的进程占了就
`pnpm exec next start -p <别的端口>`，启动的站验证完就停掉。
