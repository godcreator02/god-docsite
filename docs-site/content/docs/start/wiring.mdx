**本页回答**：按当前代码，把 docfirst 接进一个 fumadocs 站要改哪七处、每处写什么。

这个站自己就是使用方：页面上每一块代码都是 `next build` 那一刻从工作区源码里取的，页面里不存副本，
块右上角那个小圆点是状态（图例见 [入门](/docs/start)）。所以下面每一处钉的都是这个站自己的文件，
读到的就是正在运行的那一份。

建一个接好 docfirst 的站归工作台插件的 `docfirst.create`（[建站](/docs/modules/site)）：站点插件跑官方脚手架
`create-fumadocs-app` 并写盘，docfirst 在官方输出上替换、删除、新增几份文件，模板在 `packages/gwb-docfirst-workflow/template/`。
**这个站与插件建出来的是同一套形状**：同一版脚手架、同样的官方路由（docs 页面、搜索、llms），差异只有星轨整页与
站自己的组件和样式，见第四节末尾。

## 二、src/lib/source.ts：三个集合与各自的 mdxOptions

集合用 fumadocs-mdx 的 macro 写在 `src/lib/source.ts` 里，没有 `source.config.ts`；三区各一个 `defineDocs`
（自带 docs 与 meta 两个集合，`meta.json` 的侧栏排序直接可用）。macro 没有全局配置，docfirst 的插件只能按集合接，
而集合级 `mdxOptions` 会把 fumadocs 的默认插件全去掉，所以写了它的集合都用 `applyMdxPreset` 把默认插件加回来。

现状区挂上格式那一层给的 `docfirstMdxOptions`：remark 插件链末尾加上 docfirst 插件、meta 白名单放行 `data-dot`，
术语标注也在这儿；再开 processed markdown，序列化回调由格式那一层给，站上各页的机读版与 llms 路由从这里出。
术语表正本是 `src/glossary.ts`，`skipFile` 把人写的那篇规范排除——它里头的词按字面读，不该被标注：

{/* ref file="src/lib/source.ts" lines="24-43" hash="3e9dcbabc58b" blob="8f433a032289" */}

生成正本（README、AGENTS.md、SKILL.md 的 mdx）也在现状区，它们的生成物不走机读版那条路，由命令行按原文渲染。

## 四、src/app/：三条路由，外加星轨整页

### 轨迹卡页与星轨整页

轨迹这一区的 slug 是**必选**的：空 slug 归星轨整页那条路由，所以静态参数里也要把它滤掉。轨迹卡页在标题下
多两行——元信息（`born-at`、`type`、`domain`、`parent` 链到父轨迹卡页）与界面上写着「回到盘」的链接（带上第一个 `parent`
当星轨盘身份）：

{/* ref file="src/app/(trajectory-cards)/trajectory/[...slug]/page.tsx" lines="6-19" hash="6ff23e4bb903" blob="61131d6d7f84" */}

{/* ref file="src/app/(trajectory-cards)/trajectory/[...slug]/page.tsx" lines="49-52" hash="06c11836968c" blob="61131d6d7f84" */}

**星轨盘不是 mdx 里的组件，是一条独立的整页路由 `/trajectory`。**它跟轨迹卡页共用一段 URL 前缀，却要两套完全
不同的布局——星轨盘不要侧栏与目录，轨迹卡页要。Next 的路由组把两套分开，组名不进 URL：轨迹卡页那一组的 layout
直接用 docs 那一份，星轨盘这一组只用最简单的布局，并引入星轨盘的样式：

{/* ref file="src/app/(trajectory-disk)/trajectory/layout.tsx" hash="0aafe85243b0" blob="c5b3fdbb4760" */}

星轨盘页自己读轨迹卡目录建模型，把模型和 `launcherThumbs` 渲染好的启动器缩略图交给 `mode="page"` 的 `StarDisk`，
外加一条自己画的顶栏。**`searchParams.disk` 缺失时渲染启动器的缩略图网格，有则渲染那张星轨盘**——组件切换星轨盘 / 回启动器时
用 `replaceState` 写回这个参数，一个链接因此能直接指到某一张星轨盘：

{/* ref file="src/app/(trajectory-disk)/trajectory/page.tsx" hash="c173b7c05951" blob="9eb5e8658512" */}

顶栏上只有三样：回文档、报病数、主题切换。搜索、设置、帮助、图例、日期竖轨与星轨盘内的「启动器」按钮都由
组件自己放在容器四角——当前是哪张星轨盘是组件的状态、切换时要同步写 URL，放在一处才不必把整个星轨盘的状态提到页面上。

包照常导出服务端组件 `Trajectory`（读目录、渲染一张方形嵌入的星轨盘或启动器、报病列表），留给想把星轨盘嵌进一篇
长文档中间的使用方；这个站的名册里不登记它，星轨盘用独立路由。`hrefBase` 要跟 loader 的 `baseUrl` 和
`remarkTrajectoryLinks` 的 `hrefBase` 是同一个值——三处对不上，节点点开是 404。

**这是这个站跟建站模板在路由上唯一的差异**：模板把 `/trajectory` 留给轨迹卡集合的导读页，轨迹与未来两条路由
都在 `src/app/<区>/[[...slug]]/`；这个站把 `/trajectory` 让给了星轨整页，所以轨迹卡路由的 slug 必选、路由分成两组，
轨迹区也就没有导读页——区的入口是星轨盘。

## 七、next.config.mjs：外置边界与 turbopack.root

{/* ref file="next.config.mjs" lines="7-28" hash="b8bf422c84c2" blob="3dce09f0872a" */}

**`turbopack.root` 设到工作区根。**这个站的包从同一个 pnpm 工作区拿，`node_modules` 里是指向站外的
软链接；Turbopack 只认它 root 以内的文件，root 不设到工作区根，`packages/` 就不在它能读的范围里。用发布版包的项目不必管这条；
轨迹卡目录也不必管——它在站自己的 `content/trajectory/` 里，本来就在 root 之内。

**`serverExternalPackages` 是空的，那一行本身就记着一个决定。**两个包都**不许**外置：
`@godcreator/docfirst-workflow` 里同时有服务端那一半（读文件、调 git、remark 插件）与两个客户端组件
（`/fumadocs/pre` 状态点、`/fumadocs/term` 术语），而这个字段按包名匹配、没有子路径粒度——整包
一外置，Next 用 Node 单独加载它、跟站打包的 React 不再是同一份，预渲染报
`Cannot read properties of null (reading 'use')`。

**`docfirst-trajectory` 同理，还多一层。**它的 `./react` 是客户端组件，`./server` 内部用**包名自引用**
去渲染它；一外置，Next 就用 Node 单独加载 `server.mjs`、发现不了 `./react` 产物第一行那句
`"use client"`，`StarDisk` 被当服务端组件渲染，一用到 hooks 就报错。包内部为这件事也付了代价——
`server.tsx` 引 `./react` 用的是包名而不是相对源路径，为的是让 tsdown 把它当外部依赖、原样留在
产物里；写成相对路径会在这次构建里被内联或拆成共享 chunk，`"use client"` 落到一个没人标记的文件上，
两头都看不到边界。

两条是同一类：**外置的边界会让客户端指令丢失**。不外置的代价只是 Turbopack 多打包一遍服务端那一半，
那一半只在构建时运行、进不了客户端包。剩下一项是站根重定向到 `/docs`：三区各有各的 URL 前缀，
现状区自己有 `index.mdx`。

运行站要注意三件事：改了 `src/fumadocs/` 的代码**先删 `.next` 再 build**——Turbopack 只按 mdx 内容缓存，
文档一个字没改它就不重跑 remark 插件，那一层里的改动看不见；调试用 `build` + `start`，不用 `next dev`，dev 那条链的缓存
和热更新会让「这一版到底跑没跑我的插件」说不清；`start` 脚本写死的端口被别的进程占了就
`pnpm exec next start -p <别的端口>`，启动的站验证完就停掉。

## 附：分区

各区放什么、哪些进 `check`，正本是说明书 [docfirst-docs](/docs/outputs/skills/docfirst-docs) 的「分区」一节；
接进站里之后，每区的目录、集合、路由、loader、侧栏根节点一一对应。多开一个现状区，就照 `docs` 那一套各加一份。
