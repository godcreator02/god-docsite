**本页回答**：环境层把哪些东西装进判定服务、给命令行和站提供哪些接口、依赖外面的什么，以及它刻意不做什么。

它是包 `@godcreator/docfirst-workflow` 的 `packages/docfirst-workflow/src/host/` 目录，入口是 `src/host/index.ts`；
包的主出口只转出其中的 `loadProject` 与它的类型，别的只给包里的其他层和仓里的测试用。

**落点**有两种写法，归一之后是同一张表：一个相对项目根的路径，或者 `{ to, frontmatter }`，后者点名 mdx 正本头部哪几个字段
带到生成物上；字符串写法表示整段 frontmatter 都去掉。

落点在装配时就检查：得相对项目根、不许落进内容根、一个落点只许一篇文档写。违反任何一条，`loadProject` 当场报错：

{/* ref file="../packages/docfirst-workflow/src/host/placement.ts" lines="120-138" hash="134440fb80cc" blob="ac453a55d54e" */}

**`placing`** 是摆放对外的全部接口，是装好的项目上的一个字段。`render(doc)` 写一次、回落点清单；`check(doc, listing?)` 只读，
回每个落点的状态，调用方手上已有这篇的清单就传进来，不再判一遍。两个方法用同一份正文，所以写完再核对必然一致：

{/* ref file="../packages/docfirst-workflow/src/host/placement.ts" lines="61-74" hash="c816cf25273e" blob="ac453a55d54e" */}

一个落点核对完是五种状态之一，外加一个布尔判定 `fresh`，读报告的人照它决定要不要重新渲染：

{/* ref file="../packages/docfirst-workflow/src/host/placement.ts" lines="32-48" hash="5f3b6d103d1d" blob="ac453a55d54e" */}

调用方要知道两件事。**空清单不是失败**：这篇没配落点、没有格式认领它、或者认领它的格式不出生成正本，都回空清单。
**缺字段、渲染不了的落点不写**：缺了点名的字段回 `no-frontmatter` 和缺哪几个；正本里有渲染不了的东西（草稿记号、缺失的引用、
组件、mdx 表达式）回 `unrenderable` 和原因，落点上的内容一个字不动。

**`createUncommittedProbe(root)`** 造一个探针，只用于一次 check；**`migrateLedger(root)`** 是上面那个一次性迁移；
**`createReader`**、**`createGitHistory`**、**`createPlacing`** 是装配用的零件，测试换读取器、换旧内容来源、换生成物的存放时直接拿。

## 依赖

**判定层 `src/engine/`**：用它的类型、纯函数（归一化、哈希、hunk 解析）和 `createService`。环境层自己不算状态，
没有它就没有服务可装。

**格式**：由消费方写进配置的 `formats`，环境层只把名单原样交给判定服务，自己一个格式实现都不 import。摆放还要格式出生成正本；
格式不出，这篇就没有摆放这回事。

**生成物的存放 `PlacingHost`**：摆放只经这个接口认识外面，前半是项目（判定服务、这篇配了哪些落点、正本原文），
后半是读一个落点、写一个落点：

## 不做的事

**不认识任何文档格式。** `fumadocs` 这个名字只许出现在 `src/fumadocs/` 那一层：

{/* ref file="../tests/boundary.test.ts" lines="143-151" hash="f86f0c003c09" blob="421b08df5caa" */}

**不算状态。** 绿黄白红都是判定层算的，环境层只提供观察和旧内容，所以命令行和站看到的状态必然一致。

**摆放不碰 `node:fs`。** 生成物怎么落地由 `PlacingHost` 给，`placement.ts` 里没有一句文件读写。

**不往任何对象库写东西。** 被引文件可能在别人的仓里；hunk 表用两个临时文件 `diff --no-index` 算。

**不决定拦不拦提交。** 探针只回答是不是本仓未提交的改动，算不算红由[命令行](/docs/modules/cli)决定。
