# md 格式包

**本页回答**：`@godcreator02/live-doc-format-md` 在纯 md 里把一处引用写成什么样、怎么再认回来，
以及它凭什么不需要知道这处引用是新鲜还是过期。

## 管什么

一个格式包只管两件事：**认记号**、**写回记号**。md 这一份认后缀是 `.md` 的文档，别的一概不接：

{/* ref file="../packages/format-md/src/index.ts" lines="29-29" */}

它在文档里摆的是记号三件套：`<!-- ref … -->` 开头、一段围栏、`<!-- /ref -->` 收尾（目录树的尾记号
是 `<!-- /tree -->`）。中间那段围栏是**展示区**——纯 md 没有构建期，不投影进去就什么都看不见。
存在性和名字没有内容可投影，只有记号一行。

记号分两截：**载荷**（`ref file="…" lines="a-b"` 那一串）是核心定的，三种格式共用；**外壳**（那对
注释符）是这个包定的。作者不用记外壳长什么样，写核心定的草稿记号就行，确认时这个包把它换成正式形态。

## 不知道什么

**不知道状态**。新鲜 / 有变动 / 缺失 / 未确认全是核心算的，这个包交出去的是一串位置和目标，不带任何
判断。三种格式在同一串代码改动下必然给出同一串状态，正因为没有一个格式包参与算这件事。

**不知道记忆在哪**。记录簿归核心，指纹存在那儿。展示区里那段代码是投影出来的派生缓存，不是记忆——
手改围栏里的字，`parse` 认到的还是那条引用，状态一个字不变：

{/* ref file="../tests/marker.test.ts" lines="119-123" */}

<Note>
  这一条是「展示区」这个设计敢存在的前提。缓存和记忆一旦混成一件事，人随手改一行代码块就等于篡改了
  文档的记忆，check 从此说不了真话。
</Note>

**不知道磁盘**。它从不去读被引用的源文件；要投影的内容由核心通过 `Fill` 递进来，投影完就完了。

**不知道 project、不知道 cli**。方向单向：装配和命令行都不认识任何格式包，格式包更不认识它们。

**不知道别的格式怎么写**。mdx 和 html 各是一个包，三份实现之间没有共享代码，共享的只有核心那一层。

## 怎么单独测

不起进程、不建仓、不读磁盘：喂一段文本看 `parse` 交回什么，喂几条 `Fill` 看 `write` 写出什么。
要喂的假实现只有一样——`Fill.current` 里那几行字符串，测试自己编。

**证明记号两态自洽**：`parse(marker(t))` 认回 `t`，五种目标都过，位置也对。「怎么写」和「怎么认」
住同一个包，这条往返契约是它们不许分家的理由：

{/* ref file="../tests/marker.test.ts" lines="30-39" */}

**证明写回幂等**：草稿换成正式记号并长出展示区，再写一次一个字不变，也不会多出第二对围栏。

{/* ref file="../tests/marker.test.ts" lines="62-70" */}

**证明跟别的格式包一致**：同一串代码改动下，三种格式的状态和跟到的行段完全一样。这一条要真 git 仓，
所以住工作区级的契约测试里：

{/* ref file="../tests/contract.test.ts" lines="53-63" */}

两份测试都住仓根 `tests/`、不住包里：契约是跨包的，只能在能同时 import 三个格式包的地方测。
各条测试各守什么，见 [测试与边界](/docs/cli/testing)。
