**本页回答**：`@godcreator/docfirst-workflow` 这个包由哪几块组成、对外给哪些出口、依赖谁，以及它刻意不做什么。

包 `@godcreator/docfirst-workflow`，源码在 `packages/docfirst-workflow/src/`，入口是 `src/index.ts`（出口 `.`）、
`src/mdx/index.ts`（出口 `./mdx`）与 `src/project/card-dir.ts`（出口 `./cards`），可执行文件 `docfirst` 由 `src/cli/cli.ts` 构建。

## 功能

调用链从 `docfirst` 命令开始的都在这个包里：门禁、CI 与 git hook 跑的核对、确认、渲染、轨迹，以及这些命令要的项目装配与
mdx 格式。`src/` 下四个目录，各一件事：

- **命令行** `cli/`：把参数译成对装配好的项目的几次调用，把结果打印成人读的行或一行 JSON，交回退出码。见[命令行](/docs/modules/workflow/cli)。
- **项目装配** `project/`：读配置装出一个项目；读取器、git 版的旧内容来源、未提交改动的探针、生成正本的摆放、磁盘读卡与
  「卡里不许钉码」。见[项目装配](/docs/modules/workflow/project)。
- **mdx 格式** `mdx/`：认记号与写回、名册机制与名册检查、生成正本按原文渲染；站构建时 fumadocs 适配也用它在语法树上认记号。
  见 [mdx 格式](/docs/modules/workflow/mdx)。
- **格式接口** `format/`：命令行要的格式接口 `DocFormat` 与渲染拒绝的错误类，下面「接口」一节就是它的全部。

两边都要的东西（`loadProject`、语法树上认记号）按依赖方向放在这个包里：[fumadocs 适配](/docs/modules/fumadocs)依赖它，
反过来不行。分界的来由见轨迹卡[按接缝拆四包](/trajectory/2026-09-26-split-by-seams-into-four-packages)。

**`DocFormat`** 是钉码核心的 `Format` 再加两样可选的本事：名册检查给 check、按原文渲染给 render。这两样不是钉码的事，
所以接口定在这儿；一个格式只实现钉码那四样也能写进配置，只是不查名册、不渲染。渲染不了时抛 `RenderRefusal`，

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 钉码核心 `@godcreator/docfirst-pin` | 编排服务、引用与清单的类型、记号语法 | 没有服务可装，什么都核对不了 |
| 轨迹核心 `@godcreator/docfirst-trajectory` | 卡片文件建模、挑卡、校验卡字段；`docfirst trajectory` 的模型 | 读不出卡，check 不能校验轨迹卡 |
| unified、remark-parse、remark-mdx、remark-frontmatter | mdx 格式的语法树 | mdx 格式用不了 |
| `git` 命令行 | 取旧内容、算 hunk 表、查未提交改动、按 `.gitignore` 过滤 | 被引文件在 git 仓里时才用得到；都不在仓里时一次都不启动（见[项目装配](/docs/modules/workflow/project)） |

## 不做的事

**不认识任何站的宿主。** fumadocs、react、next 一个都不 import，清单里也没有，产物里也查不到——命令行跑在 git hook 与 CI 里，
那些仓不一定装了站的依赖。它也不许依赖 fumadocs 适配，包的方向表管着：

{/* ref file="../tests/boundary.test.ts" lines="123-128" hash="074213900a0b" blob="55f573c4c909" */}

**不建站。** 那件事只在 agent 手上发生一次、交出的是模板，归工作台插件的 `docfirst.create`（[建站](/docs/modules/site)）。

**不判状态、不解析卡。** 状态由[钉码核心](/docs/modules/pin)算，卡字段怎么校验、盘怎么聚归[轨迹核心](/docs/modules/trajectory)；
这个包负责把磁盘、git、配置接到它们身上，再把结果打印出来。
