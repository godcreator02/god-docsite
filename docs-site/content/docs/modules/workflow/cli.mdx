**本页回答**：命令行做什么、对外给出哪些命令与契约（开关、退出码、`check --json` 的报告）、依赖谁、哪些事不归它。

包 `@godcreator/docfirst-workflow` 的 `packages/docfirst-workflow/src/cli/` 目录，入口是 `src/cli/run.ts` 的 `main`；可执行文件 `cli.ts` 只转发参数与退出码。

## 功能

命令行只做编排：把命令行参数翻译成对装配好的项目的几次调用，把结果打印成人读的一行行、或一行机读 JSON，最后返回一个退出码。**状态一个都不在这儿判**。有哪些子命令、哪些事不在这儿，入口文件头上那段写全了：

### 先检查参数

每条命令先做同样的检查：带了求助（命令位上的 `--help` / `-h` / `help`，或任一命令后面的 `--help` / `-h`）就打用法退 0，别的一概不做；命令名不认识退 2；开关不在这条命令的表里退 2；除了 `confirm`，别的命令带了文档路径也退 2。之后 `trajectory` 与 `migrate-ledger` 在装配之前就分出去，`check` / `confirm` / `render` 先装配项目再逐篇处理：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="87-118" hash="846eb29b4c69" blob="12b6936e716e" */}

开关表**必须是封闭的**，理由在 `confirm` 身上：它把 `-` 开头的参数从页名里筛掉，开关要是被静默丢掉，`confirm --help` 就成了不带页名的全部页确认，而且不报任何错。求助的写法在命令位与命令后面宽窄不同，是同一个原因——`help` 跟在 `confirm` 后面可能是一篇文档的路径：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="53-67" hash="835f0ad5c8c0" blob="12b6936e716e" */}

### 人读输出的词表

一行一处引用：状态符号、文档、目标、一句话说明。说明后面的括号是细分理由——红说清楚是哪一种「指向空气」（整段删光、文件不在、目录不在、断言不在却出现了、文件和目录换了、名字没了），黄里只有「位置不明」一种细分：取不到确认时的内容，滑窗也找不到这段。目录树没有细分理由时，括号里是当前的项数：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="35-51" hash="5ba78c29bc99" blob="12b6936e716e" */}

行里的目标写的是**记号上的**行号；行段跟到新位置之后，今天在哪看 `--json` 报告里的 `lines`，或者站上那一块的标题。

### check：只读，报状态

逐篇核对，再跑轨迹卡校验，先汇总成一份报告再决定怎么输出：人读模式边算边打，`--json` 汇总完整份打印成一行。**两种模式算的是同一份报告**，红的口径不会对不上：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="226-249" hash="aed7c545eb4b" blob="12b6936e716e" */}

一篇文档的红有四个来源：缺失的引用；**本仓未提交改动引起的黄**；名册外组件（`docfirst.config.mjs` 里没给它压平规则）；在 `outputs` 里有映射的文档，生成物跟正本不一致。核对生成物时把这一篇刚判好的清单一起交过去，不再判一遍：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="338-358" hash="e472e6ad5379" blob="12b6936e716e" */}

黄算不算红，问的是[项目装配](/docs/modules/workflow/project)的一个探针：被钉的文件和文档在同一个 git 仓里、并且在那个仓里有未提交的改动，这个黄就是这次改动引起的，要在同一个提交里复核。已经提交的代码、别的仓里的代码引起的黄只报告：

{/* ref file="../packages/docfirst-workflow/src/project/uncommitted.ts" lines="1-8" hash="7012ae307b16" blob="3cda642bbfcc" */}

这种黄按红打印，提示写明下一步：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="323-330" hash="85058fb75fad" blob="12b6936e716e" */}

```text
🟢 content/docs/a.mdx  src/greet.ts:2-3  新鲜
⚪ content/docs/a.mdx  src/greet.ts:2-3  未确认，等作者确认
🟡 content/docs/a.mdx  src/greet.ts:4-5  有变动，等作者复核
🔴 content/docs/a.mdx  src/greet.ts:4-5  有变动，是本仓还没提交的改动引起的——在同一个提交里复核，再 docfirst confirm content/docs/a.mdx --accept
🔴 content/docs/a.mdx  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

生成物的每种状态各译成一句人读的话：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="360-367" hash="c28d8799272e" blob="12b6936e716e" */}

末尾顺带跑内容根下 `trajectory/` 的轨迹卡校验，病卡一条一行，也算红；目录还没建时扫出来是空集合，不算红。读卡目录与「卡里不许钉码」归[项目装配](/docs/modules/workflow/project)的 `scanCardDir`，卡字段的校验归[轨迹核心](/docs/modules/trajectory)，这边只负责把病打印成行、计进红：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="251-261" hash="f3ba233e6f42" blob="12b6936e716e" */}

### confirm：机械写回，复核过的黄才重新记

`confirm` 不需要人判断：未确认的（草稿记号、没写记录属性的正式记号）换成正式记号并写上记录；绿的行段挪了位置的，写回新行号与新记录；然后把在 `outputs` 里有映射的正本全部重新生成一遍，内容有变才写。黄原样留着、逐条列出；红的那几处不动、别的照写，有红退 1。每处记号各带各的记录，所以一处写不上不牵连别处。

**带 `--accept`** 才把黄按今天的内容重新记下，而且必须点名页——同一个仓里别人没复核的黄不能替他重新记下。点名的页之外一个都不碰；生成物不按页限定，按内容判，没变的一个字节都不写：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="127-155" hash="235a864d0ce8" blob="12b6936e716e" */}

点名的路径三种写法都收（反斜杠、`./` 开头、绝对路径），归成文档身份的是项目装配那一份 `docIdOf`；对不上的当场退 2，不静默跳过——少确认一页比报错难发现得多：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="157-168" hash="7a5facf9721b" blob="12b6936e716e" */}

每处引用做了什么，打印一行；原地没动的绿不打印：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="170-202" hash="bfbc18e5bd67" blob="12b6936e716e" */}

```text
✅ content/docs/a.mdx  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ content/docs/a.mdx  src/greet.ts:2-3  内容没变、挪到了 4-5，已写回新行号
🟡 content/docs/a.mdx  src/greet.ts:4-5  有变动，等作者复核——复核后 docfirst confirm content/docs/a.mdx --accept
🔴 content/docs/a.mdx  第 3 行 src/greet.ts:4-5  缺失，引用指向空气（整段已被删光），这处没动
```

带了 `--accept` 的：

```text
·  按页限定：只动 content/docs/a.mdx，别的页不碰
✅ content/docs/a.mdx  src/greet.ts:4-5  已按今天的内容重新记下
```

### render：生成有映射的生成物

只处理在 `outputs` 里有映射的正本，别的文档不渲染。渲成什么、frontmatter 带哪几个字段、跟目标位置上现有的那份比，全归项目装配的 `Placing`，这边只把回执打印成行：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="369-381" hash="4e82fffef190" blob="12b6936e716e" */}

```text
→  content/docs/outputs/readme.mdx  摆放到 ../README.md
·  content/docs/outputs/claude.mdx → ../CLAUDE.md  没变
🔴 content/docs/outputs/skills/x.mdx → ../skills/x/SKILL.md  mdx 源的 frontmatter 里没有 description——补上再 render
🔴 content/docs/outputs/agents.mdx → ../AGENTS.md  正本渲染不了：第 3 行是草稿记号，先 docfirst confirm——改好再 render
```

### trajectory：列盘、树、主干

不遍历文档。内容根下还没有 `trajectory/` 目录就报错退 2；`--json` 出整份模型给别的工具读，不带就按盘打印每棵树的主干，末尾一行汇总支线、孤星、虫洞数。盘怎么聚、主干怎么挑，归[轨迹核心](/docs/modules/trajectory)：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="263-284" hash="b13c8318090a" blob="12b6936e716e" */}

### migrate-ledger：一次性迁移

给从旧版升级的站用一次：旧版把确认记录存在项目根的一个单独文件里，这条命令把记录写进各记号、删掉那个文件，再列出配置里还要手工改的键。各站迁完后的下一个版本连同命令一起删掉，来由见轨迹卡[记录进记号](/trajectory/2026-09-25-records-live-in-markers)：

## 接口

对外一个函数 `main(argv)`：收去掉 node 与脚本名之后的参数，返回退出码。

{/* has file="../packages/docfirst-workflow/src/cli/run.ts" text="export async function main" */}

**它自己不 `process.exit`**，退出留在可执行那一头，别的程序可以直接调它、当场拿到退出码和打印。可执行文件整个就这么点：

{/* ref file="../packages/docfirst-workflow/src/cli/cli.ts" hash="435cd11017b0" blob="83f53d30c0ad" */}

`main` 跟报告类型、`loadProject` 一起从包的主出口出去。主出口给想在程序里跑一次核对、不必启动子进程的调用方，也给 [fumadocs 适配](/docs/modules/fumadocs)（它要 `loadProject`）；mdx 格式在 `./mdx` 出口，读卡目录另有 `./cards` 出口：

{/* ref file="../packages/docfirst-workflow/src/index.ts" hash="39ac1ddf9cd3" blob="abe11e116ab4" */}

退出码三档，是契约，门禁靠它拦提交：

| 码 | 什么时候 |
| --- | --- |
| 0 | 没有红。**黄和白不是错**：黄等作者复核，白等作者确认；只有本仓未提交改动引起的黄算红。求助（`--help` 一类）也是 0 |
| 1 | 有红：缺失、本仓未提交改动引起的黄、名册外组件、生成物不新鲜、病卡；`confirm` 遇到红、`render` 与 `confirm` 遇到生成不了的生成物 |
| 2 | 命令名不认识；开关不在那条命令的表里；`confirm` 之外的命令带了文档路径；`--accept` 没点名页；点名的路径不是项目里的文档；没有轨迹卡目录时跑 `trajectory` |

所以门禁里直接跑 `pnpm docfirst check`：它拦的是「引用指向空气」和「这次改了被钉的代码却没复核」这两类。

`check --json` 的报告也是**契约**：读它的是别的程序（门禁、编辑器、想列出「待重写页与漂移的引用」的 agent），加字段可以，改名、删字段不可以：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="1-3" hash="c3a95fdf89b0" blob="bbed2d1475b2" */}

整份的形状（谁套谁、哪几个数组、哪些字段有才带）在同一个文件头上一眼看完。本仓未提交改动引起的黄带 `blocking: true`：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="5-32" hash="530a1c3373e5" blob="494fdbb8aec1" */}

报告里 outputs 那一段**形状不在这儿定**：直接引项目装配导出的类型，只起个别名给报告用——把别人的状态在自己的类型里再声明一遍，就成了同一件事的两份正本：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="36-41" hash="cdd59bc58929" blob="494fdbb8aec1" */}

| 接口 | 用来做什么 | 实现在 |
| --- | --- | --- |
| `loadProject(cwd)` | 装配：读配置、认格式，交出文档清单、读写、判定服务、生成物模块 | 项目装配 `project/load.ts` |

## 不做的事

- **不判状态**：绿黄白红是[钉码核心](/docs/modules/pin)判的，这边只把状态映成符号和一句中文。
- **不认识记号长什么样**：认记号、写回、渲染都问格式。
- **不管生成物怎么算**：正文怎么渲、跟目标位置上那份怎么比、缺了 frontmatter 字段写不写，都归[项目装配](/docs/modules/workflow/project)。
- **不取旧内容、不启动 git**：旧内容怎么取、哪些文件有未提交的改动，是项目装配的事，这边只问探针要一个是或否。
- **不认识轨迹卡的语义**：读卡交给 `scanCardDir`、建模交给轨迹核心，这边只把交回来的病和模型打出来。
- **不建站**：那件事只在 agent 手上发生一次、交出的是模板，归工作台插件的 `docfirst.create`（[建站](/docs/modules/site)）。
- **不知道站怎么编译**：命令行没见过 next，也没见过 mdx 编译器，不依赖 [fumadocs 适配](/docs/modules/fumadocs)。

`cli/` 认识 workflow 里另外三个目录（`format`、`mdx`、`project`），另外三个谁都不认识它。四个目录在同一个包里，编译器不会拦跨目录的 import，目录方向靠一份手写的禁止表检查，它是**唯一**的边界守卫：
