**本页回答**：mdx 格式做哪几件事、对外给哪些出口、依赖谁，以及 `Format` 这条接缝到底分离了什么。

包 `@godcreator/docfirst-workflow` 的 `packages/docfirst-workflow/src/mdx/` 目录，入口是 `src/mdx/index.ts`，包出口 `./mdx`。

## 功能

{/* ref file="../packages/docfirst-workflow/src/mdx/index.ts" lines="21-41" hash="178174d6e2b2" blob="73a54f8abd37" */}

认记号走语法树：这个目录自己启动一个 remark 解析器（remark-parse、remark-mdx、remark-frontmatter），正式记号是顶层的
`mdxFlowExpression`，属性里带着确认时的记录；草稿记号是单独成段的一行普通文字。写在围栏里、句子里的同样文字分别是
`code` 和 `mdxTextExpression` 节点，认不出来。写回只重写记号所在那一行：草稿换成正式记号，行号与记录换成确认时算好的。

`Format` 这条接缝留着**不是**为了「将来换个宿主」。它分离的是两种变化原因：怎么认记号（花括号注释还是 HTML 注释、
走语法树还是走正则）与怎么判新鲜（记录怎么比、段落怎么跟随、状态怎么定）。这条接缝上真有两个实现：生产用这一份，
测试用一份假格式。

### 名册

名册是一张「组件名 → 规则」的表。mdx 里的组件是 JSX 节点，序列化成 md 时要么原样漏成一个裸标签（AI 读到一个 `Tabs`
标签不知道是什么），要么整个丢掉（内容也没了），所以得有一张表说清**每个组件在 md 里变成什么**。

这个目录只有机制，**没有默认表**：哪些组件、怎么压平由项目在 `docfirst.config.mjs` 里写，fumadocs 自带那几个组件的规则
在 [fumadocs 适配](/docs/modules/fumadocs)的 `./roster` 出口。规则三种写法：

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="35-36" hash="69cdb1ca8839" blob="d192d3db2a0c" */}

`"children"` 只留子内容、去掉外层；`"drop"` 整个不进机读版；函数收一个节点，交回一个或一组普通 markdown 节点。
嵌套的组件不用规则处理——子节点还在树上，各自有各自的标记。

函数规则只能通过 helpers 读节点（`attr` / `textOf`）、造节点（`text` / `heading` / `paragraph` / `quote` / `children`），
节点本身对规则不透明：

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="22-33" hash="efedd191320a" blob="d192d3db2a0c" */}

<Note>
  守住这一条，同一张表换个宿主照样能用：宿主各自提供一套 helpers，造的是自己的节点。规则里一旦直接读写 mdast 的字段，这张表就只能跟 mdast 一起用了。
</Note>

`inline` 告诉规则「这处是不是写在句子里」——行内的位置只能交回行内节点。这一条没有机制检查，靠规则作者遵守，记在[路线图](/future/roadmap)里。

**打标记**按名册给树上每个组件加上「机读版里它长什么样」：

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="109-128" hash="c5990a4e9fe5" blob="d192d3db2a0c" */}

只加标记不换节点：`data.docfirstAi` 是一组替换节点，空的就设上 fumadocs 自己的 `data._stringify` 表示整个不要；
机制放进去的节点（目录树那棵 `Files`）标记已经打好，跳过、不往里走。表外的组件直接报错，报到行。同一棵树接着还要出页面，
所以**打标记不改树**。真正把标记序列化成 md 的是 fumadocs，回调在 [fumadocs 适配](/docs/modules/fumadocs)。

名册检查 `lintComponents` 用同一张表，让命令行 `check` 提前报出名册外的组件，不用等构建才发现。

### 生成正本按原文渲染

**生成正本**（README、AGENTS.md、SKILL.md 这类）走 `renderAi`，不经过 fumadocs 编译：按原文处理，去掉 frontmatter，
每个正式记号换成一个代码块，其余文字一个字节都不改。草稿记号、缺失的引用、JSX 组件、别的 mdx 表达式都渲染不了，
一次列全后抛 `RenderRefusal`：

{/* ref file="../packages/docfirst-workflow/src/mdx/render.ts" lines="107-124" hash="fc085e616933" blob="3c202787cdfc" */}

记号换成的代码块，info 串是语言加 `title="路径:起-止"`（目录树是 `目录/`），内容是清单里今天的那几行；围栏比内容里最长的
一串反引号多一个：

{/* ref file="../packages/docfirst-workflow/src/mdx/render.ts" lines="37-48" hash="da5e04e79a4b" blob="3c202787cdfc" */}

所以生成正本里可以钉码，但不能用组件；这几页在站上的机读版与生成物也不保证逐字节相同。为什么这样取舍见轨迹卡
[按原文渲染](/trajectory/2026-09-25-outputs-render-from-source-text)。

## 接口

对钉码核心，它是一个普通格式：`name`、`claims`、`parse`、`write`、`marker`；对命令行，另有 `DocFormat` 的两样可选本事
`lintComponents` 与 `renderAi`（接口定义见 [workflow](/docs/modules/workflow)）。

对 [fumadocs 适配](/docs/modules/fumadocs)，出口还交出语法树上的零件：`parseTree`、`recognize`（在一棵 mdast 上认引用）、
`stamp` 与写规则用的帮手、`walk` / `lineOf`、按文件后缀取代码块语言的 `langOf`。站构建时 remark 插件拿到的树已经解析好了，
用这几样认记号、打标记，不再解析一遍；按原文渲染与站上的代码块用同一张语言表，两边的代码块标同一种语言。

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 钉码核心 `@godcreator/docfirst-pin` | `formalOf` 给出正式记号的载荷，`Reference` / `Target` / `Listing` 等类型 | 认不出记号、出不了正式记号 |
| workflow `src/format/` | `RenderRefusal`：渲染不了时抛它，摆放按这一类报红 | 渲染不了的正本分不出是拒绝还是出错 |
| unified、remark-parse、remark-mdx、remark-frontmatter | 认记号、写回、名册检查、`renderAi` 用的语法树 | 这个格式整个不能用 |

## 不做的事

- **不认识项目装配与命令行**：`mdx/` 不许 import `project/` 与 `cli/`，由边界测试的目录方向表检查（见[项目装配](/docs/modules/workflow/project)的「不做的事」）。
- **不认识 fumadocs、react、next**：workflow 整个包连同产物都不许出现站的宿主，命令行读配置加载这个模块时不会带进任何站的代码：

{/* ref file="../tests/boundary.test.ts" lines="262-276" hash="d5b710f640dc" blob="55f573c4c909" */}

- **不带默认名册**：组件和规则是站的，fumadocs 自带组件的规则归 [fumadocs 适配](/docs/modules/fumadocs)。
- **不管生成物写到哪**：`renderAi` 交出一份 md 正文，写到哪个落点、带不带 frontmatter，归[项目装配](/docs/modules/workflow/project)的摆放。
- **不判状态**：清单是钉码核心算的，这里只认记号、按清单换内容。
