**本页回答**：两条建站命令怎么从官方脚手架建出一个站、`docfirst.create` 在官方输出上多改了什么、端口怎么挑、依赖什么、刻意不做什么。

建站是工作台插件 `@godcreator/gwb-docfirst-workflow` 的一部分，源码在 `plugins/docfirst/src/`（除 `index.ts` 以外的几份）：建站函数在 `src/scaffold.ts`，端口在 `src/ports.ts`，算 docfirst 站选项的是 `src/create.ts`；模板在包根的 `template/` 下，分 `add/` 与 `replace/` 两个目录。

## 依赖

`src/` 只 import node 内置模块（`node:fs`、`node:path`、`node:url`、`node:os`、`node:child_process`），不认识四个 `@godcreator/docfirst-*` 包里的任何代码，也不认识别的插件。守卫在插件的产物检查里，见 [工作台插件](/docs/modules/plugin) 的「不做的事」。

写进站 `devDependencies` 的是 `@godcreator/docfirst-workflow` 与 `@godcreator/docfirst-fumadocs` 两条（钉码核心与轨迹核心随它们装上），版本来自一张手写的表，一律精确号。工作区里那两份写的是 `workspace:*`，写进别人的站装不上，所以只能手写；这两个包发版升版本号时跟着改，插件的测试检查它跟工作区各包的版本一致。这两个包名出现在这儿不算插件的依赖：它们是写进别人 `package.json` 的字符串。

{/* ref file="../plugins/docfirst/src/deps.ts" hash="add69b585ae8" blob="4229f60b43d3" */}

**官方脚手架的输出是一份外部契约。** 本机约定与三个清单都是对着 `create-fumadocs-app@16.2.8` 的输出写的：`tests/fixtures/create-fumadocs-app-16.2.8/` 是它的样本，本机约定的测试读样本；`tests/create.test.ts` 里写死一份应用本机约定之后的文件表，检查三个清单对得上；慢测试 `tests/scaffold.slow.test.ts` 真的运行脚手架、跟样本比较（`pnpm test` 不跑它，`pnpm test:all` 跑）。换脚手架版本时这三样与替换的几份模板一起跟着改，理由见 [在官方输出上只改几份文件](/trajectory/2026-09-25-fumadocs-macro-collections)。

{/* ref file="../plugins/docfirst/tests/scaffold.slow.test.ts" lines="8-11" hash="51c7958e077e" blob="e2f6c391492f" */}

构建配置用本机约定那一份：`next.config.mjs` 带 `/` 到 `/docs` 的重定向、不写 `serverExternalPackages`，正合 docfirst 的要求（fumadocs 适配与轨迹核心都不许外置，见 [fumadocs 适配](/docs/modules/fumadocs)）。

## 不做的事

**不给已有的站接线。** 目标目录必须还不存在，所以不会改到任何人写过的文件。给一个用了很久的站加 docfirst 走人工接线。

**docfirst 的清单不碰本机约定管的文件。** 依赖版本、脚本里的端口、根 layout、`global.css` 都由本机约定定；docfirst 的样式放在自己新增的 `src/app/docfirst.css` 里。

**不检查此刻有没有进程占着端口。** 只按别的站脚本里写死的端口查重。

**不读 docfirst 配置。** 那正是它要生成的文件；核对、确认、渲染都是「对一个已经接好 docfirst 的站做事」，建站是「让站接好 docfirst」，前提正相反。

**不改仓根。** 仓根的 `README.md` / `AGENTS.md` / `CLAUDE.md` 由之后的 `render` 生成；建站只把「仓根已经有、第一次 render 会覆盖」报出来。

**不装依赖、不渲染、不核对。** 只写文件；接着要在站目录里跑的命令由插件写进回执。
