**本页回答**：`docfirst.create` 建站时本插件交出什么、写盘交给谁、依赖什么、刻意不做什么。

建站是工作台插件 `@godcreator/gwb-docfirst-workflow` 的一部分，源码在 `plugins/docfirst/src/`（除 `index.ts` 以外的几份），算参数的是 `src/create.ts`；模板在包根的 `template/` 下，分 `add/` 与 `replace/` 两个目录。

## 功能

**站从官方脚手架出发，本插件只改几份文件。** 站点插件 `@godcreator/gwb-docs-site` 先跑版本写死的官方脚手架 `create-fumadocs-app`，套上本机约定（`package.json`、`next.config.mjs`、根 layout、`global.css`、`src/lib/shared.ts` 等几份由它管，本插件不能再换、再删），再按调用方给的三个清单改文件：新增的在官方输出里不能已有，替换与删除的在官方输出里必须有。本插件的模板就按这三类放：

入口是插件的总线命令：校验参数、读模板与仓根、调 `planCreate`、按名字调 `docs-site.create`、组回执，见 [工作台插件](/docs/modules/plugin)。

**写盘由站点插件做**，规矩写在它的契约里：目标目录必须还不存在、上一级得在；清单里的路径重复、越出站目录、新增的已存在、替换或删除的不存在、改动了本机约定管的文件，都报错且一个文件都不写；写盘失败就把整个目标目录删掉。所以本插件不做写盘前检查，也没有回滚。清单跟官方输出对不对得上，插件的测试里写死了一份官方输出的文件表来检查，站点插件换脚手架版本时那张表跟着改。

## 依赖

`src/` 只 import `node:fs`、`node:path`、`node:url` 三个内置模块，对站点插件只有 `import type`（`CreateSiteArgs`、`SiteFile` 与它给 `Context` 加的 `gwbDocsSite`），不认识四个 `@godcreator/docfirst-*` 包里的任何代码。守卫在插件的产物检查里，见 [工作台插件](/docs/modules/plugin) 的「不做的事」。

写进站 `devDependencies` 的是 `@godcreator/docfirst-workflow` 与 `@godcreator/docfirst-fumadocs` 两条（钉码核心与轨迹核心随它们装上），版本来自一张手写的表，一律精确号。工作区里那两份写的是 `workspace:*`，写进别人的站装不上，所以只能手写；这两个包发版升版本号时跟着改，插件的测试检查它跟工作区各包的版本一致。这两个包名出现在这儿不算插件的依赖：它们是写进别人 `package.json` 的字符串。

{/* ref file="../plugins/docfirst/src/deps.ts" hash="add69b585ae8" blob="4229f60b43d3" */}

构建配置用站点插件那一份：它的 `next.config.mjs` 带 `/` 到 `/docs` 的重定向、不写 `serverExternalPackages`，正合 docfirst 的要求（fumadocs 适配与轨迹核心都不许外置，见 [fumadocs 适配](/docs/modules/fumadocs)）。替换的几份是在官方脚手架那一版的输出上改的，站点插件升脚手架版本时它们可能要跟着改，理由见 [在官方输出上只改几份文件](/trajectory/2026-09-25-fumadocs-macro-collections)；建站为什么交给站点插件见 [建站交给站点插件](/trajectory/2026-09-25-site-plugin-builds-docfirst-supplies-structure)。

**模板里写的包名与出口名只靠约定跟四个包对上**：模板渲染出的站 import `@godcreator/docfirst-workflow/mdx` 与
`@godcreator/docfirst-fumadocs` 的几个出口，包改出口时模板要在同一个提交里跟着改。插件的测试列着模板可以引用的出口，

模板假设站在仓根下一层（约定叫 `docs-site/`）、被钉的代码在仓根，所以引用写 `../src/…`，`outputs` 映射把生成物写到 `../`。形状不同就改生成的配置里的相对路径，这是模板的前提，不是配置项。

## 不做的事

**不写盘、不检查站目录。** 目录在不在、文件重不重名、失败后怎么清理，都是 `docs-site.create` 的事；本插件只交参数。

**不给已有的站接线。** 目标目录必须还不存在，所以不会改到任何人写过的文件。给一个用了很久的站加 docfirst 走人工接线。

**不改本机约定管的文件、不挑端口。** 依赖版本、脚本里的端口、根 layout、`global.css` 都归站点插件；docfirst 的样式放在自己新增的 `src/app/docfirst.css` 里；`port` 不给就由站点插件挑。

**不读 docfirst 配置。** 那正是它要生成的文件；核对、确认、渲染都是「对一个已经接好 docfirst 的站做事」，建站是「让站接好 docfirst」，前提正相反。

**不改仓根。** 仓根的 `README.md` / `AGENTS.md` / `CLAUDE.md` 由之后的 `render` 生成；建站只把「仓根已经有、第一次 render 会覆盖」报出来。

**不装依赖、不渲染、不核对。** 只写文件；接着要在站目录里跑的命令由插件写进回执。
