# 装配六区

**本页回答**：插件里那摊装配代码往目标站上装的到底是哪些东西、骨架那半为什么不归它、它凭什么敢整套覆盖，以及这摊代码为什么住在插件里而不在包里。

## 管什么

**在一个已经铺好的 fumadocs 骨架上加 docfirst 的六区。** 装上去的是：六个集合、六条路由、侧栏六个根节、`docfirst.config.mjs`、mdx 接线、投影块与术语组件、名册脚本、构建配置里那条不许外置的账、各区的骨架页，外加往站的 `package.json` 里补依赖与几条 doc 脚本。

{/* ref file="../packages/gwb-docfirst-workflow/src/attach.ts" lines="1-7" */}

**这摊代码住在工作台插件 `@godcreator/gwb-docfirst-workflow` 里，不住在这两个 npm 包里。** 判据是「这件事要在**哪儿**发生」：核对 / 确认 / 渲染要在**仓**里发生（门禁跑、站构建跑），所以归包；装六区只在 **agent** 手上发生一次，从头到尾不碰判定引擎、不碰比较器、不碰记录簿，连 `docfirst.config.mjs` 都不读——**它是铺模板不是判定**，所以归插件。

{/* ref file="../packages/gwb-docfirst-workflow/src/attach.ts" lines="9-13" */}

这条判据怎么推出来的，见[包给仓，插件给人](/trajectory/2026-09-10-package-serves-repo-plugin-serves-agent)。

**骨架那半不在这一层**。「铺一个标准 fumadocs 骨架」是「谁装了 fumadocs 谁就该有」的能力，归工作台的站点插件（`@godcreator/gwb-docs-site` 的 `docs-site.create`）。所以装配的模板里 `package.json` / `tsconfig` / `postcss` / `pnpm-workspace` / `.npmrc` 五份配置一份都没有——留一份进去，装配就会把站点插件一分钟前铺的那份盖掉，两家各出一份同名配置，谁赢看谁后跑。这条有测试守着：

{/* ref file="../packages/gwb-docfirst-workflow/tests/attach.test.ts" lines="109-113" */}

端口同理不挑：骨架的 `next dev -p` 里写着几就是几，装配只把它认出来、写进正文、报给人看。

装一次要的输入只有一个站目录，剩下两样都可以不给：

## 不知道什么

**那两个包一个字都不认识。** 装配这几份源码只 import `node:fs` / `node:path` / `node:url` 三个内建模块，判定、环境、格式实现、命令行一个不认识，第三方包一个不 import。它得能被插件在进程内直接调、不拖进整套判定，所以这条是硬的：

{/* ref file="../packages/gwb-docfirst-workflow/src/attach.ts" lines="32-37" */}

守它的是插件自己的产物守卫——`package.json` 的三档依赖面加 `src/` 下每一行 import，哪一档出现 `@godcreator/docfirst-workflow` 都红：

{/* ref file="../packages/gwb-docfirst-workflow/tests/artifact.test.ts" lines="103-118" */}

<Note>
  插件与包是两个独立发布的包，可 npm 拦不住「顺手把包写回 devDependencies」这一手。写回去，插件就攥着 home 里一条解析出来、当场定死的真实路径，包升级之后照读旧文件、零报错——那条守卫是唯一的门。
</Note>

**连 `docfirst.config.mjs` 都不读**——那正是它要写出来的东西。别的活（check / confirm / render）都是「对一个已经接好的站做事」，装配是「把线接上」，前置条件正相反，所以它绝不能走装配项目那条路。

**不知道调它的人在写什么。** 它不认识任何生态：不知道骨架是谁铺的、装完的站属于哪个仓做什么用。

**不改仓根一个字。** 模板的 `outputs` 映射会往仓根摆 `README.md` / `AGENTS.md`，但那是 `render` 的事；装配只把「仓根已经有这两份、第一次 render 会覆盖」报出来。

**不装依赖、不跑构建。** 只写文件；装、渲、核对三步都得人或 agent 自己 `cd` 到那个仓里跑，回执里那几条话就是清单：

{/* ref file="../packages/gwb-docfirst-workflow/src/index.ts" lines="62-71" */}

`.tpl` 后缀是故意的：带着它躺在包里，才不会被别的工具当成真配置去解析。模板的位置**写死一层** `../template/attach/`——源码态 `src/template.ts` 与产物态 `dist/template.js` 都在包根下一层，是同一个相对位置：

{/* ref file="../packages/gwb-docfirst-workflow/src/template.ts" lines="15-24" */}

模板从不进 `dist/`，它原地躺在包根，靠 `package.json` 的 `files` 发出去。站点插件带它那份骨架模板用的是同一套摆法——**两个插件各带各的模板，是有意的对称**。

**模板假设的仓形状**：站住仓根下一层（约定叫 `docs-site/`），被钉的代码在仓根，所以引用写 `../src/…`。换一种形状，`docfirst.config.mjs` 里的相对路径就得跟着改——那是模板的前提，不是可配置项。

## 提供的接口

**面上只有两个方法。** `planAttach` 算一套，一个字都不写盘：

{/* ref file="../packages/gwb-docfirst-workflow/src/attach.ts" lines="78-103" */}

`attachSite` 算完直接落，落盘那一步只剩写文件加删让位的那几个：

{/* ref file="../packages/gwb-docfirst-workflow/src/attach.ts" lines="105-116" */}

**算与写分开是刻意的**：占位符认不出是最可能的失败，而目录一旦开始写就没有干净的回滚点。所以验骨架、认名字、整套渲染、合 package.json 全排在碰盘之前。`planAttach` 把这个中间态直接交出去，于是「先看看会铺出什么、会占哪个口」不必先弄脏一个目录再回滚——**它是接口的一部分，不是实现细节**。

调用方不必知道模板放在哪、占位符叫什么、`package.json` 怎么合。那份合并**只加不减**：

{/* ref file="../packages/gwb-docfirst-workflow/src/manifest.ts" lines="20-30" */}

骨架写的 name / version / dev / build / start 一个字不动（端口就钉在那几条脚本里），补的是这个站接了 docfirst 之后才有的东西：五条 doc 脚本进 `scripts`，两条 docfirst 依赖进 `devDependencies`（站构建 import 接线、门禁跑 check，都是开发期的事），外加一句描述。补进去的依赖表按名字排——散在原表中间的话，diff 就看不出加了什么。

那张依赖表是**第二份真相**，手写的：

{/* ref file="../packages/gwb-docfirst-workflow/src/deps.ts" */}

工作区里那份写的是 `workspace:*`，摆进别人的站里装不动；发布版那份又要等 pnpm 在发版那一刻改写。所以它只能手写，靠一条测试守着它跟工作区各包的版本对得上（见下节）。**这两个包名出现在这儿不算依赖**：它们是写进别人 `package.json` 的字符串，插件自己一行都不 import。

**入口是插件的总线命令 `docfirst.attach`**——那个包的命令行里没有这一条，插件在自己的进程里直接调 `attachSite`，不起子进程、不转发命令行：

{/* has file="../packages/gwb-docfirst-workflow/src/index.ts" text="docfirst.attach" */}

{/* ref file="../packages/gwb-docfirst-workflow/src/index.ts" lines="88-97" */}

插件那头只留两样：**参数校验**与**回执组装**。`dir` 要给、要是绝对路径（插件跑在工作台主进程里，相对谁都不知道）、要是个目录——最后这条点得出「dir 给成仓目录了」这个最常犯的错；「是不是刚铺好的骨架」一概归装配那道门判，它抛的那句话原样进 `{ ok: false, error }`，那些错误文本本身就是文档。

{/* ref file="../packages/gwb-docfirst-workflow/src/index.ts" lines="36-54" */}

装配的逻辑一行都不许回流到命令层——这一层得能被别的程序直接调，不必经总线。

## 依赖的接口

这一层没有注进来的接口——它认的是**盘上的事实**，全是 `node:fs` 现读的。

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| 目标站的 `package.json` | 认它是不是 fumadocs 骨架、认端口、合并的底本 | 站点插件铺出来的那份 | 临时目录里现写的一份最小骨架清单 |
| 站的 `content/` 目录 | 判「有没有人写过内容」 | 骨架那三样 | 临时目录里多塞几页，验它拒 |
| 仓根的 `package.json` | 认站的显示名 | 仓自己的那份 | 临时目录里可有可无，验退回目录名 |
| 仓根的 `src/index.ts` | 起手页第一条引用钉哪一行 | 仓自己的入口 | 临时目录里现写，有 / 没有 `export const name` 各一遍 |
| 模板目录 | 整套 `.tpl` | 插件里带的 `template/attach` | `template` 选项换成一份临时小模板 |

**整个装配唯一的那道门**是目标站这一头的检查，不合规当场抛：

站不在、不是目录、不是 fumadocs 骨架（`package.json` 的依赖里没有 `fumadocs-core` / `-mdx` / `-ui` 任一）、已经有 `docfirst.config.mjs`、`content/` 下有骨架之外的内容——这几条挡在前头，**放行之后整套覆盖就是安全的，因为中间没人改过文件**。给一个跑了半年的站加 docfirst 报一句「这个站已有内容，请人工接线」，比自作聪明地 AST 改写安全得多。

## 怎么单独测

账全在插件包里，用 **vitest**（插件跟 devkit 建出来的骨架一致，`pnpm check` 一趟带类型、lint 与测试），一个文件把模板、算、落三摊全兜住：

{/* ref file="../packages/gwb-docfirst-workflow/tests/attach.test.ts" lines="9-18" */}

假的是**一个刚被站件铺好的骨架**：临时目录里造 `<仓>/docs-site`，写一份最小的骨架 `package.json`（带 `fumadocs-core` 与 `next dev -p`）、`content/docs/` 那两样、一份骨架自己的 `src/app/docs/layout.tsx`，仓根按用例可选地放几个文件。

{/* ref file="../packages/gwb-docfirst-workflow/tests/attach.test.ts" lines="43-60" */}

**全部跨面上那两个方法测，一个内部函数都不用点名。** `planAttach` 那半证明的是：算完盘上什么都没有、`.tpl` 后缀在计划里就脱掉了；端口从骨架的脚本里认、认不出退默认；`package.json` 只加不减（骨架的 name / 依赖 / build 脚本原样，doc 脚本与依赖表补上）；名字三条退路；起手页钉块两种形态、行号是数出来的；模板换成一份自带的小模板验占位符抛。拒的理由各说各的那一条单独一测：

{/* ref file="../packages/gwb-docfirst-workflow/tests/attach.test.ts" lines="206-214" */}

模板本身另有一组不进临时目录的账：读得出来、后缀脱得掉、整套渲完不留占位符、骨架那半一份都不在、反馈区只有孵化一页。

## 代码地图

**在哪**：

{/* tree dir="../packages/gwb-docfirst-workflow/src" depth="1" */}

插件的 `src/` 是**平的一层**，没有子目录——`tsconfig.build.json` 的 `include` 只写 `src/*.ts`，产物于是也是平的，`../template/attach/` 那条写死一层的路才在源码态与产物态是同一个位置。树里那份 `index.ts` 不属于这一层：它是插件本身，管命令注册与说明书目录。

**先读** `attach.ts`：两个方法与那份计划的形状全在它头上，头注释把这一层的约定与「为什么住在插件里」说完了。

**读序**：`attach.ts`（面）→ `skeleton.ts`（唯一那道门、目标站的事实）→ `template.ts`（读模板、渲染）→ `manifest.ts`（合 `package.json`）→ `values.ts`（认名字、起手页钉块）→ `deps.ts`（一张手写的依赖表）。后五份**互不认识**，只被 `attach.ts` 串起来，各读各的。

`index.ts` 读完面再看——它只有参数校验、命令注册与回执组装，装配的逻辑一行都没有。

**可跳过**：`template/attach/` 是模板正本（改模板改的是那儿的 `.tpl`，不是这一层的逻辑）、`skills/`（随插件发的说明书）、`dist/`（产物）。
