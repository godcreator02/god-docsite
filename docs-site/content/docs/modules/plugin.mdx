包名 `@godcreator/gwb-docfirst-workflow`，包目录是 `plugins/docfirst/`（devkit 的 workspace 布局，插件放在 `plugins/<短名>/`），源码在 `src/`，入口是 `src/index.ts`。

## 功能

这是 god 工作台（gwb）的一个插件，也是这个工作区里唯一不发成 npm 库的包。它提供两样东西：**两条建站命令**，`docfirst.create` 建一个接好 docfirst 三个区（现状 `docs`、轨迹 `trajectory`、未来 `future`）的文档站，`docfirst.create-plain` 建一个不接 docfirst 的普通 fumadocs 站；**七份说明书**，随插件发布、注册给 skills 插件。分工写在入口文件的文件头上：

{/* ref file="../plugins/docfirst/src/index.ts" lines="12-20" hash="8f696f6f8968" blob="a9aa2f4c2ca3" */}

判据一句话：**包的使用者是仓，插件的使用者是 agent。** 要在仓里发生的事（核对、确认、渲染，门禁与站构建都要运行）归 `@godcreator/docfirst-*` 那四个包（命令行在 `@godcreator/docfirst-workflow`），agent 自己 `cd` 到那个仓里跑 `pnpm doc`；只在 agent 手上发生一次的事（读一份说明书、给一个仓建一次站）归插件。这条判据怎么推出来的、否掉了哪几条候选，见 [包给仓、插件给人](/trajectory/2026-09-10-package-serves-repo-plugin-serves-agent)。

建站本身——运行官方脚手架、本机约定、挑端口、在官方输出上增、换、删哪些文件、写盘——全在 [建站](/docs/modules/site)；入口文件这一侧只做参数检查、读容器根设置、组选项与回执。入口文件往下认识的是算 docfirst 站选项的纯函数与两条命令共用的建站函数：

七份说明书分三类。讲 docfirst 这套机制的三份：`docfirst`（插件自己怎么用）、`docfirst-docs`（文档站怎么写）、`trajectory`（轨迹卡怎么记）；讲文档站本身的一份：`docs-site`（每页怎么写成讲清原理的网页、两条建站命令、fumadocs 站的组件与构建）；讲通用开发纪律的三份：`spec-grill`（接到需求先盘问）、`parallel-by-module`（按模块派子代理）、`docs-governance`（文档与注释治理）。

{/* tree dir="../plugins/docfirst/skills" depth="1" hash="fb82986da185" */}

七份的正本都在这个站的 `content/docs/outputs/skills/` 下（跟包在同一个仓才改得动，纪律那三份也要跟钉码写法、分区保持一致），由 `docfirst.config.mjs` 的 `outputs` 映射生成到插件的 `skills/`。纪律那三份为什么放回本仓，见 [三份纪律并回本仓](/trajectory/2026-09-10-dev-discipline-comes-home)：

{/* ref file="docfirst.config.mjs" lines="20-30" hash="ec44c3a085e4" blob="d6fce2c7e95b" */}

生成物放插件、不放包：包装在 `node_modules` 里，没有任何说明指向它，agent 不会去读；说明书能被 agent 读到，全靠插件把自己包里的 `skills/` 目录注册给 skills 插件。

## 依赖

注入了哪些服务、是必需还是局部注入、peer 怎么写、按名字调了哪条命令，见[插件之间怎么连](/docs/wiring)。

插件用 `tsc` 编译、跑在 TS 7 上、测试用 vitest；四个 npm 包是 tsdown + TS 6、测试用 `node --test`。两套工具链并存，以各自的 `package.json` 为准，不互相照搬。

## 不做的事

**不依赖 `@godcreator/docfirst-*` 四个包。** 三类依赖字段一个都不写、`src/` 里一行都不 import：不启动它们的命令行、不登记 node CLI、不查 home 里这些包的路径。装了插件就能注册说明书、能建站，不存在「装了插件没装包」那种只装了一半的状态。代价是 agent 要核对得自己 `cd` 到仓里跑，比调一条命令多一步。守卫在产物检查里：

{/* ref file="../plugins/docfirst/tests/artifact.test.ts" lines="118-139" hash="f004ec5622c9" blob="0e911a7127c9" */}

**不转发命令行。** 核对、确认、渲染都不经过插件——转发一条命令行，就是把要在仓里发生的事又挪回插件里。插件唯一启动的子进程是 `src/scaffold.ts` 运行官方脚手架，带超时：

{/* ref file="../plugins/docfirst/tests/artifact.test.ts" lines="141-157" hash="0e0c85cbf401" blob="0e911a7127c9" */}

**不读核对结果。** 判定、比较、报告的形状一样都不认识，连 `check --json` 的机读报告都不读。哪一页漂移了、一处钉码为什么黄，问的是仓里那条命令行。

**不经别的插件建站。** 运行官方脚手架、本机约定、端口、写盘都在本插件里；依赖表、源码、注入与命令调用里都没有站点插件 `@godcreator/gwb-docs-site`，理由见 [站点插件并入](/trajectory/2026-09-26-site-plugin-merges-into-docfirst)：

{/* ref file="../plugins/docfirst/tests/artifact.test.ts" lines="166-178" hash="70d1ca67ed97" blob="0e911a7127c9" */}

**不管站的运行。** 扫描有哪些站、启动与停止站、判断 build 是不是最新都不归本插件，端口只在建站时选一次；站建好以后在站目录里运行 `pnpm dev` / `pnpm build`。

**不注册窗格。** 插件只在建站那一刻做事，没有要一直显示的界面。所以本插件没有浏览器端的代码，`build` 只有一步 `tsc`：

{/* ref file="../plugins/docfirst/tests/artifact.test.ts" lines="180-184" hash="8db102ca10f4" blob="0e911a7127c9" */}

{/* ref file="../plugins/docfirst/package.json" lines="24-32" hash="b1e8f7ece99c" blob="f285e7cbd770" */}

**不装依赖、不渲染、不核对。** 建站只写文件；建完有没有人真去跑回执里那几条，是人和 agent 的事。
