# 装配包

**本页回答**：`@godcreator02/live-doc-project` 把哪些零件装进核心服务、一处引用拿到哪种记忆是谁决定的、一篇 mdx 正本怎么摆到落点上、换一个读取器或记录簿要动哪儿。

## 管什么

一个项目 = 一个根目录 + 一份 `livedoc.config` + 一本记录簿。这个包把三者串起来，交出一个装好的项目——核心服务是它的主体，摆放挂在旁边：

{/* ref file="../packages/project/src/load.ts" lines="1-5" */}

零件是四样：**读取器**（读工作区文件、列目录名字表、看路径是文件还是目录）、**json 记录簿**、**比较器**、加上配置里声明的格式包名单。比较器这一样是这个包的主戏——`auto` 按被引文件的位置挑记忆，git 那条线（定位文件在哪个仓、取 blob、出 hunk 表、跟着行段走）也住这儿，因为它要起子进程，而核心不起。

**摆放是另一摊。** 配置的 `outputs` 里，一篇 mdx 正本挂着几个落点（仓根的 README、AGENTS.md、包内的 SKILL.md）；摆放把它渲成一份干净 md、戴上点名的 frontmatter 字段、写到每个落点上，也负责回头核对盘上那份还跟不跟源一致。它落在这个包的理由跟 git 那条线一样：要写盘、要问格式包要渲染，核心两样都不做。

{/* ref file="../packages/project/src/placement.ts" lines="1-10" */}

## 不知道什么

**不知道文档是什么格式。** 格式包是消费方在配置里挂的，这个包只把名单原样交给核心，自己一个格式包都不依赖：

{/* ref file="../tests/boundary.test.ts" lines="84-89" */}

**不知道状态怎么算。** 判定的编排在核心：这个包只交两样东西——观察（读取器给的）和记忆实现（比较器）。绿黄白红是核心算出来的，命令行和站看到的状态因此必然一致。

**不知道命令行、站、轨迹卡、工作台件长什么样。** 依赖只有一条边，方向单向：

{/* ref file="../packages/project/package.json" lines="20-22" */}

**摆放不知道装配的别的部分。** 它认得的项目面只有六样——根、配置、核心服务、组件名册、这篇挂了哪些落点、这篇的原文。这张脸是摆放自己声明的，装好的项目结构上正好满足它，装配时把自己递进去；多的一样摆放也拿不到。

{/* ref file="../packages/project/src/placement.ts" lines="61-69" */}

**摆放认得 fumadocs 留下的两处痕迹，仅此而已。** 站上 `.md` 路由给标题加的锚记、序列化器紧跟标点时保守转义的加粗星号，摆放都认得——认它们只为把产物还原成可读文本，产物是给 agent 直接读的，不该带着站的痕迹。除这两处之外，这个包不认识 fumadocs 的任何东西：不认识它的集合、loader、组件表，也不依赖它。这是一处真实的轻微耦合，写在这儿比藏起来强。

## 数据结构

**配置的形状**就是这个包对消费方的全部契约面——声明挂哪些格式包、哪几个目录进 check、记录簿落哪、用哪种记忆、生成物摆哪、组件名册、轨迹卡目录：

{/* ref file="../packages/project/src/load.ts" lines="18-41" */}

**落点两种写法，归一之后是同一张表。** 一个落点要么是一个相对项目根的路径，要么是 `{ to, frontmatter }`——后者点名 mdx 源头部的哪几个字段随行到生成物（SKILL.md 要的那两个就是这么来的）；字符串写法的意思是「整段 frontmatter 剥掉」。

{/* ref file="../packages/project/src/placement.ts" lines="16-27" */}

**一个落点核对完是四态加一个判定。** 四态说的是发生了什么：生成物跟源一致、生成物还不在、跟源不一致、源头部缺点名的字段（缺哪几个一并交回）。判定是另一个布尔字段，读报告的人照它决定要不要重摆——四态怎么归到「新不新鲜」由这儿说了算，命令行和件不必各解释一遍。

{/* ref file="../packages/project/src/placement.ts" lines="29-47" */}

**git 记忆记什么**：blob、commit、旧 blob 里的行段、段哈希。不记仓在哪——blob 是内容寻址的，核对时从文件位置重新找仓，所以同一条记录换台机器、换个 clone 路径照样认得。

{/* ref file="../packages/project/src/git-comparator.ts" lines="19-26" */}

**记录簿落盘就是一个 json**，两层键：文档 → 目标 → 记录。整个实现一眼看得完，`save` 只在内容真变了才写盘——记录簿会被构建工具登记成依赖，白改一次 mtime 就是一次全站重编。

{/* ref file="../packages/project/src/json-ledger.ts" */}

## 提供的接口

**`loadProject(root)`** 是唯一入口，交回装好的项目。同一个根只装配一次：站构建时几十个 loader 并发调它，没这一条就是几十次读配置、几十本记录簿。

{/* ref file="../packages/project/src/load.ts" lines="83-91" */}

配置里的 `comparator` 有四种写法。强制成 `git` 或 `hash` 时只换掉行段和整文件那一半，目录树、存在性、名字照旧走核心那三个：

{/* ref file="../packages/project/src/load.ts" lines="103-110" */}

**`createReader(root)`** 是核心看到的全部世界。目录名字表在 git 仓里按 `.gitignore` 过滤（`dist/`、`node_modules/` 不进清单，也不往里走），`.git` 自己去掉；不在仓里就原样列。

{/* ref file="../packages/project/src/fs-reader.ts" lines="1-8" */}

**`createAutoComparator`** 是默认的那个。被引文件不限于项目自己的仓：另一个单元的仓、上游 clone、被忽略的 `node_modules`、不在任何仓里的目录，都能钉。规则一条——在任何 git 仓里、已跟踪、工作区干净的走 git，本仓外仓一视同仁；仓里但被 `.gitignore` 忽略的走 hash；不在任何仓里的走 hash。未跟踪且没被忽略的、已跟踪但脏的，一律拒并让人先 commit，**不退成 hash**；仓一次提交都没有的也拒。

{/* ref file="../packages/project/src/auto-comparator.ts" lines="24-29" */}

「该进 git 的东西」不能悄悄退成一份弱记忆，所以只有明确被忽略的才走 hash。文件在哪个仓按它的真实路径定，pnpm 的软链按指向的地方算。

核对时不看文件在哪，按**记录的 kind** 转发——记录是当时哪种记忆记的，就让哪个比较器判，认不得的 kind 当没确认过：

{/* ref file="../packages/project/src/auto-comparator.ts" lines="41-45" */}

一个项目里 git 记录和 hash 记录并存。哪一处拿到的是 hash 记忆，`confirm` 那一行会标出来（见 [命令行](/docs/modules/cli)）——写手得知道自己拿到的是弱记忆。

**`createGitComparator`** 管行段和整文件。确认那头守几道门：得在某个仓里、那个仓得有过提交、文件得在 HEAD 里（未跟踪、被忽略、大小写不符都拒）、工作区得干净。核对那头拿 `git diff -U0` 出 hunk 表，把旧行段映到今天：

{/* ref file="../packages/project/src/git-comparator.ts" lines="97-104" */}

**绿只认段哈希**：hunk 说没碰到也再比一次，行映射跟内容对不上时宁可报黄让人复核，也不把红判成绿。整段没了是 `vanished`，文件没了是 `file-missing`，blob 不在对象库（浅克隆、历史重写、换了个仓）是 `blob-missing`。这条线为什么这么设计、`hash-object` 为什么自己算，见 [git 记忆原理](/docs/principles/git)。

**`placing`** 是摆放的全部对外面貌，挂在装好的项目上，两个方法。`render(doc)` 摆一趟：渲一份正文，给每个落点戴上它点名的 frontmatter 字段，写过去，回一张落点清单。`check(doc)` 只读盘，回每个落点的四态。两个方法用的是同一份正文，所以摆完再核对必然新鲜——守着的和摆出去的不可能是两份东西。

{/* ref file="../packages/project/src/placement.ts" lines="49-59" */}

调用方得知道两件事。**空清单不是失败**：这篇没挂落点、没有格式包认领它、或者认领它的格式包不出 ai 产物，三者任一都回空清单，意思是「这篇没有摆放这回事」，不是「摆了零个」。**缺字段的落点不写**：点名了源里没有的字段，那个落点回 `no-frontmatter` 加缺哪几个，盘上一个字不动——摆一份缺 `name` 的 SKILL.md 比不摆更糟。

frontmatter 是**逐行原样搬**的，不解析 YAML：一条字段从它的顶层键行起、到下一条顶层键行止，块式列表和多行标量的缩进续行都跟着走。作者在源里写下的那几行，就是生成物头部那几行，一眼对得上。

{/* ref file="../packages/project/src/placement.ts" lines="134-142" */}

正文本身由格式包渲，摆放只在上面还原两处序列化痕迹：站上 .md 路由给标题加的锚记，和紧跟标点时被保守转义的加粗星号。生成物是给 agent 直接读的，不该带着站的痕迹。

{/* ref file="../packages/project/src/placement.ts" lines="71-78" */}

落点的地盘在装配那一刻就查死：目标得相对项目根、不许落进任何一个文档目录（那是源的地盘）、一个目标只许一个文档写。犯一条 `loadProject` 当场抛，check 与 render 都还没轮到。

{/* ref file="../packages/project/src/placement.ts" lines="103-121" */}

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `Format`（核心定） | 认领文档、认出引用、写回；摆放还问它要 ai 产物 | 消费方在 `livedoc.config` 里挂的格式包 | `tests/fake-format.ts` 的假格式包；摆放那摊用真的 md 格式包 |

## 怎么单独测

分派规则的账在 `tests/auto-comparator.test.ts`：夹具在临时目录里起**真的 git 仓**，喂**假格式包**，记录簿换成内存的。记忆分派是跟 git 的真行为对账，假不了。

{/* ref file="../tests/auto-comparator.test.ts" lines="1-10" */}

夹具本身不走 `loadProject`——临时目录里解析不到包名，零件直接拿来装；装配走一整趟（真扫目录）在 `tests/cli.test.ts`，地盘规则拒掉哪几种配置在 `tests/cli-outputs.test.ts`。

{/* ref file="../tests/repo.ts" lines="1-4" */}

配置归一化与文档身份那几个是纯函数，直接喂输入看输出，不起仓：

{/* ref file="../tests/project-config.test.ts" lines="1-5" */}

摆放那一摊的账在 `tests/placement.test.ts`：临时目录里起一个**真 git 项目**，`loadProject` 装好之后直接调两个方法——不起命令行、不劫持 stdout、不 `process.chdir`。摆放的判定不该只有走一趟命令行才验得着。

{/* ref file="../tests/placement.test.ts" lines="1-6" */}

证明的是这几件：一个落点从「还不在」到摆过去、再核对成「一致」的整条来回；生成物被手改了、被删了各判成哪一态，重摆之后回一致；点名的字段原样随行、没点名的剥掉、字符串写法整段剥掉；点名了源里没有的字段那个落点不写、两个方法都说得出缺哪几个；没挂映射的文档两个方法都回空清单、一个字不写。命令行怎么把这些印成人话、退什么码，归 `tests/cli-outputs.test.ts`。

还有两处从外面守着：`tests/contract.test.ts` 拿产品用的 git 版比较器，验三个格式包在同一串改动下状态一致；`tests/boundary.test.ts` 读依赖图，验这个包不认识任何格式包、不认识轨迹包与工作台件。

**读序**：`git.ts` 是子进程原语（定位仓、blob、hunk、忽略判定），不吃本包任何人；`git-comparator.ts` 吃 `git.ts` 加核心的纯函数；`auto-comparator.ts` 吃前两者加核心的 hash 版；`fs-reader.ts` 只吃 `git.ts`；`json-ledger.ts` 只吃核心的键函数；`placement.ts` 只吃核心的类型加 `load.ts` 里配置的那个类型，本包别的实现一个不吃；`load.ts` 吃全部，交给核心的 `createService`。

`placement.ts` 与 `load.ts` 之间因此是一圈**只有类型的**循环引用：`load.ts` 吃摆放的实现，摆放回头只借它一个 `ProjectConfig` 类型（`import type`，编译期擦掉）。运行时没有这条边，读的时候也不必先读 `load.ts`——从摆放那份文件头读起就行。

**可跳过**：`dist/` 是构建产物。
