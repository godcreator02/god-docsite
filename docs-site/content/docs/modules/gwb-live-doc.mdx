# 工作台件

**本页回答**：`gwb-live-doc` 这一块管到哪儿为止、它跟七个 `live-doc-*` 包是什么关系、它的起停状态机怎么在一个进程都不起的前提下测。

## 管什么

`packages/gwb-live-doc` 是这个工作区里唯一不叫 `live-doc-*` 的包：它是 god 工作台（gwb）的一枚插件，
包名 `@godcreator02/gwb-live-doc`，命令名前缀 `live-doc.`，界面上占一格窗格。它是这套机制在工作台里的入口。

管两摊。一摊是**站的起停**：扫容器根下所有 fumadocs 站，判 build 新不新鲜，现挑一个空口起 `next start`，
到点自动关，件卸载时把自己起的全杀掉。另一摊是**接 livedoc**：把 cli 包内那个可执行登记给运行器、跑一趟命令行；
`init` 给一个还没有站的仓铺一个；`stale` 把 `check --json` 的机读报告收敛成一张「待重写页」的表；
`feedback` 往别的仓的文档站反馈区追加一条。后两块是纯逻辑，进程那半在别处。

命令名是常量，件挂载时注册到命令总线上：

{/* ref file="../packages/gwb-live-doc/src/index.ts" lines="47-58" */}

前六条是起停那摊。**先 `sites` 再别的**：那几条要的 `dir` 就是 `sites` 回包里的 `dir`，不自己拼——`start`
还会挡下容器根之外的目录。后五条是接 livedoc 那摊。`cli-raw` 不算一条给人用的，它是运行器登记出来的裸口。

`init` 那条的 `dir` 是**目标仓**目录，不是站目录——它是这一串里唯一一条对着「还没有站的仓」说话的命令，
所以它也是唯一不从 `sites` 回包里抄 `dir` 的。

扫的范围是硬的：容器根下一层一个单元，每个单元往下最多三层，点开头的目录与 `node_modules` / `dist` / `out`
不进。

{/* ref file="../packages/gwb-live-doc/src/sites.ts" lines="35-43" */}

三层这个数不是随手定的——容器根下是单元，单元下是仓，仓下是 `docs-site`，正好第三层。

**退役单元一层都不进**：出生证 `unit.json` 里写了 `retired: true` 的单元整个跳过，名字进回执的 `retired`。

{/* ref file="../packages/gwb-live-doc/src/sites.ts" lines="98-120" */}

退役单元里的站还在盘上、还起得来，但它讲的是已经作废的东西，列在清单里只会被人和 agent 当成现状去读。
跳了几个要说出来——**静默少几条站比多几条更难查**。判据只认布尔的真，写成 `"true"`、`1` 的一律不算退役：
宁可多列一个站，也不要因为一个字符串把一个还在用的单元藏起来。

起来的站默认两小时后自己关，到点前五分钟界面上给「延长」。用的是**绝对到期时刻加定期对表**，不是一个
`setTimeout`：机器睡一觉 `setTimeout` 会漂，醒来时它还以为没到点；对表是每半分钟拿当前时刻跟到期时刻比一次，
睡多久都对。

{/* ref file="../packages/gwb-live-doc/src/deadline.ts" lines="44-52" */}

这三个数是提前量、对表间隔与缺省时长，状态机与界面两头用的是同一份：

{/* ref file="../packages/gwb-live-doc/src/deadline.ts" lines="9-16" */}

设置项 `auto-stop-minutes` 写 0 就是不自动关，改了只对之后起的与延长的生效。

## 不知道什么

件手里只有三件事：**哪些目录是 fumadocs 站、怎么把一个站起起来又关掉、怎么把别人算出来的结论摆给人看**。
剩下的全在别处。

**不知道站里写的是什么。** 认站只看 `package.json` 的两档依赖里有没有 fumadocs 家的包——**泛 fumadocs 站，
不只认 livedoc 站**：

{/* ref file="../packages/gwb-live-doc/src/sites.ts" lines="10-25" */}

站根另有 `livedoc.config.mjs` 的界面上多亮一个记号，**只是记号，不影响能不能起**。一个工具如果只肯伺候
自己家的站，它在这台机器上就只能用来看一个仓。

**不知道站是怎么编译出来的。** 要 build 就在站目录里原样跑那个站自己的脚本，next 与 fumadocs 那条编译链
一个字都不认识；新鲜度同理只看文件时间，一个 mdx 都不解析。

{/* ref file="../packages/gwb-live-doc/src/runner.ts" lines="70-72" */}

**不知道 livedoc 是怎么核对的。** 报告的形状是契约，件只认 `check --json` 打出来的那一行，五个契约字段
全在才认；加字段照样认，少字段就不认：

{/* ref file="../packages/gwb-live-doc/src/stale.ts" lines="131-145" */}

少字段说明对面那份 cli 太老，报「没拿到机读报告」比在下游读出 `undefined` 强。同理 `check` 有红时退出码
是 1，那是核对结果不是命令失败——件把退出码与 stdout 原样交出去，不替它解释。

**不知道一处钉为什么黄、一个落点为什么不新鲜。** 一处钉是绿是黄是红、行段挪了跟不跟得上，归比较器；
一个落点四态里的哪一态、算不算新鲜，归 project 的摆放模块——判定结果随报告里每个落点的 `fresh` 一起过来。
件哪一样都不重新解释，只照一条现成的口径筛：

{/* ref file="../packages/gwb-live-doc/src/stale.ts" lines="7-9" */}

筛的时候 `fresh` 原样取、四态原样带出去，件只答「这一页要不要重写」：

{/* ref file="../packages/gwb-live-doc/src/stale.ts" lines="83-96" */}

只有孤儿记录或名册外组件的页也红，但那不是「重写正文」能解决的事，单列进 `others`——混在一起会让 agent
去重写一篇其实只要 `confirm` 一下的页。`unconfirmed`（白）不算漂移：那是还没确认过，不是现状漂了。

**不知道反馈条目该长什么样。** 格式是 cli 的站模板 `template/docs-site/content/feedback/inbound.mdx.tpl`
那份注释定的，件只照着摆：`## <日期> <标题>` + `来源：` 一行 + 正文。

{/* ref file="../packages/gwb-live-doc/src/feedback.ts" lines="47-51" */}

投的时候三条纪律——**只追加**（不动已有条目、不碰别的页）、**不 commit**（那个仓的人自己看了再提交）、
**页不在就建**（对面的站可能还没改成六区，缺一页不该让跨仓反馈投不进去）。日期取本机时区，不用
`toISOString`：那是 UTC，晚上八点之后写的条目会落到明天。

**不知道一个站是怎么铺出来的。** `live-doc.init` 把「哪个仓、叫什么、用哪个口」翻译成一趟子进程就完了：
六区骨架长什么样、端口按什么认、起手页钉哪一行，全在 cli 包的[建站模块](/docs/modules/cli)里。件这头只
拦两件参数的事——路径得是绝对的、得是个目录（不然运行器会去抱怨 cwd，看不出是仓给错了），其余的判断连同
错误文本原样交出去。

{/* ref file="../packages/gwb-live-doc/src/index.ts" lines="499-506" */}

**实现不许搬进件**：livedoc 得能在没装工作台的仓里独立用，铺站搬进来就等于让建站依赖一整台桌面工作台。

**不知道七个包的任何事。** 依赖方向单向：件依赖 [cli](/docs/modules/cli)，七个包一个字都不认识件、也不认识
任何 `@godcreator02/gwb-*`。运行时、peer、开发期三档全查的那条边界测试守着：

{/* ref file="../tests/boundary.test.ts" lines="189-199" */}

件跟包同住一个工作区，方向一旦反过来——哪怕只是一条 devDependency——这套包就再也发不出去了：装它的人
不该被迫拉进一整个桌面工作台生态。

**不知道七个包那套工具链。** 那七个是 tsdown + TS 6、测试跑 `node --test`；这个件是 `tsc` 出 node 半、
`esbuild` 打浏览器半、`tailwindcss` 编一张带 `livedoc` 前缀的样式表，跑在 TS 7 上，测试用 vitest。
各自的 `package.json` 说了算，**两套并存、不互相搬**。

**不知道站该在哪个端口跑。** 端口现挑，不用站脚本里钉的那个：钉的口只对手跑有意义，工作台里同时起两个
站就撞了。

**不知道自己之外的进程。** 杀的只有自己起的那棵树；盘上别人起的 `next` 它看不见也不动。

## 提供的接口

对外三个面。

**命令总线上那一串 `live-doc.*`**，加运行器登记出来的裸口 `live-doc.cli-raw`。命令名是公共面，产物守卫
那条测试一个个数着，改名就是破约。

{/* ref file="../packages/gwb-live-doc/tests/artifact.test.ts" lines="77-95" */}

**一格窗格**：浏览器那半与样式表的地址由 node 半从 `import.meta.url` 算成 `file://` 报给外壳；窗格叫什么
归运行时，`ctx.gwbShell.describeSelf` 报。

**内核事件口上的一个记号**，页面 `window.gwb.on` 认它：

{/* ref file="../packages/gwb-live-doc/src/index.ts" lines="44-45" */}

起停每次相位变化发 `kind: 'run'`，选中单元变了发 `kind: 'selection'`——页面不直接认识 unit-folder，
只认本件这一个记号。

说明书随包发（`skills/live-doc/SKILL.md`），装了 skills 件的 home 里自动挂给 agent 读；**livedoc 随 cli 包
发的那几份（cli 包 `skills/` 下的每一份）也由本件代挂**——那是个 CLI 包，自己挂不上工作台。

## 依赖的接口

**对 livedoc 命令行那条边是起子进程，不是 import 一个值。** 件跑在工作台的主进程里，进程内 `import` 一个
CLI 就等于把 livedoc 那一整棵依赖、连同它加载项目与问 git 的那些副作用，一起拉进工作台自己的进程；所以
这条边上只过两样东西：一个可执行的绝对路径（起进程时交给运行器），和 `import type` 借来的报告形状。

{/* ref file="../packages/gwb-live-doc/src/stale.ts" lines="13-14" */}

形状只借类型、不抄一份——抄的那份必然漂。这条也不靠自觉：cli 是真依赖，而 `index.ts` 里一旦出现一句非
type 的 import，产物守卫当场红。

{/* ref file="../packages/gwb-live-doc/tests/artifact.test.ts" lines="129-134" */}

`gwbShell` 与 `gwbCommands` 进 `export const inject`，缺哪个都不挂；其余全走 `ctx.inject` 的局部注入
——那些件不在的 home 里本件照常挂，只是少一块功能。

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `RunnerDeps`（挑口 / build / serve / 杀树 / 时钟） | 起停真进程 | `runner.ts` 的 `realRunnerDeps()` | `tests/manager.test.ts` 里一整套可操控的假运行器 |
| `gwbShell` | 注册窗格、报自己的名字 | 外壳件 | 不测（要开窗，走实机） |
| `gwbCommands` | 挂那一串 `live-doc.*` 命令 | 命令总线件 | 不测（命令名由产物守卫数） |
| `gwbNodeCli` | 起 livedoc 的进程 | node-cli 件，登记包内 `dist/cli.mjs` 的绝对路径 | 不测；不在时 `live-doc.cli` / `live-doc.init` / `live-doc.stale` 回 `code: 'no-node-cli'` |
| `gwbSettings` | 读 `units-root` 与 `auto-stop-minutes` | 设置件；`units-root` 空着时经 `settings.get` 借 unit-folder 那份 | `autoStopMinutes(raw)` 直接喂原始值 |

## 怎么单独测

判据一条：**这段逻辑能不能不起进程、不开窗、只喂输入看输出**。能就写成 vitest 用例；不能（要起子进程、
要 Electron、要真装进 home）那不是不测，是走实机验证那条路。两者不互相替代——`pnpm check` 全绿从来不
代表装出来能跑，它吃的是源码。

{/* tree dir="../packages/gwb-live-doc/tests" depth="1" */}

**起停状态机喂一整套假运行器**：挑口回递增号，build 与 serve 的完成由用例手动兑现，杀树只记 pid，
时钟是一个可以往前推的数。

{/* ref file="../packages/gwb-live-doc/tests/manager.test.ts" lines="25-63" */}

证的就是那几件难改的：build 失败不 serve、serve 没就绪就退要杀树兜底、已经在跑不起第二个进程、正在起时
再起要拒绝、进了五分钟提前量只提醒一次、延长之后提前量重新算、到点自动停、dispose 把还在 build 的那次
start 也收尾不悬着。真起子进程的那半在 `runner.slow.test.ts`，打了 `slow` 标签，日常 `pnpm test` 跳过，
`pnpm test:all` 才跑。

认站、限深扫描、build 三态、退役单元判据喂的是 `os.tmpdir()` 下现造的一棵目录树，一条用例一棵、跑完删；
`stale` 喂一份手造的 `CheckReport`，证的是筛的那两条口径（钉全绿但落点不新鲜的页照样要重写、只有孤儿
记录的页不进那张表）与从 stdout 里捞报告那一步；`feedback` 喂一页 mdx 文本，
证一来一回不丢字段、围栏里的 `## ` 不算条目。产物守卫那一组要 `dist/` 三样齐了才跑，缺产物整组跳过
——门禁不依赖 build。

门禁是这个包自己的一摊，跟工作区那摊 `node --test` 分开跑：

{/* ref file="../packages/gwb-live-doc/package.json" lines="24-31" */}

发版顺序是 **cli 先、件后**：件装的是发出去的那份 cli，工作区里的软链只在这个仓里成立。

## 代码地图

**在哪**：

{/* tree dir="../packages/gwb-live-doc/src" depth="2" */}

**先读** `index.ts`。node 半只剩接线：窗格、命令、内核事件口，以及设置 / 选中单元 / 运行器 / 说明书那四处
局部注入，全在那儿挂；
件 dispose 时杀光自己起的站也在那儿——工作台关了还留着 node，那才是爆内存的路。

{/* ref file="../packages/gwb-live-doc/src/index.ts" lines="187-190" */}

**读序**：`index.ts` 往下吃四份纯逻辑——`sites.ts`（认站、限深扫描、build 三态、挑缺省站）、`manager.ts`
（起停状态机，再往下吃 `deadline.ts` 的到期算术）、`stale.ts`（报告收敛）、`feedback.ts`（条目格式与追加）。
`runner.ts` 只被 `index.ts` 用来把真运行器注给状态机，它不认识上面任何一个。`src/client/` 是浏览器那半，
esbuild 单独打，跟 node 半只经窗格地址与那个内核事件记号相连，只从 `deadline.ts` 借剩余时间的格式化。

**可跳过**：`dist/`（三步构建的产物，`tsc` / `esbuild` / `tailwindcss` 各出一样）、
`src/client/components/ui/`（脚手架摆进来的组件）。
