# fumadocs 那一层

**本页回答**：`src/fumadocs/` 管到哪为止、它往 fumadocs 上插哪几处、组件怎么压平成给 AI 读的 md，以及 `Format` 这条接缝到底分离了什么。

## 管什么

三摊，读的时候要分得开。

**格式实现那一摊**：认领 `.mdx`、认记号、写回记号，加一个名册检查和一份 `renderAi`。判定层看到的只有这一摊，`Format` 那几样出口就摆在文件头上：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/index.ts" lines="29-49" */}

**站接线那一摊**：remark 插件挂进 fumadocs 的链尾、整张换掉 rehype 的 meta 白名单、给集合的 postprocess 一个序列化回调、侧出口交出状态点的 pre 组件与术语组件，各配一份随包发的样式表。判定、环境、命令行三层都不知道这一摊存在。

**两张表的机制**：名册（一个组件在 AI 那份 md 里压成什么）与术语表（站上自动标注）。机制在这一层，表的内容在站那边——组件和词条是站的，规则当然也该是站的。

捏在一层不是图省事：mdx 没有展示区，记号旁边不存投影，页面上那块代码是构建期从源码现拿的，所以「认记号」和「站怎么构建」本来就是同一件事。**`fumadocs` 这个名字只出现在这一层**——engine / host / cli 一个不碰它，这条不靠自觉：

{/* ref file="../tests/boundary.test.ts" lines="143-151" */}

`Format` 这条接缝留着**不是**为了「将来换个宿主」。它分离的是两种变化原因：怎么认记号（记号写成花括号注释还是 HTML 注释、走语法树还是走正则）与怎么判新鲜（记忆怎么记、段落怎么跟随、四态怎么定）。而且这条接缝上真有两个适配器——生产是这一层，测试是 `tests/fake-format.ts`，判定层与命令行的测试全喂它。

代价是一条反方向的依赖：这一层是包里唯一同时吃判定与环境两层的（`docfirstMdxOptions` 要 `loadProject`）。站的 remark 链上没有命令行帮它装配，插件得在构建期自己装一次。

{/* ref file="../packages/docfirst-workflow/src/fumadocs/index.ts" lines="1-21" */}

## 不知道什么

**不认识 Next**。这一层里没有一处 `next`，也不知道站的路由长什么样：状态点那半只是个读 `data-dot` 的组件，挂在哪个页面、走哪条渲染链是站的事；`renderAi` 只认得项目根和 fumadocs 的 loader，不知道这篇文档在站上是哪个地址。

**不知道摆放**。`renderAi` 交出的是一份 md 正文，摆到哪个落点、要不要带 frontmatter，归 [环境那一层](/docs/modules/host)——这一层只管把这一篇编译出来。

**不带 fumadocs、不带 react**：两者只能是 peer，用消费方项目装的那份，而且全可选——只跑命令行的仓一个都不必装。

{/* ref file="../packages/docfirst-workflow/package.json" lines="47-66" */}

peer 这条边界也不靠自觉，产物里同样盯着：

{/* ref file="../tests/boundary.test.ts" lines="161-170" */}

三条一起守着——宿主不许进 `dependencies`、产物里不许打进 fumadocs 或 react（只许 `import`）、`/fumadocs/pre` 的 `"use client"` 指令得留在产物头一行。

**不知道自己的输出最后长什么样**。节点上只塞颜色、标题和标，画成什么样归站侧的 pre 组件和随包发的样式表。**也不存副本**：mdx 没有展示区，页面上的代码每次构建现拿。

**术语表的正本不在这儿**：这一层只有匹配和在树上换节点，词条数据是站的。

## 数据结构

一处引用在树上变成一个节点，五种目标三种长相：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/blocks.ts" lines="188-219" */}

行段和整文件是一个 mdast `code` 节点，状态写在 meta 里。四种状态各一种长相：绿 / 白是一块当前段，`lineNumbers` 从今天的起始行起、行号跟源文件对得上，白的标题后面缀「· 未确认」；黄不另起「当前段」，把判定层出的 `-` / `+` 换成 shiki 原生的增删行标记（得写在那个语言真正的行注释里 shiki 才认，所以这一层带着一张行注释表，没有行注释的语言退成一块 `diff`），旧行新行渲在同一块，所以这一块**不带 `lineNumbers`**——块里夹着已经不存在的旧行，行号一定对不上源文件，与其错不如不给；红摆的是从记忆里取回的旧段，标题写「文档写下时这段是」。hash 记忆找不到这段了（`unlocated`）就**不摆代码**，只留一句「位置不明，重钉」。标题一律写**今天的位置**：行段跟随之后，记号上那几行可能已经不是这段了。

颜色只有四种，有变动和未确认同是黄，实心 / 空心的区别在样式表：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/blocks.ts" lines="23-25" */}

目录树不变成代码块，变成 fumadocs 自己的 `<Files>` / `<Folder>` / `<File>`——这就是 mdx 比纯文本格式多出来的那点意义，这一层能往树上放真组件：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/blocks.ts" lines="170-185" */}

根是一个展开的文件夹，名字是这处的来源，下面按路径切成嵌套，到深度尽头没孩子的子目录禁用。容器带 `data-docfirst="tree"` 和 `data-dot`，样式表在右上角画同一颗点——作者手写的 `<Files>` 没这两个属性，一个像素不多。黄的时候旧表新表并在一棵树里，多的项标 `docfirst-add`、少的标 `docfirst-del`；红只剩一个禁用的根文件夹，里面一行「目录不在了」。

存在性和名字没有代码可摆，还是 `code` 节点，meta 里多一个 `data-chip`，站的 pre 组件见到它画一行芯片，不画代码块。

节点上另挂两条标，都只给 AI 那份 md 用，不影响页面：`data.docfirst` 是一处引用的来源、状态标签和一份干净内容；`data.docfirstAi` 是一个组件的替换节点。同一棵树接着还要出页面，所以**打标不动树**。

名册是一张「组件名 → 规则」的表。要它是因为 mdx 里的组件是 JSX 节点：序列化成 md 时，要么原样漏成一个裸标签（AI 读到一个 `Tabs` 标签一头雾水），要么被整个丢掉（内容也没了）。两条都不行，所以得有一张表说清**每个组件在 md 里变成什么**。

规则三种写法：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/roster.ts" lines="34-35" */}

`"children"` 只留子内容、去掉外壳；`"drop"` 整个不进 AI 那份；函数收一个节点，交回一个或一组普通 markdown 节点。嵌套的组件不用规则操心——子节点还在树上，各自有各自的标。

函数规则只能通过 helpers 读节点（`attr` / `textOf`）、造节点（`text` / `heading` / `paragraph` / `quote` / `children`），节点本身对规则是黑盒：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/roster.ts" lines="21-32" */}

<Note>
  守住这一条，同一张表换个宿主照样能用：宿主各自提供一套 helpers，造的是自己的节点。规则里一旦直接摸 mdast 的字段，这张表就跟 mdast 绑死了。
</Note>

`inline` 告诉规则「这处是不是写在句子里」——行内的位置只能交回行内节点。这一条没有机制守，靠规则作者自觉，记在[待定](/future/roadmap)里。

这一层自带一张默认表，按语义定，不知道组件在哪个站上长什么样：

{/* has file="../packages/docfirst-workflow/src/fumadocs/roster.ts" text="export const defaultRoster" */}

这张表这一页**只用名字钉、不摆投影**：表里的注释拿尖括号包着组件名，投影进机读版会撞上站测试那条「组件没被名册压平」的断言。这是这套机制自己写自己才会撞上的一处，绕法是钉名字，正文照说不误（见[路线图](/future/roadmap)）。表里：块级的 `Note` 变一个引用块（前面缀 `[note]`），写在句子里的变一段行内文字——别把句子拆断；再加 fumadocs 文件树那三件，作者手写的 `<Files>` 压成一行一个名字、文件夹带尾斜杠。站一般把它展开，再加上自己的组件。

## 提供的接口

包外一共三个口加两张样式表，出口表一眼看全：

{/* ref file="../packages/docfirst-workflow/package.json" lines="10-29" */}

`./fumadocs` 是站的 `source.config.ts` import 的那一份，`.` 走命令行与程序调用那条，`/fumadocs/pre` 与 `/fumadocs/term` 含 React、单独出去。

对判定层那一面，它是个普通格式：五样必选出口，加一个名册检查和一份 `renderAi`。`lintComponents` 让命令行 `check` 提前报出名册外的组件，不用等构建才发现。

对站那一面是三个插头加一层可选的术语标注：`docfirstMdxOptions({ root })` 挂进 `source.config.ts`（remark 链**尾巴**上挂插件，顺带换掉 rehype 的 meta 白名单）、`docfirstMarkdownOptions()` 挂进集合的 `postprocess.includeProcessedMarkdown`、侧出口 `/fumadocs/pre` 覆盖 `mdx.tsx` 里的 `pre` 并配一份 css；给 `docfirstMdxOptions` 一份词表就多开术语标注，不给就不开。

{/* ref file="../packages/docfirst-workflow/src/fumadocs/host.ts" lines="46-64" */}

挂在链尾是有讲究的：前面是 fumadocs 自己的 `remarkInclude` 和一整套预设（标题 id、gfm……），后面就是它自己的 postprocess——插件看到的是一棵已经归置好的树。术语标注排在 docfirst 那个**之前**：那时树上还只有作者写的散文，投影的代码块与目录树都还没注入，标注碰不到它们。`<Term>` 的定义是构建期写进属性的，组件不带词表进客户端包，也不需要一行 JS。

这个站自己就是这么接的，全站接线一个文件：

{/* ref file="source.config.ts" lines="68-76" */}

meta 白名单要整张换掉——fumadocs 的 `rehypeCode` 只放行白名单里的字段，别的一律丢掉，状态点的颜色因此得自己带进去：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/host.ts" lines="29-29" */}

跟 fumadocs 的默认白名单同形，只多 `data-dot` 和 `data-chip`。值一律带引号——它的 meta 解析器只认 `key="字符串"` / `key=数字` / 裸 `key` 三种，裸单词会被解析成 `null`。

remark 插件四步，一步一件事：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/remark-plugin.ts" lines="22-28" */}

**认**：`recognize` 在 mdast 上找引用，正式记号是顶层的 `mdxFlowExpression`，草稿记号是单独成段的一行普通文字；围栏里、行内的同样文字分别是 `code` 和 `mdxTextExpression`，认不出来。**算**：交给判定层的 `resolveRefs`，树都解析完了，不必再 parse 一遍。**换**：`applyListing` 把记号节点换成代码块或文件树。**打标**：`stamp` 按名册给每个组件挂上「AI 那份里它长什么样」。同一棵树接着既出页面又出 md，所以状态走两个通道：`meta` 字符串给页面，`data` 上的标给序列化回调。

打标的机制这一头：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/roster.ts" lines="118-137" */}

只挂不换：`data.docfirstAi` 是一组替换节点，空的就挂 fumadocs 自家的 `data._stringify` 表示整个不要；机制注入的节点（目录树那棵 `Files`）标已经打好，跳过、不往里走。表外的组件硬失败，报到行。

站侧的 pre 组件：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/pre.tsx" lines="45-57" */}

有 `data-dot` 的（引用变出来的那些）套 fumadocs 的 `CodeBlock`，把一个 8px 的点塞进标题栏的 `Actions` 槽、复制按钮左边；再带 `data-chip` 的画一行小标签；都没有的（普通围栏）原样走默认路径，互不干扰。

<Note>
  这个组件必须是**客户端组件**：`CodeBlock` 是 `"use client"`，状态点要靠 `Actions`（一个函数）传进去，而服务端组件不能把函数递给客户端组件。所以它单独一个侧出口，`"use client"` 指令还得留在产物头一行——边界测试盯着这一条。
</Note>

站的构建配置里 `serverExternalPackages` 因此**必须留空**。这一个包里同时住着服务端那半（读盘、调 git、remark 插件）与两个客户端组件，而那个字段按包名匹配、没有子路径粒度，整包外置的边界会把 `"use client"` 指令吃掉：

{/* ref file="next.config.mjs" lines="12-25" */}

给 AI 那份 md 的是一个序列化回调：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/markdown.ts" lines="24-46" */}

fumadocs 序列化每个节点前先问它，看到我们打的标就按标出，没标的交回 `undefined` 让它照默认走。组件的标交给它的状态机接着序列化（嵌套组件顺着走）；引用的标出一行来源注释加一块干净的代码——不要 meta、不要 diff 标记；芯片没有内容，只留来源那一行。

`renderAi` 不自己拼 md：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/render.ts" lines="56-71" */}

从消费方项目根 `register()` fumadocs 的 Node loader，`import` 那篇 mdx（带 `?collection=`，loader 靠它知道该跑哪份 postprocess），读它导出的 `_markdown`。站上 `getText("processed")` 读的是同一个导出——两边逐字节相同，是**同一条管线**的结果，不是对齐出来的。命令行和站就是这条管线的两个调用方，算状态的服务只有一份。

`?collection=` 里那个名字按文档所在的目录定：

{/* ref file="../packages/docfirst-workflow/src/fumadocs/render.ts" lines="38-49" */}

六区站一区一个集合，所以默认取文档目录的最后一截，跟 `defineDocs` 变量名按目录起的习惯对上；目录套目录时取最长的那个；要一刀切或改名，站在 `docfirst.config.mjs` 的 `fumadocs.collection` 里写字符串或一张表。

## 代码地图

**在哪**：

{/* tree dir="../packages/docfirst-workflow/src/fumadocs" depth="1" */}

**先读** `index.ts`：出口总表，格式那五样出口就摆在文件头，四个侧出口写在头注释里。三摊各是一条线，读一条时另外两条整条跳过。

**读序**：

- **引用这条线**（格式实现那一摊，加它在站上显示成什么）：`recognize.ts` 认引用 → `transform.ts` 换节点（换成什么长相在 `blocks.ts`）→ `roster.ts` 打标 → `markdown.ts` 序列化、`render.ts` 出 md；`remark-plugin.ts` 把前四步串成一趟。
- **站接线这条线**：`host.ts` 一个文件，把上面那趟挂进 fumadocs 的 remark 链、换掉 meta 白名单，在最外层装配、只装一次；页面上画成什么样在侧出口 `pre.tsx`。
