**本页回答**：fumadocs 适配做哪几件事、往 fumadocs 上接哪几处、对外给哪些出口、依赖谁，以及它刻意不做什么。

包 `@godcreator/docfirst-fumadocs`，源码在 `packages/docfirst-fumadocs/src/`，入口是 `src/index.ts`（出口 `.`），
另有侧出口 `./roster`、`./pre`、`./term`、`./trajectory` 与两张样式表。

## 功能

这个包里的代码都由 fumadocs 或 Next 调用：mdx 加载器编译页面时调的插件、集合的 schema 与回调、页面渲染时的组件。
从 `docfirst` 命令开始的调用链一条都不经过它。入口文件头把几样东西各接到哪写全了：

{/* ref file="../packages/docfirst-fumadocs/src/index.ts" lines="1-17" hash="677de7c33676" blob="8f4947e20dfb" */}

**现状集合的 remark 插件。** 四步，一步一件事：

{/* ref file="../packages/docfirst-fumadocs/src/remark-plugin.ts" lines="21-27" hash="1b4fd315e4b5" blob="2efb8db2a72b" */}

**认**：workflow `./mdx` 的 `recognize` 在 mdast 上找引用。**算**：交给钉码服务的 `resolveRefs`，树已经解析好了，不再解析一遍。
**换**：`applyListing` 把记号节点换成代码块、文件树或小标签。**打标记**：`stamp` 按名册给每个组件加上「机读版里它长什么样」。
同一棵树接着既出页面又出 md，所以状态走两条通道：`meta` 字符串给页面，`data` 上的标记给序列化回调。

### 一处引用在页面上长什么样

五种目标三种样子。行段和整文件是一个 mdast `code` 节点，状态写在 meta 里。绿和白是一块当前段，`lineNumbers` 从今天的起始行起，行号跟源文件对得上，白的标题后面加「· 未确认」；黄把钉码核心给的 `-` / `+` 换成 shiki 原生的增删行标记（要写在那个语言真正的行注释里 shiki 才认，所以这里带着一张行注释表，没有行注释的语言退成一块 `diff`），旧行新行在同一块里，所以**不带 `lineNumbers`**；取不到确认时的内容、没有 diff 的黄退成一块普通的当前段，标题里写「有变动」；「位置不明」**不放代码**，只留一句提示。红放的是确认时那段（取得到才有），标题写「文档写下时这段是」。标题一律写**今天的位置**：行段跟随之后，记号上那几行可能已经不是这段了。

{/* ref file="../packages/docfirst-fumadocs/src/blocks.ts" lines="167-198" hash="8e8924529a15" blob="8cf656b5cdc2" */}

颜色只有四种，有变动和未确认同是黄，实心、空心的区别在样式表：

{/* ref file="../packages/docfirst-fumadocs/src/blocks.ts" lines="26-28" hash="74bf6269f8c9" blob="8cf656b5cdc2" */}

目录树不变成代码块，变成 fumadocs 自己的 `Files` / `Folder` / `File` 组件——mdx 能往树上放真组件，这是它比纯文本格式多出来的地方：

{/* ref file="../packages/docfirst-fumadocs/src/blocks.ts" lines="150-164" hash="3f1c0692e282" blob="8cf656b5cdc2" */}

根是一个展开的文件夹，名字是这处的来源，下面按路径切成嵌套，到深度尽头没孩子的子目录禁用。容器带 `data-docfirst="tree"` 和 `data-dot`，样式表在右上角画同一颗点；作者手写的文件树没有这两个属性，外观不变。记录里只有名字表的哈希，所以黄的时候放的是今天的名字表，说不出多了哪项少了哪项；红只剩一个禁用的根文件夹，里面一行「目录不在了」。

存在性和名字没有代码可放，还是 `code` 节点，meta 里多一个 `data-chip`，站的 pre 组件见到它画一行小标签，不画代码块。

节点上另加两个标记，都只给机读版用，不影响页面：`data.docfirst` 是一处引用的来源、状态和一份干净内容；`data.docfirstAi` 是一个组件的替换节点。

### 机读版

站上各页给 AI 读的 md 走 fumadocs 自己的 processed markdown，序列化回调由这个包给：

{/* ref file="../packages/docfirst-fumadocs/src/markdown.ts" lines="24-46" hash="0455bbfbe401" blob="26542dea70a7" */}

fumadocs 序列化每个节点前先问它，看到打过的标记就按标记出，没标记的交回 `undefined` 照默认走。组件的标记交给它的状态机接着序列化（嵌套组件照常处理）；引用的标记出一行来源注释加一块干净的代码，不要 meta、不要 diff 标记；小标签没有内容，只留来源那一行。生成正本（README、AGENTS.md 这类）不走这条路，由 workflow 的 [mdx 格式](/docs/modules/workflow/mdx)按原文渲染。

### 状态点组件

{/* ref file="../packages/docfirst-fumadocs/src/pre.tsx" lines="45-57" hash="cc45214abd3a" blob="d991b4ac2515" */}

有 `data-dot` 的（引用换出来的那些）交给 fumadocs 的 `CodeBlock`，把一个 8px 的点放进标题栏的 `Actions` 位置、复制按钮左边；再带 `data-chip` 的画一行小标签；都没有的（普通围栏）照默认路径走，互不干扰。

<Note>
  这个组件必须是**客户端组件**：`CodeBlock` 带 `"use client"`，状态点要经 `Actions`（一个函数）传进去，而服务端组件不能把函数传给客户端组件。所以它单独一个侧出口，`"use client"` 指令还得留在产物第一行——边界测试检查这一条。
</Note>

### 术语标注

给 `docfirstMdxOptions` 一份词表就开术语标注，不给就不开。它排在 docfirst 插件**之前**：那时树上还只有作者写的正文，引用换出来的代码块与目录树都还没放进去，标注碰不到它们。`Term` 的定义在构建时写进属性，组件是服务端组件，不把词表带进客户端包，也不需要一行 JS。入参单独一份，`skipFile` 实际上必须给：术语页自己不能标，否则会自己引用自己。

{/* ref file="../packages/docfirst-fumadocs/src/glossary-plugin.ts" lines="26-35" hash="6e3562a4b1af" blob="8bc7141770f1" */}

这个包只有匹配和在树上换节点，词条数据是站的。

### fumadocs 组件的名册规则

fumadocs 自带的几个组件在机读版里压成什么，规则在 `./roster` 出口，站在 `docfirst.config.mjs` 里展开它、再加自己的组件：

{/* has file="../packages/docfirst-fumadocs/src/roster.ts" text="export const fumadocsRoster" */}

这张表在这一页**只钉名字、不放代码**：表里的注释用尖括号包着组件名，放进机读版会触发站测试「组件没被名册压平」的断言。这是这套机制写自己时才会遇到的一处，办法是钉名字，正文照说（见[路线图](/future/roadmap)）。表里：块级的 `Note` 变一个引用块（前面加 `[note]`），写在句子里的变一段行内文字，不把句子拆断；再加 fumadocs 文件树那三个组件，作者手写的文件树压成一行一个名字、文件夹带尾斜杠。

`./roster` 只放数据与纯函数：命令行读 `docfirst.config.mjs` 时会加载它，而命令行跑的环境（git hook、CI）不一定装了 fumadocs。规则的类型从 workflow 的 `./mdx` 取，运行时一句 import 都没有。remark 插件在站没给名册时也用这张表。

### 轨迹卡集合

轨迹卡用自己的集合，这个包给集合两样东西。frontmatter schema `cardSchema`：缺 `born-at` 校验失败，缺 `label` 用文件名代替，六个卡字段都没写的页当普通页通过：

remark 插件 `remarkTrajectoryLinks`：把关系边段落转成带 `data-kind` 的 div，把指向卡身份的链接和 wikilink 改成卡页地址，带路径的 `.md` 链接（引用材料）不改：

{/* ref file="../packages/docfirst-fumadocs/src/card-collection.ts" lines="125-129" hash="21ed7eae1628" blob="2179f5ccdf19" */}

哪几个字段算卡，从轨迹核心的 `CARD_KEYS` 取，跟命令行校验卡用的是同一条判据。

### 星轨盘服务端组件

`./trajectory` 出口有两样：`loadTrajectory(dir)` 读一个卡目录并建模，要自己排页面的站直接拿数据；服务端组件 `Trajectory` 读卡、建模，绘制 `StarDisk`，有问题的卡列在盘下方。卡目录可以写绝对路径，也可以写相对站根目录的路径：

{/* ref file="../packages/docfirst-fumadocs/src/trajectory.tsx" lines="17-29" hash="d7d894adb801" blob="f8b43c49b05a" */}

读卡目录走 workflow `./cards` 出口的 `scanCardDir`（它顺带查卡里不许钉码；不从 `.` 取，免得把命令行与配置加载带进 Next 的服务端构建），建模与缩略图走轨迹核心的纯函数，`StarDisk` 按包名从 `@godcreator/docfirst-trajectory/disk` 取——那份产物头一行是 `"use client"`，按包名 import 才会原样留在产物里，Next 认得出客户端边界。

## 接口

主出口、四个侧出口、两张样式表：

{/* ref file="../packages/docfirst-fumadocs/package.json" lines="7-30" hash="f9522bea440a" blob="56f4689ae118" */}

对站，是三个接入点加一层可选的术语标注：`docfirstMdxOptions({ root })` 经 fumadocs-mdx 的 `applyMdxPreset` 接进现状集合的 `mdxOptions`（remark 链**末尾**加插件，同时换掉 rehype 的 meta 白名单）；`docfirstMarkdownOptions()` 接进同一个集合的 `postprocess.includeProcessedMarkdown`；侧出口 `./pre` 覆盖 `mdx.tsx` 里的 `pre`，并配一份 css。轨迹卡集合另用 `cardSchema` 与 `remarkTrajectoryLinks`；`./roster` 给 `docfirst.config.mjs`；`./trajectory` 给星轨盘路由。

集合写在站的 `src/lib/source.ts` 里（fumadocs-mdx 的 macro），没有全局配置，所以接线按集合写；集合级 `mdxOptions` 会去掉 fumadocs 的默认插件，`applyMdxPreset` 把它们加回来。返回值的类型按结构对上 `applyMdxPreset` 的参数，这个包不 import fumadocs 的类型，站里也不用强转；代码高亮选项里写上 fumadocs 的默认主题，是因为它的类型要求主题必填，运行时先铺默认再盖这一份，结果不变：

## 不做的事

- **不认识 Next**：这个包里没有一处 `next`，也不知道站的路由：状态点只是个读 `data-dot` 的组件，星轨盘的卡页地址由调用方传 `hrefBase`，用在哪个页面、走哪条渲染链是站的事。
- **不认记号、不判状态**：认记号与打标记用 workflow `./mdx` 的函数，状态由钉码核心算；这个包只把清单换成页面上的节点。
- **不管生成物**：生成正本的渲染与写到哪归 workflow。
- **不把宿主打进产物**：fumadocs、react 与另外三个包都只按包名 import；`./pre` 的 `"use client"` 在产物第一行，别的出口不带这条指令：

{/* ref file="../tests/boundary.test.ts" lines="280-314" hash="39d7e86b49f8" blob="55f573c4c909" */}

- **不管自己的输出最后长什么样**：节点上只放颜色、标题和标记，画成什么样归站侧的 pre 组件和随包发的样式表。
- **不存副本**：页面上的代码每次构建时现取，文件里只有记号那一行。
- **不被命令行加载**（`./roster` 除外）：workflow 不许依赖这个包，边界测试的包方向表管着。
