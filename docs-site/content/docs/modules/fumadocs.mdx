## 功能

这个包里的代码都由 fumadocs 或 Next 调用：mdx 加载器编译页面时调的插件、集合的 schema 与回调、页面渲染时的组件。
入口文件头写明了每样接到站的哪里：

{/* ref file="../packages/docfirst-fumadocs/src/index.ts" lines="1-17" hash="677de7c33676" blob="8f4947e20dfb" */}

**remark 插件**四步：workflow `./mdx` 的 `recognize` 在树上认引用，钉码服务的 `resolveRefs` 算清单，`applyListing` 把记号节点换成
代码块、文件树或小标签，`stamp` 按名册打标记。同一棵树既出页面又出机读版，所以状态走两条通道：`meta` 字符串给页面，
节点 `data` 上的标记给机读版的序列化回调。

{/* ref file="../packages/docfirst-fumadocs/src/remark-plugin.ts" lines="21-27" hash="1b4fd315e4b5" blob="2efb8db2a72b" */}

五种引用在页面上是三种节点：行段与整文件是带状态点的代码块，目录树是 fumadocs 的 `Files`，存在性与名字是一行小标签：

{/* ref file="../packages/docfirst-fumadocs/src/blocks.ts" lines="4-6" hash="794e2891d151" blob="8cf656b5cdc2" */}

取不到旧内容、全文也找不到的黄不摆代码。目录树与小标签：

{/* ref file="../packages/docfirst-fumadocs/src/blocks.ts" lines="10-16" hash="400ed50913d1" blob="8cf656b5cdc2" */}

**机读版**走 fumadocs 的 processed markdown，序列化回调由这个包给：看到标记就按标记出，引用出一行来源注释加一块不带 meta 与 diff
标记的代码，没标记的交回 `undefined` 照默认走：

{/* ref file="../packages/docfirst-fumadocs/src/markdown.ts" lines="24-46" hash="0455bbfbe401" blob="26542dea70a7" */}

**状态点组件** `DocfirstPre` 覆盖站的 `pre`：有 `data-dot` 的交给 fumadocs 的 `CodeBlock`，点经 `Actions` 放进标题栏；再带 `data-chip`
的画小标签；普通围栏照默认走。`Actions` 是函数，服务端组件不能把函数传给客户端组件，所以 `./pre` 是客户端组件：

## 不做的事

- **不认识 Next**：包里没有一处 `next`，卡页地址由调用方传 `hrefBase`。
- **不认记号、不判状态**：认记号与打标记用 workflow `./mdx`，状态由[钉码核心](/docs/modules/pin)算，这个包只把清单换成树上的节点。
- **不管生成物**：生成正本的渲染与写到哪归 [workflow](/docs/modules/workflow)。
- **不把宿主与兄弟包打进产物**：只按包名 import；`./pre` 的 `"use client"` 在产物第一行，别的出口不带：

{/* ref file="../tests/boundary.test.ts" lines="296-321" hash="42167dd07c3d" blob="e450056cc091" */}

- **不被命令行加载**（`./roster` 除外）：workflow 不许依赖这个包；`./roster` 的产物不许 import 宿主：
