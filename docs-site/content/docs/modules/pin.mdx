## 功能

确认对每一处的结果只有六种。`recorded` 与 `moved` 是机械写回；黄的只在带 `accept` 时才按今天的内容重新记：

见[git 那一侧](/docs/pinning/git)。

## 依赖

源码只 import 包内文件和 `node:crypto`（算段 hash 与 blob 名），`package.json` 里没有运行时依赖和 peer。
其余三样在创建服务时传进来，生产实现都在 [workflow](/docs/modules/workflow)。

**格式 `Format`**：认领文档、认出引用、写回、给出正式记号。一篇文档没有格式认领、或有两个格式认领，都报错。
名册检查与按原文渲染不在这个接口上，由 workflow 的 `DocFormat` 另加：

## 不做的事

**不碰磁盘，不启动子进程，不知道 git 存在。** 边界测试只许源码 import 包内文件和 `node:crypto`，清单里不许有依赖：

{/* ref file="../tests/boundary.test.ts" lines="169-178" hash="a91ae39e41d4" blob="e450056cc091" */}

**不认识别的包。** 它不依赖任何兄弟包：

{/* ref file="../tests/boundary.test.ts" lines="121-135" hash="6240de2040d1" blob="e450056cc091" */}

**不认识任何文档格式。** 文档归谁认领、记号外壳长什么样、写回时怎么改那一行，都归格式实现。

**不渲染，不知道项目根、配置文件和生成物放哪。** 装配、渲染与摆放在 workflow。

**不存旧内容。** 记号上只有 `hash` 与 `blob`；目录树只记名字表的 hash，变了只能报黄、给出当前的名字表。
理由见[记录进记号](/trajectory/2026-09-25-records-live-in-markers)。

**不决定黄灯拦不拦提交。** 这个包只给状态，哪些黄算红由 check 决定，见[门禁](/docs/pinning/gate)。
