# html 格式包

**本页回答**：`@godcreator02/live-doc-format-html` 怎么让一个 html 元素同时当记号和展示区，
以及「文件本身就是终态」这一条把哪些职责整个从这个包里拿掉了。

## 管什么

认后缀是 `.html` / `.htm` 的文档，认记号、写回记号。跟另外两个格式包最不一样的一条就写在导出面上：

`final` 的含义由核心的接口定：

{/* ref file="../packages/core/src/types.ts" lines="129-130" */}

**文件即终态**：html 没有构建管线，也没有下游产物。人打开的是这个文件，AI 读的也是这个文件，
不存在「站上一份、AI 一份」的分叉。所以这个包不出 `renderAi`、不出 `renderHuman`，
`livedoc render` 对一篇 html 文档无事可做——文档写成什么样，两边读到的就是什么样。

正式记号是 html 自己的东西：一个带 livedoc `data-` 属性的元素，**既是记号又是展示区**，
**没有尾记号**，元素的闭合就是边界。有内容可摆的种类用 `<pre>`，存在性和名字用 `<code>`、
元素里就是那个路径或名字：

{/* ref file="../packages/format-html/src/index.ts" lines="55-57" */}

容器是作者的，内容归格式包：外面的 `figure`、`figcaption` 随便写，元素里面每次确认整个重写。

## 不知道什么

**不知道渲染这回事**。这是它跟 md、mdx 两个包分岔的地方：那两个包各自还欠着一份「给 AI 的样子」，
这个包连这个问题都没有：

{/* ref file="../packages/format-html/src/index.ts" lines="14-15" */}

**不知道状态、不知道记忆在哪**。跟另外两个格式包一样：状态是核心算的，指纹在核心的记录簿里。
这个包交出去的是一串位置和目标。

**不知道磁盘**。要投影的内容由核心通过 `Fill` 递进来，它自己从不去读被引用的源文件。

**不知道任何第三方**。整个 import 面就这两行，一条 npm 依赖都没有：

{/* ref file="../packages/format-html/src/index.ts" lines="19-20" */}

**不知道 `<script>` / `<style>` 里写了什么**。那两种块整块跳过，里面的同样文字不算记号；
写成 `&lt;pre` 的转义文本也天然不匹配。

**不知道容器该长什么样**。它只重写元素内部：容器不是 `<pre>`（比如作者写了个 `<div data-file=…>`），
就往里放一层 `<pre><code>`，空白才保得住。作者的外壳一个字不动。

**不知道 project、不知道 cli**。方向单向。

## 数据结构

这个包自己只多出一样形状：`Reference.extra`。核心把它当不透明私货，原样带回、从不读它：

{/* ref file="../packages/core/src/types.ts" lines="55-56" */}

里面装的是**偏移**，不是行号——写回改的是元素内部那一段，不是整行，行号定位不到那么细：

{/* ref file="../packages/format-html/src/index.ts" lines="91-94" */}

正式记号存元素内容的起止（开标签末到闭标签头），草稿记号存整行去掉缩进的那一段，外加 `tag` 和 `draft`
两个标。md 那头存的是一个收尾行号，这里存一对偏移，差别全在「展示区是不是独立于记号存在」。

## 提供的接口

核心只认五样：`name` / `claims` / `parse` / `write` / `marker`。前三样和 `marker` 见上一节。

`parse` **逐行扫，不走语法树**——html 没有一棵现成的 mdast 可用。扫的时候维护一个跳过状态，
`<script>` / `<style>` 里的一律不算，然后才轮到草稿记号和开标签：

{/* ref file="../packages/format-html/src/index.ts" lines="103-111" */}

逐行扫的代价写在两条约束里：**带 livedoc `data-` 属性的开标签必须写在一行里**，拆成多行报到行号；
元素**必须闭合**，找不到闭合也报到行号。闭合是按标签名数嵌套找的，所以元素里面套同名元素也不会认错边界：

{/* ref file="../packages/format-html/src/index.ts" lines="78-89" */}

`write` 把元素内容整个换掉，草稿记号那一行整行换成带投影的元素、缩进保留；**从后往前改**，
前面几处的偏移才不受影响——跟 md 那头从下往上改是同一个道理：

{/* ref file="../packages/format-html/src/index.ts" lines="138-160" */}

## 怎么单独测

不起进程、不建仓、不读磁盘：喂一段 html 文本看 `parse` 交回什么，喂几条 `Fill` 看 `write` 写出什么。
要喂的假实现只有一样——`Fill.current` 里那几行字符串，测试自己编。

**证明记号两态自洽**：`parse(marker(t))` 认回 `t`，五种目标都过，位置也对。「怎么写」和「怎么认」
住同一个包，这条往返契约是它们不许分家的理由：

{/* ref file="../tests/marker.test.ts" lines="30-39" */}

**证明外壳没被动、写回幂等**：草稿行换成元素并投影，缩进和外面的 `figure` / `figcaption` 原样留着；
再写一次一个字不变，也不会多出第二个 `<code>`；容器是 `<div>` 时往里补一层 `<pre>`：

{/* ref file="../tests/marker.test.ts" lines="83-94" */}

**证明写坏了能定位**：开标签拆成多行、元素没闭合，两种都报到出问题的那一行：

{/* ref file="../tests/marker.test.ts" lines="106-109" */}

**证明跟别的格式包一致**：同一串代码改动下，三种格式的状态和跟到的行段完全一样。这一条要真 git 仓，
所以住工作区级的契约测试里：

{/* ref file="../tests/contract.test.ts" lines="53-63" */}

两份测试都住仓根 `tests/`、不住包里：契约是跨包的，只能在能同时 import 三个格式包的地方测。
各条测试各守什么，见 [测试与边界](/docs/cli/testing)。
