# 命令行

**本页回答**：`@godcreator/docfirst-workflow` 的 `src/cli/` 编排哪四条子命令、求助与开关怎么认、哪些事**不**归它、`--json` 报告与退出码的契约长什么样、怎么把它单独架起来测。

## 管什么

这一层是**动作的编排**，做两件事：把命令行参数翻译成对装配出来的项目的几次调用，再把结果打成人读的一行行、或机读的一行 JSON，最后返回一个退出码。**判定一件都不在这儿算**——它只负责打印和返回退出码。四条子命令各是什么、为什么到此为止，入口文件头上那段说了：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="1-20" */}

每条命令先做两项检查，四条命令一视同仁：带了求助（命令位上的 `--help` / `-h` / `help`，或任一命令后面的 `--help` / `-h`）就打用法退 0、别的一概不做；然后每条命令只收自己表里的开关，表外的一律报错退 2、不动手。之后分两路。主干 `check` / `confirm` / `render` 是一套：cwd 就是项目根——`docfirst.config.mjs` 在哪儿就在哪儿跑——先装配，再逐篇处理文档目录下被格式认领的每一篇。`trajectory` 是另一路：它不遍历文档，做完这两项检查就单独处理，不进 `loadProject`。

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="78-97" */}

开关表**必须是封闭的**，理由在 `confirm` 身上：它把 `--` 开头的参数从页名里筛掉，开关要是被静默吞掉，`confirm --help` 就成了不带页名的整仓确认，替别人没复核的黄灯签字，一声不吭。求助的写法在命令位与命令后面不一样宽，也是同一个原因——`help` 跟在 `confirm` 后面可能是一篇文档的路径：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="51-64" */}

### 输出的词汇表

一行一处引用：状态符号、文档、`文件:起-止`、一句话说明。

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="30-49" */}

`REASON` 里除了 `unlocated`（「有变动」的细分：hash 记忆找不到这段了，位置不明），都是「缺失」的细分——说清楚是哪一种指向空气，而不是含糊地报一句「代码没了」：行段的整段删光、文件没了、blob 取不回，目录树的目录没了，存在性的断言不在却出现了、文件和目录换了个，名字的找不到了。`MEMORY` 是 `confirm` 用的：哪一处拿到的是 hash 记忆（文件不在 git 里），那一行标出来。目录树那行还会带上项数，黄的时候带多了少了哪些：

```text
🟢 docs/handbook.mdx  tree src depth=1  新鲜（4 项）
🟡 docs/handbook.mdx  tree src depth=1  有变动，等作者复核（+ tag.ts）
```

### check：只读，报状态

次序是逐篇核对 → 失踪文档 → 卡校验，先攒成一份报告再决定怎么出：人读模式边算边打，`--json` 攒完整份一行打出去。**两种模式算的是同一份报告**，红的口径不可能对不上。

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="169-193" */}

```text
🟢 content/docs/modules/cli.mdx  ../packages/docfirst-workflow/src/cli/run.ts:48-58  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/docfirst-workflow/src/engine/types.ts:11-16  未确认，等作者确认
🟡 docs/a.md  src/greet.ts:2-3  有变动，等作者复核
🟡 docs/a.md  vendor/lib.ts:2-3  有变动，等作者复核（hash 记忆找不到这段了，位置不明——重读源码、重钉）
🔴 docs/a.md  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

红有四个来源，都算数：**缺失**的引用、**孤儿记录**（记录簿里有、文档里已经没有了）、**名册外组件**（`docfirst.config.mjs` 里没给它压平规则）、**摆放的落点不新鲜**——挂了 `outputs` 映射的文档，落点新鲜不新鲜是问环境层的摆放要来的，一个落点回一个四态加一个 `fresh`，不新鲜的都红。问的时候把这一篇刚判好的清单一起交过去，摆放不再判一遍：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="267-292" */}

四态各译成一句人话，就是这一层全部的活：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="294-301" */}

```text
🔴 docs/a.md  src/greet.ts:4-5  孤儿记录：文档里已经没有这处引用
🔴 docs/b.mdx  第 7 行 <Callout>  名册外组件，docfirst.config.mjs 里没给它压平规则
🔴 content/outputs/readme.mdx → ../README.md  生成物跟 mdx 源不一致（源改了没重摆，或有人直接改了生成物）——重跑 render
```

配了 `trajectory` 目录的项目，`check` 末尾还**顺带**跑一次轨迹卡校验——病卡一条一行，也算红。没配就整个不管；配了但目录还不存在扫出来是空集合，不算红：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="195-206" */}

卡的四层校验各拦什么归 [轨迹包](/docs/modules/trajectory)——这边只负责把病打成行、计进红。

### confirm：出记录、清孤儿、换记号

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="303-319" */}

顺利的时候一处一行 `✅`，清掉的孤儿一行 `🧹`。文档本身删了、挪了的，逐篇确认时看不到它的记录，`check` 按文档清单一览算红，`confirm` 末尾整个忘掉，也是一行 `🧹`：

```text
✅ docs/a.md  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ docs/a.md  vendor/lib.ts:2-3  已确认，草稿记号已换成正式记号（hash 记忆：不在 git 里）
🧹 docs/a.md  src/greet.ts:4-5  孤儿记录已清
🧹 docs/old.md  文档已不存在，记录已清
```

后面那句会说清楚这次确认到底动没动文档：草稿记号换掉了、文档写回了、还是什么都没改。末尾的括号说清楚拿到的是哪种记忆——弱记忆得让写手知道，分派规则归 [环境层](/docs/modules/host)。

有一处钉不住就整篇拒，problems 逐条打出来，末尾补一句「这篇整篇没确认」：

```text
🔴 docs/a.md 第 3 行：src/greet.ts:2-3 未提交——钉住只对已提交的内容做，先 commit
·  docs/a.md  这篇整篇没确认——上面几处先处理掉
```

#### 按页限定：`confirm <文档路径…>`

命令名后面跟几个文档路径，就只动点名的那几篇。同一个仓里常有别人钉的黄等着他自己复核，整仓确认会替他签字；改了哪几页就确认哪几页，是让「只改这几页」的改动能独立成一个提交的前提。

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="111-147" */}

孤儿清理**分两层，限定模式里去处不同**：一页之内的孤儿（这一页正文里已经没有的引用）照清，它本来就只看这一页；整仓那层（记录簿里有、项目里已经没有这篇文档了）不能按限定后的清单算——那份清单是人点名的一小撮，拿它当「现存文档的全集」，没点名的页会被全部当成失踪抹掉。所以限定模式只清点名了的那几篇。**挪一篇文档就是点两次**：旧路径点一次（忘掉旧记录）、新路径点一次（按新身份重钉），一条命令做完。

点名的路径长什么样不归这儿认——反斜杠、`./` 开头、绝对路径怎么归成文档身份，是环境层那一份 `docIdOf`。这边只分三类：还在的页去确认，已经不在、记录簿里还留着的页去清记录，两边都对不上当场退 2——拼错一个路径导致少确认一页，比报错难发现得多。

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="149-167" */}

```text
·  按页限定：只动 docs/a.md、docs/old.md，别的页与它们的记录不碰
✅ docs/a.md  src/greet.ts:2-3  已确认
🧹 docs/old.md  文档已不存在，记录已清
```

### render：摆到落点，或问格式要产物

渲染只有一种输出，给 AI 读的那份 md——人看的那份就是文档在站上的样子。挂了 `outputs` 映射的文档不落 `out/`，直接**摆**到映射给的位置（可以出项目根，`../README.md` 这种）；渲成什么、整形到什么程度、缺字段摆不摆，全部归环境层的摆放，这边只把回执印成行：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="321-335" */}

```text
→  content/outputs/readme.mdx  摆放到 ../README.md
→  content/outputs/agents.mdx  摆放到 ../../AGENTS.md
🔴 content/outputs/skills/docfirst.mdx → ../packages/gwb-docfirst-workflow/skills/docfirst/SKILL.md  mdx 源的 frontmatter 里没有 description——补上再 render
```

没挂映射的落 `out/` 当调试产物；格式没有对应的渲染函数就说一声、退 0，不当错：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="336-358" */}

```text
→  docs/a.md  渲染成 out/a.md.ai.md
·  docs/a.html  html 的产物就是文档本身，人和 AI 都读它
```

fumadocs 那份的 `renderAi` 是借站自己的 loader 出的 md，见 [fumadocs 层](/docs/modules/fumadocs)。

### trajectory：列盘、树、主干

这条不遍历文档、不碰记录簿。没配 `trajectory` 目录直接说一声、退 2；`--json` 出整份模型（给别的工具读），不带就按盘打印每棵树的主干，末尾一行汇总支线 / 孤星 / 虫洞数：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="208-229" */}

```text
盘 记事本（2026-01-09-notes）  17 张卡
  主干：2026-02-18-bdd-probe → 2026-03-04-drop-bdd → 2026-05-06-pytest-only
  支线 3 条，孤星 5 张，虫洞 1 个
```

盘是怎么聚出来的、主干凭什么这么挑，归 [轨迹包](/docs/modules/trajectory)。

## 不知道什么

**不知道摆放怎么算。** 一篇 mdx 摆出去的正文该长什么样、跟盘上那份怎么比、四态凭什么这么定、缺了点名的 frontmatter 字段该不该写——一件都不知道。它拿到的是环境层那个摆放对象，对外只有两个方法，`render` 摆一次、`check` 核对一次，回来一张落点清单；这一层的活是把那张清单译成人话和一个退出码。

{/* ref file="../packages/docfirst-workflow/src/host/placement.ts" lines="51-64" */}

**不认识任何格式的记号长什么样。** 认记号、写回记号、渲染，全走判定层定的 `Format` 接口，实现在 fumadocs 那一层；这里只知道「这一篇归哪个格式」，那也是问装配好的项目要的。

{/* ref file="../packages/docfirst-workflow/src/engine/types.ts" lines="119-134" */}

**不自己算状态。** 绿黄白红是 [判定层](/docs/modules/engine) 的服务判的，这边只把状态映成符号和一句中文。

**不知道记忆怎么记、怎么比。** 被引文件怎么读、算哪种记忆、变了之后段落跟到哪儿去了，是环境层的读取器与比较器的事——它连「这个文件在不在 git 里」都不问，只在打印时把记录的 `kind` 是 `hash` 的那几处标出来，好让写手知道自己手上是弱记忆。

**不认识轨迹卡的语义。** 卡的字段、盘怎么聚、主干怎么挑一概不知，只把目录交给轨迹包，把交回来的病和模型打出来。

**不知道六区长什么样。** 给一个新骨架铺六区那件事根本不在这个包里：它只在 agent 手上发生一次、铺的是模板不碰判定，所以归工作台插件的 `docfirst.attach`（[装配六区](/docs/modules/site)）。这一层连模板都没见过。

**不知道站怎么编译。** mdx 变成 md 是 fumadocs 那一层借站自己的 loader 干的；这一层没见过 next、没见过 mdx 编译器。

**这一层认识别的三层，谁都不认识它。** 四层在同一个包里，`engine/` 随手写一句 `import "../host/git.ts"` 编译器不会吭一声，pnpm 那层严格 node_modules 的保护也没有了——目录方向由一份手写的禁止面表守着，它是**唯一**的边界守卫：

{/* ref file="../tests/boundary.test.ts" lines="85-103" */}

<Note>
这张表报红的时候，红的是设计不是测试。真要改方向，改的是表本身加一段说明为什么，不是把断言删掉。
</Note>

## 数据结构

这一层自己定形状的只有一样：`check --json` 那份机读报告。它是**契约**——读它的是别的程序（门禁、编辑器、想列「待重写页与漂移的钉」的 agent），所以加字段可以、改名删字段不可以：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="1-4" */}

整份的形状（谁套谁、哪几个数组、哪些字段有才带）在同一个文件的头上一眼看完：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="6-33" */}

报告里 outputs 那一段是个例外：**形状不是这儿定的**。四态是摆放判出来的，这边直接引环境层导出的那个类型，只借个名字给报告用——把别人的四态在自己的类型里再声明一遍，就是给同一件事留了两份真相：

{/* ref file="../packages/docfirst-workflow/src/cli/report.ts" lines="37-42" */}

记录簿是这些命令产出的东西，形状也不归这一层定——两层键（文档 → `文件:起-止` → 记录），除了 `kind`，字段归记它的那个比较器自己定，一本记录簿里 `git` 和 `hash` 两种并存：

```json
{
  "docs/a.md": {
    "src/greet.ts:2-3": {
      "kind": "git",
      "blob": "51e8ec8849b61cbf6589846f637126cae78e4a0e",
      "commit": "4107961e9d27c8a9d2d0d8f9260495a61406d323",
      "lines": [2, 3],
      "hash": "c60d683fa80ca87e474727647e96b0d2d9354e32c6420587e04c8fc476d3ee0f"
    }
  }
}
```

{/* ref file="../packages/docfirst-workflow/src/host/git-comparator.ts" lines="19-26" */}

**代码内容一个字都不在里面**——`blob` 指着 git 对象库里那份，要旧内容时现取。读写它的是环境层的记录簿实现，这边只经服务用。

## 提供的接口

对外一个函数：`main(argv)`，接收去掉 node 与脚本名之后的参数，返回退出码。

{/* has file="../packages/docfirst-workflow/src/cli/run.ts" text="export async function main" */}

**它自己不 `process.exit`**——退出这件事留在可执行那一头，所以测试能直接调它、当场看退出码和打印，不用起子进程。可执行的那个文件整个就这么点：

{/* ref file="../packages/docfirst-workflow/src/cli/cli.ts" */}

`main` 跟报告类型、`loadProject` 一起从包的主出口出去，给想在别的程序里跑一次核对、不必起子进程的人用。**主出口的读者只有写测试的**，这句话就是它这么窄的理由：

{/* ref file="../packages/docfirst-workflow/src/index.ts" lines="1-18" */}

退出码三档，是契约——门禁靠它拦人：

| 码 | 什么时候 |
| --- | --- |
| 0 | 全绿、全黄、全白都算过——**黄和白不是错**，黄是等作者复核，白是等作者确认；求助（`--help` 一类）也是 0 |
| 1 | 有红：缺失、孤儿记录、名册外组件、摆放的落点不新鲜、**病卡**；`confirm` 里有 problems、`render` 遇到缺 frontmatter 字段的落点也是 1 |
| 2 | 命令名不认识；开关不在那条命令的表里；`confirm` 点名的路径两边都对不上；`trajectory` 没配卡目录 |

所以门禁里可以直接 `pnpm docfirst check`：它只在「引用指向空气」这一类真错上拦人。

## 依赖的接口

进这一层的东西一共就这几个名字，import 表一眼看全：

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `loadProject(cwd)` | 装配：读配置、认格式、给出文档清单与读写 | 环境层 `host/load.ts` | 同一个真实现，跑在临时真 git 项目上 |
| `project.service`（判定层的服务，经装配递来） | `resolve` 出清单、`confirm` 出记录、`strays` / `forget` 清记录簿 | 判定层 `engine/service.ts` | 同上 |

## 怎么单独测

这一层没有假实现可传——它是编排，传入假的就什么都没验到。**假的是「项目」本身**：测试夹具在临时目录里起一个真 git 仓，写几篇文档、一份 `docfirst.config.mjs`，然后直接调 `main`：
