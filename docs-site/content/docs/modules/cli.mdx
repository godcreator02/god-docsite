# 命令行

**本页回答**：`@godcreator02/live-doc-cli` 编排哪几条命令、哪些事**不**归它、`--json` 报告与退出码的契约长什么样、怎么把它单独架起来测。

## 管什么

这个包是**动作的编排层**：把命令行参数翻译成几趟对 project 装配出来的服务的调用，再把结果打成人读的一行行、或机读的一行 JSON。五条命令各是什么，入口文件头上那段说了：

{/* ref file="../packages/cli/src/run.ts" lines="1-15" */}

主干 `check` / `confirm` / `render` 三条是一套：cwd 就是项目根——`livedoc.config.mjs` 在哪儿，
就在哪儿跑——逐篇处理文档目录下被格式包认领的每一篇。`trajectory` 与 `init` 是另一路，在参数
解析的最前面就分流走了。另外随包发三份 skill 与一整套六区站模板，见本段末尾。

### 输出的词汇表

一行一处引用：状态符号、文档、`文件:起-止`、一句话说明。

{/* ref file="../packages/cli/src/run.ts" lines="28-47" */}

`REASON` 里除了 `unlocated`（「有变动」的细分：hash 记忆找不到这段了，位置不明），都是「缺失」的细分——
说清楚是哪一种指向空气，而不是含糊地报一句「代码没了」：行段的整段删光、文件没了、blob 取不回，
目录树的目录没了，存在性的断言不在却出现了、文件和目录换了个，名字的找不到了。`MEMORY` 是 `confirm` 用的：
哪一处拿到的是 hash 记忆（文件不在 git 里），那一行标出来。目录树那行还会带上项数，黄的时候带多了少了哪些：

```text
🟢 docs/handbook.mdx  tree src depth=1  新鲜（4 项）
🟡 docs/handbook.mdx  tree src depth=1  有变动，等作者复核（+ tag.ts）
```

### check：只读，报状态

{/* ref file="../packages/cli/src/run.ts" lines="244-308" */}

```text
🟢 content/docs/formats/wiring.mdx  livedoc.config.mjs:11-21  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/core/src/types.ts:11-16  未确认，等作者确认
🟡 docs/a.md  src/greet.ts:2-3  有变动，等作者复核
🟡 docs/a.md  vendor/lib.ts:2-3  有变动，等作者复核（hash 记忆找不到这段了，位置不明——重读源码、重钉）
🔴 docs/a.md  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

红有四个来源，都算数：**缺失**的引用、**孤儿记录**（记录簿里有、文档里已经没有了）、
**名册外组件**（`livedoc.config.mjs` 里没给它压平规则）、**摆放的生成物跟 mdx 源不一致**——
挂了 `outputs` 映射的文档，`check` 在内存里重渲染跟盘上那份比；mdx 源改了没重摆、有人直接改了生成物，都抓得住：

{/* ref file="../packages/cli/src/run.ts" lines="276-307" */}

```text
🔴 docs/a.md  src/greet.ts:4-5  孤儿记录：文档里已经没有这处引用
🔴 docs/b.mdx  第 7 行 <Callout>  名册外组件，livedoc.config.mjs 里没给它压平规则
```

配了 `trajectory` 目录的项目，`check` 末尾还**顺带**跑一趟轨迹卡校验——病卡一条一行，也算红。
没配就整个不管；配了但目录还不存在扫出来是空集合，不算红：

{/* ref file="../packages/cli/src/run.ts" lines="164-175" */}

```text
🔴 content/trajectory/2026-09-05-foo.mdx  born-at：born-at 格式须 YYYY-MM-DD 或 YYYY-MM-DDTHH:mm（2026-9-5）
```

卡的四层校验各拦什么归 [轨迹包](/docs/modules/trajectory)——这边只负责把病打成行、计进红。

### confirm：出记录、清孤儿、换记号

{/* ref file="../packages/cli/src/run.ts" lines="310-326" */}

顺利的时候一处一行 `✅`，清掉的孤儿一行 `🧹`。文档本身删了、挪了的，它的记录逐篇那圈看不到，`check` 按文档清单一览算红，`confirm` 末尾整个忘掉，也是一行 `🧹`：

```text
✅ docs/a.md  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ docs/a.md  vendor/lib.ts:2-3  已确认，草稿记号已换成正式记号（hash 记忆：不在 git 里）
🧹 docs/a.md  src/greet.ts:4-5  孤儿记录已清
🧹 docs/old.md  文档已不存在，记录已清
```

后面那句会说清楚这一趟到底动没动文档：草稿记号换掉了、文档写回了、还是什么都没改。
末尾的括号说清楚拿到的是哪种记忆——弱记忆得让写手知道，分派规则归 [装配包](/docs/modules/project)。

有一处钉不住就整篇拒，problems 逐条打出来，末尾补一句「这篇整篇没确认」：

```text
🔴 docs/a.md 第 3 行：src/greet.ts:2-3 未提交——钉住只对已提交的内容做，先 commit
·  docs/a.md  这篇整篇没确认——上面几处先处理掉
```

#### 按页限定：`confirm <文档路径…>`

命令名后面跟几个文档路径，就只动点名的那几篇。同一个仓里常有别人钉的黄等着他自己复核，
整仓一趟会替他签字；改了哪几页就确认哪几页，是让「只改这几页」的改动能独立成一个提交的前提。

{/* ref file="../packages/cli/src/run.ts" lines="88-110" */}

路径按项目根算，反斜杠、`./` 开头、绝对路径都收；既不是这个项目的文档、记录簿里也没有的路径
当场退 2——拼错一个路径导致少确认一页，比报错难发现得多。

孤儿清理**分两层，限定模式里去处不同**：一页之内的孤儿（这一页正文里已经没有的引用）照清，
它本来就只看这一页；整仓那层（记录簿里有、项目里已经没有这篇文档了）不能按限定后的清单算——
那份清单是人点名的一小撮，拿它当「现存文档的全集」，没点名的页会被全部当成失踪抹掉。所以
限定模式只清点名了的那几篇。**挪一篇文档就是点两次**：旧路径点一次（忘掉旧记录）、新路径点一次
（按新身份重钉），一趟走完。

```text
·  按页限定：只动 docs/a.md、docs/old.md，别的页与它们的记录不碰
✅ docs/a.md  src/greet.ts:2-3  已确认
🧹 docs/old.md  文档已不存在，记录已清
```

### render：问格式包要产物

{/* ref file="../packages/cli/src/run.ts" lines="328-337" */}

格式包没有对应的渲染函数就说一声、退 0，不当错：

```text
→  docs/a.md  渲染成 ai：out/a.md.ai.md
·  docs/a.html  html 的产物就是文档本身，人和 AI 都读它
```

挂了 `outputs` 映射的文档不落 out/，直接**摆**到映射给的位置（可以出项目根，`../README.md` 这种）。
摆的那份不是管线原样——站上 .md 路由的形态（标题锚记、被保守转义的加粗星号、frontmatter 留下的开头空行）
整理成 README 认的干净 md：

{/* ref file="../packages/cli/src/run.ts" lines="201-213" */}

render 里挂了映射就走这条分支，只写目标：

{/* ref file="../packages/cli/src/run.ts" lines="339-358" */}

```text
→  content/docs/maintain/readme.mdx  摆放到 ../README.md
→  content/docs/maintain/agents.mdx  摆放到 ../../AGENTS.md
```

fumadocs 那份的 `renderAi` 是借它自己的 loader 出的 md，见 [fumadocs 格式包](/docs/modules/format-fumadocs)。
人看的那份就是站本身，所以 `--target human` 在这几个格式包上都没有实现。

### trajectory：列盘、树、主干

这条不认 `--target`、不遍历文档、不碰记录簿，所以在参数解析的最前面就分流走了，不挤进那条命令白名单。
没配 `trajectory` 目录直接说一声、退 2；`--json` 出整份模型（给别的工具吃），不带就按盘打印每棵树的主干，
末尾一行汇总支线 / 孤星 / 虫洞数：

{/* ref file="../packages/cli/src/run.ts" lines="177-198" */}

```text
盘 记事本（2026-01-09-notes）  17 张卡
  主干：2026-02-18-bdd-probe → 2026-03-04-drop-bdd → 2026-05-06-pytest-only
  支线 3 条，孤星 5 张，虫洞 1 个
```

盘是怎么聚出来的、主干凭什么这么挑，归 [轨迹包](/docs/modules/trajectory)。

### init：给一个还没有站的仓铺一个站

这条同样在最前面就分流走了，而且理由更硬：**它连 `livedoc.config.mjs` 都不读**——那正是它
要铺出来的东西。前置条件是「仓已经在、`<仓>/docs-site` 还不在」，跟别的命令「项目已经装配好」
正相反，所以它绝不能走 `loadProject` 那条路。

一趟的次序是：校验 → 认名字 → 挑端口 → **在内存里渲染整套** → 落盘 → 报还缺哪几条 gitignore。
**渲染排在碰盘之前**是刻意的：占位符认不出是最可能的失败，而目录一旦开始写就没有干净的回滚点。

{/* ref file="../packages/cli/src/init.ts" lines="262-302" */}

端口**按脚本内容认，不按目录名认**——站不一定叫 `docs-site`，认的是同级各仓 package.json 里
那个 `next dev -p <口>` / `next start -p <口>`。手给的 `--port` 一律让给你，被占了只警告一声：
占它的那个站早就不跑了这种事，只有人知道。

{/* ref file="../packages/cli/src/init.ts" lines="111-122" */}

起手页的第一条引用是**现找的**：仓根 `src/index.ts` 里有 `export const name` 就钉那一行，
找不到就不钉、改成写一段「第一条引用怎么钉」。硬塞一条钉不住的引用，等于让刚铺好的站开局
就报一条红的；样例记号写在围栏里，围栏内容是 `code` 节点，`check` 认不出它。

{/* ref file="../packages/cli/src/init.ts" lines="140-152" */}

## 不知道什么

**不认识任何格式的记号长什么样。** 认记号、写回记号、渲染，全走 core 定的 `Format` 接口，
实现住三个格式包；这个包只知道「这一篇归哪个格式」，那也是问 project 要的。

**不自己算状态。** 绿黄白红是 core 的服务判的，这边只把状态映成符号和一句中文。

**不自己读盘取被引内容。** 被引文件怎么读、算哪种记忆，是 project 的读取器与比较器的事——
它连「这个文件在不在 git 里」都不问。

**不认识轨迹卡的语义。** 卡的字段、盘怎么聚、主干怎么挑一概不知，只把目录交给 trajectory 包，
把交回来的病和模型打出来。

**不认识 fumadocs、不认识 next、不认识工作台。** 依赖表里只有自家三个包，没有任何渲染框架、
也没有任何 `gwb-*`：件依赖它，它不依赖件。

`./init` 是第二个入口：`initSite` 与那几个纯函数（挑端口、渲染模板、认名字）单独导出，
给想在别的程序里铺站的人用，不必绕命令行：

退出码三档，是契约——门禁靠它拦人：

| 码 | 什么时候 |
| --- | --- |
| 0 | 全绿、全黄、全白都算过——**黄和白不是错**，黄是等作者复核，白是等作者确认 |
| 1 | 有红：缺失、孤儿记录、名册外组件、摆放的生成物跟 mdx 源不一致、**病卡**；`confirm` 里有 problems 也是 1 |
| 2 | 命令名不认识；`trajectory` 子命令没配卡目录。`init` 的失败（仓不在、站已经在、`--port` 不合法）算 1 |

所以门禁里可以直接 `pnpm livedoc check`：它只在「引用指向空气」这一类真错上拦人。

## 怎么单独测

这个包没有假实现可喂——它是编排层，喂假的就什么都没验着。**假的是「项目」本身**：台子在临时目录里
起一个真 git 仓，写几篇文档、一份 `livedoc.config.mjs`，然后直接调 `main`：

{/* ref file="../tests/cli-project.ts" lines="1-9" */}

三处约束是台子的形状定死的：配置按**绝对 `file:` 地址**引格式包的构建产物（临时目录里解析不到包名，
所以跑测试前得先 build）；**不起子进程**，退出码和打印当场看得见；台子要 `process.chdir` 到临时目录，
那是进程全局的，所以**同一个文件里的用例只能串着跑**——命令行这摊按主题拆成三个 `.test.ts`，
`node --test` 每个文件一个进程，文件之间才并发得起来。

三个文件各守一摊。三个动作的主线、五类引用各自的报法、忽略文件退回 hash 记忆、记录簿的两种清扫、

## 代码地图

**在哪**：

{/* tree dir="../packages/cli/src" depth="1" */}

**先读** `run.ts` 的 `main`：五条命令的分流、白名单、装配都在那十几行里，读完就知道剩下的往哪儿分。

**读序**：`cli.ts`（薄壳）→ `run.ts`（全部编排，check / confirm / render 三趟各一个函数）→ 岔出去的三个——
`report.ts` 是机读形状的契约（只有类型和注释，没有逻辑）、`placed.ts` 是摆放产物的整形（纯文本函数，
render 与 check 共用同一份，所以摆出去的和守着的一定一致）、`init.ts` 是自成一路的铺站，它谁都不认识、
也不被上面三条调用。

**可跳过**：`dist/` 是产物；`template/` 是站模板正本（改模板改的是那儿的 `.tpl`，不是这个包的逻辑）；
`skills/` 是随包发的文档正本，同理。
