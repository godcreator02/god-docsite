# 命令行

**本页回答**：`@godcreator02/livedoc` 的 `src/cli/` 编排哪五条命令、哪些事**不**归它、`--json` 报告与退出码的契约长什么样、怎么把它单独架起来测。

## 管什么

这一层是**动作的编排**，做两件事：把命令行参数翻译成几趟对装配出来的项目的调用，再把结果打成人读的一行行、或机读的一行 JSON，最后退一个码。**判定一件都不在这儿算**——它只负责印和退。五条命令各是什么，入口文件头上那段说了：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:1-15 @@

分两路。主干 `check` / `confirm` / `render` 是一套：cwd 就是项目根——`livedoc.config.mjs` 在哪儿就在哪儿跑——先装配，再逐篇处理文档目录下被格式认领的每一篇。`trajectory` 与 `attach` 是另一路，它们不遍历文档，命令名解出来就分流走了，连那条命令白名单和 `loadProject` 都不进；`attach` 那条的理由更硬：**它连 `livedoc.config.mjs` 都不读**，那正是它要写出来的东西。

@@livedoc ref ../packages/livedoc/src/cli/run.ts:48-58 @@

### 输出的词汇表

一行一处引用：状态符号、文档、`文件:起-止`、一句话说明。

@@livedoc ref ../packages/livedoc/src/cli/run.ts:27-46 @@

`REASON` 里除了 `unlocated`（「有变动」的细分：hash 记忆找不到这段了，位置不明），都是「缺失」的细分——说清楚是哪一种指向空气，而不是含糊地报一句「代码没了」：行段的整段删光、文件没了、blob 取不回，目录树的目录没了，存在性的断言不在却出现了、文件和目录换了个，名字的找不到了。`MEMORY` 是 `confirm` 用的：哪一处拿到的是 hash 记忆（文件不在 git 里），那一行标出来。目录树那行还会带上项数，黄的时候带多了少了哪些：

```text
🟢 docs/handbook.mdx  tree src depth=1  新鲜（4 项）
🟡 docs/handbook.mdx  tree src depth=1  有变动，等作者复核（+ tag.ts）
```

### check：只读，报状态

一趟的次序是逐篇核对 → 失踪文档 → 卡校验，先攒成一份报告再决定怎么出：人读模式边算边打，`--json` 攒完整份一行打出去。**两种模式算的是同一份报告**，红的口径不可能对不上。

@@livedoc ref ../packages/livedoc/src/cli/run.ts:130-154 @@

```text
🟢 content/docs/modules/cli.mdx  ../packages/livedoc/src/cli/run.ts:48-58  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/livedoc/src/engine/types.ts:11-16  未确认，等作者确认
🟡 docs/a.md  src/greet.ts:2-3  有变动，等作者复核
🟡 docs/a.md  vendor/lib.ts:2-3  有变动，等作者复核（hash 记忆找不到这段了，位置不明——重读源码、重钉）
🔴 docs/a.md  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

红有四个来源，都算数：**缺失**的引用、**孤儿记录**（记录簿里有、文档里已经没有了）、**名册外组件**（`livedoc.config.mjs` 里没给它压平规则）、**摆放的落点不新鲜**——挂了 `outputs` 映射的文档，落点新鲜不新鲜是问环境层的摆放要来的，一个落点回一个四态加一个 `fresh`，不新鲜的都红：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:228-253 @@

四态各译成一句人话，就是这一层全部的活：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:255-262 @@

```text
🔴 docs/a.md  src/greet.ts:4-5  孤儿记录：文档里已经没有这处引用
🔴 docs/b.mdx  第 7 行 <Callout>  名册外组件，livedoc.config.mjs 里没给它压平规则
🔴 content/outputs/readme.mdx → ../README.md  生成物跟 mdx 源不一致（源改了没重摆，或有人直接改了生成物）——重跑 render
```

配了 `trajectory` 目录的项目，`check` 末尾还**顺带**跑一趟轨迹卡校验——病卡一条一行，也算红。没配就整个不管；配了但目录还不存在扫出来是空集合，不算红：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:156-167 @@

卡的四层校验各拦什么归 [轨迹包](/docs/modules/trajectory)——这边只负责把病打成行、计进红。

### confirm：出记录、清孤儿、换记号

@@livedoc ref ../packages/livedoc/src/cli/run.ts:264-280 @@

顺利的时候一处一行 `✅`，清掉的孤儿一行 `🧹`。文档本身删了、挪了的，它的记录逐篇那圈看不到，`check` 按文档清单一览算红，`confirm` 末尾整个忘掉，也是一行 `🧹`：

```text
✅ docs/a.md  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ docs/a.md  vendor/lib.ts:2-3  已确认，草稿记号已换成正式记号（hash 记忆：不在 git 里）
🧹 docs/a.md  src/greet.ts:4-5  孤儿记录已清
🧹 docs/old.md  文档已不存在，记录已清
```

后面那句会说清楚这一趟到底动没动文档：草稿记号换掉了、文档写回了、还是什么都没改。末尾的括号说清楚拿到的是哪种记忆——弱记忆得让写手知道，分派规则归 [环境层](/docs/modules/host)。

有一处钉不住就整篇拒，problems 逐条打出来，末尾补一句「这篇整篇没确认」：

```text
🔴 docs/a.md 第 3 行：src/greet.ts:2-3 未提交——钉住只对已提交的内容做，先 commit
·  docs/a.md  这篇整篇没确认——上面几处先处理掉
```

#### 按页限定：`confirm <文档路径…>`

命令名后面跟几个文档路径，就只动点名的那几篇。同一个仓里常有别人钉的黄等着他自己复核，整仓一趟会替他签字；改了哪几页就确认哪几页，是让「只改这几页」的改动能独立成一个提交的前提。

@@livedoc ref ../packages/livedoc/src/cli/run.ts:72-108 @@

孤儿清理**分两层，限定模式里去处不同**：一页之内的孤儿（这一页正文里已经没有的引用）照清，它本来就只看这一页；整仓那层（记录簿里有、项目里已经没有这篇文档了）不能按限定后的清单算——那份清单是人点名的一小撮，拿它当「现存文档的全集」，没点名的页会被全部当成失踪抹掉。所以限定模式只清点名了的那几篇。**挪一篇文档就是点两次**：旧路径点一次（忘掉旧记录）、新路径点一次（按新身份重钉），一趟走完。

点名的路径长什么样不归这儿认——反斜杠、`./` 开头、绝对路径怎么归成文档身份，是环境层那一份 `docIdOf`。这边只分三类：还在的页去确认，已经不在、记录簿里还留着的页去清记录，两边都对不上当场退 2——拼错一个路径导致少确认一页，比报错难发现得多。

@@livedoc ref ../packages/livedoc/src/cli/run.ts:110-128 @@

```text
·  按页限定：只动 docs/a.md、docs/old.md，别的页与它们的记录不碰
✅ docs/a.md  src/greet.ts:2-3  已确认
🧹 docs/old.md  文档已不存在，记录已清
```

### render：摆到落点，或问格式要产物

渲染只有一种输出，给 AI 读的那份 md——人看的那份就是文档在站上的样子。挂了 `outputs` 映射的文档不落 `out/`，直接**摆**到映射给的位置（可以出项目根，`../README.md` 这种）；渲成什么、整形到什么程度、缺字段摆不摆，整趟归环境层的摆放，这边只把回执印成行：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:282-296 @@

```text
→  content/outputs/readme.mdx  摆放到 ../README.md
→  content/outputs/agents.mdx  摆放到 ../../AGENTS.md
🔴 content/outputs/skills/live-doc.mdx → ../packages/gwb-live-doc/skills/live-doc/SKILL.md  mdx 源的 frontmatter 里没有 description——补上再 render
```

没挂映射的落 `out/` 当调试产物；格式没有对应的渲染函数就说一声、退 0，不当错：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:297-319 @@

```text
→  docs/a.md  渲染成 out/a.md.ai.md
·  docs/a.html  html 的产物就是文档本身，人和 AI 都读它
```

fumadocs 那份的 `renderAi` 是借站自己的 loader 出的 md，见 [fumadocs 层](/docs/modules/fumadocs)。

### trajectory：列盘、树、主干

这条不遍历文档、不碰记录簿。没配 `trajectory` 目录直接说一声、退 2；`--json` 出整份模型（给别的工具吃），不带就按盘打印每棵树的主干，末尾一行汇总支线 / 孤星 / 虫洞数：

@@livedoc ref ../packages/livedoc/src/cli/run.ts:169-190 @@

```text
盘 记事本（2026-01-09-notes）  17 张卡
  主干：2026-02-18-bdd-probe → 2026-03-04-drop-bdd → 2026-05-06-pytest-only
  支线 3 条，孤星 5 张，虫洞 1 个
```

盘是怎么聚出来的、主干凭什么这么挑，归 [轨迹包](/docs/modules/trajectory)。

### attach：给一个已经铺好的骨架装六区

`livedoc attach --dir <站目录>` 要的前置条件跟别的命令正相反：**站已经在、但还没接过 livedoc**。骨架谁铺不归 livedoc——装了 fumadocs 的人才该有那个能力；工作台里是站件那条 `docs-site.create`，手铺也行。

@@livedoc ref ../packages/livedoc/src/cli/attach.ts:11-20 @@

这一层跟别的四条一样薄：认参数、调 [装配层](/docs/modules/site) 面上的方法、把结果与「接着做什么」打出来。**装配的逻辑一行都不许回流到这儿**——它得能被别的程序直接调，不必绕命令行。

@@livedoc ref ../packages/livedoc/src/cli/attach.ts:1-7 @@

打出来的那几段是有次序的：装在哪、写了哪些文件、让位删了哪些、仓根已有的哪些文件下次 `render` 会被覆盖，最后才是接着跑哪几条命令。**覆盖那一条单独警告**：`outputs` 预置了 `AGENTS.md` / `README.md` 的映射，第一次 `render` 就会把仓里手写的那份摆掉，得先把内容搬进 `content/outputs/` 的 mdx 正本。

@@livedoc ref ../packages/livedoc/src/cli/attach.ts:62-88 @@

## 不知道什么

**不知道摆放怎么算。** 一篇 mdx 摆出去的正文该长什么样、跟盘上那份怎么比、四态凭什么这么定、缺了点名的 frontmatter 字段该不该写——一件都不知道。它拿到的是环境层那个摆放对象，对外只有两个方法，`render` 摆一趟、`check` 核一趟，回来一张落点清单；这一层的活是把那张清单译成人话和一个退出码。

@@livedoc ref ../packages/livedoc/src/host/placement.ts:51-61 @@

**不认识任何格式的记号长什么样。** 认记号、写回记号、渲染，全走判定层定的 `Format` 接口，实现在 fumadocs 那一层；这里只知道「这一篇归哪个格式」，那也是问装配好的项目要的。

@@livedoc ref ../packages/livedoc/src/engine/types.ts:119-134 @@

**不自己算状态。** 绿黄白红是 [判定层](/docs/modules/engine) 的服务判的，这边只把状态映成符号和一句中文。

**不知道记忆怎么记、怎么比。** 被引文件怎么读、算哪种记忆、变了之后段落跟到哪儿去了，是环境层的读取器与比较器的事——它连「这个文件在不在 git 里」都不问，只在打印时把记录的 `kind` 是 `hash` 的那几处标出来，好让写手知道自己手上是弱记忆。

**不认识轨迹卡的语义。** 卡的字段、盘怎么聚、主干怎么挑一概不知，只把目录交给轨迹包，把交回来的病和模型打出来。

**不知道六区长什么样。** `attach` 那条只认两个参数：站目录与显示名。模板怎么渲、名字从哪儿认、`package.json` 怎么合、端口从骨架里怎么读出来，全在装配层。

**不知道站怎么编译。** mdx 变成 md 是 fumadocs 那一层借站自己的 loader 干的；这一层没见过 next、没见过 mdx 编译器。

**这一层认识以上全部四层，谁都不认识它。** 塌成一个包之后，同一个包里 `engine/` 随手写一句 `import "../host/git.ts"` 编译器不会吭一声，pnpm 那层严格 node_modules 的保护也没有了——目录方向由一份手写的禁止面表守着，它是**唯一**的边界守卫：

@@livedoc ref ../tests/boundary.test.ts:86-104 @@

<Note>
这张表报红的时候，红的是设计不是测试。真要改方向，改的是表本身加一段说明为什么，不是把断言删掉。
</Note>

## 数据结构

这一层自己定形状的只有一样：`check --json` 那份机读报告。它是**契约**——`gwb-live-doc` [件](/docs/modules/plugin) 的 `live-doc.stale` 靠它列「待重写页与漂移的钉」：

@@livedoc ref ../packages/livedoc/src/cli/report.ts:1-4 @@

整份的形状（谁套谁、哪几个数组、哪些字段有才带）在同一个文件的头上一眼看完：

@@livedoc ref ../packages/livedoc/src/cli/report.ts:6-33 @@

报告里 outputs 那一段是个例外：**形状不是这儿定的**。四态是摆放判出来的，这边直接引环境层导出的那个类型，只借个名字给报告用——把别人的四态在自己的类型里再声明一遍，就是给同一件事留了两份真相：

@@livedoc ref ../packages/livedoc/src/cli/report.ts:37-42 @@

记录簿是这些命令产出的东西，形状也不归这一层定——两层键（文档 → `文件:起-止` → 记录），除了 `kind`，字段归记它的那个比较器自己定，一本记录簿里 `git` 和 `hash` 两种并存：

```json
{
  "docs/a.md": {
    "src/greet.ts:2-3": {
      "kind": "git",
      "blob": "51e8ec8849b61cbf6589846f637126cae78e4a0e",
      "commit": "4107961e9d27c8a9d2d0d8f9260495a61406d323",
      "lines": [2, 3],
      "hash": "c60d683fa80ca87e474727647e96b0d2d9354e32c6420587e04c8fc476d3ee0f"
    }
  }
}
```

@@livedoc ref ../packages/livedoc/src/host/git-comparator.ts:19-26 @@

**代码内容一个字都不在里面**——`blob` 指着 git 对象库里那份，要旧内容时现取。读写它的是环境层的记录簿实现，这边只经服务用。

## 提供的接口

对外一个函数：`main(argv)`，吃去掉 node 与脚本名之后的参数，回退出码。

@@livedoc has ../packages/livedoc/src/cli/run.ts "export async function main" @@

**它自己不 `process.exit`**——退出这件事留在可执行那一头，所以测试能直接调它、当场看退出码和打印，不用起子进程。可执行的那个文件整个就这么点：

@@livedoc ref ../packages/livedoc/src/cli/cli.ts @@

`main` 与装配层那几个名字一起从包的主出口出去，给想在别的程序里跑一趟核对、或不绕命令行装一次六区的人用：

@@livedoc ref ../packages/livedoc/src/index.ts:1-17 @@

退出码三档，是契约——门禁靠它拦人：

| 码 | 什么时候 |
| --- | --- |
| 0 | 全绿、全黄、全白都算过——**黄和白不是错**，黄是等作者复核，白是等作者确认 |
| 1 | 有红：缺失、孤儿记录、名册外组件、摆放的落点不新鲜、**病卡**；`confirm` 里有 problems、`render` 遇到缺 frontmatter 字段的落点、`attach` 的各种失败（没给 `--dir`、站不在、站里已有内容）也是 1 |
| 2 | 命令名不认识；`confirm` 点名的路径两边都对不上；`trajectory` 没配卡目录 |

所以门禁里可以直接 `pnpm livedoc check`：它只在「引用指向空气」这一类真错上拦人。

## 怎么单独测

这一层没有假实现可喂——它是编排，喂假的就什么都没验着。**假的是「项目」本身**：台子在临时目录里起一个真 git 仓，写几篇文档、一份 `livedoc.config.mjs`，然后直接调 `main`：
