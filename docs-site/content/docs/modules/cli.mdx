# 命令行

**本页回答**：`@godcreator02/live-doc-cli` 编排哪几条命令、哪些事**不**归它、`--json` 报告与退出码的契约长什么样、怎么把它单独架起来测。

## 管什么

这个包是**动作的编排层**，做的是两件事：把命令行参数翻译成几趟对 project 装配出来的服务的调用，再把结果打成人读的一行行、或机读的一行 JSON，最后退一个码。判断一律不在这儿——它只负责印和退。五条命令各是什么，入口文件头上那段说了：

{/* ref file="../packages/cli/src/run.ts" lines="1-15" */}

分两路。主干 `check` / `confirm` / `render` 是一套：cwd 就是项目根——`livedoc.config.mjs` 在哪儿，
就在哪儿跑——先装配，再逐篇处理文档目录下被格式包认领的每一篇。`trajectory` 与 `init` 是另一路，
它们不遍历文档，命令名解出来就分流走了，连那条命令白名单和 `loadProject` 都不进：

{/* ref file="../packages/cli/src/run.ts" lines="48-70" */}

另外随包发几份 skill 与一整套六区站模板，见本段末尾。

### 输出的词汇表

一行一处引用：状态符号、文档、`文件:起-止`、一句话说明。

{/* ref file="../packages/cli/src/run.ts" lines="27-46" */}

`REASON` 里除了 `unlocated`（「有变动」的细分：hash 记忆找不到这段了，位置不明），都是「缺失」的细分——
说清楚是哪一种指向空气，而不是含糊地报一句「代码没了」：行段的整段删光、文件没了、blob 取不回，
目录树的目录没了，存在性的断言不在却出现了、文件和目录换了个，名字的找不到了。`MEMORY` 是 `confirm` 用的：
哪一处拿到的是 hash 记忆（文件不在 git 里），那一行标出来。目录树那行还会带上项数，黄的时候带多了少了哪些：

```text
🟢 docs/handbook.mdx  tree src depth=1  新鲜（4 项）
🟡 docs/handbook.mdx  tree src depth=1  有变动，等作者复核（+ tag.ts）
```

### check：只读，报状态

一趟的次序是逐篇核对 → 失踪文档 → 卡校验，先攒成一份报告再决定怎么出：人读模式边算边打，`--json`
攒完整份一行打出去。两种模式算的是同一份报告，红的口径不可能对不上。

{/* ref file="../packages/cli/src/run.ts" lines="135-154" */}

```text
🟢 content/docs/formats/wiring.mdx  livedoc.config.mjs:11-21  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/core/src/types.ts:11-16  未确认，等作者确认
🟡 docs/a.md  src/greet.ts:2-3  有变动，等作者复核
🟡 docs/a.md  vendor/lib.ts:2-3  有变动，等作者复核（hash 记忆找不到这段了，位置不明——重读源码、重钉）
🔴 docs/a.md  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

红有四个来源，都算数：**缺失**的引用、**孤儿记录**（记录簿里有、文档里已经没有了）、
**名册外组件**（`livedoc.config.mjs` 里没给它压平规则）、**摆放的落点不新鲜**——挂了 `outputs`
映射的文档，落点新鲜不新鲜是问装配包的摆放要来的，一个落点回一个四态加一个 `fresh`，不新鲜的都红：

{/* ref file="../packages/cli/src/run.ts" lines="228-253" */}

四态各译成一句人话，就是这一层全部的活：

{/* ref file="../packages/cli/src/run.ts" lines="255-262" */}

```text
🔴 docs/a.md  src/greet.ts:4-5  孤儿记录：文档里已经没有这处引用
🔴 docs/b.mdx  第 7 行 <Callout>  名册外组件，livedoc.config.mjs 里没给它压平规则
🔴 content/docs/maintain/readme.mdx → ../README.md  生成物跟 mdx 源不一致（源改了没重摆，或有人直接改了生成物）——重跑 render
```

配了 `trajectory` 目录的项目，`check` 末尾还**顺带**跑一趟轨迹卡校验——病卡一条一行，也算红。
没配就整个不管；配了但目录还不存在扫出来是空集合，不算红：

{/* ref file="../packages/cli/src/run.ts" lines="156-167" */}

```text
🔴 content/trajectory/2026-09-05-foo.mdx  born-at：born-at 格式须 YYYY-MM-DD 或 YYYY-MM-DDTHH:mm（2026-9-5）
```

卡的四层校验各拦什么归 [轨迹包](/docs/modules/trajectory)——这边只负责把病打成行、计进红。

### confirm：出记录、清孤儿、换记号

{/* ref file="../packages/cli/src/run.ts" lines="264-280" */}

顺利的时候一处一行 `✅`，清掉的孤儿一行 `🧹`。文档本身删了、挪了的，它的记录逐篇那圈看不到，`check` 按文档清单一览算红，`confirm` 末尾整个忘掉，也是一行 `🧹`：

```text
✅ docs/a.md  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ docs/a.md  vendor/lib.ts:2-3  已确认，草稿记号已换成正式记号（hash 记忆：不在 git 里）
🧹 docs/a.md  src/greet.ts:4-5  孤儿记录已清
🧹 docs/old.md  文档已不存在，记录已清
```

后面那句会说清楚这一趟到底动没动文档：草稿记号换掉了、文档写回了、还是什么都没改。
末尾的括号说清楚拿到的是哪种记忆——弱记忆得让写手知道，分派规则归装配包。

有一处钉不住就整篇拒，problems 逐条打出来，末尾补一句「这篇整篇没确认」：

```text
🔴 docs/a.md 第 3 行：src/greet.ts:2-3 未提交——钉住只对已提交的内容做，先 commit
·  docs/a.md  这篇整篇没确认——上面几处先处理掉
```

#### 按页限定：`confirm <文档路径…>`

命令名后面跟几个文档路径，就只动点名的那几篇。同一个仓里常有别人钉的黄等着他自己复核，
整仓一趟会替他签字；改了哪几页就确认哪几页，是让「只改这几页」的改动能独立成一个提交的前提。

{/* ref file="../packages/cli/src/run.ts" lines="86-108" */}

孤儿清理**分两层，限定模式里去处不同**：一页之内的孤儿（这一页正文里已经没有的引用）照清，
它本来就只看这一页；整仓那层（记录簿里有、项目里已经没有这篇文档了）不能按限定后的清单算——
那份清单是人点名的一小撮，拿它当「现存文档的全集」，没点名的页会被全部当成失踪抹掉。所以
限定模式只清点名了的那几篇。**挪一篇文档就是点两次**：旧路径点一次（忘掉旧记录）、新路径点一次
（按新身份重钉），一趟走完。

点名的路径长什么样不归这儿认——反斜杠、`./` 开头、绝对路径怎么归成文档身份，是装配包那一份
`docIdOf`。这边只分三类：还在的页去确认，已经不在、记录簿里还留着的页去清记录，两边都对不上
当场退 2——拼错一个路径导致少确认一页，比报错难发现得多。

{/* ref file="../packages/cli/src/run.ts" lines="110-128" */}

```text
·  按页限定：只动 docs/a.md、docs/old.md，别的页与它们的记录不碰
✅ docs/a.md  src/greet.ts:2-3  已确认
🧹 docs/old.md  文档已不存在，记录已清
```

### render：摆到落点，或问格式包要产物

渲染只有一种输出，给 AI 读的那份 md——人看的那份就是文档在站上的样子。挂了 `outputs` 映射的文档
不落 `out/`，直接**摆**到映射给的位置（可以出项目根，`../README.md` 这种）；渲成什么、整形到什么
程度、缺字段摆不摆，整趟归装配包的摆放，这边只把回执印成行：

{/* ref file="../packages/cli/src/run.ts" lines="282-296" */}

```text
→  content/docs/maintain/readme.mdx  摆放到 ../README.md
→  content/docs/maintain/agents.mdx  摆放到 ../../AGENTS.md
🔴 content/outputs/skills/live-doc.mdx → ../packages/gwb-live-doc/skills/live-doc/SKILL.md  mdx 源的 frontmatter 里没有 description——补上再 render
```

没挂映射的落 `out/` 当调试产物；格式包没有对应的渲染函数就说一声、退 0，不当错：

{/* ref file="../packages/cli/src/run.ts" lines="297-319" */}

```text
→  docs/a.md  渲染成 out/a.md.ai.md
·  docs/a.html  html 的产物就是文档本身，人和 AI 都读它
```

fumadocs 那份的 `renderAi` 是借它自己的 loader 出的 md，见 [fumadocs 格式包](/docs/modules/format-fumadocs)。

### trajectory：列盘、树、主干

这条不遍历文档、不碰记录簿，所以在装配之前就分流走了。没配 `trajectory` 目录直接说一声、
退 2；`--json` 出整份模型（给别的工具吃），不带就按盘打印每棵树的主干，末尾一行汇总支线 / 孤星 / 虫洞数：

{/* ref file="../packages/cli/src/run.ts" lines="169-190" */}

```text
盘 记事本（2026-01-09-notes）  17 张卡
  主干：2026-02-18-bdd-probe → 2026-03-04-drop-bdd → 2026-05-06-pytest-only
  支线 3 条，孤星 5 张，虫洞 1 个
```

盘是怎么聚出来的、主干凭什么这么挑，归 [轨迹包](/docs/modules/trajectory)。

### init：给一个还没有站的仓铺一个站

这条同样在装配之前就分流走了，而且理由更硬：**它连 `livedoc.config.mjs` 都不读**——那正是它
要铺出来的东西。前置条件是「仓已经在、`<仓>/docs-site` 还不在」，跟别的命令「项目已经装配好」
正相反，所以它绝不能走 `loadProject` 那条路。

**建站在这个包里是一个独立模块 `src/site/`**，跟核心三包零耦合：`init.ts` 只剩命令那一层
（认参数、把结果打成话），铺站的逻辑一行都不在它那儿。这条边是硬的——livedoc 得能在没装
工作台的仓里独立用，所以实现留在命令行这边，[工作台件](/docs/modules/gwb-live-doc) 那条
`live-doc.init` 只是起个子进程调它。模块面上只有两个方法：`planSite` 算一套不碰盘、
`createSite` 算完直接铺。

{/* ref file="../packages/cli/src/site/index.ts" lines="78-114" */}

**算与写分开**是刻意的：占位符认不出是最可能的失败，而目录一旦开始写就没有干净的回滚点。
所以校验、认名字、挑端口、整套渲染都排在碰盘之前，落盘那一步只剩写文件。`planSite` 把这个
中间态直接交出去，于是「先看看会铺出什么、会占哪个口」不必先弄脏一个目录再回滚——它是接口
的一部分，不是实现细节。

端口**按脚本内容认，不按目录名认**——站不一定叫 `docs-site`，认的是同级各仓 package.json 里
那个 `next dev -p <口>` / `next start -p <口>`。手给的 `--port` 一律让给你，被占了只警告一声：
占它的那个站早就不跑了这种事，只有人知道。

{/* ref file="../packages/cli/src/site/ports.ts" lines="54-65" */}

起手页的第一条引用是**现找的**：仓根 `src/index.ts` 里有 `export const name` 就钉那一行，
找不到就不钉、改成写一段「第一条引用怎么钉」。硬塞一条钉不住的引用，等于让刚铺好的站开局
就报一条红的；样例记号写在围栏里，围栏内容是 `code` 节点，`check` 认不出它。

{/* ref file="../packages/cli/src/site/values.ts" lines="37-49" */}

规矩与铺站的模板：

{/* ref file="../packages/cli/package.json" lines="19-23" */}

skill 谁触发谁读，有哪几份由目录树的钉兜着：

模板是一整套六区站（`content/` 六个集合、六条路由、预置的 `livedoc.config.mjs` 与 outputs 映射），

## 不知道什么

**不知道摆放怎么算。** 一篇 mdx 摆出去的正文该长什么样、跟盘上那份怎么比、四态凭什么这么定、
缺了点名的 frontmatter 字段该不该写——一件都不知道。它拿到的是装配包摆放那个对象，对外只有两个
方法，`render` 摆一趟、`check` 核一趟，回来一张落点清单；这个包的活是把那张清单译成人话和一个退出码。

{/* ref file="../packages/project/src/placement.ts" lines="51-61" */}

**不认识任何格式的记号长什么样。** 认记号、写回记号、渲染，全走 core 定的 `Format` 接口，
实现住三个格式包；这个包只知道「这一篇归哪个格式」，那也是问 project 要的。

**不自己算状态。** 绿黄白红是 core 的服务判的，这边只把状态映成符号和一句中文。

**不知道记忆怎么记、怎么比。** 被引文件怎么读、算哪种记忆、变了之后段落跟到哪儿去了，是 project
的读取器与比较器的事——它连「这个文件在不在 git 里」都不问，只在打印时把记录的 `kind` 是 `hash`
的那几处标出来，好让写手知道自己手上是弱记忆。

**不认识轨迹卡的语义。** 卡的字段、盘怎么聚、主干怎么挑一概不知，只把目录交给 trajectory 包，
把交回来的病和模型打出来。

**不知道站怎么编译。** mdx 变成 md 是 fumadocs 格式包借站自己的 loader 干的；这个包没见过 next、
没见过 mdx 编译器，依赖表里只有自家三个包，也没有任何 `gwb-*`：件依赖它，它不依赖件。

{/* ref file="../packages/cli/package.json" lines="29-33" */}

## 数据结构

这个包自己定形状的只有一样：`check --json` 那份机读报告。它是**契约**——`gwb-live-doc` 件的
`live-doc.stale` 靠它列「待重写页与漂移的钉」：

{/* ref file="../packages/cli/src/report.ts" lines="1-4" */}

整份的形状（谁套谁、哪几个数组、哪些字段有才带）在同一个文件的头上一眼看完：

{/* ref file="../packages/cli/src/report.ts" lines="6-33" */}

报告里 outputs 那一段是个例外：**形状不是这儿定的**。四态是摆放判出来的，这边直接引装配包导出的
那个类型，只借个名字给报告用——把别人的四态在自己的类型里再声明一遍，就是给同一件事留了两份真相：

{/* ref file="../packages/cli/src/report.ts" lines="37-42" */}

记录簿是这些命令产出的东西，形状也不归这个包定——两层键（文档 → `文件:起-止` → 记录），
除了 `kind`，字段归记它的那个比较器自己定，一本记录簿里 `git` 和 `hash` 两种并存：

```json
{
  "docs/a.md": {
    "src/greet.ts:2-3": {
      "kind": "git",
      "blob": "51e8ec8849b61cbf6589846f637126cae78e4a0e",
      "commit": "4107961e9d27c8a9d2d0d8f9260495a61406d323",
      "lines": [2, 3],
      "hash": "c60d683fa80ca87e474727647e96b0d2d9354e32c6420587e04c8fc476d3ee0f"
    }
  }
}
```

{/* ref file="../packages/project/src/git-comparator.ts" lines="19-26" */}

**代码内容一个字都不在里面**——`blob` 指着 git 对象库里那份，要旧内容时现取。读写它的是
[装配包](/docs/modules/project) 的记录簿实现，命令这边只经服务用：

## 提供的接口

对外一个函数：`main(argv)`，吃去掉 node 与脚本名之后的参数，回退出码。

{/* has file="../packages/cli/src/run.ts" text="export async function main" */}

**它自己不 `process.exit`**——退出这件事留在可执行那一头，所以测试能直接调它、当场看退出码和打印，
不用起子进程。可执行的那个文件整个就这么点：

{/* ref file="../packages/cli/src/cli.ts" */}

`./site` 是第二个入口：建站模块的两个方法 `planSite` / `createSite` 从这儿出去，给想在别的
程序里铺站的人用，不必绕命令行。模板放在哪、占位符叫什么、端口怎么挑一概不在面上：

{/* ref file="../packages/cli/package.json" lines="9-18" */}

退出码三档，是契约——门禁靠它拦人：

| 码 | 什么时候 |
| --- | --- |
| 0 | 全绿、全黄、全白都算过——**黄和白不是错**，黄是等作者复核，白是等作者确认 |
| 1 | 有红：缺失、孤儿记录、名册外组件、摆放的落点不新鲜、**病卡**；`confirm` 里有 problems、`render` 遇到缺 frontmatter 字段的落点也是 1 |
| 2 | 命令名不认识；`confirm` 点名的路径两边都对不上；`trajectory` 子命令没配卡目录。`init` 的失败（仓不在、站已经在、`--port` 不合法）算 1 |

所以门禁里可以直接 `pnpm livedoc check`：它只在「引用指向空气」这一类真错上拦人。

## 依赖的接口

进这个包的东西一共就这几个名字，import 表一眼看全：

{/* ref file="../packages/cli/src/run.ts" lines="16-23" */}

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `loadProject(cwd)` | 装配：读配置、认格式、给出文档清单与读写 | `live-doc-project` | 同一个真实现，跑在临时真 git 项目上 |
| `project.service`（core 的服务，经 project 递来） | `resolve` 出清单、`confirm` 出记录、`strays` / `forget` 清记录簿 | `live-doc-core` | 同上 |

## 代码地图

**在哪**：

{/* tree dir="../packages/cli/src" depth="1" */}

**先读** `run.ts` 的 `main`：五条命令的分流、白名单、装配都在那二十行里，读完就知道剩下的往哪儿分。

**读序**：`cli.ts`（薄壳）→ `run.ts`（全部编排，check / confirm / render 三趟各一个函数，
外加打印用的那几张词表）→ `report.ts`（机读形状的契约，只有类型和注释，没有逻辑）。三个文件读完，
命令这条线就完整了。

**`src/site/` 是独立的一块**：整套铺站，跟核心三包零耦合——不读配置、不装配、不认识记号，
上面那三条也从不调它，只有 `main` 里那一句分流经 `init.ts` 碰得到它。读命令那条线的时候整个
跳过；要动的是站模板与铺站流程时才进去，那时先读它的 `index.ts`（两个方法与那份计划的形状），
再按需下到 `template.ts`（读模板、渲染）、`ports.ts`（扫口挑口）、`values.ts`（名字与起手页钉块）、
`repo.ts`（目标仓的事实与落盘）四份内部件——它们互不认识，只被 `index.ts` 串起来。

**可跳过**：`dist/` 是产物；`template/` 是站模板正本（改模板改的是那儿的 `.tpl`，不是这个包的逻辑）；
`skills/` 是随包发的文档正本，同理。
