## 功能

两件事：**卡**（轨迹卡的格式、解析、校验）与**盘**（把一批卡分盘建模、布局、画成星轨盘）。卡有哪些字段、
怎么校验、怎么分盘、半径和角度怎么排，见[轨迹](/docs/trajectory)。

卡的身份是文件名去掉 `.mdx` / `.md` 后缀的部分，同一身份两种后缀都在时只认 `.mdx`：

## 不做的事

**不读盘，不认识别的包。** `.` 入口的产物一条 import 都没有，连 `node:` 也没有；`.ts` 源码只有相对 import。
所以浏览器、服务端、命令行都能直接用：

{/* ref file="../tests/boundary.test.ts" lines="180-193" hash="c35ca7bc8225" blob="e450056cc091" */}

它不依赖钉码核心、workflow、fumadocs 适配，反过来 workflow 与 fumadocs 适配依赖它：

{/* ref file="../tests/boundary.test.ts" lines="121-135" hash="6240de2040d1" blob="e450056cc091" */}

**不把 react 打进产物。** `./disk` 的产物第一行是 `"use client"`，只许 import react：

{/* ref file="../tests/boundary.test.ts" lines="195-207" hash="321c5491dda8" blob="e450056cc091" */}

**不认识钉码记号。** 卡里不许钉码这条由 workflow 读卡目录时另查，病并进同一份清单；这个包只在问题类型里留着这个字段名：

{/* ref file="../packages/docfirst-trajectory/src/types.ts" lines="94-98" hash="55cdacf410b9" blob="b20fdb03c00f" */}

**不管 fumadocs 集合与服务端组件。** 卡集合的 schema、正文链接改写、读卡目录的服务端组件都在 [fumadocs 适配](/docs/modules/fumadocs)。

**不认识站的路由。** 当前是哪张盘只看 `initialDisk` 与地址栏的 `?disk=`；顶栏不归组件画。

**不提供写卡工具，不支持同时打开多张盘。** 卡手写，写完用 `docfirst check` 校验；换盘只经过启动器和虫洞。
