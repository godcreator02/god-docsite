# 核心包

**本页回答**：`@godcreator02/live-doc-core` 管哪几件事、它凭什么敢说自己不认识磁盘和文档格式、外面要换一种格式或一种记忆时照着哪个接口写。

## 管什么

四摊。**接口正本**——五种目标、引用、记录、清单、状态，加格式包、读取器、记录簿、比较器四个接口，全在 `types.ts` 里定死，别的包只认这一份。**编排服务**——核对出清单、确认写记录簿、文档删了挪了之后一览与遗忘。**记号两态**——草稿记号的写法和正式记号的载荷都是核心定的，各格式包只管自己的外壳。**判定的默认实现**——hash 比较器，加目录树、存在性、名字三种目标各自的比较器，以及它们共用的归一化、哈希、hunk 解析与行段映射。

## 不知道什么

**不碰磁盘。** 每种目标要看的东西（观察）由读取器递进来：行段、整文件、名字看文件的行，目录树看名字表，存在性看类型。`Reader` 这个接口就是为这条立的——核心从不自己去读一个路径，也就无所谓工作区、提交、软链。

**不起子进程，也不知道 git 存在。** 源码里的 import 只许指向自己和 `node:crypto`，一条测试正着守着：

**不认识任何文档格式。** 一篇文档是谁认领的、记号长什么样、写回时怎么改那一行，都归格式包。核心只拿到「一串引用」和「一段文本」。

**不知道摆放。** 渲染在格式包接口上是可选的一项，出的是一份正文：

**不看记录的 kind。** 取记录时原样递给比较器，认不认是比较器自己的事——核心不翻译、不猜。

**不知道项目根、配置文件、命令行、站。** 装配是 [装配包](/docs/modules/project) 的活；核心只吃已经造好的四样零件。这条约束还有一个具体形状：格式包自留的私货核心原样带回、从不读它。

## 数据结构

**目标五种**（行段、整文件、目录树、存在性、名字），**引用**是文档里的一处声明，**记录**是确认时记下的指纹，**状态**四种。这几样的形状就是全部对外契约：

{/* ref file="../packages/core/src/types.ts" lines="48-66" */}

**引用的身份 = 文档 + 引用写的目标。** 同一篇里指向同一段的两处引用共用一条记录；记录簿的键就是目标的文本形态，跟目标之间来回可逆：

{/* ref file="../packages/core/src/types.ts" lines="312-330" */}

**记录带 kind，字段归那个比较器自己定。** 比较器看到别家的 kind 就交回「未确认」，不把一种记忆的记录翻译成另一种：

{/* ref file="../packages/core/src/hash-comparator.ts" lines="65-75" */}

所以配置里把记忆强制成某一种，原来别家记的记录一律退回未确认，等人重新确认。

**四种状态**，颜色跟着状态走：

<Tabs>
  <Tab title="🟢 新鲜">
    观察跟记忆里那份一样。行段挪了位置但内容没变也是绿的——跟到哪儿由比较器说，`Item.lines` 交回的是今天的位置。
  </Tab>
  <Tab title="🟡 有变动">
    内容变了，等作者复核，不退非零。给不给得出 `- / +` 的 diff、给不给得出旧内容，看比较器手上有没有旧的那一份。
  </Tab>
  <Tab title="⚪ 未确认">
    还没确认过：新写的引用，或者记录是别家比较器记的。跟「改过了」是两回事。
  </Tab>
  <Tab title="🔴 缺失">
    引用指向空气：整段没了、文件没了、目录没了、断言不在却出现了、名字找不到了。细分理由写在 `Item.reason` 里。
  </Tab>
</Tabs>

**归一化只做三件事**：换行统一成 LF、去每行行尾空白、去掉末尾空行。缩进和注释保留——JSDoc 是契约的一部分，改了就该黄。规矩一条，展示前做的归一化就是哈希前做的：

## 提供的接口

**编排服务**是唯一算状态的地方。命令行逐篇喂文本，站构建喂已经认好的引用，走的是同一条路：

{/* ref file="../packages/core/src/service.ts" lines="20-39" */}

**确认是全篇原子的**：有一处钉不住就整篇拒——记录簿一条不写、文档一个字不改，problems 原样交给上层打印。

{/* ref file="../packages/core/src/service.ts" lines="133-137" */}

不是「能钉的先钉上」：半本记录簿比没有更难查。确认还顺手做两件事——行段按今天的位置记（判定跟到哪儿就钉到哪儿），旧键与文档里已经没有的引用一并当孤儿清掉。

**草稿记号是核心定的**，三种格式一个写法。整行匹配，头尾的 `@@` 是哨兵，少一头就是普通文字、不报错；动作词五个，载荷交给校验函数，行号不合理、depth 不是正整数都报到行：

{/* ref file="../packages/core/src/types.ts" lines="270-282" */}

**正式记号分两截。** 载荷是核心出的，三种格式共用，认回来也走核心：

{/* ref file="../packages/core/src/types.ts" lines="220-224" */}

外壳归格式包：`marker(target)` 出一行，`parse(marker(t))` 必须认回 `t`——「怎么写」和「怎么认」住同一个包。各格式包的外壳长什么样见 [md 格式包](/docs/modules/format-md)、[fumadocs 格式包](/docs/modules/format-fumadocs)、[html 格式包](/docs/modules/format-html)。五类引用各该说哪种话，见 [五类引用手册](/docs/start/handbook)。

**核心自带的比较器**管两摊。行段和整文件那摊是 hash 版：只记段哈希和旧行号，不问 git，也没有旧内容。行段靠滑窗跟——先看旧位置，不对就按段长在整个文件里逐行滑一遍找同哈希的窗口；撞车取离旧位置最近的一处，两处一样近就不猜；找不到就是「有变动、位置不明」，给不出 diff，行号停在旧位置。

{/* ref file="../packages/core/src/hash-comparator.ts" lines="65-86" */}

另一摊是按目标种类分派：行段和整文件交给外面给的那个（[装配包](/docs/modules/project) 的 auto、git，或核心的 hash），目录树、存在性、名字各走核心自己的一个。

{/* ref file="../packages/core/src/kinds.ts" lines="115-126" */}

这三种的记忆各不相同：目录树记名字表本身（几十个名字不是代码，不这么存就说不出多了哪个少了哪个，是「不存第二份内容」的唯一例外），存在性记类型，名字只记「在」。后两种没有黄，要么绿要么红；目录树也不设提交门——新建还没提交的文件正该报黄。

{/* ref file="../packages/core/src/kinds.ts" lines="1-8" */}

## 怎么单独测

核心的账在 `tests/core.test.ts`，喂三样假的：**假格式包**（记号是一行 `REF <记录簿键>`，草稿记号仍交给核心认）、**内存读取器**（一张文件表就是全部世界）、**内存记录簿**。核心不读盘、不认识任何真格式，这么测正好把这两条也守住。

{/* ref file="../tests/fake-format.ts" */}

证明的是这几件：四种状态的完整来回（未确认 → 新鲜 → 有变动 → 缺失）；一篇文档两个格式包都认领时报错而不是靠顺序静默定胜负；同一段被引两处只写一条记录；文档里删掉引用报孤儿、再确认一次清掉；文档整个删了或挪了走 strays / forget；一处钉不住整篇拒；草稿记号的哨兵与五种写法；别家 kind 的记录当没确认过；目录树、存在性、名字三种各自的黄红语义；hash 滑窗的挪位、撞车取近、并列不猜、找不到时位置不明；归一化与行段切片。

记号那条契约跨包，由三个格式包一起过的 `tests/marker.test.ts` 守着——`parse(marker(t))` 必须认回 `t`：

{/* ref file="../tests/marker.test.ts" lines="30-39" */}

「认得出」只是一半，「什么时候不认」才是这套写法敢往正文里塞的理由：哨兵不齐的、写在句子中间的、写在围栏里的、写在 `script` 与 `style` 里或转义过的，一律不认。

{/* ref file="../tests/marker.test.ts" lines="46-60" */}

还有一条从外面守核心的：三个格式包在同一串改动下状态必须一致——状态是核心算的，格式包只交引用，不一致就是有人抄了近道。

{/* ref file="../tests/contract.test.ts" lines="1-5" */}
