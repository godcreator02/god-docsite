这个仓是一个 pnpm 工作区，住着三族能力与一个部署侧：**地基**（文档站基础包与它的插件、自述站骨架）、**docfirst**（把文档里对代码说的话钉在源码上的工作流）、**协作站**（课题组协作的站点、数据模型与插件）、**Gitea 与 NAS**（协作站那侧要配的东西）。本页是全仓的体系地图：每个包、每个插件的每个功能在这里都有一两句，细节在各分区。

| 分区 | 讲什么 |
| --- | --- |
| [docsite](/docsite) | 地基：能力包怎么用、功能包约定、gwb-docsite 插件与一步建站 |
| [docfirst](/docfirst) | docfirst：钉码、核对与确认、轨迹卡、命令行、它的功能包与插件 |
| [collab](/collab) | 协作站：三包与 gwb-collab 插件、怎么用、系统组成 |
| [gitea](/gitea) | Gitea 与 NAS 上配的东西：权限、实时推送、执行器 |
| [原理](/docs/principles) | 设计原则、开发方案、[fumadocs 原理](/docs/fumadocs) |
| [维护者手册](/maintain) | 改这个仓要知道的：布局、检查、提交与发布 |

## 地基：文档站基础包

组合包 `@godcreator/docsite-kit` 只做接线（vite 插件 `./vite`、功能包约定的类型 `./feature`、路由表换算 `./routes`、`@site` 别名的类型声明 `./site-modules`），站点功能全部在各能力包里：

| 能力包 | 管什么 |
| --- | --- |
| `docsite-identity` | 人员与身份：`people.json` 的读取与校验、身份码认人、写入请求核对、@ 提及、头像组件 |
| `docsite-comments` | 评论：评论串模型与文件读写、页面旁的评论界面（CommentsDock）、正文外批注覆盖层、划字锚点找回 |
| `docsite-page-sources` | 页面来源：TSX/HTML 页面进同一棵页面树与搜索、中文搜索服务、`content/` 资产的读取与快照 |
| `docsite-ui` | UI 外壳：侧栏分组、侧栏入口横排、站内链接卡片、全宽切换、主题切换与身份标识、中文界面文字 |
| `docsite-writing` | 写作组件：术语 `Term` 与标注插件、TSX 页面里的公式 `Tex` |
| `docsite-feed` | 推送通道：协议、进程内存储、开发服务收发端点、浏览器 hook `useSiteFeed` |
| `docsite-explainer` | 讲解组件：分步/动画/选情况三种外壳、画帧零件、接缝图（seam-graph） |
| `docsite-docfirst` | docfirst 接到地基上的功能包（见 docfirst 分区） |

`site/` 是地基的**骨架正本**：`app/` 与根目录配置手写在那里，建站模板从它派生；[原理](/docs/principles)与[fumadocs](/docs/fumadocs)的讲解也在本站。用地基搭的站有：本站（docfirst 文档站）、地基自述站、协作站各项目的站点、论文阅读站。

### 插件 gwb-docsite

能力包的组合层与契约持有者，用基础包搭的站都由它托管：

- 本 home 的**身份码**（`docsite.identity`）：站点按它在 `people.json` 里认人，认不出只读
- **一步建站**（`docsite.site.init`）：从空目录拉功能包模板、内存组装、一次写盘、一次装依赖、探活
- **托管站点**（`docsite.site.add` / `start` / `stop` / `list`）：登记进设置、工作台启动时逐个拉起，崩溃标 failed 不静默重启
- **加入人员**（`docsite.people.join`）：把本 home 的码加进站点的人员列表
- **读写评论**（`docsite.comments` / `comment.create` / `comment.reply`）：agent 不开浏览器写评论，与网页同一套规则
- **推送通道**（服务 `gwbDocsite.push`）：别的插件往站点按频道推数据（协作站的通知走它）
- 服务面 `gwbDocsite` 给别的插件注入：建站 `init`、站点启停与状态、身份码、推送、加入人员

## docfirst 文档工作流

把文档里对代码说的话**钉在源码上**：文档说「我引的是这个文件的第几行」「这个目录下有这几个文件」，工具替你检查这些话还成不成立——变了报黄等作者复核，引用的东西没了报红。页面上那块内容是构建时现从源码读的，文档里不存副本。另一部分是**轨迹卡**：一次方向上的决定记下来就不再改，防止历史被改写。

| 包 | 管什么 |
| --- | --- |
| `code-pin` | 钉码核心：目标、记录、判定，只对文件工作，谁都能单独使用 |
| `trajectory-disk` | 星轨盘：把轨迹卡画成项目方向演变的圆盘 |
| `docfirst-workflow` | docfirst 本身：命令行（check / confirm / render）、项目装配、mdx 与讲解组件源码两种格式；子入口 `./fumadocs` 是 remark 插件与名册 |
| `docsite-docfirst` | 地基的功能包：remark 插件（术语标注、钉码投影、卡链接改写）、`Term` 与文件树组件、星轨盘与卡页两条路由 |
| `docfirst-explainer` | 讲解组件薄壳（冻结，转发 `docsite-explainer`） |

### 插件 gwb-docfirst-workflow

- **建站**（`docfirst.create`）：认站名、选端口，把 `docsite-docfirst` 交给 `gwbDocsite.init` 一步建好接了现状、轨迹、未来三个区的站
- **三份说明书**随插件注册给 agent：`docs-writing`（文档怎么写）、`docs-site`（核对、确认、生成、构建）、`trajectory`（轨迹卡怎么记）

## 协作站

课题组协作的整套系统：一个项目是 Gitea 上的一个私有组织，组织里**协作仓**（`site/` 是项目站点、`collab/` 是任务与模块记录）与**别的仓**各走一套操作；每个成员在自己电脑上打开同一个网站，改动经 git 与 Gitea 同步，合并由 NAS 上的执行器做，没有站点服务器。

| 包 | 管什么 |
| --- | --- |
| `collab-model` | 数据模型：项目仓布局、任务与模块的文件格式与写入规则、待办筛选、通知与推给网站的数据 |
| `collab-site` | 功能包：接在基础包上的任务页（人员、模块甘特图、看板）、任务与模块各自那一页、日历与日志页、通知栏、站点检查 |
| `collab-merge-check` | 合并检查：合并请求有没有冲突、有没有改只有负责人能改的内容；命令行给执行器跑 |

### 插件 gwb-collab

装在每个成员的工作台里，两套仓各自交出此刻的状态、写成一条条通知交给四处（网站提示栏、协作窗格、QQ 私聊、交给 AI 的提示词）：

- **协作仓那一套**：提交审核（`collab.submit` 推成合并请求、盯到执行器合并或打回）、取回 main 与自动同步、本机状态监视、读项目负责人、规矩核对（`collab.repo.setup` 配分支保护）
- **别的仓那一套**：取回与快进（`collab.repos.update`）、读合并请求与 issue 筛出「等我处理的」、各仓规矩核对
- **组织级**：收 ntfy 位置消息按仓分派、完整刷新（`collab.check`）、组织 webhook 配置（`collab.org.setup`）、建仓（`collab.repo.create`）
- **项目与人员**：打开（`collab.project.open`）、克隆、加入（把自己的码写进人员列表）、加减项目、设 QQ 命令（起了命令的项目注册成 QQ 任务组）
- **记录与待办**：任务与模块的建改删、我的待办（`collab.inbox`）
- **通知**：19 种 `kind` 分协作仓、别的仓、找我的三组；QQ 私聊按通知 `id` 只发新出现的；「交给 AI」经可替换接口交给 ZCode 或新开 Claude Code 终端
- **站点**：交给 gwb-docsite 初始化、托管、推数据（`collab.site.init`）

## Gitea 与 NAS

协作站的远端侧：Gitea（存全部仓、npm 源）、执行器 `gitea-runner`（只管协作仓的合并请求）、ntfy（把组织 webhook 转成实时推送）。要配什么、哪条命令配，见 [gitea 分区](/gitea)。

## 怎么跑这个仓

工作区一套 `pnpm install`、`pnpm build`、`pnpm check` 全覆盖；两个站的开发服务交给 gwb-docsite 托管。改这个仓的完整规矩在[维护者手册](/maintain)。
