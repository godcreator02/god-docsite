# 现状

**本页回答**：`god-live-doc` 是什么、这一区只写什么、从哪一页开始读。

这套机制把文档里对代码说的话钉在真实源码上：文档只写「我引的是哪个文件哪几行」「这个目录下有哪些
东西」「这个名字还在」，内容在构建那一刻现拿。代码变了，页面上那处的状态点变色，作者确认过才回绿。
**文档里不存代码的副本**，记忆只有一条指纹。

这一区只写**现状**：设计、原理、边界、接口。为什么变成这样去 [星轨盘](/trajectory)，往哪儿去看
[未来](/future/overview)，正在做的活在 [交接](/spec)。判据一句话：一句话如果能被代码推翻，
它就该带引用；一句话如果只是在复述代码，它就不该存在。

## 从哪读

四样东西撑起交接面，读序就这一条线：

1. [系统地图](/docs/system-map)：这套东西分成哪四类角色、各住哪、谁依赖谁、先读哪块。
2. [入门](/docs/start)：它解决什么问题、一分钟接起来、五类引用怎么挑、一条引用的一生、
   怎么接进自己的 fumadocs 站。
3. [模块](/docs/modules/engine)：一模块一页，七个固定块——管什么 / 不知道什么 / 数据结构 /
   提供的接口 / 依赖的接口 / 怎么单独测 / 代码地图。接口与边界逐条钉住。
4. [术语表](/docs/glossary)：这个仓里的词各指什么。

轨迹按需查。交接面上的钉码在、`docfirst check` 绿，交接面就没有说谎。

## 这个站自己就是消费方

站装的是工作区里的这两个包，钉的是工作区里的真源码——「装了这几个包的项目长什么样」在这儿是活的，
所以仓里不另留示例。文档怎么写（读者是谁、六区怎么分、每页写到哪为止）由随
`@team/docfirst-workflow` 发的 skill「docfirst-docs」说了算；人写的那份总规范是
[文档规范](/docs/human-write-spec-dont-change)，agent 不改它，只在别处提建议。
