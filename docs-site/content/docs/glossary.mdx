# 术语表

**本页回答**：这个仓里反复出现的词各指什么、每个词的正本在哪、想加一个词该改哪儿。

## 四个基本词

这四个是接口正本上的名字，代码里就是这么写的：

{/* ref file="../packages/core/src/types.ts" lines="1-10" */}

目标（target）是「文档指着的那样东西」，引用（reference）是「文档里的一处指」，记录（record）是
「确认那一刻留下的指纹」，清单（listing）是「一篇文档核对完的结果」。四个词在代码、命令行输出、
这个站上是同一套。

## 站上自动标出来的那些词

正文里命中术语表的词，站构建时自动包一层标注，鼠标移上去显示定义——源文件里干净，没有手写的标签。
这张表的正本是一份数据文件，一条 `term` / `aliases` / `def` / `href`：

{/* has file="src/glossary.ts" text="export const terms" */}

收词的判据与「定义里不许写什么」写在数据文件的头注释里，改词之前先读它：

{/* ref file="src/glossary.ts" lines="1-12" */}

**定义只写概念，不写服务名、类型名、路径**——这份数据钉不住（它不是 mdx，引用管不到它），
写进去的具体名字会悄悄腐化。具体名字留给 `href` 指的那一页，在那儿钉码。

作者手写 `<Term>` 也行，但要在名册里有一条，机读版里只留术语原词、装饰不带过去。
机制那一半见 [fumadocs 格式包](/docs/modules/format-fumadocs)。

## 只在这个站里出现的几个词

这几个词不进自动标注（太短或太常见会误伤），但读文档时得知道：

| 词 | 意思 |
| --- | --- |
| 草稿记号 | 作者手写的那一行，三种格式一个写法：`@@livedoc ref 文件:起-止 @@` |
| 正式记号 | 确认时格式包换上的形态，各格式各长各的 |
| 投影 | 引用在页面上摆出来的那块内容——构建时现拿，不是抄进文档的副本 |
| 孤儿记录 | 记录簿里有、文档里已经没有这处引用了 |
| 摆放 | `outputs` 挂了映射的文档，render 直接写到目标路径，不落 `out/` |
| 六区 | 现状 / 轨迹 / 交接 / 未来 / 生成正本 / 反馈，六种生命周期各一个目录 |
