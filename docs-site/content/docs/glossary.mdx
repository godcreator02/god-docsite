## 基本词

下面几个是钉码核心接口正本上的名字，代码里就是这么写的：

{/* ref file="../packages/code-pin/src/types.ts" lines="1-12" hash="3f45a209cece" blob="32a0167e8d8f" */}

目标（target）是「文档指着的那样东西」，记录（record）是「确认那一刻算出、写在正式记号上的 hash 与 blob 名这类属性」，
钉（pin）是目标加记录，判定（verdict）是「一处钉核对完的结果」，状态（status）是判定里的结论。带上文档位置之后是 workflow 的两个词：
引用（reference）是「文档里指向目标的一处」，清单（listing）是「一个文件核对完的结果」；格式（format）是「认领一类文件、在里面认记号与写回的那一份实现」，
有 mdx 页面与讲解组件的源码两种。这些词在代码、命令行输出、这个站上是同一套。

## 站上自动标出来的那些词

正文里命中术语表的词，站构建页面时自动加一层标注，鼠标移上去显示定义——源文件里干净，没有手写的标签。

收词的判据与「定义里不许写什么」写在数据文件的头注释里，改词之前先读它：

{/* ref file="src/glossary.mjs" lines="1-12" hash="db3dfcd39133" blob="a704d7eb53c9" */}

**定义只写概念，不写服务名、类型名、路径**——这份数据钉不住（它既不是 mdx 页面，也不在讲解组件的 `src/components/` 下，引用管不到它），
写进去的具体名字会悄悄过时。具体名字留给 `href` 指的那一页，在那儿钉码。

作者手写 `<Term>` 也行：`Term` 由功能包提供，页面里不用 import；名册里它的规则是只留子内容，生成物里只剩术语原词、样式不带过去。
机制那一半见 [workflow 的 mdx 格式](/docs/workflow) 的名册与 [fumadocs 适配](/docs/fumadocs) 的术语标注。

## 只在这个站里出现的几个词

这几个词不进自动标注（太短或太常见会误标），但读文档时得知道：

| 词 | 意思 |
| --- | --- |
| 正式记号 | 引用写在文档里的那一行注释：作者只写目标属性（mdx 页面里是 `{/* ref file="…" lines="起-止" */}`，讲解组件的源码里去掉花括号），确认时在同一行添上记录属性（段哈希、blob 名这类） |
| 投影 | 引用在页面上显示出来的那块内容——构建时现从源码读，不是抄进文档的副本 |
| 摆放 | 把 `outputs` 里有映射的生成正本渲染后写到映射指定的落点 |
| 通用包 | 不认识 docfirst、谁都能单独使用的包：钉码核心 `code-pin`、星轨盘 `trajectory-disk`。docfirst 只是它们的一个使用者；docfirst 自己的包是 `docfirst-workflow` 与讲解组件包 `docfirst-explainer`。边界测试里的名单是 `GENERIC_PACKAGES` |
| 自成一体的包 | 不依赖本仓任何别的包、各自单独安装与升版的包：两个通用包加上 `docfirst-explainer`。边界测试里的名单是 `SELF_CONTAINED_PACKAGES` |
| 讲解组件包 | `docfirst-explainer`：docfirst 站上用的讲解组件，给分步、动画、选情况三种外壳、画帧用的零件与接缝图；只有站用 |
