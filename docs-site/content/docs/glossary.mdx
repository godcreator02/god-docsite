## 基本词

下面几个是钉码核心接口正本上的名字，代码里就是这么写的：

{/* ref file="../packages/docfirst-pin/src/types.ts" lines="1-12" hash="d8d2bce5db34" blob="f7ca47b13c53" */}

目标（target）是「文档指着的那样东西」，记录（record）是「确认那一刻算出、写在正式记号上的 hash 与 blob 名这类属性」，
钉（pin）是目标加记录，判定（verdict）是「一处钉核对完的结果」，状态（status）是判定里的结论。带上文档位置之后是 workflow 的两个词：
引用（reference）是「文档里的一处指」，清单（listing）是「一篇文档核对完的结果」。这些词在代码、命令行输出、这个站上是同一套。

## 站上自动标出来的那些词

正文里命中术语表的词，站构建时自动加一层标注，鼠标移上去显示定义——源文件里干净，没有手写的标签。
这张表的正本是一份数据文件，一条 `term` / `aliases` / `def` / `href`：

{/* has file="src/glossary.ts" text="export const terms" */}

收词的判据与「定义里不许写什么」写在数据文件的头注释里，改词之前先读它：

{/* ref file="src/glossary.ts" lines="1-12" hash="8ad6862f4817" blob="bfef81e8e166" */}

**定义只写概念，不写服务名、类型名、路径**——这份数据钉不住（它不是 mdx，引用管不到它），
写进去的具体名字会悄悄过时。具体名字留给 `href` 指的那一页，在那儿钉码。

作者手写 `<Term>` 也行，但要在名册里有一条，机读版里只留术语原词、样式不带过去。
机制那一半见 [workflow 的 mdx 格式](/docs/workflow) 的名册与 [fumadocs 适配](/docs/fumadocs) 的术语标注。

## 只在这个站里出现的几个词

这几个词不进自动标注（太短或太常见会误标），但读文档时得知道：

| 词 | 意思 |
| --- | --- |
| 正式记号 | 引用写在文档里的那一行 mdx 花括号注释：作者只写目标属性（`{/* ref file="…" lines="起-止" */}`），确认时在同一行添上记录属性（段哈希、blob 名这类） |
| 投影 | 引用在页面上显示出来的那块内容——构建时现从源码读，不是抄进文档的副本 |
| 摆放 | 把 `outputs` 里有映射的生成正本渲染后写到映射指定的落点 |
