# 工作台件

`packages/gwb-live-doc` 是这个工作区里唯一不叫 `live-doc-*` 的包：它是 god 工作台（gwb）的一枚
插件，包名 `@godcreator02/gwb-live-doc`，命令名前缀 `live-doc.`。**它跟七个包住同一个仓，
方向却是单向的**——件依赖 cli，七个包一个字都不认识 gwb，`tests/boundary.test.ts` 最后那条守着。

它是这套机制在工作台里的入口，管两摊：**起停**（坐在工作台里看某个单元时，一键把那个单元的
文档站起起来看——认站、判 build 新不新鲜、现挑端口起 `next start`、杀整棵进程树、到点自动关），
与**接 livedoc**（跑命令行、列待重写页、跨仓投反馈）。

退役单元里的站还在盘上、还起得来，但它讲的是已经作废的东西，列在清单里只会被人和 agent 当成

## build 三态

`.next/BUILD_ID` 是 `next build` 成功留下的唯一标志（`next dev` 不写它）。有没有这个文件、
它跟源比谁新，凑出三态：

{/* ref file="../packages/gwb-live-doc/src/sites.ts" lines="196-210" */}

`missing` 就先 build 再起；`stale` 不传 `rebuild` 也起得来，起的是旧产物，回执的 `note` 里
说明白。**这一条是防「改完 mdx 起旧产物，看到旧页面还以为没生效」**——三态里最值钱的就是 stale。

「源」算的是 `content` / `src` / `public` 三棵树加站根下的所有文件，`node_modules`、`.next`、
`.source`、`out`、`dist`、`.git`、`.turbo` 不算。

## 起停：状态机不碰真进程

一个站一条记录，五态 `idle → building → starting → running → stopping → idle`。

真机那份在 `runner.ts`，测试喂假的——所以整台状态机在 node 里跑得起单测，一个子进程都不起。
两处值得记：**端口现挑，不用站脚本里钉的那个**（钉的口只对手跑有意义，工作台里同时起两个站

占着端口的 node 孤儿。

## 到点自动关

起来的站默认两小时后自己关，到点前五分钟界面上给「延长」。算术是纯函数，时间由调用方传进来：

{/* ref file="../packages/gwb-live-doc/src/deadline.ts" lines="44-52" */}

用的是**绝对到期时刻加定期对表**，不是一个 `setTimeout`：机器睡一觉 `setTimeout` 会漂，醒来时
它还以为没到点；对表是每半分钟拿当前时刻跟到期时刻比一次，睡多久都对。

{/* ref file="../packages/gwb-live-doc/src/deadline.ts" lines="9-16" */}

设置项 `auto-stop-minutes` 写 0 就是不自动关，改了只对之后起的与延长的生效。

## 接命令行：`live-doc.cli` 与那个裸口

livedoc 是个 CLI 包、不是件，自己挂不上工作台。件把它**包内那个 `dist/cli.mjs` 的绝对路径**
登记进 `gwbNodeCli`——不读 `bin` 字段、不查 `.bin` 垫片，垫片在 Windows 上是 `.cmd`、
`process.execPath` 起不了：

{/* ref file="../packages/gwb-live-doc/src/index.ts" lines="65-71" */}

于是有两个口，看着重复其实是一层缺省：**运行器登记什么名字，就往总线上挂同一个名字**，
而它的缺省 cwd 是登记那一刻定死的一个字符串——「落在选中单元的站」必须在调用那一刻才算得出来。
所以裸口 `live-doc.cli-raw`（cwd 自己给）归运行器，缺省那一层是件自己的命令 `live-doc.cli`：
算好 cwd 再经 `run` 递给运行器。

缺省怎么挑：`gwbUnitFolder.current()` 报的选中单元里，名字正好叫 `docs-site` 的优先，
整个单元只有一个站时就是它；

{/* ref file="../packages/gwb-live-doc/src/sites.ts" lines="152-157" */}

挑不出就回一句 `code: 'no-site'` 让调用方给 `cwd`——**不替人猜**，猜错的代价是在错误的仓里
跑了一次 `confirm`。时限顶到运行器的上限 110 秒：`check` 要 load 整个项目、对每处引用问一次 git。

`check` 有红时退出码是 1，那是核对结果不是命令失败——回执照原样把退出码与 stdout 交出去。

## 哪几页该重写：`live-doc.stale`

半自动重写的入口：内部跑 `livedoc check --json`，把整份机读报告收敛成一张「待重写页」的表。
**口径不是件定的，是 cli 的 `report.ts` 头注释定的**——待重写页 = items 里有 changed / missing 的、
或 outputs 里有非 fresh 的文档：

{/* ref file="../packages/gwb-live-doc/src/stale.ts" lines="82-95" */}

只有孤儿记录或名册外组件的页也红，但那不是「重写正文」能解决的事，单列进 `others`——
混在一起会让 agent 去重写一篇其实只要 `confirm` 一下的页。`unconfirmed`（白）不算漂移：
那是还没确认过，不是现状漂了。

报告从 stdout 里捞：`--json` 整份打成一行，但同一条流里还可能有别的话，所以**从后往前找第一行
`{` 开头、且五个契约字段都在的**。少字段就不认——那说明对面那份 cli 太老，报「没拿到机读报告」
比在下游读出 `undefined` 强。

## 跨仓投反馈：`live-doc.feedback`

在 A 仓干活时发现 B 仓的东西不好用，不离开会话就能把话投进 B 的文档站：往
`<站>/content/feedback/inbound.mdx` 末尾**追加**一节，页不在就先建。

{/* ref file="../packages/gwb-live-doc/src/feedback.ts" lines="47-51" */}

格式不是件发明的，是 cli 的站模板 `template/docs-site/content/feedback/inbound.mdx.tpl`
那份注释定的：`## <日期> <标题>` + `来源：` 一行 + 正文。三条纪律——**只追加**（不动已有条目、
不碰别的页）、**不 commit**（那个仓的人自己看了再提交）、**页不在就建**（对面的站可能还没改成
六区，缺一页不该让跨仓反馈投不进去）。日期取本机时区，不用 `toISOString`：那是 UTC，
晚上八点之后写的条目会落到明天。

`live-doc.feedback-list` 把条目读回来。读回来只认二级标题，**围栏里的 `## ` 不算**
——正文里贴一段 markdown 是常事。

## 它自己怎么跑

件用 vitest，不是工作区那七个包的 `node --test`；构建是 `tsc` 出 node 半、`esbuild` 打浏览器半、
`tailwindcss` 编本件那张带 `livedoc` 前缀的样式表。所以它是门禁上单独的一摊：

```powershell
cd packages/gwb-live-doc
pnpm check          # typecheck + oxlint + vitest
pnpm build
```

发版顺序是 **cli 先、件后**：件要装的是发出去的那份 cli，工作区里的软链只在这个仓里成立。
