仓根的 README.md、AGENTS.md、CLAUDE.md 和插件里的 SKILL.md 都是生成物，正本是现状区里的 mdx。
`docfirst.config.mjs` 的 `outputs` 把每篇正本对到一个或几个落点，`docfirst render` 渲染后写过去，`docfirst confirm`
写回记号之后也会渲染一遍。下面用一篇小 SKILL 正本从头走到尾：

## outputs 映射

映射的键是正本路径，值是落点列表，落点相对项目根（放 `docfirst.config.mjs` 的站目录）。落点写成字符串，生成物不带
frontmatter；写成 `{ to, frontmatter }`，点名的字段逐行搬进生成物头部，SKILL.md 就是靠这样保住 `name` 与 `description`。
装配项目时检查每个落点：不能是绝对路径、不能落进内容根（配置的 `content`，默认 `content/`）、同一个落点只许一篇正本写，违反任何一条直接报错：

## check 怎么守生成物新鲜

`check` 用 render 同一个 `bodyOf` 在内存里再渲染一次，跟落点上的文件比，只读不写：

只有 `fresh` 算新鲜，其余状态（落点上还没有文件、内容不一致、缺点名的字段、渲染不了）每个落点记一次红：

{/* ref file="../packages/docfirst-workflow/src/cli/commands.ts" lines="168-173" hash="a1553519e7ac" blob="937001d7a349" */}

代码块的内容取自被钉文件今天的内容，所以有人直接改了生成物、改了正本没渲染、改了被钉的代码没渲染，这三种都会让
check 变红。

## 渲染拒绝什么

四样东西渲染不了：还没确认的引用、指向的东西已经不在的引用、JSX 组件、mdx 表达式（`import` / `export` 也算）。
生成物里只放确认过的代码，所以正本里新写的引用要先 `confirm`，再渲染。
`renderAi` 先走完整棵树，把每一处连同行号列全再拒绝；这一篇的落点一个都不写，render 与 check 都报红：
