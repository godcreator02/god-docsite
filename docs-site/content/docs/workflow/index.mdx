### 钉码编排 pinning

一篇文档的核对与确认只在这里串起来：mdx 格式认出引用，每处剥成目标与记录交给钉码核心，结果按原来的顺序配回文档路径与
行号；确认时把钉码核心算出的新记录交回 mdx 格式写回。命令行、生成物摆放与站构建共用这一份，入口有三个：

钉码核心交回的结果与传入的引用一一对应、同序，配回靠下标；写回只交有新记录的那几处：

### mdx 格式

钉码编排要的 `parse`、`write` 与给 check 的名册检查都在入口文件上，写回只重写记号所在那一行；`marker` 把记号写法给的一截文字包成花括号注释：

{/* ref file="../packages/docfirst-workflow/src/mdx/index.ts" lines="19-37" hash="ed0232ccd320" blob="78a17aca2a24" */}

认记号走 remark 语法树：正式记号是 `mdxFlowExpression` 节点，草稿记号是只含一段文字的段落。写在围栏里、句子里的同样文字分别是
`code` 与 `mdxTextExpression` 节点，不算记号：

{/* ref file="../packages/docfirst-workflow/src/mdx/recognize.ts" lines="16-29" hash="43cde5b2e9d5" blob="0b6b4748c743" */}

**名册**是一张「组件名 → 规则」的表，说明每个组件在机读版里变成什么。这里只有机制，没有默认表：组件与规则写在项目的配置里，
fumadocs 自带组件的规则在 [fumadocs 适配](/docs/fumadocs)的 `./roster`。规则三种写法，函数规则只经 helpers 读节点、造节点：

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="35-36" hash="69cdb1ca8839" blob="d192d3db2a0c" */}

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="22-33" hash="efedd191320a" blob="d192d3db2a0c" */}

`stamp` 按名册给树上每个组件加标记、不换节点（同一棵树还要出页面），名册外的组件报错并给出行号；把标记序列化成 md 的回调在 fumadocs 适配：

{/* ref file="../packages/docfirst-workflow/src/mdx/roster.ts" lines="109-128" hash="c5990a4e9fe5" blob="d192d3db2a0c" */}

`renderAi` 把生成正本按原文渲染成 md，不经过 fumadocs，见[生成物渲染](/docs/workflow/rendering)。
按原文渲染拒绝渲染时抛的错误类也在这里。摆放按错误名认、不用 `instanceof`：渲染与摆放可能各从一份产物加载，
拿到的不是同一个类：

{/* ref file="../packages/docfirst-workflow/src/mdx/render.ts" lines="19-25" hash="6d024e48e50e" blob="9fe43e0b5dbe" */}

### 记号写法 marker

一处引用写成文字是什么样、文字怎么解析回目标与记录，都在 `src/marker/`：正式记号里的属性（先目标、后记录）、草稿记号、
命令行报告用的目标文本 `targetKey`。它只从钉码核心 import 目标与记录的类型，不认识 mdx，也不判状态：

{/* ref file="../packages/docfirst-workflow/src/marker/index.ts" lines="44-53" hash="0de2148a78a2" blob="b24178592311" */}

**正式记号一定带着记录**：`ref` 要有 hash 与 blob，`tree` 要有 hash，`has` 的记号本身就是记录。未确认的引用只有草稿记号一种写法，
正式记号缺记录直接报错到行：

{/* ref file="../packages/docfirst-workflow/src/marker/index.ts" lines="98-118" hash="7959bba562d7" blob="b24178592311" */}

每个动作词认哪些属性是固定的；多出属性、值不合法都报错到行：

### 命令行 cli

子命令与各自做什么写在入口文件头上：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="1-21" hash="be5d2d90c369" blob="75cc83db6ebd" */}

每条命令只收自己开关表里的开关，别的一律退 2、什么都不动。表必须封闭：`confirm` 把 `-` 开头的参数从页名里筛掉，
开关若被静默丢掉，`confirm --help` 就成了不带页名的全部页确认：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="44-57" hash="ec22d1956cc8" blob="75cc83db6ebd" */}

人读输出一行一处引用：状态符号、文档、目标（记号上的行号）、一句说明，括号里是细分理由或目录树的项数：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="36-42" hash="9ebfdcac2bf1" blob="75cc83db6ebd" */}

```text
🟢 content/docs/a.mdx  src/greet.ts:2-3  新鲜
⚪ content/docs/a.mdx  src/greet.ts:2-3  未确认，等作者确认
🟡 content/docs/a.mdx  src/greet.ts:4-5  有变动，等作者复核
🔴 content/docs/a.mdx  src/greet.ts:4-5  有变动，是本仓还没提交的改动引起的——在同一个提交里复核，再 docfirst confirm content/docs/a.mdx --accept
🔴 content/docs/a.mdx  src/greet.ts:4-5  缺失（整段已被删光）
```

`check` 先把逐篇核对与轨迹卡校验汇总成一份报告，人读模式边算边打，`--json` 汇总完打印一行，两种模式的红出自同一份报告：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="212-235" hash="5f938c9ee287" blob="75cc83db6ebd" */}

`confirm` 带路径时只动点名的页；`--accept` 必须点名页，点名的路径对不上项目里的文档当场退 2。重新生成生成物不按页限定，按内容判：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="113-141" hash="235a864d0ce8" blob="75cc83db6ebd" */}

`trajectory` 不遍历文档，打印卡目录那一张盘的树与主干，没有轨迹卡目录就退 2：

{/* ref file="../packages/docfirst-workflow/src/cli/run.ts" lines="249-269" hash="931ad6970d4e" blob="75cc83db6ebd" */}

退出码、红的来源、未提交改动的黄怎么算红，见[提交门禁](/docs/pin/gate)。

## 不做的事

- **不认识任何站的宿主**：fumadocs、react、next 在源码、清单、产物里都不出现，命令行跑在 git hook 与 CI 里，那些环境不一定装了站的依赖：

{/* ref file="../tests/boundary.test.ts" lines="320-334" hash="d5b710f640dc" blob="e77be7ebc154" */}

- **不依赖 fumadocs 适配**：包方向表里 workflow 一行禁止它：

{/* ref file="../tests/boundary.test.ts" lines="129-135" hash="f64865a8c24f" blob="e450056cc091" */}

- **不判状态**：绿黄白红由[钉码核心](/docs/pin)算，这个包把磁盘、git、配置接给它，再把结果打印出来。
- **不给卡建模**：卡字段怎么校验、盘怎么建归[轨迹核心](/docs/trajectory)。
- **摆放不读写文件**：`placement.ts` 经 `PlacingHost` 读写落点，读写磁盘的那份实现在 `load.ts`，测试换成内存那份：

{/* ref file="../packages/docfirst-workflow/src/project/placement.ts" lines="77-91" hash="90be89518ac3" blob="6dc0e3cf3ba7" */}

- **不建站**：建站命令与模板归[工作台插件](/docs/plugin)。
