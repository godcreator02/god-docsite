## 一处钉：目标加记录

钉的目标有三种：行段（某文件某几行）、整文件、目录树（某目录下有哪些名字，不看内容）。

{/* ref file="../packages/code-pin/src/core/types.ts" lines="11-33" hash="671e59c4c83c" blob="aee292173867" */}

记录是确认时算出来的：行段与整文件记**段哈希**（那几行归一化后 sha256 的前 12 位）和**整文件的 blob 名**（按 git 的算法在进程里算，不问 git）；目录树只记名字表的哈希。没确认过的钉，记录是空的。

{/* ref file="../packages/code-pin/src/core/types.ts" lines="35-54" hash="59c29f221215" blob="aee292173867" */}

## 核对：行段怎么判

图上第 6—9 号：核对要看的今天内容从 `Reader` 接口来，旧内容从 `History` 接口来，两个接口都由 node 层接上磁盘与 git，核心只收接口。整文件只比段哈希，目录树只比名字表的哈希，都是一步出结论。行段多两步，因为代码上面加几行、行号就整体挪了，单比原来那几行会把没变的段误判成变了。
判定按四步走，前一步能下结论就不往下走。选一种改动看看：

<JudgeCases />

第 2 步的用处是省一次取旧内容：blob 名没变说明整文件没变，旧内容就是今天的内容。第 4 步是有意设计的降级：记录里的 blob 名是确认时在进程里算的，确认之后、提交之前又改了文件，或者仓按 CRLF 存，这个 blob 就不在对象库里，少的只是对比，不是错。

## 哈希前先归一化

站上显示什么就哈希什么，两边用同一个归一化：换行统一成 LF、去掉每行行尾空白、去掉末尾空行；缩进和注释保留——JSDoc 是契约的一部分，改了就该黄。

<Normalize />

blob 名也按换行统一成 LF 的内容算，所以工作区是不是 CRLF 不影响判定。

## 两种文档格式

标记写在两种文件里，里面那一截一字不差，只是外壳不同：

| 格式 | 认领 | 标记的外壳 | 怎么认 |
| --- | --- | --- | --- |
| mdx | `.mdx` 页面 | 单独一行的花括号注释 `{/* … */}` | 走语法树：围栏代码里、行内的同样文字不算标记 |
| 组件 | `.ts`、`.tsx`、`.mjs` | 单独一行的块注释 `/* … */` | 按行认，一行里还有别的代码就不算 |

组件格式给讲解组件用：数据里照源码抄来的那几行，在正上方钉一处，源码变了组件的数据也得跟着复核。哪些代码文件算文档由使用方决定（docfirst 收内容根里的：页面旁边、组里 `_` 开头的文件夹与内容根下的 `_components/`）。

## 站点上：标记换成钉码外框

图上第 3、4 号。建站器把这份接线文件写进站点的 `app/features/code-pin/`，钉上的路径相对站点目录：

{/* ref file="../packages/code-pin/template/mdx.ts" hash="b4d99f833bb9" blob="7bdbd0f61408" */}

编译每一页时插件核对全部标记，每处换成一个可以收起的外框（`<details>`），状态写在外框的属性上，由 `pin.css` 画状态点。
收起时只剩一行：状态点、今天的位置、状态字，点开才看代码。钉码是给维护者核对用的，读者读正文和讲解组件就够，所以新鲜与未确认默认收起；有变动与缺失要人处理，默认展开。
点开以后显示什么按结论定：新鲜与未确认显示今天的那几行（行号跟源文件对上）；有变动且有对比时，旧行新行放在同一块里标出增删；位置不明只留一句说明；缺失显示确认时那段；目录树显示成文件树。

插件没有向 Vite 登记被钉的文件：开发服务运行时改了被钉的代码，页面不会跟着变，要再存一下这一页或重启开发服务。

## 分层与谁在用它

{/* tree dir="../packages/code-pin/src" depth="1" hash="efe277dfc658" */}

| 层 | 导出 | 做什么 |
| --- | --- | --- |
| `core/` | `@godcreator/code-pin` | 标记的读写、核对与确认、一篇文档的核对与确认（收全文、交回改好的全文）。看到的一切都从传入的读取器（`Reader`）与旧内容来源（`History`）来 |
| `node/` | `@godcreator/code-pin/node` | 读工作区的读取器、从 git 对象库按 blob 名取旧内容、判断一处黄灯是不是本仓未提交的改动引起的、整篇核对与确认（读全文、调核心、写回） |
| `site/` | `@godcreator/code-pin/site` | 站点的 remark 插件：认出页面里的标记、一次核对完，每处换成一个带状态、可以收起的钉码外框 |

核心只收接口，所以测试不用建临时仓，换一种旧内容来源（比如不用 git）也不用动核心。
