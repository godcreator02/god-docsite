## 报告文档：一棵带 id 的块树

一份文档是 `format: "docreport"`、`schemaVersion: 1` 的 JSON：`metadata`（标题、语言、作者、日期、版本、封面字段），`blocks`（节、段落、列表、图、公式、表格、代码、参考文献标记、摘要、`include`），以及文档级的 `notes`（脚注）与 `references`（参考文献）。凡是带 `id` 的东西 id 在整份报告里唯一；引用、脚注、文献引用都写目标的 id，不写编号；`include` 只能出现在文档的顶层 `blocks` 里。

{/* ref file="../packages/word-report/src/core/types.ts" lines="1-37" hash="fdc94a4af4d6" blob="ac61de1cb12f" */}

读 JSON 用包里自己写的解析器，为的是抓重复的键——`JSON.parse` 会悄悄留下后一个。

## MDX 报告：先编译成一份报告文档

MDX 报告不另有一套组装、显示和导出：`core/mdx/` 的编译器把入口 `index.mdx`、文件头 `chapters` 列的各章、可选的 `references.mdx` 编译成**一份**不含 `include` 的报告文档，再交给下面同一个 `assembleDocument`。编译器只用 remark（`remark-parse`、`remark-frontmatter`、`remark-mdx`、`remark-gfm`、`remark-math`）把 MDX 解析成语法树，逐个节点对照到报告文档的块与行内节点，不执行 MDX；对照不上的节点（`import`、表达式、没列出的组件与属性、Markdown 图片、引用块等）直接报错。各写法对应哪种节点见用法页的「MDX 写法」。

{/* ref file="../packages/word-report/src/core/mdx/compile.ts" lines="80-107" hash="27b97daef28e" blob="33f858e48d38" */}

**id**：手写的 id 只出现在要被引用、或要在 `layout.json` 里调版式的地方；其余要 id 的节点由编译器在整份转完后一次分配，写成 `auto-<种类>-<指纹>`：指纹是种类加去掉所有 id 的节点内容的 FNV-1a 散列，节只取标题。同样的内容每次编译得到同样的 id，重复的内容按先后加 `-2`、`-3`；手写的 id 不许以 `auto-` 开头，两边不会撞。所以 MDX 报告里段落改了字，它的 id 就变，按元素 id 定位的评论随之对不上原段，和站里其他 MDX 页面的评论一样。

{/* ref file="../packages/word-report/src/core/mdx/ids.ts" lines="38-60" hash="a579ad7c04c8" blob="7b54fac7e217" */}

**出错位置**：编译器给每个生成的节点记下 MDX 的文件与「行:列」。编译时的错直接带上它；组装时报的错指着编译结果里的 JSON 指针，`assembleMdxReport` 接住后按最长前缀找到最近的有记录的节点，换成 MDX 的文件与行列再抛。组装结果的 `sources` 也换成 MDX 的位置。

{/* ref file="../packages/word-report/src/core/mdx/compile.ts" lines="109-131" hash="76aa864eb688" blob="33f858e48d38" */}

`report-docx convert` 方向相反：`mdxReportPlanOf` 把组装好的 JSON 报告写成 MDX 文件，只写出被引用的、`layout.json` 里出现的、文献与脚注的 id，写不出的内容记进清单；`convertReportToMdx` 写完立刻编译回来，按「只留写出的 id、图片只看文件名、相邻同样式的文字合并」的口径逐项比对，对不上就删掉新目录。

## 分章组装

`assembleDocument(entry, files, { mode })` 接收入口路径与「路径 → 原文或已解析的文档」的表，不读写磁盘；返回组装好的文档，以及编号表 `index`、每个 id 出自哪个文件哪个位置 `sources`、图片的新旧路径 `assets`、读到的文件 `dependencies`、提示 `warnings`。一步一步看例子怎么组装：

`include` 的路径相对引入它的那个文件；同一个文件被引入两次、绕回自己、文件不在表里都直接报错；只取入口的 `metadata`，各章的标题与封面字段不进来。

{/* ref file="../packages/word-report/src/core/assemble.ts" lines="42-78" hash="cc676245174b" blob="4b0af29ddb00" */}

每个带 `id` 的东西登记一次、记下出处，重名就报错；图片路径改成 `assets/<那一章的文档 id>/<文件名>`，两章各有一张 `assets/image.png` 不会冲突，只差大小写的名字在 Windows 上会冲突、报错。多图里的每张图同样登记、同样改路径，另查每张图的格子在网格里、一格只放一张、编号不重复。

{/* ref file="../packages/word-report/src/core/assemble.ts" lines="17-40" hash="b579575dd49c" blob="c8e97b0046c1" */}
{/* ref file="../packages/word-report/src/core/assemble.ts" lines="219-229" hash="d96df210509f" blob="b0aed26b2b3a" */}

编号规则：顶层编号的节依次是 1、2、…，附录是 A、B、…（附录之后不能再有正文章），子节是「上一级.n」；图、编号表格、编号公式三者各自按所在的顶层章从 1 编，写成「章号-n」（「图 1-2」「表 B-2」「式（2-3）」），所以它们不在编号的章里就报错。多图占一个图号，其中每张编成「图号(label)」，如「图 1-2(a)」，`label` 由报告手写，不自动编。导出的 Word 里题注同样是「章号-序号」：章号取自本章标题的 `STYLEREF`，序号是每章从 1 起的 `SEQ`，交叉引用的书签包住这两段，引用显示完整的「1-2」。

{/* ref file="../packages/word-report/src/core/assemble.ts" lines="126-167" hash="d1a7f86908a6" blob="b0aed26b2b3a" */}

解引用：整份组装（`complete`）时目标不在就报错；单独组装（`standalone`）时目标不在、又写了 `externalLabel`，才换成那段文字并记一条提示，没写还是报错；输出里不留 `externalLabel`。

## 组装里的另外几条规则

- **参考文献**：各章的 `references` 合成一份，同一个 id 两章写得不一样就报错；参考文献标记只认入口里的那一个，各章里的会被移除；入口里没有、又有文献时在末尾自动加一个
- **脚注与文献的编号**：每条脚注必须正好被引用一次，脚注里不能再套脚注；脚注按第一次引用的先后编号；文献按正文阅读顺序里第一次被引用的先后编号，没被引用的排在最后
- **公式**：要交给 MathType，LaTeX 只能是非空 ASCII，不带 `$`、`\(`、`\[` 这类定界符，不写 `\tag`、`\label`；`aligned` 只收两列
- **摘要与表格**：摘要至多一个、必须是第一个顶层块；表格的合并单元格要正好铺满网格、不跨表头

## 三处调用、两种模式

图上第 1、2、4 号。三处都调 `assembleDocument`，差在模式与读文件的方式：

| 调用方 | 读文件 | 模式 | 结果怎么用 |
| --- | --- | --- | --- |
| 网页（`/reports` 与 `/reports/<报告 id>`） | 只读 JSON 或 MDX 原文，不读图片；MDX 报告的每个原文都和上次一样时用上次的编译结果 | `complete` | 列表里读不对的报告照样列出、带原话；报告页读不对直接报错 |
| `report-docx check` | 还解码图片、核对快照 | 每个 `content.json` 都 `standalone` 组装一次；有 `include` 的再 `complete` 组装一次；每份 MDX 报告只 `complete` 一次 | 例子里检查 3 份文档、组装 4 次：入口两次，a、b 各一次；b 单独组装记一条提示 |
| `report-docx export` | 同 check | `complete` | 组装结果写进快照，交给 Word 引擎 |

`check` 把站点 `reports/` 下每一个 `content.json`（报告与各章）都当一份文档查，所以 JSON 报告的每一章自己也要能单独组装：这就是「单独组装一章时，指向别章的引用要写 `externalLabel`」的来历。MDX 的章文件不是独立的文档，只认报告目录根上的 `index.mdx`，整份查一次。哪种入口由报告目录里有 `content.json` 还是 `index.mdx` 定（`reportEntryIn`），两个都有直接报错。

## 读文件：网页现读，检查与导出取快照

图上第 1、5 号。网页每次请求都从磁盘现读 JSON 或 MDX 原文，不读图片，只拒绝超出站点目录的路径。报告列表、报告页与图片共用每份报告最近一次的组装：先拿上次读过的每个原文和磁盘上的比，再看当时不存在、一出现就会改变结果的文件（另一种入口、MDX 报告的 `references.mdx`）是否仍不存在，都没变就沿用上次的结果，同时到的请求共用同一次组装。一页几十张图各自发请求，组装（MDX 还要先编译）一次几百毫秒到几秒，又都在一个线程上排队，不共用的话最后一张图要等半分钟以上；比原文不比修改时间，是因为修改时间在读完文件到取时间之间被改，会把旧内容当成新的留下来。

结果放在引擎目录的 `out/` 下，不放进站点。

引擎里一次导出启动三次 Word。第一次按模板写出排版稿：域、编号、要交给 MathType 的公式先写成 `@FIELD3@`、`@MATH3@` 这类占位符，写完再逐个换成域与书签；只有一段文字的单元格整格一次写入。第二次把公式占位符逐个换成 MathType 对象、写入 TeX 并读回比对，存盘后重新打开再逐个读回核对。第三次更新域与目录、导出 PDF，最后核对正文文字、表格数、图片字节与页数。占位符按写入的先后排在正文里，找下一个时从上一个的位置往后找，找不到才搜整篇与脚注、页眉页脚。

行内公式只用到字母、数字、希腊字母、一层上标或下标、`\mathrm` 与 `\text`、函数名和简单运算符的，不交给 MathType：`plain_math.py` 把它解析成几段文字，字母与小写希腊字母斜体、其余正体，上下标用 Word 的上标下标，应用字符样式「DR Inline Math」（Times New Roman）。Word 把 φ、≈ 这类字符插进中文段落时会给它们加上东亚字体提示、显示成宋体，而 COM 改不了这个提示，所以排版稿存盘、Word 关掉之后，引擎直接改 docx 里这个字符样式的那些段，去掉提示。带根号、分式、求和、偏导、帽子、自动大小括号，或者同一个字母同时带上下标的行内公式，以及全部行间公式，照旧是 MathType 对象。模板设置里关掉了 Word 存盘时压缩图片，docx 里的图片和源图逐字节相同，最后核对图片字节靠这一条。

时间主要花在 Word 的 COM 调用与 MathType 对象上。协作站初步设计报告（155 页、74 张表、806 个行内公式与 52 个行间公式）一次导出约 6.5 分钟：排版稿约 4.6 分钟，98 个 MathType 公式约 40 秒，更新域与目录约 20 秒。为什么这样改、试过哪些没用，见轨迹卡[「Word 导出提速：行内公式写成文字」](/trajectory/2026-10-17-word-export-speed)。

## 分层与谁在用它

| 层 | 导出 | 做什么 |
| --- | --- | --- |
| `core/` | `@godcreator/word-report` | 报告文档的类型、Schema 与校验、严格 JSON 解析、分章组装；`core/mdx/` 是 MDX 编译器与反方向的写出；不碰磁盘、不 import React |
| `node/` | `@godcreator/word-report/node`，命令行 `report-docx` | 认报告入口、读报告目录、取快照、检查、导出（指纹、锁、启动引擎）、JSON 报告转 MDX、命令行 |
| `site/` | `@godcreator/word-report/site`、`@godcreator/word-report/site/server` | 报告列表页与报告页、报告的显示组件；服务端的三个 loader |
| `engine/` | 随包发出的文件（不是 JS 出口） | 驱动本机 Word 与 MathType 的 Python 引擎、`.dotx` 模板、引擎那份 Schema |

层之间的方向与不许有环由 `tests/dependency-rules.cjs` 检查；word-report 只依赖 comments。

用它的就是总图上的右列：站点经 `template/` 下的接线文件调三个 loader 与页面组件，由 gwb-docsite 的 `docsite.feature.add` 装进站点（协作站建站时不默认带）；测试站 `full-test/site` 装着它，e2e 的 report 组在它上面查列表、整份一页、目录、公式、图片、404，以及报告页的评论（dev 写一串，start 只读）。两个 gwb 插件都不 import 这个包，导出只走命令行。
