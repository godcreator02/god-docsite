平台包 `@godcreator/god-docsite` 是每个站点的公共部分，别的包都不依赖它。它分两部分：

- **模板与建站器**：`template/` 是唯一的站点模板，`./scaffold` 是建站器（`createSite` 建站、`addFeature` 加功能、`regenerateFeatureIndex` 重写汇总文件），负责把站点写出来
- **运行时出口**：`./server`、`./react`、`./vite`、`./mdx` 等，由模板写出的站点文件调用，管页面树、布局与侧栏、搜索、推送与术语标注

另有 `./identity`：站点根的身份文件 `docsite.json`（站点类别与布局代号）的读写，插件靠它认出平台建的站、分出类别，见下面「站点身份文件」一节。

本站的 `app/features/` 就是建站器建出来的样子：`code-pin`、`comments`、`explainer`、`trajectory` 四个功能目录，和「`createSite` → `addBaseFeatures` → 依次 `addFeature` code-pin、trajectory、explainer」得到的一字不差——`pnpm test:scaffold` 就是这么比对的。这一页的例子从头到尾都是本站自己。

## 站点里的三类文件

平台包的 `template/` 是唯一的站点模板。站点里的文件分三类，谁写、之后归谁不一样：

| 文件 | 谁写 | 之后 |
| --- | --- | --- |
| 模板写出的文件：`app/routes.ts`、`app/root.tsx`、`app/routes/*`、`app/lib/*`、`vite.config.ts`、`source.config.ts`、`react-router.config.ts` 等 | `createSite` 从 `template/` 复制 | 建站后归站点，建站器不再写（`app/routes/home.tsx` 就是站点自己改的首页） |
| 功能目录 `app/features/<功能>/` | `addFeature` 从功能包的 `template/` 补 | 已有的文件不覆盖，只补缺的 |
| 汇总文件 `app/features/*.generated.ts`、`styles.generated.css` | `regenerateFeatureIndex` | 每次重写，不手改 |

站点路由表 `app/routes.ts` 里：平台自己的六个资源路由——搜索 `api/search`、Markdown `api/markdown`、内容文件 `api/content/*`、两份 llms 文本、推送 `__docsite/feed/:channel`；首页在整站布局之外；功能的 `standaloneRoutes` 也在布局之外；功能的默认路由嵌在布局里、排在通配的 `*` 前面。布局路由的 id 固定是 `routes/layout`，这是外部契约——功能的 `LayoutTop` 用 `useRouteLoaderData('routes/layout')` 取自己那份布局数据。

## 建站器：按功能目录生成汇总文件

`createSite` 往空目录里复制模板，把模板 `package.json` 里的 `{{version}}` 换成依赖写法——registry（发版后从 registry 装，写 `^<版本>`）、link（直接用仓里的包）、file（`pnpm pack` 的 tarball）三种——再写站名、`people.json`、`pnpm-workspace.yaml`，最后写出空的汇总文件。它不装依赖、不启动开发服务。

{/* ref file="../packages/god-docsite/src/node/scaffold/create-site.ts" lines="112-132" hash="78906872439f" blob="c32d8e1255e1" */}

装好依赖之后 `addBaseFeatures` 补基础功能：模板 `package.json` 里写成 `{{version}}` 的包（平台包自己除外）里带 `template/` 的才算功能——基础站就是 comments；identity 没有 `template/`，跳过。`addFeature` 加一个功能：功能包要先装进站点的 `node_modules`，它把功能包的 `template/` 补进 `app/features/<包名去掉作用域>/`，已有的文件不覆盖，再重写汇总文件；对同一站点重复运行只补缺的。

{/* ref file="../packages/god-docsite/src/node/scaffold/add-feature.ts" lines="25-66" hash="dbd4cb465912" blob="99d25946e005" */}

功能目录固定在 `app/features/`；建站器只认目录里的四种文件——`routes.ts`、`feature.tsx`、`mdx.ts`、`styles.css`，含其中任一个的子目录才算功能；五份汇总文件是 `routes.generated.ts`、`runtime.generated.ts`、`mdx.generated.ts`、`collections.generated.ts`、`styles.generated.css`，都在 `app/features/` 下。

{/* ref file="../packages/god-docsite/src/node/scaffold/feature-index.ts" lines="7-20" hash="a9cdf57d595c" blob="778f5b87a5f7" */}

`regenerateFeatureIndex` 是核心：扫 `app/features/` 下的子目录，含四种文件之一的才算功能，按名字排序；有 `mdx.ts` 的去站点依赖里找功能名对得上的那个包，读它 `package.json` 的 `godDocsite.collections`；集合名要全站唯一，与 `source.config.ts` 自己的集合也不能重名；然后重写五份汇总文件。汇总文件每次都按目录重新生成，所以加一个功能不用改模板，平台包也不用知道有哪些功能包。下面把本站建出来的六步依次看一遍：

## 站点身份文件

站点根的 `docsite.json` 写明这个站拿来干什么、按哪一代布局建的，只有两项：

```json
{ "kind": "collab", "format": 1 }
```

- `kind` 是 `base`（基础站）、`docs`（文档站）、`collab`（协作站）之一，说的是用途，不是装了哪些功能：测试站装了全部功能，`kind` 仍是 `collab`。装了哪些功能看 `package.json` 的依赖
- `format` 是布局代号，现在是 `1`。布局再变时加一，读到不认识的号直接报错、写明照模板手动升级，不自动搬
- 写坏了就报错，写明哪一项不对：不是 JSON、`kind` 不在三个值里、`format` 不对、多了认不出的键

`createSite` 不写它：建站的一方建完站接着调 `writeSiteIdentity` 写一次，之后归站点。gwb-docsite 的 `docsite.site.init`、`docfirst.create`、gwb-collab 的 `collab.site.init` 分别写 `base`、`docs`、`collab`。gwb-docsite 托管前、gwb-collab 认协作仓都只看它，没有这个文件的站（旧平台 docsite-kit 建的站、有身份文件之前建的站）不认。

## 功能目录里的四种文件

这一节写给功能包作者。四种文件各能导出什么、平台怎么用：

| 文件 | 能导出 | 进哪份汇总文件 | 站点里谁用 |
| --- | --- | --- | --- |
| `routes.ts` | 默认导出（嵌在整站布局里的路由）、`standaloneRoutes`（布局之外、占满窗口） | `routes.generated.ts` | `app/routes.ts` |
| `feature.tsx` | `FeatureRuntimeModule` 的六样，都可选：`mdxComponents`、`pageTreePlugins`、`linkKinds`、`sidebarLinks`、`layoutData`、`LayoutTop` | `runtime.generated.ts` → `siteFeatureRuntime` | 布局路由、`app/lib/source.ts`、`app/lib/mdx-components.tsx` |
| `mdx.ts` | `remarkPlugins`、`rehypePlugins`、`collections`（集合工厂，名单写在包的 `package.json` 的 `godDocsite.collections`） | `mdx.generated.ts`；有集合的再进 `collections.generated.ts` | `source.config.ts`、`app/lib/mdx-plugins.ts` |
| `styles.css` | 样式 | `styles.generated.css` | `app/app.css` |

{/* ref file="../packages/god-docsite/src/node/scaffold/feature-index.ts" lines="123-182" hash="0005b519c4d9" blob="778f5b87a5f7" */}

合并规则三条：

- `feature.tsx` 会进浏览器：不能 import `.server` 模块或 Node 内置模块，`layoutData` 要的服务端数据只能经第二个参数 `base`（站点上下文）取；它的返回值以功能名为键并进布局数据。
- 两个功能导出同名 MDX 组件时报错；侧栏入口按 `order` 排，同样大的按功能名。
- 集合工厂收一份全站插件 `sitePlugins` 并进自己的选项；`source.config.ts` 用 `export *` 再导出 `collections.generated.ts`，因为 fumadocs-mdx 要求那份文件只导出集合。

## 三种页面进一棵页面树

站点的 `app/lib/source.ts` 把三种页面来源交给同一个 fumadocs `loader`，键是 `mdx`、`tsx`、`html`——这个键就是每一页的 `type`，所以三种页面在同一棵页面树、同一个搜索索引里。`import.meta.glob` 的参数要能静态分析，只能写在站点模块里；平台的 `tsxPageSource`、`htmlPageSource` 只把 glob 的结果换成虚拟文件。

## 站点上下文

站点的 `app/lib/site.server.ts` 造一个 `site`，平台与功能包的 loader、action 都经参数拿到它，自己不 import 站点代码。字段：站点目录、`mode`（`dev` / `start`）、loader 结果 `source`（平台只用到它的四个方法：`getPage`、`getPages`、`getPageTree`、`serializePageTree`，页面是三种来源之一）、内容目录、评论目录与评论条目，以及每次调用都重新读取的四个函数——人员列表、本机身份（start 一律只读）、可信来源、推送通道某频道现在的值。功能包模板里的 `site.server.ts` 从它组装本功能要的上下文。

## vite 插件、端口与可信来源

站点 `vite.config.ts` 里 `godDocsite({ collections })` 排在 `fumadocsMdx()`、`tailwindcss()` 之后、`reactRouter()` 之前；参数是 `source.config.ts` 的全部导出，插件从中认出内容目录。它由六个插件组成：

| 插件 | 做什么 | 何时生效 |
| --- | --- | --- |
| `devPort` | 开发服务没给端口就随机挑一个，并把地址告诉站点 | dev |
| `frameworkPackages` | 认出平台与功能包（peer 里有 fumadocs 或导出 `./site` 的包）让它们经 Vite 处理 | dev 与 build |
| `devDotServerGuard` | 补查 dev 下带查询的 `.server` 模块被浏览器端 import | dev |
| `invalidateContentCollectors` | 内容目录增删文件时让收集内容的模块重新转换 | dev |
| `checkContentLayout` | 检查内容目录的文件放对了没有 | build 与 dev 启动 |
| `copyContentAssets` | 把内容目录里的文件复制进客户端产物 | build |

## 其余能力

- **布局与侧栏**：整站布局是 fumadocs 的 `DocsLayout`；目录切换按钮按 `meta.json` 写了 `"root": true` 的文件夹生成，不在任何一组里的页面归进以站名命名的一组；在任务、全站评论这类不在页面树里的功能页面上，侧栏显示最近看过的那一组。站名下一横排是搜索按钮与各功能的侧栏入口。
- **首页**：`app/routes/home.tsx` 在整站布局之外、地址是 `/`，内容目录根上不能再写 index 页；「文档」链接指向第一组的第一页。
- **TSX 与 HTML 页面**：TSX 页的标题、描述、搜索文字来自它导出的 `meta`；HTML 页的标题取 `<title>`，只有写了 `id` 的标题才进目录与搜索锚点。
- **内容目录的放法**：组文件夹只放页面、`meta.json`、页面的同名文件夹、下划线开头的文件夹与子组，同名文件夹里不放页面；vite 插件在 build 与 dev 启动时检查，放错了就报错、不启动；dev 运行中每增删一个文件或文件夹就重查一遍，放错了在终端与浏览器的错误层里报出来。重查途中子文件夹被删掉（git 改名、挪目录时一次删几百个文件）按已经不存在算，开发服务不退出；内容目录本身不在照旧报错。
- **搜索**：中文站点把 fumadocs 搜索的容错与命中阈值都设成 0，每个词都要原样出现。
- **Markdown 与 llms**：每一页都有 Markdown 形式（MDX 走 `getText('processed')`，TSX、HTML 页在来源数据里），`/api/markdown`、`llms.txt`、`llms-full.txt` 用它；构建时只预渲染两份 llms 文本。
- **术语标注**：站点根的 `glossary.json` 列术语；构建时长词优先、西文要词边界、一篇只标第一次，代码、公式、标题、链接里不标，所以排在 `remark-math` 之后。

## 谁在用它

- **gwb-docsite**：`./scaffold` 的 `createSite`、`addBaseFeatures`、`addFeature`、`isPortFree`（`docsite.site.init`、`docsite.feature.add`）；`./identity` 的 `writeSiteIdentity`、`siteIdentityOf`（建站时写身份文件、托管前核对、站点列表的类别）；`.` 的 `feedTokenEnvName`、`feedTokenHeader`、`feedUrlOf`（托管开发服务、往推送通道推数据）
