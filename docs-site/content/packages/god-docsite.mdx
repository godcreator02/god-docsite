平台包 `@godcreator/god-docsite` 是每个站点的公共部分，别的包都不依赖它。它分两部分：

- **模板与建站器**：`template/` 是唯一的站点模板，`./scaffold` 是建站器（`createSite` 建站、`addFeature` 加功能、`regenerateFeatureIndex` 重写汇总文件），负责把站点写出来
- **运行时出口**：`./server`、`./react`、`./vite`、`./mdx` 等，由模板写出的站点文件调用，管页面树、布局与侧栏、搜索、推送与术语标注

另有 `./identity`：站点根的身份文件 `docsite.json`（站点类别、给谁看与布局代号）的读写，插件靠它认出平台建的站、分出类别，见下面「站点身份文件」一节。

本站的 `app/features/` 就是建站器建出来的样子：`code-pin`、`comments`、`explainer`、`identity`、`trajectory` 五个功能目录，和「`createSite` → `addBaseFeatures` → 依次 `addFeature` code-pin、trajectory、explainer」得到的一字不差——`pnpm test:scaffold` 就是这么比对的。这一页的例子从头到尾都是本站自己。

## 站点里的三类文件

平台包的 `template/` 是唯一的站点模板。站点里的文件分三类，谁写、之后归谁不一样：

| 文件 | 谁写 | 之后 |
| --- | --- | --- |
| 模板写出的文件：`app/routes.ts`、`app/root.tsx`、`app/routes/*`、`app/lib/*`、`vite.config.ts`、`source.config.ts`、`react-router.config.ts` 等 | `createSite` 从 `template/` 复制 | 建站后归站点，建站器不再写（`app/routes/home.tsx` 就是站点自己改的首页） |
| 功能目录 `app/features/<功能>/` | `addFeature` 从功能包的 `template/` 补 | 已有的文件不覆盖，只补缺的 |
| 汇总文件 `app/features/*.generated.ts`、`styles.generated.css` | `regenerateFeatureIndex` | 每次重写，不手改 |

站点路由表 `app/routes.ts` 里：平台自己的六个资源路由——搜索 `api/search`、Markdown `api/markdown`、内容文件 `api/content/*`、两份 llms 文本、推送 `__docsite/feed/:channel`；首页在整站布局之外；功能的 `standaloneRoutes` 也在布局之外；功能的默认路由嵌在布局里、排在通配的 `*` 前面。布局路由的 id 固定是 `routes/layout`，这是外部契约——功能的 `LayoutTop` 用 `useRouteLoaderData('routes/layout')` 取自己那份布局数据。

## 建站器：按功能目录生成汇总文件

`createSite` 往空目录里复制模板，把模板 `package.json` 里的 `{{version}}` 换成依赖写法——registry（发版后从 registry 装，写 `^<版本>`）、link（直接用仓里的包）、file（`pnpm pack` 的 tarball）三种——再写站名、`people.json`、`pnpm-workspace.yaml`，最后写出空的汇总文件。它不装依赖、不启动开发服务。

{/* ref file="../packages/god-docsite/src/node/scaffold/create-site.ts" lines="112-132" hash="78906872439f" blob="c32d8e1255e1" */}

装好依赖之后 `addBaseFeatures` 补基础功能：模板 `package.json` 里写成 `{{version}}` 的包（平台包自己除外）里带 `template/` 的才算功能——基础站就是 comments（全站评论页兼评论写入路由、侧栏入口、样式）与 identity（头像写入路由）。`addFeature` 加一个功能：功能包要先装进站点的 `node_modules`，它把功能包的 `template/` 补进 `app/features/<包名去掉作用域>/`，已有的文件不覆盖，再重写汇总文件；对同一站点重复运行只补缺的。

{/* ref file="../packages/god-docsite/src/node/scaffold/add-feature.ts" lines="25-66" hash="d9cf99c74551" blob="5274e23e10ca" */}

功能目录固定在 `app/features/`；建站器只认目录里的五种文件——`routes.ts`、`feature.tsx`、`mdx.ts`、`styles.css`、`site.server.ts`，含其中任一个的子目录才算功能；六份汇总文件是 `routes.generated.ts`、`runtime.generated.ts`、`mdx.generated.ts`、`collections.generated.ts`、`styles.generated.css`、`server.generated.ts`，都在 `app/features/` 下。

{/* ref file="../packages/god-docsite/src/node/scaffold/feature-index.ts" lines="7-34" hash="50aef65b5e80" blob="98f876f836b7" */}

`regenerateFeatureIndex` 是核心：扫 `app/features/` 下的子目录，含五种文件之一的才算功能，按名字排序；有 `mdx.ts` 的去站点依赖里找功能名对得上的那个包，读它 `package.json` 的 `godDocsite.collections`；集合名要全站唯一，与 `source.config.ts` 自己的集合也不能重名；`site.server.ts` 里导出了 `sections` 的才进服务端汇总；然后重写六份汇总文件。汇总文件每次都按目录重新生成，所以加一个功能不用改模板，平台包也不用知道有哪些功能包。下面把本站建出来的六步依次看一遍：

## 站点身份文件

站点根的 `docsite.json` 写明这个站拿来干什么、给谁看、按哪一代布局建的，只有三项：

```json
{ "kind": "collab", "audience": "shared", "format": 2 }
```

- `kind` 是 `base`（基础站）、`docs`（文档站）、`collab`（协作站）之一，说的是用途，不是装了哪些功能：测试站装了全部功能，`kind` 仍是 `collab`。装了哪些功能看 `package.json` 的依赖
- `audience` 是 `personal`（只有自己在本机看）或 `shared`（别人也会 clone 下来看）。一个站会给谁看，它就只能依赖那些人都拿得到的东西：`personal` 的站可以读工作台插件提供的本机目录，`shared` 的站只读自己目录里的文件。协作站只能是 `shared`。站点运行时经站点上下文的 `audience` 读到它，功能包按它决定读哪里的数据
- `format` 是布局代号，现在是 `2`。布局再变时加一，读到不认识的号直接报错、写明用 gwb-docsite 的 `docsite.site.upgrade` 列出要照模板改的文件，不自动搬
- 写坏了就报错，写明哪一项不对：不是 JSON、`kind` 不在三个值里、`audience` 缺了或不在两个值里、协作站写了 `personal`、`format` 不对、多了认不出的键

`createSite` 不写它：建站的一方建完站接着调 `writeSiteIdentity(siteDir, kind, audience)` 写一次，之后归站点。gwb-docsite 的 `docsite.site.init`、`docfirst.create` 分别写 `base`、`docs`，`audience` 由调用的人给；gwb-collab 的 `collab.site.init` 写 `collab` 与 `shared`。gwb-docsite 托管前、gwb-collab 认协作仓都只看它，没有这个文件的站（旧平台 docsite-kit 建的站、有身份文件之前建的站）不认。模板的 `app/lib/site.server.ts` 在站点加载时经 `./server` 的 `siteAudienceOf` 读它，写错了站点起不来。

## 功能目录里的五种文件

这一节写给功能包作者。五种文件各能导出什么、平台怎么用：

| 文件 | 能导出 | 进哪份汇总文件 | 站点里谁用 |
| --- | --- | --- | --- |
| `routes.ts` | 默认导出（嵌在整站布局里的路由）、`standaloneRoutes`（布局之外、占满窗口） | `routes.generated.ts` | `app/routes.ts` |
| `feature.tsx` | `FeatureRuntimeModule` 的六样，都可选：`mdxComponents`、`pageTreePlugins`、`linkKinds`、`sidebarLinks`、`layoutData`、`LayoutTop` | `runtime.generated.ts` → `siteFeatureRuntime` | 布局路由、`app/lib/source.ts`、`app/lib/mdx-components.tsx` |
| `mdx.ts` | `remarkPlugins`、`rehypePlugins`、`collections`（集合工厂，名单写在包的 `package.json` 的 `godDocsite.collections`） | `mdx.generated.ts`；有集合的再进 `collections.generated.ts` | `source.config.ts`、`app/lib/mdx-plugins.ts` |
| `styles.css` | 样式 | `styles.generated.css` | `app/app.css` |
| `site.server.ts` | `sections`（侧栏分区，见下面「侧栏分区」）；别的导出只给功能自己的路由 import，汇总文件不管 | 导出了 `sections` 才进 `server.generated.ts` | 布局路由的 loader |

{/* ref file="../packages/god-docsite/src/node/scaffold/feature-index.ts" lines="154-238" hash="b7db776ccfdf" blob="98f876f836b7" */}

合并规则三条：

- `feature.tsx` 会进浏览器：不能 import `.server` 模块或 Node 内置模块，`layoutData` 要的服务端数据只能经第二个参数 `base`（站点上下文）取；它的返回值以功能名为键并进布局数据。
- 两个功能导出同名 MDX 组件时报错；侧栏入口按 `order` 排，同样大的按功能名。
- 集合工厂收一份全站插件 `sitePlugins` 并进自己的选项；`source.config.ts` 用 `export *` 再导出 `collections.generated.ts`，因为 fumadocs-mdx 要求那份文件只导出集合。
- `site.server.ts` 只在服务端加载、可以读盘；`server.generated.ts` 只由布局路由的 loader 用，它 import 的都是 `.server.ts`，浏览器端误引用时 React Router 直接报错。

## 侧栏分区

功能要在侧栏里列不在 `content/` 里的东西（论文库的论文、资料库的视频）时，在 `site.server.ts` 导出 `sections(site)`，回若干个分区。每个分区有名字 `name`、先后 `order`、检索页 `searchUrl` 和条目 `entries`；条目有三种：

- **一页**：`name` 加 `url`
- **一组**：`name` 加 `children`，做成不带 index 的文件夹，首页由功能作为第一个子项给出。带 index 时首页既是文件夹又是子项，上一页、下一页会把它算两次
- **分隔线**：`separator` 是线上的字，按视频、知乎、书籍分段时用

{/* ref file="../packages/god-docsite/src/site/site-sections.ts" lines="4-21" hash="478b66ebf193" blob="553caf0d92f4" */}

布局路由的 loader 每次请求经 `siteLayoutData` 把各功能的 `sections` 调一遍，所以条目变了刷新页面就跟上；算得慢的由功能自己按文件修改时间缓存。平台把每个分区换成页面树里的一个 `root` 文件夹，接在内容目录的顶层之后，按 `order` 从小到大排，相同时按功能名、再按分区名；文件夹最上面一项由平台加成「检索」，指向 `searchUrl`，所以各功能的分区开头都一样。因为是 root 文件夹，目录切换按钮里多一项，当前页在分区里时侧栏停在这一组。分区里的页也并进站内地址到标题，正文里指向这些页的链接显示成带标题的小卡片。

{/* ref file="../packages/god-docsite/src/site/layout.server.ts" lines="38-55" hash="1eef29b41ba7" blob="813a3afc2296" */}

分区放在 `site.server.ts` 里，而不是 `feature.tsx` 的页面树插件里：页面树在 `loader()` 建起时只算一次、只含 `content/` 里的页，元数据变了也不更新；`feature.tsx` 又会进浏览器，不能读盘。

## 引用扫描与自包含检查

正文里用组件引用别处的条目（`<Paper id="…">` 引用一篇论文）时，哪些条目被用到、本站有没有，由平台统一扫，不由各功能包自己扫：条目的页面里也会引用别的功能包的条目，只扫自己组件的功能包看不到这种引用。功能包只告诉平台两件事。

一是组件名，写在功能包的 `package.json` 里：

```json
{ "godDocsite": { "references": { "components": ["Paper"] } } }
```

二是 `./node` 出口导出的两个函数（类型 `ReferenceResolverModule`，从平台包的 `.` 出口取）：`resolveReference(id, place)` 回这一条在本站的 mdx 文件，本站没有回 `undefined`；`publishHint(id, siteDir)` 回本站缺这一条时怎么补的一行。`place` 是 `{ siteDir, audience, providedDirs }`，`shared` 站只在站点目录里找，个人站在托管方提供的目录里找。组件名和这两个函数登记在 `package.json` 与 `./node`，而不在接线文件里，是因为命令行和 build 时的检查不经 Vite，加载不了接线文件。

`./node` 出口的 `siteReferences(place)` 从内容目录 `content/` 的全部 mdx 出发：每个文件只解析成语法树（不编译），按「路径 + 修改时间 + 大小」缓存；收集名字是已登记组件的 JSX 元素，交给登记它的功能包的 `resolveReference`，回了文件就接着扫那些文件，直到走完。回 `{ references, missing, problems }`：

- `references` 与 `missing` 每条是 `{ component, id, from }`，`from` 是写这处引用的文件
- `id` 没写、写成表达式，或文件解析不了，记进 `problems`
- 只扫从内容页走得到的页面，所以个人站提供了整个库，用到的也只是内容页引用的条目和它们再引用的条目；代码块里写的组件例子不是 JSX 元素，不算引用
- 一个组件名只许一个功能包登记，两个包登记了同一个名字时报错写明是哪两个

{/* ref file="../packages/god-docsite/src/node/references.ts" lines="136-176" hash="18e9627376fb" blob="2f82617f13e3" */}

站点上下文的 `references()` 每次调用都按现在的文件重扫，同时来的调用共用一次扫描：一次请求里布局 loader 同时调各功能的 `sections`，它们取到的是同一份结果。

**自包含检查**是在 `shared` 站上跑一次扫描：`missing` 与 `problems` 每条一行，写明哪个文件引用了哪一条、功能包给的补法；个人站不查。它在两处运行：vite 插件的 `checkSelfContained`（build 没过就停下，dev 只报进问题按钮），与命令行 `docsite-check`（在站点目录里运行，同时查内容放法，有问题退出码 1）。

## 三种页面进一棵页面树

站点的 `app/lib/source.ts` 把三种页面来源交给同一个 fumadocs `loader`，键是 `mdx`、`tsx`、`html`——这个键就是每一页的 `type`，所以三种页面在同一棵页面树、同一个搜索索引里。`import.meta.glob` 的参数要能静态分析，只能写在站点模块里；平台的 `tsxPageSource`、`htmlPageSource` 只把 glob 的结果换成虚拟文件。

## 外部 mdx 页

论文的排版稿、资料的笔记这类 mdx 不在 `content/` 里，进不了页面树，功能包用自己的路由显示它们。平台给四样，功能包的路由文件只写几行：

| 工具 | 出口 | 做什么 |
| --- | --- | --- |

写法和内容页一样：同一套插件，组件表是站点的 `mdxComponents` 再加上这类页才有的组件，`{…}` 表达式、`$…$` 公式照常。不一样的有两处：

- **图只能放在 `rootDir` 里**：Markdown 图片与 JSX 元素上写成字符串的 `src`，相对地址按 mdx 文件所在目录解析，再经 `assetsHrefOf` 换成功能包文件路由的地址；越出 `rootDir` 就编译不过，因为没有路由能把文件夹外的文件送出去。
- **不能写 `import`**：这些文件不在 Vite 的构建里，没有东西替它打包被引用的文件。编译时就拦下，报错写明要共用的组件放进功能包或平台的组件表。

## 站点上下文

站点的 `app/lib/site.server.ts` 造一个 `site`，平台与功能包的 loader、action 都经参数拿到它，自己不 import 站点代码。字段：站点目录、`mode`（`dev` / `start`）、`audience`（身份文件写的给谁看，站点加载时读一次）、loader 结果 `source`（平台只用到它的四个方法：`getPage`、`getPages`、`getPageTree`、`serializePageTree`，页面是三种来源之一）、内容目录、评论目录与评论条目，以及每次调用都重新读取的八个函数——人员列表、本机身份（dev 按托管方上下文里的身份码认人，没有就只读；start 一律只读）、可信来源、推送通道某频道现在的值、托管方上下文、托管方提供的本机目录、全站的 remark 与 rehype 插件（用到时才加载，外部 mdx 页按它编译）、引用扫描的结果（同时来的调用共用一次扫描）。功能包模板里的 `site.server.ts` 从它组装本功能要的上下文。

同一地址 GET 回这个频道现在的值（还没推过是 null）；协议的常量两边都从平台包的 `.` 出口取。

订阅地址的最后一段可以写逗号隔开的几个频道（`/__docsite/feed/collab,collab-submit`），一条事件流收这几个频道，每条事件的 data 是 `{"channel":频道,"data":值}`；只写一个频道时 data 就是值本身，gwb-docsite 订阅用的就是这种。读现在的值、推送一次只能一个频道。

浏览器这边，一页里所有 `useSiteFeed` 合用一条事件流，页面隐藏时断开、重新显示时再连。原因是 Chrome 对同一个协议、主机、端口的 HTTP/1.1 连接整个浏览器合起来最多 6 条，长连接占着名额，再点链接、刷新的请求只能排队，站点就像打不开了；这样一个站只占「看得见的页数」条。频道只留最新一份、连上先发现在的值，所以后台页断开不丢状态。一页里后来新要的频道会让这条流重连一次，要的频道只增不减。

反过来，站点要启动方替它做事时也走这条通道：启动方（gwb-docsite）带着同一个令牌订阅事件流，站点就知道有人在听这个频道（`siteFeedHasLauncher`）；站点自己的服务端代码用 `publishSiteFeed` 往频道里写一份请求，在听的启动方收到后去做，做到哪一步再推回同一个频道。浏览器订阅不带令牌，不算启动方；令牌不对 403。协作站的一键提交就是这样：网页写 `requested`，gwb-collab 接手提交审核，再推回 `running`、`merged`（见 collab 包页）。

## 托管方上下文

托管站点的 gwb-docsite 把自己知道的事合成一份，推进推送通道的频道 `host`，站点每次请求读频道里现在的值，不读环境变量、不读文件：

```json
{ "format": 1, "identityCode": "<本 home 的身份码>", "dirs": { "papers": "<绝对路径>" }, "readerFonts": { "body": "…", "heading": null, "mono": null } }
```

- `readerFonts`：读者选的三项字体，见下面「阅读字体」

推送时就核对：频道 `host` 收到的值不是这个形状（不认识的字段、`format` 不对、字体名里有放不进 CSS 的字符），推送回 400 并写明哪一项，频道里的值不变。没推过（手动 `pnpm dev`、发布版、测试站）时三样都是空：只读、没有本机目录、默认字体。gwb-docsite 在开发服务报出地址之后、`docsite.site.start` 回执之前推第一次，所以站点收到的第一个请求就有上下文；身份码、字体或提供的目录变了再推，不用重启站点。

## dev 下页面怎么跟着变、问题怎么报

开发服务和浏览器之间本来就有一条 Vite 的热更新连接（WebSocket）。平台不另开连接，下面这些事都走它，浏览器这一边放在平台的两个布局（文档页的 `SiteLayout`、首页的 `SiteHomeLayout`）和根路由的错误页里，所以站点模板不用改，发布版里这些代码什么也不做。事件名与载荷类型在 `core/dev-events.ts`，两边共用。

**站外改了数据，页面就地更新**。任务记录、日志这类数据由功能的 loader 直接读文件，不在 Vite 的模块图里：agent 调命令改了、git 同步进来了，已经打开的页面原本不会变。功能包在自己 `package.json` 的 `godDocsite.dataDirs` 里登记这些目录（相对站点根，协作包登记 `../collab` 与 `journal`），vite 插件启动时读站点直接依赖的每个包，把这些目录加进文件监视；有改动就等 0.3 秒、把这段时间里的改动合成一次，再发一次 `god-docsite:data-dirs-changed`。浏览器收到后调 React Router 的 `revalidate()` 重新跑当前页的 loader，数据就地换掉，不整页刷新，表单与展开的评论都还在。

{/* ref file="../packages/god-docsite/src/vite/data-dirs.ts" lines="54-76" hash="f49071bba5a6" blob="cf8abbffb21c" */}

**问题按钮**。dev 下的问题不再弹 Vite 的全屏报错层，而是在页面顶上正中显示一个带数字的小按钮，点开分四组列出，每条再点开看完整原话。顶上正中那一行是平台的 `TopNotices`：问题按钮排在最前，各功能的 `LayoutTop`（协作站的提示栏）跟在后面，放不下就折行；两边点开的列表都显示在这一行正下方、按视口居中，不挤动旁边的按钮。这一行撑满视口宽、本身不接鼠标，所以 `LayoutTop` 的按钮自己写 `pointer-events-auto`，点开的列表写 `absolute inset-x-0 top-full mx-auto`：

| 组 | 从哪来 | 什么时候消失 |
| --- | --- | --- |
| 内容放法 | 下面「内容目录的放法」的检查结果 | 放好后自动消失 |
| 引用了本站没有的条目 | `shared` 站的自包含检查结果，每处一条，标题是写这处引用的文件 | 补上后自动消失 |
| 改代码后编译失败 | Vite 推来的 `vite:error`（文件、行列、代码片段、调用栈） | 下一次热更新成功时 |
| 浏览器里的报错 | `window` 上没接住的 `error` 与 `unhandledrejection`，同样的原话只留一条、最多 20 条 | 人点「清空浏览器报错」 |

问题清单存在模块里、不放在组件状态里：页面渲染不出来时布局卸载、换成错误页，清单不丢，错误页会把开发服务报的原因（哪个文件第几行写错了）放在最上面——浏览器这一边这时只拿到一句「动态导入失败」。改好以后页面自己恢复。

**只在打不开时整屏提示**。开发服务断开（崩溃或正在重启）时整页显示「开发服务断开了」，连回来后 Vite 自己刷新页面；页面在服务端就渲染不出来时，开发服务回的是 Vite 自己的 500 报错页，本来就是整页，不受关掉报错层的影响。

## 阅读字体

正文、标题、代码三种字体是每个读者自己的设置：读者在 gwb 设置里选，经 [gwb-docsite](/plugins/gwb-docsite) 交给它托管的每个站，站点本身不指定字体。这一节讲站点这一边：三个 CSS 变量的约定，和根路由怎么把读者选的字体写进页面。

**三个变量就是全部约定**：正文 `--font-sans`、标题 `--font-heading`、代码 `--font-mono`。fumadocs 自己的 CSS 不设字体，全靠 Tailwind 的基础样式：`html` 用 `--font-sans`，`code`、`pre`、`kbd` 用 `--font-mono`，所以换这两个变量，fumadocs 的组件就跟着变。标题的变量由平台的 `styles.css` 声明，默认等于正文字体，h1–h6 都用它：

{/* ref file="../packages/god-docsite/styles.css" lines="78-90" hash="224f5bbd2d39" blob="c189388c0c4d" */}

各包的组件只写 `font-sans`、`font-heading`、`font-mono` 三个类或这三个变量，不写字体名；讲解组件的 `--dx-mono` 就是 `var(--font-mono)`。仓根 `pnpm test:fonts`（`tests/font-family-check.mjs`）扫 `packages/` 下的 css、ts、tsx，`font-family` 声明、名字里带 font 或 mono 的 CSS 变量、React 的 `fontFamily`、SVG 的 `font-family` 属性与 Tailwind 的 `font-[…]` 类里写了字体名就失败；`var(…)` 里的后备串不算。唯一的例外是报告页（word-report 的 `report.css`）：它照导出 Word 用的模板排版，正文与标题固定用模板的字体。KaTeX 公式也用它自己的字体，不跟变量走。

**根路由把读者的字体写进 `<head>`**。读者选的字体在托管方上下文的 `readerFonts` 里；模板的 `app/root.tsx` 有一个 loader 调 `readerFontsCss()`，`Layout` 把回来的 CSS 放进 `<style>`。放在根路由是因为首页与功能的独立页面不在布局路由里；出错页也用 `Layout` 渲染，那时没有 loader 数据，就不出这段 CSS：

{/* ref file="../packages/god-docsite/template/app/root.tsx" lines="8-25" hash="e7a1e7a0528f" blob="1f3f6c78dc6e" */}

`readerFontsCss()` 在没推过上下文时回 `null`（手动 `pnpm dev`、发布版、测试站都是这样，用站点默认字体）。改了字体，gwb-docsite 重推上下文，vite 插件让浏览器重新取数据，页面不用刷新就换上新字体。

转成 CSS 的规则在 `src/core/reader-fonts.ts`，gwb-docsite 拼上下文、站点收上下文用的是同一份：`body`、`heading`、`mono` 各是字体族名或 `null`；名字里有引号、反斜杠、分号、花括号、尖括号或控制字符就拒绝，免得跳出 CSS 字符串或 `<style>`。只写设了的项，名字后面接一串通用后备字体，选的字体里没有的字（英文字体里的中文、emoji）浏览器逐字往后找：

`<style>` 不在任何 `@layer` 里，比 Tailwind 主题层里的同名变量优先，直接覆盖默认值。

已经建好的站，`app/root.tsx` 归站点自己，模板改了不会自动跟上：在 `root.tsx` 里照模板加上 `loader` 与 `<style>` 那几行，再把平台包升到带 `readerFontsCss` 的版本。没加的站照常运行，只是不跟读者设的字体。

## 错误页

根路由的错误页 `SiteErrorBoundary`：404 写明是哪个地址或 loader 给的原因（没有路由匹配时 React Router 自己造的 404 只带英文原话，这时写成「这个地址没有页面」），其余错误显示原话与调用栈；底下一个「回首页」，浏览器里有上一页时再给一个「返回上一页」。

## 其余能力

- **布局与侧栏**：整站布局是 fumadocs 的 `DocsLayout`；目录切换按钮按 `meta.json` 写了 `"root": true` 的文件夹生成，不在任何一组里的页面归进以站名命名的一组；在任务、全站评论这类不在页面树里的功能页面上，侧栏显示最近看过的那一组。站名下一横排是搜索按钮与各功能的侧栏入口。
- **首页**：`app/routes/home.tsx` 在整站布局之外、地址是 `/`，内容目录根上不能再写 index 页；「文档」链接指向第一组的第一页。
- **MDX 组件**：站点的 `mdxComponents` 合并 fumadocs 的默认组件、平台的 `siteMdxComponents` 与各功能导出的组件。平台的有 fumadocs 的排版组件（`Accordions`、`Tabs`、`Steps` 等）、术语标注的 `Term`、点了能放大的 `ImageZoom`（Markdown 图片也换成它），以及排图用的 `Figure`（一张图加图注，`width` 是占正文宽度的百分比）、`FigureRow`（几张图等宽并排，容器窄了改成上下排）与 `FigureRowCaption`（含公式的总图注，只能是 `FigureRow` 的最后一个子元素）；写错了直接报错并说明该怎么写。
- **TSX 与 HTML 页面**：TSX 页的标题、描述、搜索文字来自它导出的 `meta`；HTML 页的标题取 `<title>`，只有写了 `id` 的标题才进目录与搜索锚点。
- **内容目录的放法**：组文件夹只放页面、`meta.json`、页面的同名文件夹、下划线开头的文件夹与子组，同名文件夹里不放页面。build 放错了就报错停下；dev 只报不拦（别人提交了一个放错的文件，不能让每个人的站都起不来）：启动时查一次，运行中增删文件或文件夹后攒 0.3 秒再查，结果变了才在终端打印、列进问题按钮，刚打开的页面向开发服务要一次当前结果。重查途中子文件夹被删掉（git 改名、挪目录时一次删几百个文件）按已经不存在算；读目录出了别的错（文件被占用、权限）报成「这次没查成」并写明原因，下次增删文件再查，开发服务不退出。gwb-collab 的提交审核用 `./content-layout` 出口的同一份规则，在进 main 之前拦下放错的文件。
- **搜索**：中文站点把 fumadocs 搜索的容错与命中阈值都设成 0，每个词都要原样出现。
- **Markdown 与 llms**：每一页都有 Markdown 形式（MDX 走 `getText('processed')`，TSX、HTML 页在来源数据里），`/api/markdown`、`llms.txt`、`llms-full.txt` 用它；构建时只预渲染两份 llms 文本。
- **术语标注**：站点根的 `glossary.json` 列术语；构建时长词优先、西文要词边界、一篇只标第一次，代码、公式、标题、链接里不标，所以排在 `remark-math` 之后。
