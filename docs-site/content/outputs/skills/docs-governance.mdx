# 文档与注释治理

**总纲是三层分流**（正本在各仓 AGENTS）：AGENTS 只装硬约束；文档站装「为什么」；注释只装
现状。下面四类手术都是把放错层的东西归位——小到一个模块只用手术一，大到整仓或全生态
就在外面套治理循环。

## 手术一：代码自解释扫描

**一个文件读一遍，四件事同时做**：注释怎么处置、名字够不够长、函数该不该拆、有没有设计
思路要搬进文档。分成几轮扫会让同一批文件被读好几遍，而读代码是这整件事里最贵的一步。

范围一次一个模块，不要全仓一把梭——改动越大，「没改行为」越难证明。

### 注释三分法

读到一条注释，只有三个去处：

**搬去文档**：讲为什么这么切、否掉了什么、边界在哪、这个取舍的代价是什么。这些是设计
思路，属于文档，不属于代码。搬走之后**文档必须钉回这段代码**，否则你只是把漂移换了个
地方发生。

**删掉**：复述代码在干什么的（`// 遍历列表` 上面跟着一个 for）、写着「原来是 xx 现在是
yy」的、写给某次调试的、注释掉的旧代码。历史归轨迹卡，git 记得住，代码里留着只会骗人。

**留下**：真正的现状约束——不变式、外部契约（那个 API 会回 null）、踩过的坑（这里不能用
map，会吞掉 undefined）、以及为什么这段看起来蠢的写法是必要的。留下的写成一行，只写现状。

判据一句话：**删掉这条注释，读者会做出错误的判断吗**？会就留或搬，不会就删。

### 搬去哪一梁

- 模块怎么切、依赖往哪个方向、接口的语义与边界 → **模块页**（设计梁）
- 一次选择、否掉了什么候选、判据是什么 → **轨迹卡**（choice 形态，一次了断一张）
- 怎么用、命令与配置 → **用法页**
- 一个词在这个仓里的确切含义 → **术语表**

哪一梁住哪一区、每页写到哪为止，正本在 `docfirst-docs` 的「五梁一横」。搬完检查一遍：
模块页的「不知道什么」那段是不是变厚了？注释里最值钱的往往正是这类边界陈述。

顺手订正撞见的过期注释（报错文本还说旧话、头注还写着退役机制）——它们跟「写历史」一样
骗人，只是方向相反。

### 命名

**长度无所谓，清晰才算数。** 忌讳短得像很优雅、其实说不明白自己的名字。一个名字要能回答
「它是什么 / 它做什么 / 什么时候用它」里的至少一个。

- 变量：`d` → `daysSinceLastConfirm`
- 函数：`check()` → `checkPlacementsAgainstDisk()`
- 布尔：加上它为真时的含义，`ok` → `everyPinIsFresh`
- 集合：复数加上它装的是什么，`items` → `driftedReferences`

改名不顺手改逻辑。这是两次改动，混在一起就没人能复核。

### 拆函数

**拆到每个函数名就是它的注释。** 一个函数里出现「这一段在干 X」这类注释，那一段就该是个
叫 `X` 的函数。拆完之后原来的注释自然消失——不是被删掉，是被名字吸收了。

判据：读函数体时需要在脑子里给某几行起个名字，就把那个名字变成真的。嵌套超过两层、或者
一个函数要滚屏才看得完，通常是没拆够。但不要为拆而拆：**只在能起出一个诚实名字时才拆**，
起不出名字说明那几行还没形成一个概念。

### 怎么证明没改行为

**测试先绿，改完还绿，测试本身一个字不改。** 这是唯一的证据。测试要改，说明你改的不只是
形状。没有测试的模块，先补测试再重构——补测试时用的是现在的行为，不是你以为的行为。

提交分两笔落：**文档改动**（搬进去的页 + 钉码，过文档门禁）与**代码改动**（瘦身、改名、
拆函数，过测试）——它们的验收面不同，出问题时也要分别回退。

## 手术二：术语改口

黑话退出现状面，换成正常中文表述：

- 单字黑话逐句换：件→插件、井→窗格容器（首现挂注 well / 代码模块名）、口→端口/入口/张、
  格→窗格、档→布局文件、照片→快照、门→入口、皮→皮肤、刀→第 X 阶段、枚→个
- **禁机械替换**：「文件 / 事件 / 条件 / 接口 / 六件事 / 口径」是正常词；「格」按义分流
  （窗格实例 / 数据目录 / 记录字段→「那个字段」）
- 不动：命令名、包名、代码标识符、模块名（`well-hub`）；UI 字面名引号钉住（代码没改时
  文档跟代码走）
- glossary「退役的词」一节收编旧词对照；**改口本身落轨迹卡**（名字定了就别改口——改口是
  历史）；扫描模式里别漏「枚」这类量词

## 手术三：历史出清

现状页只写现状。规则与一句话理由留下；日期叙事、改名史、事故故事、版本演进史删——
轨迹区已有对应卡的直接删（正本在卡里），确有长期判据价值又无卡可收的才新建卡。walls 页
的教训本体（症状与判据）不动，只换术语。轨迹区只增不改，旧卡里的旧词与悬空内链是历史
快照，接受。

## 手术四：所有权重分家

每仓只写自己实现的东西。判据（正本在各仓轨迹卡 docs-ownership-split）：

1. **所有权**：谁实现谁写正本
2. **行为归做的人，契约归定的人**：接口两端各写各的半边，不算复述
3. **边界声明是自己的**：「内核一条原生命令都没有」这类否定句留在家，不带指路尾巴
4. **跨仓钉不了码**：没有钉码又讲别人机制的段落，正本变了不会黄——就是漂移候选

教程与手册（写插件手册那类）允许引用+一句概括+指路，不复述完整定义；边界声明式整页
（如站件与 docfirst 的边界页）合规。

## 治理循环（整仓以上时套在手术外面）

1. **冻结期先对齐**：三扫侦查（黑话字符模式含枚、日期与版本号信号、别人机制的关键词），
   摆判据与方案，AskUserQuestion 收范围/幅度/判据，等用户说 go
2. 对照表落总控台 `out/`（工作底稿，gitignore；长期正本落各仓 glossary 与轨迹卡）
3. **最小仓试刀**交用户验收样式，再铺开
4. 同构任务（如逐仓术语替换）并行子代理，派单带：先读该仓 AGENTS、对照表、样板仓；
   异构手术（逐处判断的）自己做
5. 每仓验证链：`pnpm doc` → `confirm`（钉码变动、删页清死账）→ `render` 重摆生成物 →
   复查全绿 → 仓根门禁 → `git add` 精确路径 + `git commit --only`
6. **复核不信子代理自述**：rg 复扫（黑话模式+白名单）、轨迹只增核对、并行会话中途落的
   新提交要重扫（别人会带进新黑话）
7. 收尾扫各仓 feedback/inbox；点名别人在途的红黄，不替人收

## 坑（实战撞过）

枚字漏网｜字段义「格」≠窗格义「格」｜注释瘦身引起全下游钉码行移要 confirm｜render 脚本名
各仓不一（读该仓 scripts，有 `doc:render` 也有直调 `docfirst render`；`--target` 是旧包线开关、
现被静默忽略，别写；且 `doc` script 有的在仓根有的在 docs-site）｜删文档页 confirm 清死记录｜AGENTS/README/SKILL 是
生成物，只改 outputs 正本｜「行为零改变」的注释提交也先绿后绿｜改完顺手订正撞见的过期
事实（如退役命令还在被文档引用）｜并行会话在同一仓活跃时，别人未提交的改动不看、不收、
不回退
