报告是功能包 `@godcreator/word-report` 提供的。一份报告是 `reports/<报告 id>/` 下的一组文件，网页上整份显示成一页，也能用本机的 Word 导出成 docx 和 pdf，两边读的是同一份数据。

正文有两种写法：**MDX**（新写的报告用它）和 **JSON**（`docreport` 格式）。MDX 报告读进来先编译成和 JSON 报告一样的一份文档，之后的检查、网页、导出完全一样。一个报告目录里只能有其中一种。

## 装上报告功能

```text
docsite.feature.add  {"dir":"<站点目录>","package":"@godcreator/word-report"}
```

装上以后，侧栏横排里多一个「报告」入口。任何站点都能装，协作站建站时不默认带。

## 文件放在哪

报告放在站点根下的 `reports/<报告 id>/`，不放进 `content/`，所以报告不出现在文档目录里。报告 id 是网址的一段，只用小写字母、数字和 `-`；MDX 报告的目录名还要以字母开头。

### MDX 报告

| 文件 | 内容 |
| --- | --- |
| `index.mdx` | 入口：文件头写标题、语言、版本、日期、作者、封面字段与章节列表 `chapters`；正文放摘要 |
| `c1.mdx`、`a1.mdx` …… | 各章，文件名随意，按 `chapters` 的顺序接在入口正文后面；都放在报告目录根上，不放子目录 |
| `references.mdx` | 可选：文献列表 |
| `assets/` | 图片，只能是 png 或 jpg；正文里写 `assets/<文件名>` |
| `layout.json` | 可选，只给 Word 用的版式，和 JSON 报告一样 |

### JSON 报告

| 文件 | 内容 |
| --- | --- |
| `content.json` | 入口：标题、版本、日期、作者、封面上的字段；正文按顺序用 `include` 引入各章 |
| `chapters/<章>/content.json` | 一章，它本身也是一份完整的报告文档 |
| `chapters/<章>/assets/` | 这一章的图片，只能是 png 或 jpg；正文里写 `assets/<文件名>` |
| `layout.json` | 只给 Word 用的版式：按块的 id 写宽度、最小行高、分页、横版，网页不读它 |

不分章的 JSON 报告就只有一个 `content.json`，正文直接写在里面。

## MDX 写法

普通内容照 Markdown 写；图、表、引用这类要编号的东西，以及在 Word 里写成文字的行内公式，用几个固定的组件，名字都以 `Word` 开头，只在报告里用。编译器只解析、不执行 MDX，下面没列的写法一律报错，报在哪个文件的第几行第几列。

一份最小的报告：

````mdx title="index.mdx"
---
title: 10 kV 固态变压器初步设计报告
language: zh-CN
revision: V0.1
date: 2026-10-17
chapters: [c1.mdx]
---

<WordAbstract keywords="固态变压器；双有源桥">

摘要正文。

</WordAbstract>
````

````mdx title="c1.mdx"
# 主电路设计 [#c1]

单元额定功率见<WordRef to="tab-unit" />，由<WordRef to="eq-pcell" />算出<WordCite to="ref-iec" />；
单元直流电容 <WordPlainMath tex="C_1">*C*<sub>1</sub></WordPlainMath> 的电压纹波取 $\Delta V/\sqrt{2}$。

```math eq-pcell
P_{cell} = \frac{P_N}{3N_{on}}
```

<WordTable id="tab-unit">
  <WordCaption>功率单元额定参数</WordCaption>

| 参数 | 数值 |
| --- | --- |
| $P_{cell}$ | 69.4 kW |

</WordTable>

<WordFigure id="fig-main" src="assets/main-circuit.png">主电路</WordFigure>
````

````mdx title="references.mdx"
<WordReference id="ref-iec" url="https://example.com/iec">IEC 61800-5-1:2022[S]. Geneva: IEC, 2022.</WordReference>
````

### 块

| 写法 | 是什么 |
| --- | --- |
| `#`、`##`、`###` | 节，`#` 是章；标题末尾可写 `[#id]` 给节一个固定的 id。标题里只写文字，不跳级 |
| 段落、`-` 列表、`1.` 列表 | 段落与列表 |
| ` ```math ` 或 ` ```math <id> ` | 编号的公式 |
| `$$ … $$` | 不编号的公式，不能被引用 |
| ` ```<语言> ` | 代码块 |
| `<WordFigure id? src alt?>图题</WordFigure>` | 一张图；不写 `alt` 时取图题的纯文字 |
| `<WordFigures id? rows columns>`，里面一个 `<WordCaption>` 和若干 `<WordPanel id? row column label src alt?>小标题</WordPanel>` | 一个图号下的多张图，每张写明第几行第几列和编号 |
| `<WordTable id?>`，里面先写可省的 `<WordCaption>表题</WordCaption>`，再写一张 GFM 表格 | 编号的表格 |
| `<WordTable>` 里写小写的 `<table>`、`<tr>`、`<th>`、`<td rowSpan colSpan>` | 有合并单元格的编号表格；开头全是 `<th>` 的行是表头 |
| 不在 `<WordTable>` 里的 GFM 表格 | 不编号、没有表题的表格 |
| `<WordAbstract keywords="甲；乙">段落</WordAbstract>` | 摘要，只写在 `index.mdx` 正文最前面；关键词用全角分号隔开 |
| `<WordBibliography />` | 可选，参考文献的位置，不写时放在文末 |
| `[^id]` 与 `[^id]: …` | 脚注；定义要和引用写在同一个文件里 |

章文件的文件头只能写 `numbering: appendix`（附录）或 `numbering: none`（不编号），作用于这个文件的一级标题，下级随上级。
组件的属性都写成字符串（`rows="2"`），不写成 `{…}`；正文里要写花括号或小于号就写成 `\{`、`\<`；注释写成 `{/* … */}`。

### 行内

| 写法 | 是什么 |
| --- | --- |
| `**加粗**`、`*斜体*`、`` `代码` ``、`<sub>`、`<sup>` | 文字的样式，可以嵌套；加粗或斜体的内容以标点开头或结尾时（如 `**（1）方案**`），`**` 在中文旁边读不出来，改写 `<strong>…</strong>`、`<em>…</em>` |
| `$…$` | 行内公式，Word 里插成 MathType 对象 |
| `<WordPlainMath tex="C_1">*C*<sub>1</sub></WordPlainMath>` | 在 Word 里写成文字的行内公式：网页按 `tex` 显示，Word 照组件里的文字写；组件里只能写文字、`*斜体*`、`<sub>`、`<sup>` |
| `<WordRef to="id" />` | 交叉引用，显示「图 3-2」「表 1-1」「式（2-3）」「第 2.1 节」；加 `show="number"` 只显示编号，`show="title"` 显示标题 |
| `<WordCite to="ref-a ref-b" />` | 文献引用，几个 id 用空格隔开 |
| `[文字](https://…)` | 链接 |
| `<br />` | 换行 |

段落里的换行两边都是中文时直接连上，否则换成一个空格。

### id

- **要引用、或要在 `layout.json` 里调版式的才写 id**，起一个看得懂的名字（`fig-main`、`tab-unit`），以后一直用它。id 以字母开头，只用字母、数字、`_` 与 `-`，不以 `auto-` 开头
- 其余的 id 由编译器按内容生成（`auto-p-1x2y3z` 这种），不写回文件：同样的内容每次得到同样的 id，段落改了字 id 就变，针对这一段的评论随之对不上


## 网页上怎么看

| 地址 | 显示什么 |
| --- | --- |
| `/reports` | 报告列表：每份一行，写标题、版本、日期、作者、章数，以及检查的结果 |
| `/reports/<报告 id>` | 整份报告一页：各章按顺序接在一起，编号连着排；右侧目录列出前两层的节 |

- 每次打开都从文件现读：改了文件，刷新页面就能看到
- 读不对的报告在列表里照样列出来，「检查」一栏写出错的原话；打开它的页面直接报错
- 报告页能评论：和内容页一样，右下角「批注」「评论」，评论一段文字、一个元素或整页；全站评论页里也列出来
- 网页上没有导出按钮，只能用下面的命令行导出

## 检查

在站点目录里运行：

```bash
pnpm exec report-docx check
```

它核对每份报告的格式、引用、编号和图片，有问题时把原话列出来，退出码不是 0。加 `--json` 按 JSON 输出结果。

- MDX 报告整份检查一次，问题报在 MDX 文件的第几行第几列
- JSON 报告整份组装一次，每一章再单独组装一次；单独组装一章时，指向别的章的引用要写 `externalLabel`，否则报错

## 导出 Word

导出驱动本机的 Word 和 MathType 排版，所以只能在装了这两样的 Windows 上做。版式由 Word 模板 `engine/templates/project-report.dotx` 里的样式决定。

第一次用之前，在 Word 引擎目录里建好 Python 环境：

```bash
python -m venv .venv
```

```bash
.venv\Scripts\pip install -r requirements.txt
```

```bash
.venv\Scripts\pip install --no-build-isolation --no-deps -e .
```

最后一条把引擎自己装进环境，少了它导出时报找不到 `docreport`。

引擎目录默认是包里自带的 `engine/`。装进站点的包在 `node_modules` 里，路径很长，Word 插入图片时会因为路径超长报「这不是有效文件名」，所以要把 `engine/` 复制到一个路径短的固定目录、在那里建 `.venv`，再用环境变量 `DOCREPORT_ENGINE_ROOT`（或参数 `--engine`）指过去。

然后在站点目录里：

```bash
pnpm exec report-docx export <报告 id>
```

```bash
pnpm exec report-docx status <报告 id>
```

`export` 等这次导出做完，把结果按 JSON 输出，里面有 docx 和 pdf 的路径；`status` 只看状态，不启动 Word。导出结果放在引擎目录的 `out/` 下，附带自动核对的记录（页数等）；
版式还要人看一遍。报告在导出前固定成一份快照（MDX 报告是入口、各章、文献列表与图片），导出过程中改了文件不会混进这一次的结果。同一时间只能导出一份。

公式在 Word 里分两种，由源文件决定，引擎不自己判断：

- `<WordPlainMath>` 写成文字，照组件里写的斜体、上标、下标，字体 Times New Roman，应用字符样式「DR Inline Math」。只有字母、数字、一层上标或下标、单位和简单运算符的行内公式适合这样写，插 MathType 对象是导出里最慢的一步
- `$…$` 和全部行间公式插成 MathType 对象

网页上两种都由 KaTeX 按 TeX 显示。`<WordPlainMath>` 的 `tex` 与组件里的文字是两份，改公式时两边一起改，编译器不比对它们。
