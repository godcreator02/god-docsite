报告是功能包 `@godcreator/word-report` 提供的。一份报告是一组 JSON 文件，网页上整份显示成一页，也能用本机的 Word 导出成 docx 和 pdf，两边读的是同一份数据。

## 装上报告功能

```text
docsite.feature.add  {"dir":"<站点目录>","package":"@godcreator/word-report"}
```

装上以后，侧栏横排里多一个「报告」入口。任何站点都能装，协作站建站时不默认带。

## 文件放在哪

报告放在站点根下的 `reports/<报告 id>/`，不放进 `content/`，所以报告不出现在文档目录里。报告 id 是网址的一段，只用小写字母、数字和 `-`。

| 文件 | 装什么 |
| --- | --- |
| `content.json` | 报告的入口：标题、版本、日期、作者、封面上的字段；正文按顺序用 `include` 引入各章 |
| `chapters/<章>/content.json` | 一章，它本身也是一份完整的报告文档 |
| `chapters/<章>/assets/` | 这一章的图片，只能是 png 或 jpg；正文里写 `assets/<文件名>` |
| `layout.json` | 只给 Word 用的版式：按块的 id 写宽度、最小行高、分页、横版，网页不读它 |

不分章的报告就只有一个 `content.json`，正文直接写在里面。

### 文档格式

每个 `content.json` 的 `format` 是 `docreport`。正文由块组成：节、段落、列表、图、公式、表格、代码、摘要、参考文献；段落里有文字、行内公式、交叉引用、链接、脚注和文献引用。
每个块有一个随机的 id，交叉引用写目标的 id，编号都自动算。节按整份报告里的先后编；图、编号的表格和编号的公式按所在的顶层章各自从 1 编，写成「章号-序号」：
第 2 章的第 4 张表是「表 2-4」，附录 A 的第一张图是「图 A-1」、第一个公式是「式（A-1）」，网页和导出的 Word 一样。
所以图、编号的表格和编号的公式都要写在编号的章里（顶层的节，`numbering` 是 `decimal` 或 `appendix`），写在章外或不编号的章里直接报错。
字段的完整说明在包里的 `engine/schemas/report-content.schema.json`，例子是同目录的 `report-content.example.json`。

### 多图

一个图号下放几张图时，图不写 `src` 与 `alt`，改写网格的大小 `rows`、`columns`（各 1 到 6）和 `panels`（2 到 36 张）。每张图写明自己的位置和编号：

| 字段 | 写什么 |
| --- | --- |
| `row`、`column` | 放在第几行、第几列，从 1 起 |
| `label` | 图下显示的编号，不带括号：写 `a`，显示「(a)」 |
| `id`、`src`、`alt` | 和单张图一样 |
| `caption` | 可选，这张图的小标题，写在编号后面 |

网页照写的位置摆，不自动排列：各列等宽，没有图写到的格子留空，任何宽度下都不重排；编号也不自动编。
两张图写在同一格、格子超出网格、同一个图里编号重复都直接报错。整个图的图题照常写在图的 `caption` 里，排在最下面一行。田字格是 `rows: 2, columns: 2` 放 4 张：

```json
{
  "type": "figure", "id": "fig_waveforms", "rows": 2, "columns": 2,
  "caption": [{ "type": "text", "text": "四种工况下的电流波形" }],
  "panels": [
    { "id": "fig_waveforms_a", "row": 1, "column": 1, "label": "a", "src": "assets/light-load.png", "alt": "轻载电流", "caption": [{ "type": "text", "text": "轻载" }] },
    { "id": "fig_waveforms_b", "row": 1, "column": 2, "label": "b", "src": "assets/full-load.png", "alt": "满载电流", "caption": [{ "type": "text", "text": "满载" }] },
    { "id": "fig_waveforms_c", "row": 2, "column": 1, "label": "c", "src": "assets/startup.png", "alt": "启动电流" },
    { "id": "fig_waveforms_d", "row": 2, "column": 2, "label": "d", "src": "assets/fault.png", "alt": "故障电流" }
  ]
}
```

交叉引用写整个图的 `id` 显示「图 2-3」，写某一张的 `id` 显示「图 2-3(b)」，括号里是那张图的 `label`。导出 Word 还不支持多图：报告里有多图时导出直接报错，网页上照常显示。

## 网页上怎么看

| 地址 | 显示什么 |
| --- | --- |
| `/reports` | 报告列表：每份一行，写标题、版本、日期、作者、章数，以及检查的结果 |
| `/reports/<报告 id>` | 整份报告一页：各章按 `include` 的顺序接在一起，编号连着排；右侧目录列出前两层的节 |

- 每次打开都从文件现读：改了 JSON，刷新页面就能看到
- 读不对的报告在列表里照样列出来，「检查」一栏写出错的原话；打开它的页面直接报错
- 报告页能评论：和内容页一样，右下角「批注」「评论」，批一段字、一个元素或整页；全站评论页里也列出来
- 网页上没有导出按钮，导出只走下面的命令行

## 检查

在站点目录里运行：

```bash
pnpm exec report-docx check
```

它把每份报告整份组装一次，每一章再单独组装一次，核对格式、引用、编号和图片；有问题时把原话列出来，退出码不是 0。加 `--json` 按 JSON 打出结果。
单独组装一章时，指向别的章的引用要写 `externalLabel`，否则报错。

## 导出 Word

导出驱动本机的 Word 和 MathType 排版，所以只能在装了这两样的 Windows 上做。版式由 Word 模板 `engine/templates/project-report.dotx` 里的样式决定。

第一次用之前，在 Word 引擎目录里建好 Python 环境：

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

引擎目录默认是包里自带的 `engine/`。装进站点的包在 `node_modules` 里，建议把 `engine/` 复制到一个固定的目录、在那里建 `.venv`，再用环境变量 `DOCREPORT_ENGINE_ROOT`（或参数 `--engine`）指过去。

然后在站点目录里：

```bash
pnpm exec report-docx export <报告 id>
pnpm exec report-docx status <报告 id>
```

`export` 等这次导出做完，把结果按 JSON 打出来，里面有 docx 和 pdf 的路径；`status` 只看状态，不启动 Word。导出结果放在引擎目录的 `out/` 下，附带自动核对的记录（页数等）；
版式还要人看一遍。报告在导出前固定成一份快照，导出过程中改了文件不会混进这一次的结果。同一时间只能导出一份。
