功能包是一个 npm 包，往基础骨架上添加页面、侧栏入口、布局数据、样式和 MDX 的 remark 插件，比如协作站的 `@godcreator/collab-site`。
站点的 `package.json` 写明用到哪几个：

```json
"docsite": { "features": ["@godcreator/collab-site"] }
```

建站器照它生成 `app/site/` 下的几个文件，骨架只读这几个文件，所以功能包不改骨架里任何一个文件（见[项目骨架](/docsite/skeleton)）。

## 功能包要提供的

类型在出口 `./feature`：

| 出口 | 默认导出的类型 | 内容 |
| --- | --- | --- |
| `./routes` | `FeatureRoutes` | 路由列表。每条 `{ path, file }`，`file` 相对功能包的包根；`layout: false` 的放在整站布局外面（不出页面的接口）；`comments: true` 的路由下的页面能批评论（见下面「功能包页面上的评论」）；`{ index: true, file }` 是首页，全站只能有一个。在 Node 里读路由表时用，不能引用 React 组件 |
| `./site` | `FeatureSite` | 浏览器端也用的：侧栏那一排的入口 `routeLinks`（排在「评论」前面），MDX 组件 `mdxComponents`，自己的链接种类 `linkKinds`（见下面「链接种类」），包住整个布局的 `Provider`，放在每一页正文上面的 `PageTop` |
| `./site-server` | `FeatureSiteServer` | 只在服务端运行的：`layoutData({ pages })`，整站布局的 `loader` 调用它，读出的数据交给 `Provider` 的 `data` |
| `./styles.css` | | 功能包的样式，`app.css` 最后引入 |
| `./content`（可以没有） | `FeatureContent` | 构建页面时在 Node 里执行的：`remarkPlugins`，接在 fumadocs 默认的 remark 插件后面，`content/` 下的 MDX 页面与评论正文都经过它们，插件要区分就看 vfile 的路径。`package.json` 的 `exports` 里有这个键，初始化才引入它 |

## 链接种类

正文与评论里的链接由骨架的 `a` 组件（`siteLinkComponent`，`@godcreator/docsite-ui`）显示：站里的页面、评论、侧栏入口、`content/` 里的文件显示成带图标的小卡片，
找不到的页面标红（写法与样子见[写一页说明](/docsite/writing#链接)）。功能包自己的路由（比如协作站的任务页）站点不认得，会被当成找不到的页面，
所以功能包在 `linkKinds` 里登记：

```ts
const site: FeatureSite = {
  linkKinds: [{ matches: (href) => href.startsWith('/tasks/'), Chip: TaskChip }],
}
```

`matches` 认得这个地址，就由 `Chip` 显示，参数是 `href` 和正文里写的链接文字 `children`（没写时是空的，这时显示目标现在的名字）。
各功能包登记的种类按 `docsite.features` 的顺序排在站点自己的种类前面，第一个认得的显示。
`Chip` 用 `linkChipClassName`、`linkChipIconClassName` 画卡片和图标，和站里其余的链接一个样子。

## remark 插件接在 source.config.ts 里

骨架的 `source.config.ts` 用 Config API 定义集合，只在构建页面时在 Node 里加载，浏览器不解析这个文件。
有 `./content` 出口的功能包由建站器收集进 `app/site/content.ts`（`featureContents`），它们的 remark 插件与术语、公式一样
接在 `docs` 集合的 `mdxOptions` 上，插件用到的 Node 模块不会进浏览器端。评论集合不加这些插件：评论数量多，编译要快。

包根下的 `template/` 是要复制进站点的文件，分 `skeleton/`（建站时复制，只能添加文件）与 `initial/`（起始物，写完归站点）。
模板的正本是各仓自己的原型站（docfirst 的是 gwb-docfirst 仓的 docs-site），发版时从原型派生。和骨架模板里同名的文件、写在 `app/site/` 下的文件都会报错。

## 路由模块留在包里

路由模块不复制进站点，路由表直接指向装在 `node_modules` 里的文件。`app/routes.ts` 调用 `featureRouteFilesOf`（出口 `./routes`）
把 `file` 换成相对 `app/` 的**真实路径**：pnpm 的 `node_modules/<包>` 是符号链接，写链接路径时 `react-router build` 找不到打包出的文件，
也认不出它是路由模块，`loader` 引用的服务端代码会留在浏览器端。

包里的路由模块经别名 `@site`（站点的 `app/`，由 [`docsite()`](/docsite/dev-plugin) 设）读骨架里的模块：

| 模块 | 有什么 |
| --- | --- |
| `@site/lib/source.server` | `siteName()`、`sitePageRefs()` |
| `@site/lib/mdx-components` | `mdxComponents` |

类型声明在 `@godcreator/docsite-kit/site-modules`，功能包在源码里写 `/// <reference types="@godcreator/docsite-kit/site-modules" />`。
React Router 只给项目里的路由文件生成 `+types`，包里路由模块的 `loader` 参数与返回值的类型由功能包自己写。

## 功能包页面上的评论

路由写了 `comments: true`，这条路由下的页面能批评论。评论界面由路由模块自己放，接法照骨架的 `app/routes/page.tsx`：
`loader` 给这一页的评论与本机身份，`action` 核对后调评论包的写函数，页面放 `CommentsSidebar`（见[评论](/docsite/commenting#在骨架里接上)）。

## 集合定义只能在项目里

`fumadocs-mdx` 只处理项目里的 `defineDocs`、`defineCollections`，跳过 `node_modules`，而且不能配置。
功能包要列出自己的 MDX 文件（比如协作站的日志页 `journal/`），就把定义集合的文件放进 `template/docsite/skeleton/app/lib/`，
包里的路由模块经 `@site/lib/<文件名>` 读它；这个模块的类型由功能包自己声明。
