结论 现状与根因 核心思路 扩展点 组合规则 功能包 依赖方向 文件树 功能包示例 删掉与保留 执行阶段 风险 已定的决定

任何站点都是「fumadocs 官方 React Router 模板 + 挑选的功能包」组合出来的。包按功能切，名字不带站点类型：没有「docfirst 站专用包」「协作站专用包」，只有钉码、轨迹卡、协作、评论这样的功能。

不造自己的插件系统。每个功能包只通过 fumadocs 和 React Router 原生的扩展点接进站点，组合方式就是站点文件里显式的几行，由建站器写入。包从 17 个减到 10 个，仓改名为 god-docsite。

现状与根因

几十条问题归下来，是五个根上的决定出了错。

根因派生出的问题
功能包自带路由，路由模块放在 node_modules 里React Router 只认站点 app/ 里、按精确路径登记的路由。为此给 @react-router/dev 打补丁，建站器把补丁写进每个新站；.server 检查失效，出现两种互相矛盾的绕法；功能包用 @site 别名反过来 import 站点代码
骨架和库的界线没划清615 行骨架装着评论写入、页面 loader 等逻辑，在三个站各抄一份，建站器里再一份，已经走样；评论写入 action 有四份
沿站点类型切包，又靠手工协调版本同一功能的模型和站点部分分在两个包，总是一起装、一起改；版本表滞后过一次，新站首页 500；仓根构建写错包名，docsite-docfirst 一直没被构建
同一件事做了好几遍Term 3 份、术语插件 2 份、生成物渲染管线 2 条（站上那条只做一半）、frontmatter 3 种读法、报告 schema 与样例各 2 份
功能只在开发服务里能用推送借用 Vite 热更新连接、数据存在进程内存，构建出的站没有通知，协作站只能一直跑 dev

核心思路：站点 = 官方模板 + 功能包

fumadocs 本来就是一组让使用者自己组合的库，不是带插件运行时的框架。所有站从同一份模板出发，按需装功能包。基础站只是最常用的默认组合。

平台 功能包（装到站上） 命令行（装在仓里） gwb 插件
基础站

文档维护
基础站+ code-pintrajectoryexplainer+ 仓里装docfirst
项目协作
基础站+ collab
任意组合

术语标注（glossary）是 god-docsite 的一部分，每个站都有。

功能包接进站点的扩展点

fumadocs 加 React Router 没有统一的「插件对象」。一个功能包的 ./site 往下面几处各接一部分。

扩展点站点里接在哪原生支持例子
remark / rehype 插件集合的 mdxOptions（统一用 applyMdxPreset）支持钉码标记、术语、公式、记录链接
MDX 组件app/lib/mdx-components.tsx支持Term、钉码外框、RecordLink
集合app/lib/source.ts半支持：集合必须由站点声明，功能包只给 schema轨迹卡、日志
页面树（侧栏）loader({ plugins })支持，具体 API 待实验确认侧栏的「任务」「星轨盘」入口
样式app/app.css 里 @import支持各功能包的样式
根组件、布局插槽app/root.tsx、布局路由支持身份、通知栏、评论面板
带数据的页面app/routes.ts + app/features/ 下的转发文件不支持：React Router 只认站点 app/ 里的路由任务页、日历、星轨盘页、卡页

最后一行是上一版栽跟头的地方。新做法：功能包只导出 loader、action 和页面组件；站点 app/features/ 里放一两行的转发文件，由建站器写入。这和 fumadocs 自己的 CLI 把组件复制进项目是同一个思路，不需要任何补丁。

组合规则

不造插件系统

没有注册表、自动发现、生命周期钩子。组合就是站点文件里显式的几行，打开文件就能看出这个站接了什么。建站器写入这几行，并且能对已有站点重复运行，只补缺的。

共享的东西归站点

首页、* 页面路由、全站布局归站点。功能包只占自己声明的路径，通过页面树插件加侧栏入口，往指定的布局插槽放组件。

功能包互不认识站点

功能包的 site/ 不依赖 god-docsite，要用的站点信息（目录、身份、可信地址、集合）由站点经参数传入，所以装到任何 fumadocs 站都能用。

build 下必须能用

所有功能在 build + start 下都要工作。推送改成 SSE 资源路由，不再依赖开发服务。托管时跑 dev 还是 start，另作运维选择。

功能包：10 个

按功能切包，名字不带站点类型。同一功能的模型、读写、站上显示放在同一个包里，因为它们总是一起装、一起改；纯 Node 的使用方（gwb 插件、命令行、CI）不碰 React，由包内分层和可选 peer 依赖保证，不靠拆包。全部在 @godcreator/ 下。

为什么包名不以 fumadocs 开头

fumadocs-mdx 的 vite 插件会自动处理名字以 fumadocs- 或 @fumadocs/ 开头的包。但 @fumadocs/ 是官方组织，我们不能用；不带作用域的 fumadocs-x 会去公共 npm 解析，有被抢注的风险；这个前缀判断也只是 fumadocs-mdx 的内部实现。所以改由 godDocsite() 用同样的遍历方式、按「peerDependencies 里有 fumadocs」识别要一起处理的包。

依赖规则（.dependency-cruiser.cjs）

包之间

  • god-docsite 不依赖任何功能包；「我是谁」、评论面板在模板里接
  • 功能包之间只允许上图的边，出现新边或环就报红
  • 功能包的 site/ 不依赖 god-docsite
  • 没有包依赖 gwb 插件；gwb 插件只用 . 和 ./node

包内部

  • core/ 不 import node:*、react、fumadocs，也不 import 本包 node/、site/
  • node/ → core/，不 import react、fumadocs
  • cli/ → core/、node/
  • site/*.server.ts → core/、node/
  • site/ 其余文件 → core/，不碰 node:* 和 node/（以前「水合静默死」的根因）
