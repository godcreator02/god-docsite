# 包怎么划

**本页回答**：这套东西运行时到底有几类角色，现在的包划分在哪三处对不上，各自怎么改、改完怎么验。

在途页。做完拆解归梁——角色分层进 `docs/system-map`，每步的判据落轨迹卡，然后删掉这一页。

## 不做什么

- **不动 core 与外面的接缝**。`Reader` / `Ledger` / `Comparator` / `Format` 四个接口的形状这轮不碰，
  只动谁实现它们、住哪个包。
- **不管消费方**。十一个仓外站继续吃各自装着的旧版本，一个都不升。改名之后它们照旧用旧名字的旧包。
- **不趁机改行为**。每一步都是搬家与更名，测试一字不改还得全绿——测试要改就说明改的不只是边界。

## 四类角色

运行时只有四类东西，认清它们各自不认得什么，比记住包名有用：

**判定引擎**。拿到一处引用和一段文本，判它是绿是黄是红。纯的：不碰磁盘、不起子进程、不认识任何
文档格式、不知道摆放。`Reader` 这个接口就是为「不碰磁盘」立的——观察由外面递进来。

**环境适配**。真实磁盘、真实 git、真实记录簿文件，加上把这些零件按配置装配成一个能跑的项目。
它是判定引擎那些接口的实现方。摆放也在这儿，因为摆放要写盘。

**格式适配**。同一处引用在 md、html、mdx 里各长什么样：怎么认出来、怎么写回去、正式记号长什么样。
三种格式三个实现。

**入口**。把上面三样装配起来跑一趟。有三条：命令行（人与门禁）、工作台件（agent）、站构建（页面渲染）。
其中命令行与站构建**各自装配一次项目**，这是两条平行的入口，不是一条链。

## 三处对不上

**一、一个名字盖着三样东西。** `live-doc-project` 现在同时装着：四个接口里三个的实现、装配器、
以及一个需要环境的业务模块（摆放）。"project" 只说中了装配那一层，读者看到包名猜不出里面有 git。

改成 `live-doc-node`，按它与核心的真实分界线命名：核心是纯的、哪儿都能跑，这一半碰磁盘与子进程、
只在 node 跑。同一个容器里块笔记那个仓已经是这么切的（模型层两边跑、引擎层 node 侧、客户端浏览器侧），
一把刀切到底，读者不用学第二套。

影响面已经查清：**没有任何一个站 import 过这个包的 API**，它只出现在 Next 的 `serverExternalPackages`
名单里，也就是一行字符串。所以改名的代价是每个活站两行配置，而这轮不升消费方，连那两行都不用现在动。

**二、命令行包里混着一个跟它无关的完整模块。** 建站那一摊 349 行，与判定引擎、环境适配、格式适配
三边零耦合，自成一体；check / confirm / render 是「对一个已有的站做事」，建站是「造一个站」，
两者除了都从命令行敲进去之外没有共同点。

处置分两层：**实现留在这边、在包内独立成模块**（有自己的接口与测试，不与命令解析纠缠），
**件那边加一条入口命令**。实现不能搬进件——livedoc 要能独立用，没装工作台的仓也得建得了站，
"别人依赖它、它不依赖别人" 是[建站归命令行那张卡](/trajectory/2026-09-09-init-and-skills-ship-with-cli)
定过的判据。那张卡否掉的是"单开一个 npm 包"（理由是装机成本），它没有否掉"在同一个包里做成独立模块"，
这两件事一直被混为一谈。

五份 skill 同理：它们随这个包发是对的（谁装了谁就该有），但它们的正本该是站内 mdx，经 outputs 生成
到包里，而不是在包里手写。

**三、一个包跨两个角色。** fumadocs 那个格式包同时干着两件事：`Format` 接口的实现（格式适配），
以及站的接线（remark 插件、名册、术语表、展示块）。所以它 1021 行、14 个文件、66 项导出，
而站真正 import 的只有两项。它也是唯一依赖装配那一半的格式包。

这一处**先不动**，只把事实写清楚，理由见未定项。

## 验收清单

- [ ] 包改名 `live-doc-project` → `live-doc-node`，工作区内引用全跟，测试一字不改仍全绿
- [ ] 建站在包内独立成模块：有自己的接口与测试，命令解析那一路只剩一句分流
- [ ] 件加一条建站入口命令，实机验过（在一个空仓上真铺出一套六区站）
- [ ] 五份 skill 的正本迁到站内 `content/outputs/skills/`，经 outputs 生成到包里，check 守着一致
- [ ] `docs/system-map` 写清四类角色与三条入口，两次装配画明白，论断钉在真代码上
- [ ] 每步各落一张轨迹卡，本页拆解后删除

## 未定项

**fumadocs 那摊拆不拆。** 它跨两个角色是事实，但拆开的代价没算过：站的接线要换依赖、两个包要同步发版、
而站接线本来就只有一个消费者（站自己）。"一个适配器是假接缝、两个才是真的"——现在只有一个站接线，
拆出来的接缝会不会立刻空转，没想清楚。先列着。

**建站入口进件之后，开发套件那条登记怎么办。** 套件现在代跑建站、代挂 skill，件那边有了入口之后
两处重复。哪边退役要问人。

**五份 skill 的附件（记录哲学与卡的落盘格式两篇 reference）搬不搬。** 它们是 skill 的附件不是独立
知识面，放上站会让导航多两页读者用不上的东西；先只把五份主文件走通生成链。
