# 给 git 立一条接缝

**本页回答**：git 那条线现在为什么难测、这一刀改哪儿、做到哪儿了。

## 验收

- [ ] git 那条线上有一个接口，两个适配器：一个起子进程（生产用的那份，行为一个字不变），一个是内存假仓
- [ ] 分派规则、四态判定、行段跟随这些纯逻辑改喂假仓，不起子进程也验得了
- [ ] 真 git 的行为另留一小撮对账用例，门禁跑一趟起的 git 子进程数明显下降
- [ ] 模块页跟到新形状，判据落一张轨迹卡，本页拆解后删除

## 不做什么

**不动依赖方向，不动目录方向。** `engine` / `host` / `fumadocs` / `site` / `cli` 五层的方向一条不改；
这一刀全在 `host/` 内部。

**不改任何一处行为。** 生产那条路上真 git 的行为一个字不变，测试要改就说明改的不只是边界。

**不为这一刀立新的配置项**，也不改 `livedoc.config` 的形状——消费方项目一个字不用动。

## 方案

`packages/livedoc/src/host/git.ts` 是一把直接起子进程的函数：定位文件在哪个仓、读 blob、
问 hunk 表、判工作区干不干净。测试要验它就得在临时目录里起真 git 仓，夹具本身近百行，
门禁跑一趟因此起一大把 git 子进程。

这一步在 git 那条线上立一个接口，配两个适配器——真的那个起子进程，假的那个是内存仓：喂进
「文件是什么内容、提交过没有、hunk 表长什么样」，直接看输出。比较器那一层（记忆怎么记、
变没变怎么判、行段怎么跟随）改喂假仓；真 git 的行为另留一小撮对账用例，不指望假仓替它作证。

## 未定项

**接缝立在哪一层**：接口是套在 `git.ts` 那把原语上，还是套在比较器那一层（`GitDeps` 之类）——
前者假仓要仿 git 的输出格式，后者假仓更小但真实现的覆盖面也更小。走 `gwb-decide`。

**跟比较器性能那条线撞同一批文件**，先合流再动，别两头改。
