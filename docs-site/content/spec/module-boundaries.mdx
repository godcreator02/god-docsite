# 模块划分深化

**本页回答**：这个仓的模块划分还差哪几刀、每一刀改哪儿、做到哪儿了。

## 验收

- [x] 摆放收成 `live-doc-project` 的一个模块：对外只有 `render` / `check` 两个方法，判定一件都不在命令行里算；命令行那份 `placed.ts` 整份删掉
- [x] 摆放的账能直接调两个方法验，不劫持 stdout、不 `process.chdir`
- [x] 删掉死接口 `renderHuman` 与 `render` 的 `--target` 选项，`render` 只剩一种产物
- [ ] git 立一条接缝：两个适配器，一个起子进程、一个是内存假仓
- [ ] 收窄 `live-doc-project` 的导出面
- [ ] 记号语法从接口正本里分出来，三份语言表并成一份

## 不做什么

**不动依赖方向，不动包的划分。** 八个包还是八个包，`cli → project → core`、`格式包 → core`
这几条边一条不改；这四刀全是包内部的模块边界与导出面。

**不改任何一处论断的意思。** 现状文档跟着改的是「东西住哪儿、接口长什么样」，不是重新论证
这套机制该怎么设计。

**不为这几刀立新的配置项**，也不改 `livedoc.config` 的形状——消费方项目一个字不用动。

## 四步

### 一、摆放收成 project 的模块（已做）

摆放的语义原来困在命令行的 `placed.ts` 里：归一化、地盘规则、渲染、整形、frontmatter 挑行、
四态判定、落盘全在那一份，而它只有一个调用方式——起 `livedoc` 的进程，从 stdout 把结果捞回来。
测试得劫持 stdout 和 `process.chdir`，工作台件得解析打印出来的行。

这一步把整摊搬进 `packages/project/src/placement.ts`，对外只留一个 `Placing`：`render(doc)`
摆一趟回落点清单，`check(doc)` 只读盘回四态。摆放认得的项目面由它自己声明（根、配置、核心服务、
组件名册、这篇挂了哪些落点、这篇的原文），装配时把装好的项目递进去。命令行那边只剩把清单
译成人话和一个退出码，`placed.ts` 整份删除，`docIdArg` 并进 project 的 `docIdOf`。

为什么是 project 不是 core：摆放要写盘、要问格式包要渲染，核心两样都不做。这条了断记在
[摆放收成模块](/trajectory/2026-09-09-placement-becomes-a-module) 那张卡上。

### 二、删掉死接口（已做）

`Format` 上的 `renderHuman` 一个格式包都没实现过，`render` 的 `--target` 因此只有一个合法值。
两样一起删：接口上少一项可选方法，命令行少一个选项，`Format.final`（「产物就是文档本身」那个标）
保留——它还在用。文档面跟着改的是用法页与生成正本里的命令一览。

### 三、给 git 立一条接缝（未做）

`packages/project/src/git.ts` 是一把直接起子进程的函数，测试要验它就得在临时目录里起真 git 仓：
夹具本身近百行，门禁跑一趟因此起一大把 git 子进程。

这一步在 git 那条线上立一个接口，配两个适配器——一个起子进程（生产用的那份，行为一个字不变），
一个是内存假仓（喂进「文件是什么内容、提交过没有、hunk 表长什么样」，直接看输出）。分派规则、
四态判定、行段跟随这些纯逻辑改喂假仓；真 git 的行为另留一小撮对账用例，不指望假仓替它作证。

**这一步跟正在跑的比较器性能那条线撞同一批文件**，先合流再动，别两头改。

### 四、收窄导出面与分出记号语法（未做）

`live-doc-project` 的 `index.ts` 摆出二十六个值导出，其中包外的生产消费者只有 `loadProject`
一个（`report.ts` 另借一个 `PlacedCheck` 类型）；剩下那些是工作区测试与本包内部在用的。
导出面越宽，「换一个实现要动谁」就越说不清——这一步把它收到实际契约那一圈，测试要用的走
子路径或测试专用入口。

同一刀的另一半在核心：草稿记号的写法与正式记号的载荷现在跟接口正本住同一个 `types.ts` 里，
格式包只交外壳。把记号语法分出去自成一份，接口正本回到只定接口；三个格式包各自那份语言表
并成一份，`parse(marker(t))` 那条跨包契约照旧由 `tests/marker.test.ts` 守。

## 未定项

- **接缝立在哪一层**：接口是套在 `git.ts` 那把原语上，还是套在比较器那一层（`GitDeps` 之类）——
  前者假仓要仿 git 的输出格式，后者假仓更小但真实现的覆盖面也更小。走 `gwb-decide`。
- **导出面收窄怎么给测试留门**：子路径导出、测试专用入口、还是把那批测试搬进包内——三种都会改
  工作区测试的 import，选之前先数一遍谁在用。
- **记号语法分出去之后住哪**：核心里的一个新文件，还是一个新包。分出来的东西三个格式包都要吃，
  依赖方向不能因此多一条边。
