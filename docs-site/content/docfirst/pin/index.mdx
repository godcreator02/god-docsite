包 `@godcreator/code-pin`，源码在 `packages/code-pin/src/`，出口只有 `.`（`src/index.ts`）。

它是通用包，做一件事：把文字钉在代码上。它只认目标（行段、整个文件、目录树）与记录，核对出代码变没变、确认出新记录；
不读文件，不认识文档文本、记号写法与文档格式。它不认识 docfirst，谁都能单独使用；docfirst 的 workflow 是它的一个使用者，
下面讲到「钉码编排」「项目装配」的地方，说的都是 workflow 怎么用它。

## 功能

**核对与确认**是唯一算状态的地方。`check` 只收目标与记录（还没确认的记录是 null）、交回每处的判定；`confirm` 在核对的结果上逐处决定要不要重新记、记成什么，
改文件归 workflow 的钉码编排。结果与传入的顺序一一对应，一处钉不住只是那一处不动：

确认对每一处的结果只有六种。`recorded` 与 `moved` 是机械重记；黄的只在带 `accept` 时才按今天的内容重新记：

**比较器** `compare.ts` 是纯函数：每种目标各自怎么判新鲜、确认时记什么。行段按什么顺序判、取不到旧内容时怎么降级，

见[行段跟随](/docfirst/pin/git)。

**不接触文档文本。** 记号写成什么样、在文件第几行、写回时怎么改那一行、这个文件是 mdx 页面还是讲解组件的源码，

**不渲染，不知道项目根、配置文件和生成物放哪。** 在 docfirst 里，装配、渲染与摆放在 workflow。

文档里钉一处码，是在一句话下面单独写一行记号，指向源码里的几行。新写的记号只带目标，`confirm` 在同一行记号上写下两个值：`hash` 是被钉那几行（去掉行尾空白）的
sha256 前 12 位，`blob` 是整个文件当时的 git blob 名前 12 位。之后每次 `check` 都拿今天的代码去比，给出一种[状态](/docfirst/pin/judge)。

记号是 docfirst 的写法，由 workflow 认出、写回；钉码核心不认识记号，只收从记号里取出的目标与记录。

记录只写在记号自己身上，没有另外的记录文件。同一篇里两处记号指向同一段，也各带各的记录、各自写回；
一处是红，只是那一处不动，别的照写。删掉记号，它的记录也就没了。

## mdx 页面与讲解组件

讲解组件里也有照源码抄来的东西：手抄的源码片段、逐字照抄的测试名、命令行的输出格式。组件的源码里也能写引用，
被钉的代码变了，组件文件在 `check` 里跟页面一样变黄，本仓未提交的改动引起的黄照样拦提交。两种文件用同一套记号，只有外壳不同：

| | mdx 页面 | 讲解组件 |
| --- | --- | --- |
| 哪些文件 | 内容根下 `trajectory/`、`future/` 之外的 `.mdx` | 站的 `src/components/` 下的 `.ts`、`.tsx`、`.mjs` |
| 外壳 | 单独一行的 `{/* … */}` | 单独一行的 `/* … */` |
| 新写（未确认） | `{/* ref file="src/a.ts" lines="2-3" */}` | `/* ref file="src/a.ts" lines="2-3" */` |
| `confirm` 之后 | `{/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */}` | `/* ref file="src/a.ts" lines="2-3" hash="…" blob="…" */` |
| 另外能做 | 名册检查、按原文渲染生成物、站上换成带状态点的代码块 | 只核对与写回，站上不显示 |

组件里的记号必须单独占一行，放在它钉住的那段数据正上方：组件的源码不经语法树，按行认，一行里除了这个注释还有别的代码就不是记号。
一个组件文件里任何一处变黄，就是这个组件要复核。两种外壳里面的内容（记号的载荷）由记号写法一处定义，各种引用怎么写见[引用的种类](/docfirst/pin/targets)。

文档对代码说的话，说的是一个文件里的内容，或者一个目录下有哪些东西。引用分这几种：

| 引用 | 说的是 | 记号上记什么 |
| --- | --- | --- |
| 行段 `ref 文件:起-止` | 「这几行代码是这样写的」 | 这几行的 `hash`，加确认时整个文件的 `blob` 名 |
| 整文件 `ref 文件` | 「这个文件就这些，不多不少」 | 整个文件的 `hash` 与 `blob` 名 |
| 目录树 `tree 目录` | 「这个目录下就这些」 | 名字表的 `hash` |

每种目标写成记号各带哪些属性，路径相对项目根：新写的只带目标属性，`confirm` 再添上记录属性。mdx 页面与讲解组件的源码里是同一套属性，
只有外面的注释不同（见[记号的写法](/docfirst/pin/markers)）：

## 一句话该用哪一种

| 你想说的话 | 用哪一种 | 为什么不用别的 |
| --- | --- | --- |
| 「这段代码做了什么」「这条测试守着什么」「配置里这个值是多少」 | 行段 | 只在这几行真改了时黄；整文件别处一改就黄 |
| 「整个文件就这些」（几十行以内的小配置、小脚本） | 整文件 | 行段钉满全文件时，文件开头或末尾新加的行不会报 |
| 「这个目录下就这些」 | 目录树 | 行段与整文件钉不住目录 |

几条容易挑错的：

- **没有只认名字的引用**：只看一个字面量在不在，永远不会变黄。旧版的 `has` 记号 `check` 直接报错，报错里给出改成行段的写法，
  理由见轨迹卡[删掉名字引用](/trajectory/2026-09-27-drop-has-refs)。
- **钉测试，钉整条测试**：从 `test(` / `it(` 那行钉到它结束的那行。只钉测试名那一行，断言删了、条件放宽了照样是绿。
- **钉配置里的值，钉那一行**：值一变就黄，回来看正文那句话还成不成立。
- **整文件只钉短文件**：大文件里任何一处改动都黄，这种黄多了，人会不读就直接 `--accept`。要说大文件里的几件事，分别钉那几段。
- **整文件别钉随发版变的文件**：`package.json` 带着 `version`，每发一次版就黄一次，跟文档那句话毫无关系。
- **目录树按 `.gitignore` 过滤**：`dist/`、`node_modules/` 不进名字表，也不往里走。`glob` 只认 `*` 和 `?`，匹配的是名字不是路径。

{/* ref file="../packages/docfirst-workflow/src/node/fs-reader.ts" lines="4-5" hash="95d4a8b65f51" blob="5b1604322176" */}

- **跑出来的数不钉**：「几条测试」「几个路由」是命令的输出，不是哪个文件里写着的，不写进正文。

每次 `check` 都拿今天的代码跟[记号](/docfirst/pin/markers)上的记录比，给每一处四种状态之一：

{/* ref file="../packages/code-pin/src/types.ts" lines="66-67" hash="d2a2e323f0a3" blob="32a0167e8d8f" */}

| 状态点 | 状态 | 什么意思 | `check` 算不算红 |
| --- | --- | --- | --- |
| 绿 | 新鲜 | 被钉的内容跟确认时一样，位置变了也算 | 不算 |
| 黄 | 有变动 | 内容变了，等人读一遍那句话再确认 | 不算；本仓未提交的改动引起的算，见[提交门禁](/docfirst/pin/gate) |
| 红 | 缺失 | 被钉的东西不在了 | 算 |
| 空心 | 未确认 | 记号上还没有确认时写的记录 | 不算 |
