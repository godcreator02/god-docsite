# 一条记录一个文件的合并实验

## 问什么

协作记录改成一条记录一个文件（`collab/<作者>/<id>.json`）之后，上一次实验（`probes/2609252110_stacked-submit`）里「每人一个文件」会冲突的几种情况，还冲不冲突；以及文件里的 JSON 怎么排版，才能让两人改同一条记录的不同字段也不冲突。

## 怎么跑

```powershell
pwsh -NoProfile -File run.ps1 > runs/01-local.txt
```

脚本在临时目录里为每种情况建一个新仓，两条分支各改一处，用 `git merge --no-ff` 模拟机器人按「合并提交」方式依次合并，原样记下 git 的输出和合并后的文件。不需要网络。

## 结论

`runs/01-local.txt`，git 2.53.0：

| 情况 | 结果 |
| --- | --- |
| A 两人改的是「每人一个文件」时挨着的两条 | 自动合并 |
| B 成员写新记录的同时，别人改了他最新的那条 | 自动合并 |
| C 同一个人两个平行的合并请求，各写一条新记录 | 自动合并 |
| D 两人同时回复同一条批注 | 自动合并 |
| E 两人改了同一条的不同字段（一个改负责人，一个改状态） | 冲突 |
| F 两人把同一条的同一个字段改成了不同的值 | 冲突 |

只要改的不是同一条记录，就不冲突。剩下的冲突都落在同一条记录上：F 是真冲突；E 两边其实都要，但一条记录写在一行里，git 分不开。

接着试了把一条记录写成一个字段一行（任务 t1 的 id、status、title、owner、due）：

| 情况 | 结果 |
| --- | --- |
| G 一个字段一行，两人改的字段中间隔着一行（status 与 owner） | 自动合并 |
| H 一个字段一行，两人改的字段上下相邻（status 与 title） | 冲突 |
| I 字段之间空一行、没有值的字段写 `null`，两人改 status 与 title | 自动合并；合并后的文件 `JSON.parse` 照常读出 |
| J 同上，一个人给 `null` 的 due 填值，另一个人改 owner | 自动合并 |
| K 同上，两人把 status 改成不同的值 | 冲突，冲突标记只框住 status 这一行 |

git 要求两处改动之间至少隔一行没动过的内容。字段之间空一行，任意两个字段就总隔着一行；所有字段都写出来、没有值写 `null`，改值永远是原地改一行，行号不会错位。这样冲突只剩同一个字段改成不同的值。

采用的是 G、H 那种普通的一个字段一行：同一条记录的相邻字段被两人同时改的情况少见，按真冲突处理（轨迹卡 `2026-09-25-one-file-per-record`）。
