### 完整 MathType 报告：行内与行间公式均已生成

以未修改的 `fixtures/canonical.json#projectReport` 为输入，从 `templates/project-report.dotx` 重新生成完整报告，交付在 `out/project-report-mathtype-r02/word-com.docx` 和同名 PDF。共 **12 页：封面、目录各 1 页，正文 10 页**，全部页面已经逐页查看。

JSON 中的六条公式全部是 `Equation.DSMT4` MathType OLE：一条行内公式保留在正文句子中，另外五条为居中的分式、积分、矩阵、分段和多行公式，右侧显示 `(3-1)` 至 `(3-5)`。保存重开后六个对象分别通过 MathType API 激活和内容读回；DOCX 中有六份 OLE，原生 OMML 数为零。五张表、两幅图、脚注、封面内容控件、自动目录和横向宽表均保留。公式集中在 PDF 第 5 页，即正文第 3 页。

正文中的两处公式引用由 REF 域读取完整的“章号-序号”。在不保存的验证副本中，给第一条独立公式前插入编号段后，两处引用均从 `3-1` 更新为 `3-2`。手工增删或移动时应带上整段公式和编号，再按 Ctrl+A、F9 更新。

本机 MathType 7 无法直接解析样例的 `aligned` 环境，会把未识别命令以红字显示，虽然写入与读回都返回成功。生成器因此仅对本次两列多行形式转换为等价的 `array{rl}`，保留原公式正文、JSON 数据与原始 LaTeX，并把转换前后文本记入日志。`project-report-mathtype-r01/visual-review.json` 保留这一失败反例；PDF 检查新增未解析 TeX 检测，最终版另经逐页视觉验收。这个适配不代表支持任意 LaTeX 环境或宏包。

在仓根运行完整 MathType 版：

```powershell
.\.venv\Scripts\python.exe routes\word-com\build.py out\project-report-mathtype-new --mathtype
```

`build.py` 先用 Word 从模板排好正文、图表和字段，再由 `mathtype-probe.py` 的共享 API 函数把占位符逐一填成 MathType OLE，最后更新目录和引用、保存重开并导出 PDF。证据包括 `word-com-generation.json`、`mathtype-report-verification.json`、`structure-audit.json`、`visual-review.json` 和页面图。本轮验证六类公式的创建与重开读取；公式内部覆盖编辑仍未通过，已有的整体替换验证只针对分式。

### MathType 分式探针：整体替换与按章编号

本机 MathType 7.11.1.462 的接口现返回完整功能：`MTIsFullFunctionality(0) = 1`、`MTGetAppFunctionality() = 2`。使用 `.venv` Python + comtypes 调用 Word COM，并经 ctypes 调用 MathType 自带的 64 位 `MathPage.wll`，没有键盘、鼠标或剪贴板自动化，也没有修改宏安全或许可证设置。

测试公式来自 `fixtures/canonical.json` 的 `eq-fraction`。TeX 写入、读回、保存重开全部成功；分母常数由 1 改为 2 后再次保存重开，MathType API 读回内容与预期一致。原稿和修改稿分别导出一页 PDF，两页均已逐页查看：每页只有一个公式，分母常数分别为 1、2，中文正常，无重叠和裁切。DOCX 中保留 `Equation.DSMT4` 和真实 OLE 二进制对象，公式不是仅供显示的图片。

行间公式采用独立的居中制表位，编号用版心右侧的右对齐制表位；公式本体在版心居中，编号宽度不影响公式中心。章号来自一级标题的原生自动编号，公式序号在每章重新计数，使用半角括号和连字符：

```text
({ STYLEREF 1 \s }-{ SEQ Equation \* ARABIC \s 1 })
```

这里的大括号代表 Word 原生域，由 COM `Fields.Add` 创建。样稿显示 `(1-1)`、`(1-2)`、`(2-1)`：已实际验证在原公式前插入一条公式后原编号从 `(1-1)` 变为 `(1-2)`，进入第二章从 `(2-1)` 开始；保存重开后编号和三条 MathType 公式仍正确。在不保存的验证副本中删除第一条公式，余下编号恢复为 `(1-1)`、`(2-1)`。编号样稿的一页 PDF 已检查居中、右对齐和分式显示。

生成脚本在保存及导出前调用 `Fields.Update()`。手工增删或移动时应带上整段公式和编号，然后在正文按 **Ctrl+A、F9** 更新；无需手改序号，也不需要宏。这不是每次键入后立即刷新的事件机制。一级标题必须使用原生自动编号，不能把章号直接敲进标题文字。[Microsoft 的 SEQ 说明](https://support.microsoft.com/en-us/word/field-codes-seq-sequence-field)给出了顺序重排和按标题层级重置的规则。

**修改采用整体替换：在原位置创建并写入新的 MathType OLE，成功后删除旧对象。** 本机直接向已有对象再次调用 `MTSetEqnFromLangStr` 会追加公式；TeX 读回却只反映最后输入，不能独立作为正确性证据。探针因此同时核对 DOCX 对象数、PDF 公式标记数，并要求人工页面检查。这个结论覆盖当前分式的创建和整体替换，不代表原对象内部覆盖或所有复杂 LaTeX 已通过。

复测入口为 `routes/word-com/mathtype-probe.py`，仅接受仓内 `out/` 的新目录；在仓根运行：

```powershell
.\.venv\Scripts\python.exe routes\word-com\mathtype-probe.py
```

当前交付在 `out/mathtype-20261010-r10/`：优先查看 `mathtype-numbered.docx` 和同名 PDF；`mathtype-original.docx`、`mathtype-edited.docx` 及同名 PDF 保留整体替换对照。`result.json` 是 COM/API、字段和 PDF 文本检查记录，`visual-review.json` 是逐页显示验收。`r08` 是未加居中和编号的上一轮样稿，`r09` 通过编号验证后在 `r10` 将标题统一为黑色。`r04` 保留授权受限时的失败证据，`r06/visual-review.json` 保留“读回成功但页面追加”的反例，`r07` 保留首次范围替换仍残留两个 OLE 对象的失败断言。

接口签名依据本机 MathType 自带 `MathType Commands 2016.dotm` 中的 `Declarations64.bas`、`Declarations.bas` 和 `MTTeXToggle.bas`。探针直接传递 comtypes 的 IDispatch 指针，不读取 pywin32 对象的内存偏移。

#### 中文界面的问号

本机 Windows 非 Unicode 程序语言为 `en-US`，系统 ANSI 代码页为 `1252`；MathType 进程实际载入 `MT7CHS.DLL` 中文资源。这个组合是部分旧式界面中文显示为问号的主要嫌疑，[Microsoft 说明](https://learn.microsoft.com/en-us/windows/win32/intl/nls-terminology)确认系统区域设置决定非 Unicode 程序的代码页。尚未通过更换语言或系统区域设置做对照验证，不能认定所有问号只有这个原因。此次 Word/PDF 正文及公式均显示正确。

可优先尝试在 MathType 的“预置 / 工作区预置”切换英文界面并重启 MathType；[官方说明](https://docs.wiris.com/en_US/dialogs)指出语言选项只在安装了多种语言时出现。保留中文的系统方案是将非 Unicode 程序语言改为简体中文，但会影响其他旧程序并需要重启 Windows。本次没有修改这些设置。

## 本轮修复与证据

- Word 原生 UnicodeMath 的行内下标需要明确结束位置，避免把后面的括号纳入下标。
- python-docx 默认模板带有主题字体及 Title 蓝线，必须移除主题覆盖与边框，才能落实仿宋版式。
- Pandoc 原始 Markdown 表格需要追加列宽、网格与行约束；原始输出保留用于对比。
- COM 数学字母会变成 Unicode 补充字符。把 Range 截成半个代理对会报错，脚本已改用 Find 定位完整字符。

第一次试跑及发现的问题保存在 `out/sgcc-first-20261010-140600/`，交付样稿在后续独立目录。`word-verification.json` 记录实际 Word 版本、重开、公式内容和耗时；`structure-audit.json` 记录 OMML、表格结构与 PDF 文本；`manifest.json` 记录输入和脚本哈希、Python 依赖与编辑断言；`artifact.md` 记录样式约定。

内置文档渲染器依赖 LibreOffice，本机没有该程序，其失败日志已保留。本轮使用实际目标 Microsoft Word 16.0.14334 的 PDF 导出，再用 Poppler 转为 PNG 检查，显示证据来自 Word。
