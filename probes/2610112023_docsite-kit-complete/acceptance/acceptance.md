# 第 1 步验证站验收清单与操作步骤

任务 C 交付物。为第 1 步「docsite-kit 完整功能验证站」的八组功能准备独立样本与可观察的验收步骤；
静态样本在 `cases/`，样本自身契约由 `check-cases.mjs` 校验（运行方式见文末）。

- **谁在什么时候用**：主会话确认任务 B 停止写入并交付后，在同一连续上下文续派实际验证。验收时**不改 B 的实现**：
  发现问题只记录证据（编号、复现步骤、实际行为 vs 预期），交主会话定点退回 B。
- **轮次标注**：每条标 `[1.1]`～`[1.6]`。`[1.1]` 是本轮要测的；其余条目样本已备好、步骤已写好，
  等对应小段接入后再执行。后续完整功能清单是边界，不是本轮实现范围。
- **端口与路径**：步骤里的端口写 `5460`，实际以 B 交付的 handoff.json 为准（5460 或 5461）；页面路径同理。
  执行时先读 handoff.json 把端口与页面地址填进步骤，再动手。

## 验收方法与证据记录

| 检查面 | 怎么做 |
| --- | --- |
| SSR | `curl -s http://127.0.0.1:5460/<路径>` 取 HTML，查文本片段；记录命令全文与状态码 |
| 浏览器 | 用会话的浏览器工具真实打开、点击、输入；转录正文关键段或截图 |
| 控制台 | 浏览器 console 的全部 error/warn 原文转录；这是「无 Node 模块错误」的证据面 |
| 文件 | 评论、feeds、people.json 的文件操作前后状态（改了哪个文件、页面变成什么） |

每条验收在 `evidence/G#-##.md` 记一份：日期、站点与端口、逐步结果、证据（命令+输出片段、截图路径、
console 转录）、结论。状态取值：`待测 / 通过 / 未通过 / 部分 / 不适用`；SSR 200、截图、单元测试里的
任何单项都不能单独标通过——这是 30 页总验收的红线。

**断言纪律**：断言只写可观察行为（文本出现与否、数字变化、HTTP 状态码、界面状态）。禁止引用验证站
内部文件名、class 名、DOM 结构写断言；DOM 查询只按可见文本与语义（角色、label）定位。实现一换断言
就作废的那种写法，等于按 B 的实现镜像，不要写。

#### G4-05　重复文字定位 `[1.3]`

两组样本，回答两个不同的问题：完全相同的重复文本是**信息不足的边界**，可区分邻接上下文才是
**可验证的定位契约**。

**边界组**（完全相同重复，信息不足）：样本 `cases/04-comments/duplicate-lines.step1-initial.mdx`、
`step2-delete-one-occurrence.mdx`；契约样例 `comments/2026-10-11-duplicate-line-2/`。
步骤：① step1 放进站点（由主会话安排，建议路径 `content/g4/duplicate-lines.mdx`）；② 选中**第 2 句**
「同一句话。」发起评论；③ 确认标黄在第 2 处（发起时内容都在页面上，重复句批哪处标哪处——旧实验
已证，仍须重测）；④ 换 step2（三句中删掉一句，文件不指定删哪句——单看文字也指定不了）。
预期：删除后差异算法按自身对齐**认定一处**删除：被认定处上的评论显示「原文找不到了」，
批在其余处的照常找到，**不挂错位置**；同时记录算法实际认定的是哪一处（观察项，不构成断言）。
不要求实现凭空识别编辑意图，本清单也不据此宣称产品采用任何新的定位策略。
**引用纠正**：旧实验 `runs/02-anchor-mapping.txt` 记录的是「三句一模一样，删掉一句后单看文字分不出
删的是哪一句，差异算法认定删的是其中一处（该次认定为最后一句）」——它证明的是差分选择与不可分辨
的局限，**没有**证明可识别人实际删的是哪一句；本条预期据此改写。

**可区分组**（邻接上下文可判定删除位置）：样本 `cases/04-comments/distinct-neighborhood.step1-initial.mdx`、
`step2-delete-before-commented.mdx`、`step3-delete-commented.mdx`；契约样例
