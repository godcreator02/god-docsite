# 静态输入样本

这些样本是第 1 步验证站的**独立验收材料**，按八组功能的前六组建目录（第七、八组以操作步骤为主，
样本在 `../acceptance.md` 的 G7、G8 条目里描述，不另放文件）。

| 目录 | 覆盖的验收组 | 主要样本 |
| --- | --- | --- |
| `01-pages/` | G1 页面与资源 | MDX 页引用图片、TSX 交互页引用组件、HTML 页引用图片、内容文件 |
| `02-plugins/` | G2 正文与写作组件（1.1 的 A/B 集合隔离） | Node-only remark 插件与 A/B 集合正文 |
| `03-interaction/` | G3 交互与导航（1.1） | 并入 `01-pages/demo.page.tsx`，不单独设目录 |
| `04-comments/` | G4 评论 | 重复文字边界组（完全相同、两步）、可区分邻接组（三步）、折叠页与正反两个展开组件、三条评论串契约样例 |
| `05-identity/` | G5 身份与写入边界 | people.json 样本、拒写请求样例 |
| `06-feeds/` | G6 数据推送 | 同一频道三个阶段的 JSON |

## 怎么采用

- 验证站（任务 B 交付）需要这些输入时，**由主会话安排复制或要求 B 采用等价内容**；任务 C 不往 B 的
  站点目录里放任何文件。样本里的组件（`demo/`、`collapse-target/`）在页面文件旁边，采用时要连相对结构一起。
- 评论串样例（`04-comments/comments/`）的 `page` 字段写的是约定路径 `/g4/duplicate-lines`、
  `/g4/collapse-target`（对应把两个页面样本放在 `content/g4/` 下）。验证站结构不同就改 `page` 字段，
  其余不动。`snapshot.txt` 是按样本正文手工构造的近似值，`check-cases.mjs` 验证它和 `range`、`quote`、
  `openers` 自洽；放进真实站点时，若站点算出的页面文字与这份快照不一致，开发服务会按契约报错——
  这时应改用网页或评论接口在站上重新发起评论（快照自动生成），样例只当文件形状的契约参考。
- 身份码 `acc1111code1`、`acc2222code2` 是编的样本值，格式照现状（12 位小写字母数字）。

## 断言纪律

验收断言只写**可观察的行为**：文本出现与否、数字变化、HTTP 状态码、界面状态。禁止引用验证站的
内部文件名、class 名或 DOM 结构写断言——那是按实现写断言，实现一换断言就作废。
