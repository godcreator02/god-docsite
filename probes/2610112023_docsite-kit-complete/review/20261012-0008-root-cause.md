# 主会话诊断：评论集合增删与 Windows glob 路径
日期：2026-10-12（Asia/Shanghai）

## 结论与证据层级
- 当前实际版本：fumadocs-mdx 15.4.7、Vite 8.3.4、React Router 8.4.0。
- 原实现删除后 UI 条目已移除，但 CUA tab.dev.logs 仍捕获 Vite 对已删除 MDX 的 reload 错误。回复 2026-10-11-e6514d/20261011t155829-c3de.mdx 于15:59:12.659Z起六次；串头 index.mdx 于15:59:29.676Z起六次。原服务已停止，测试串已删除。
- 第一层：去掉 action 内 utimes 的真实站点对照，新文件落盘，watcher 有 add，vite:import-glob 的 client/ssr create hook 都返回 undefined，未增加集合模块。SSR 新请求中没有新条目完整路径；浏览器手动刷新也仍无新评论。
- 第二层：Fumadocs 生成 .source/server.ts/browser.ts 中 comments glob 使用 base="./../comments"。本机 Vite 的 toAbsoluteGlob 相对 base 分支用 node:path.posix.resolve；对 Windows D:/... importer 会得到混入当前目录和 D: 的错误绝对匹配路径。根相对 base="/comments" 分支走 posix.join(root, base)。
- 单变量对照：保留其余站点代码，去掉 utimes，仅在诊断 transform 中将 comments 的 base 改为 "/comments"；同一条 Vitest 真实 HTTP 新建/删除检查由失败变为通过。未修改 node_modules、生成文件或正式站点源码。
- 第三层：utimes(source.config.ts) 触发配置重载时，fumadocs 的 MDX transform 对每个模块 addWatchFile(core.configPath)，会连带更新整个 MDX 图，包含已删除模块，造成额外热更新与404。此补丁会放大删除问题，不能作为正确集合更新协议。
- removedKeys 只是 React 层的即时移除；不能修 Vite 模块图与集合失效。新建/回复/编辑原本靠开发热更新和 sessionStorage 重开评论，仍需独立验证浏览器数据刷新。

## 修复方向
先基于公开的 Vite import.meta.glob 根路径模式或根相对base，在验证站隔离相对base问题；不用手改生成物、node_modules或依赖内部闭包。保留Fumadocs编译与身份/评论包边界。移除碰source.config的补丁，补真实集合增删Vitest和浏览器console验收。若浏览器不重取数据，再补明确的宿主变更通知/重验接线，不用碰全局配置代替。
