## 一句话结论

推荐**方案 C（vite 插件在新增或删除内容文件时把集合模块补进热更新列表）加上页面树内容标识（loader 把页面树根节点 `$id` 换成内容摘要）**。
新正文页、新日志、新评论在 20 页与 300 页两种规模下，写入后 0.05–0.16 秒新地址能打开，0.1–0.23 秒出现在已打开的页面上，不整页刷新。
仓里的 vite 补丁在 C 落地后撤掉。

## 测出来的三件事

### 1. 修好 glob 只解决一半：已打开页面的侧栏不会出现新正文页

A、B、C 三者机制等价，都能让服务端和浏览器拿到新的文件清单：新地址能打开；React Router 在路由模块热更新后会重新跑 loader，
所以新日志、新评论（由 loader 数据或浏览器端集合直接渲染）会出现。**侧栏的新链接却始终不出现**，原因在 fumadocs：

- `@fumadocs/base-ui` 的 `contexts/tree.js` 里，`TreeContextProvider` 用 `useMemo(() => rawTree, [rawTree.$id])` 按根节点 `$id` 缓存整棵树
- `fumadocs-core` 生成页面树时根节点 `$id` 来自固定的路径值（`generateId(folderPath)`），新增页面不变

所以只要页面不整页刷新，侧栏就一直是旧树。补法是 loader 里把根节点 `$id` 换成页面树内容的摘要（`site/app/routes/docs.tsx` 的 `pageTreeForClient`）。
注意 `serializePageTree` 的结果是 `{ $fumadocs_loader, data }` 两层，`$id` 要写在 `data` 上，写在外层不生效。
这个补法与 A、C 都能搭配（A+树标识、C+树标识数据相同），说明侧栏问题与 vite 缺陷无关。

### 2. 方案 C 必须跳过 id 为空的模块节点

`moduleGraph.getModulesByFile()` 取到的模块里有 `id` 为 null 的节点（只登记过地址、还没解析）。把它们补进 `hotUpdate` 的返回列表，
服务端会整体重新转换，新增文件后的第一个请求从几十毫秒拖到 8.4 秒（日志：`original/hotupdate req1 : 200 took 8362ms`，
过滤后 `took 71ms`）。`site/plugins/invalidate-collections.ts` 里的 `module.id !== null` 就是为这个，正式实现要写进测试。

### 3. 重启类方案不可用

- D1：每加一个文件等一次冷启动，27–35 秒；浏览器靠 vite 客户端断线轮询重连，大站上常常 60 秒内还没恢复
- D2：`server.restart()` 每次也是 37–65 秒，且内存不释放，连续第 11 次重启时开发服务报 `JavaScript heap out of memory` 崩溃
- 两者还会打断所有正在看站的人

## 为什么选 C，不选 A 或 B

三者速度相同，区别在维护：

- A（vite 补丁）：pnpm 补丁只在执行安装的工作区根生效，库没法把它带给下游站，每个站都要自己挂一份，并且钉死 vite 8.3.4；
  docsite 建站器目前只给新站写了 React Router 的补丁，没写这个
- B（改写 base）：要从 fumadocs 生成的代码文本里找 `"base": "./…"`，fumadocs 一改格式就静默失效
- C：写在 docsite 的 vite 插件里，随库发布；只用 Vite 公开接口（`hotUpdate`、`moduleGraph`）；`order: 'post'` 排在核心插件之后，
  上游修好后 `vite:import-glob` 会自己加同一批模块，C 只补列表里没有的，不会刷两次

不选整页刷新：慢一倍，而且会冲掉页面上的状态（比如写到一半的评论），别人往站里加一个文件就会打断正在看的人。

## 正式实现要注意

1. C 需要知道哪些模块收集了内容文件。实验里写死为 `.source/server.ts`、`.source/browser.ts`、`app/lib/journal.ts`；正式版应由 docsite 的 vite 插件按站点的集合定义得出
2. C 只处理 `create` 与 `delete`，`update`（改已有文件）原本就正常
3. 树标识依赖 fumadocs 按根节点 `$id` 缓存这一行为；fumadocs 以后若改成按内容比较，换 `$id` 也无害
4. 可以给 vite 提 PR 修 `toAbsoluteGlob`（复现在 `../2610121018_vite-add-discovery`），给 fumadocs 提根节点 `$id` 不随内容变化的 issue；对外提交需用户同意
