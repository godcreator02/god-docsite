# 每人一条工作分支的连续提交实验

## 问什么

1. 协作记录每人一个 `.jsonl`、大家往文件末尾追加时，git 合并在哪些情况下报冲突：两个平行的合并请求、第二次提交接在第一次后面、改的行隔开或挨着、追加与改最后一行同时发生、同一条改成不同的值。
2. 成员在自己的工作分支上连续提交、每次都推同一个 AGit 主题时，Gitea 是更新原来的合并请求还是新建；原来的合并请求合并了或被关闭之后再推同一个主题会怎样；成员同步 main 会不会冲突。

## 怎么跑

本机部分（不需要网络）：

```powershell
pwsh -NoProfile -File run-local.ps1 > runs/01-local.txt
```

脚本在临时目录里为每种情况建一个新仓，用 `git merge --no-ff` 模拟机器人按「合并提交」方式合并，原样记下 git 的输出和合并后的文件内容。

Gitea 部分用上次实验的测试仓 https://git.tianshen02.online:28377/godcreator/agit-probe（bob-test 是只读协作者）。bob 一侧在临时目录里克隆 `https://bob-test@git.tianshen02.online:28377/godcreator/agit-probe.git`（凭据由 Git Credential Manager 提供），命令与输出按顺序在 `runs/02-gitea-bob.txt`；负责人一侧的 API 调用（合并、留言、关闭、查合并请求内容）在 `runs/03-gitea-api.txt`。重跑时照 02 的命令逐步执行，遇到括号里写的负责人操作就照 03 调一次 API。

## 结论

本机（`runs/01-local.txt`，git 2.53.0）：

| 情况 | 结果 |
| --- | --- |
| 两个平行分支都在文件末尾加一行，先合一个 | 另一个冲突 |
| 第二次提交接在第一次后面，先合第一次 | 第二次不冲突；成员同步时快进 |
| 两人改的行中间隔着一行没动过的 | 自动合并 |
| 两人改的是相邻两行 | 冲突 |
| 成员在自己文件末尾追加，同时别人改了这个文件的最后一行 | 冲突 |
| 同一条改成了不同的值 | 冲突 |

Gitea（`runs/02`、`runs/03`，Gitea 1.27.1）：

- 合并请求还开着时，再推同一个主题是**更新**它：#4 从一个提交变成两个，没有新建。
- 合并请求**合并之后**再推同一个主题，Gitea **新建**一个（#5），里面只有 main 里还没有的改动。
- 合并请求**被关闭之后**再推同一个主题，也是**新建**（#6），不会重新打开被关闭的那个。
- 成员把 main 合进自己的工作分支（`git merge origin/main`），没有冲突。
