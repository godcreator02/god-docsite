# 全文导出性能实验

2026-10-11，本机 Windows、Microsoft Word、MathType；使用仓内 `.venv`。目标是在内容和检查不缩水的条件下，减少全文 DOCX＋PDF 的生成时间。实验不证明其他机器、WPS 或在线 Word 的性能。

## 结果与计时口径

| 工作量与阶段 | 较早版本 | 当前版本 | 解释 |
| --- | ---: | ---: | --- |
| 固定小样写入，中位数 | 50.3655 s | 2.4525 s | 首轮加三轮配对；16 段正文、25×3 表格；不含 PDF；节省 95.13% |
| 全文写入至保存草稿 | 243.403 s | 95.474 s | 两次全文运行的阶段差；节省 147.929 s，约 60.77%；不是隔离变量的重复 A/B |
| 全文自动生成与检查 | 407.159 s | 215.073 s | 含 MathType、保存重开、检查及 PDF；约省 47.18%，不能全部归因于批量写入 |

小样原始记录在 `evidence/perf-repeat-final-r01/summary.json`；每次均新建私有 Word 实例，Word 启动不在 composition 计时内，OS 缓存没有清空。全文阶段来自 `perf-full-render-r03` 与 `perf-full-final-r02` 的 `verification.json`。旧接收稿 `sst-full-render-r06` 曾用 776.265 s；它属于更早一轮，不能把全部改进解释成此次批量写入收益。

最新全文 215.073 s 的分布：准备 5.883 s；写入和草稿保存 95.474 s；MathType 创建、保存重开和读回至 152.824 s（51.467 s）；文档及报告检查至 184.147 s（31.323 s）；PDF 导出 29.079 s；剩余收尾约 1.847 s。此前同路线全文测得 162–185 s，实际耗时有波动，不能选最快一次承诺固定延迟。

公式缓存单独测量了一次新缓存和三次全部命中：墙钟分别为 169.483、171.680、176.157、171.153 s，三次命中中位数 171.680 s。十个公式均保存重开并读回通过，但没有稳定的端到端收益，因此正式入口默认关闭缓存。这组重复运行在随后修正题注书签、域空格与字体提示之前，不能替代最终稿验收。

## 实现与维护成本

正式路径将连续段落、普通表格、字符格式、书签、引用域和公式占位合并为 Word 原生 XML，再通过 COM `Range.InsertXML` 写入。图片、列表、节、脚注及复杂表格继续用对象模型；MathType 和 Word 的分页、导出保持有序。PDF 文本检查及页面栅格化最多四个进程，前者测得 1.799→1.049 s 且逐页文本一致。

截至本次快照，`ContentComposer` 批量类 255 个物理行、244 个非空行；`compose.py` 对基线合计 +299/-7，包含辅助函数及对象模型调用优化。不能把这些全部叫作“补丁”。实际遇到的兼容问题分五类：

| 问题 | 处理 | 当前相关代码规模 |
| --- | --- | --- |
| 重序列化丢失 Word 命名空间声明 | 保留原生 Flat OPC 外壳，只换正文 | 约 6 行 |
| 末段合并、插入 Range 仍折叠 | 末尾空段及按需恢复 Range 终点 | 约 7 行 |
| REF 域报不能识别的开关参数 | 保留 `instrText` 首尾空格 | 3 行 |
| 题注标题书签含入编号 | 在 XML 节点层设置边界，取消字符偏移推算 | 约 21 行 |
| 纯西文公式受东亚字体提示影响而裁切 | 仅实际含 CJK 字符时添加提示 | 约 6 行 |

约 40–50 行是按现存相关语句估算，包含与正常渲染逻辑重合的部分，不是可由 Git 精确分离出的修复净增量。额外的 eligibility/fallback 防护也有维护成本。独立的 MathType 缓存模块改动 +173/-5，不属于批量正文写入；完整性能工作另有核验 +153/-3、Word 接口 +28/-1、入口 +28/-4、测试 +180/-1，不能只报主类大小代表全部投入。

不启用的方案和失败记录一并保留：仅关屏幕刷新/后台分页收益不足；逐段 InsertXML 仍慢；早期段落边界丢失、缓存导入破坏公式段落样式、早绑定 MathType 调用停滞均不作交付。最终 `perf-full-final-r01` 虽自动通过，但第 39 页裁切，视觉验收失败；修复后的 `perf-full-final-r02` 才是本次接收稿。

## 验收范围

最新稿保持 51 页、32 张表、10 个原图、10 个 MathType OLE、零 OMML。与接收基线相比，880 个单元格内容、1092 个源段落书签顺序、1288 个源书签名、158 个语义域代码以及图片字节一致；110 项标题书签检查通过。报告内容 JSON、图片和输入模板未改。

51 页均已查看，另放大第 39、47、48 页；原先第 39 页问题已消除。仍有字距、符号字体和换行差异，因此 `comparison.json` 的严格像素/逐页文本完全相同判定为 false；这份记录保留原值，不改成通过。独立的 `visual-review.json` 记录显示验收及已知排版限制，包括第 21–22 页原有字符框右边缘不齐、密集表格单位折行。这次不是内容技术审校。

示例报告另验证了 12 页、6 个行内/行间 MathType、横向节、脚注、编号插入/删除及引用更新；示例的完整逐页显示检查未在本轮重新执行。嵌套表格功能样例通过；混合行列合并表格在旧引擎和新回退路径都存在首单元格覆盖问题，已留下失败材料，不能宣称合并表格通用通过。

## 复现

从仓根执行，目录名每次换新：

```powershell
.\.venv\Scripts\python.exe probes\2610111327_export-performance\repro.py small --out out\replay-small-001
.\.venv\Scripts\python.exe probes\2610111327_export-performance\repro.py full --out out\replay-full-001
```

`repro.py` 使用 `engine/docreport/` 冻结代码，不导入后来的正式源码。`small` 做四轮新旧写入对比；`full` 用 `full-input/` 做一次新缓存加三次命中。首次依赖准备按仓根说明执行，依赖版本见本目录 `requirements.txt`。这是本机 Word/MathType 实验，仍需要本机已安装并许可的软件与字体，不是跨机器独立沙箱。

`probe.py`、`repeat.py`、`repeat_full.py` 是测量入口；`compare.py`、`semantic_compare.py`、`titles.py`、`pdf_parallel.py` 是独立检查入口。`baseline_*` 和 `frozen_*` 是原路径；`bulk.py`、`xmlbulk.py` 保留中间失败和成功方案。`freeze.py` 仅归档时调用：固定源码、输入、依赖、基线清单和小型成功/失败记录，`archive-manifest.json` 逐项记录哈希。DOCX、PDF、页面 PNG 和 profiler 大文件仍在 `out/`，只登记路径与哈希，未纳入 Git 归档。正式代码禁止反向导入本目录。
