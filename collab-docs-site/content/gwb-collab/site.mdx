站点的骨架与开发服务都不由本插件写、不由本插件运行：照模板初始化站点、常驻、意外退出后重启、打开窗口、往站点推数据、本 home 的身份码，都是 gwb 基础插件 gwb-docsite 做的，本插件注入它的服务 `gwbDocsite` 来用（方法与行为见基础包仓 `oz47p-docsite-kit/docsite-kit` 的自述站「gwb 基础插件」一页）。
`site-process/` 不认识两种仓，也不算通知：`collab-sites.ts` 的 `CollabSites` 在调 gwb-docsite 之前查一遍站点，从通知那里拿推给网站的数据（接缝 20），把站点在不在运行告诉协作窗格（接缝 21）；`site-files.ts` 是查站点的函数（站名由基础包 `@godcreator/docsite-kit/files` 的 `siteTitleOf` 读，站点没运行时的预期地址由 gwb-docsite 的 `status(dir).expectedUrl` 给）；`dependencies.ts` 在 `site/` 里运行 pnpm。

## 初始化站点与更新骨架

`collab.site.init {repo, port?, title?}` 交给 `gwbDocsite.init(<仓根>/site, …)`，骨架怎么写由 gwb-docsite 与基础包定（见 [功能包](/collab-site) 的「交给基础包的东西」），本插件只多给一样：功能包 `@godcreator/collab-site` 的范围写成 `^` 加本插件打包时带的那一版。
这一版在构建插件时由 `build.ts` 从 `node_modules` 里的功能包读出、写进常量 `__COLLAB_SITE_VERSION__`，所以写进站点的功能包和插件打包的数据模型包是同一个站点协议号。

- `site/` 还没有 `package.json` 是新站点，要给 `port`（开发端口）与 `title`（站名）；已有站点不能给这两样
- gwb-docsite 先装依赖，再照装好的基础包与功能包的模板整个重写 `site/app/`、覆盖 `site/` 根下的配置文件，模板带来新依赖就再装一次；`content/`、`comments/`、`people.json`、`journal/` 已有的不动。站点在运行就先停、做完再启动
- `repo` 不要求在项目列表里：新建项目时协作仓还没加进列表。在列表里的，做完再查一遍（下面「托管之前查什么」），通过了交给 gwb-docsite 托管
- 只写文件、不提交：用 `collab.submit` 提交审核；`site/package.json` 里 `dependencies`、`devDependencies` 两段以外的键、`site/` 根下的配置文件只有项目负责人能改

用在三处：新建项目时建出站点（见 [建项目与人员变动](/gitea/setup)）；旧形态的协作仓由仓里的 `scripts/migrate-site.mjs` 迁完页面与评论以后写骨架、装依赖；基础包或功能包升级以后，让骨架和装上的那一版对上。

## 交给 gwb-docsite 托管

插件加载后、项目加进列表后，组织这一层对每个项目调 `CollabSites.keep(repo)`：查过（下一节）就交给 `gwbDocsite.keep(<仓根>/site)` 常驻，再推一次数据；查不过不交，只把原因按仓根记下。

gwb-docsite 托管以后，常驻失败停下（5 分钟内失败 3 次）、没装依赖、它自己的启动前检查不过，原因都在它的 `status(dir).error` 里。窗格读 `stateOf(repo)`：地址在运行时取 gwb-docsite 的 `status(dir).url`，没运行时取预期地址 `status(dir).expectedUrl`，原因先取本插件记下的、没有再取 gwb-docsite 的（接缝 21）。原因不为空时窗格那一行标红「站点没能启动」、端口是红点、原话写在那一行下面，`collab.projects` 的 `site.error` 就是这句原话。

项目移出列表时调 `forget`：gwb-docsite 停掉它、忘掉它的推送，这里忘掉检查的原因；插件卸载时对交给过 gwb-docsite 的全部项目做同样的事。

## 托管之前查什么

`site-files.ts` 的 `requireCollabSitePasses(siteDir)` 查两样，不过就抛 `CollabRejected`，原话写明每条问题和怎么改：

1. **站点协议号**：读 `site/node_modules/@godcreator/collab-site/package.json` 的 `collabSiteProtocol`，和插件打包的数据模型包的 `siteProtocol` 比。没装功能包就让人在 `site/` 里 `pnpm install`；`site/` 装的更新，让人升级 gwb-collab；更旧或没写，让人把 `site/package.json` 里功能包的范围改成 `^<siteProtocolSince>`、重装、锁文件一起提交审核
2. **站点检查**：插件打包的功能包 `./site-check` 的 `collabSiteProblems(siteDir)`：基础包查人员列表、评论文件的格式与作者、评论快照，功能包再查 `journal/` 里日志页的文件名（见 [功能包](/collab-site)）

{/* ref file="../plugins/collab/src/site-process/site-files.ts" lines="35-62" hash="ed5c7112b51a" blob="023aa2266b55" */}

只查这两样，因为 gwb-docsite 启动前自己还会查有没有 `package.json`、装没装依赖、基础包那部分站点检查；协议号与日志页是协作站自己的约定，它不知道。

查的时机：

| 什么时候 | 调哪个方法 | 不过时 |
| --- | --- | --- |
| 插件加载、项目加进列表 | `keep` | 不托管，只记下原因 |
| `collab.site.init` 做完、项目在列表里 | `init` 里调 `keep` | 同上 |
| `collab.site.start` | `start` | 命令拒绝，原话就是原因 |
| 自动同步快进进来的提交改了 `site/`、依赖没变 | `recheck` | 让 gwb-docsite 停掉、不再托管，原因留给窗格；通过了就重新 `keep`，之前因为检查不过停着的，修好的版本同步进来就托管上 |
| 装完依赖（协议号可能跟着变了） | `whileStopped` | 同上 |

## 打开与停止

`collab.site.start` 先查一遍，再交给 `gwbDocsite.open`：没在运行就启动，清掉人为停止与连续失败的记录，照 gwb-docsite 的设置 `site-window` 打开（默认 Chrome 的应用窗口）。`collab.site.stop` 交给 `gwbDocsite.stop`，这次加载期间不再自动启动，直到 `collab.site.start` 或插件重新加载。协作窗格里点站点端口或通知标签都调 `collab.site.start`。

{/* ref file="../plugins/collab/src/site-process/commands.ts" lines="32-55" hash="c526def4954d" blob="1820bf292242" */}

用什么窗口打开、窗口怎么认、身份码怎么交给开发服务，都在 gwb-docsite 里，本插件没有这方面的设置。

## 推给网站的数据

网站自己不运行 git，推给网站的数据由插件算好交过去，网站只显示，也不向插件发请求。交给站点的只有一份 `SiteFeed { notifications, projectLeads }`（形状在数据模型包的通知模型里，见 [数据模型包](/collab-model)）：按组排好的通知和协作仓那一套最近读到的项目负责人，由 `ProjectNotifications.feedOf` 在推的那一刻现算（见 [通知](/gwb-collab/notices)）。

两边哪一样状态变了（本机状态、自动同步的结果、提交审核失败、读到的负责人与合并请求、规矩的问题、组织 webhook 的问题、各步的出错），都调通知的 `changed(repo)`，它调 `CollabSites.feedChanged`，经 `gwbDocsite.push(<仓根>/site, 'collab', feed)` 推到站点推送通道的频道 `collab`（接缝 20）。站点没在运行时 gwb-docsite 只记下最新的一份，启动后补推，所以本插件不用等站点起来再推。`collab/` 与 `site/` 里的文件一变协作仓的本机状态就重算，有人写了记录或评论、自动同步带进新的，找我的通知也跟着重算、推过去。

推是排队一个一个推的，轮到时才读最新的一份，接连变化时后推的一定是新的；推不上写一行警告，同样的原因只写一次。

## 装依赖与类型检查

`site-process/dependencies.ts` 在 `site/` 里运行 `pnpm install` 与 `pnpm run typecheck`，退出码不是 0 就把 pnpm 输出的最后 40 行报出来。

- **装依赖**由「克隆项目」与自动同步（快进进来的改动动了 `site/package.json` 或 `site/pnpm-lock.yaml`）调，经 `CollabSites.whileStopped` 交给 `gwbDocsite.whileStopped`：站点先停，装完按常驻的规矩启动；装失败时站点保持停着，报错写明装好后用 `collab.site.start` 再启动
- **类型检查**由提交审核调，站点的 `package.json` 没写 `typecheck` 脚本就不运行，回 `no-script`
