一个项目是 Gitea 上的一个组织。成员把组织克隆下来、把本 home 的身份码加进协作仓的人员列表、加进插件的项目列表，之后刷新、站点、提交审核都按这个列表做；身份是身份码在人员列表里认出的人，联网用 gwb-gitea 的令牌。这一页的代码在 `project/`、`organization/setup/`、`collab-repo/leads.ts` 与 `pane/`。

## 身份与负责人

插件不存「我是谁」，也不存令牌。身份由两样定：本 home 的**身份码**（gwb-docsite 的设置 `identity-code`，它第一次加载时生成，本插件经 `gwbDocsite.identityCode()` 取），和协作仓里的**人员列表** `site/people.json`（基础包的格式，每项 `{ id, name, codes?, gitea?, agent? }`）。码在哪一项的 `codes` 里，本 home 就是那个人，`id` 就是他的 Gitea 用户名；站点认人用的是同一份列表、同一个码，所以插件与网站认出的是同一个人。

打开项目（`openProject`）每次都现读：先查清 `repo` 是仓根、是协作仓，再用数据模型包的 `personOfCode` 认人；码不在列表里就拒绝，写明运行 `collab.project.join`。

**协作仓怎么认**：仓根下同时有 `collab/` 与 `site/people.json` 的仓就是协作仓（`isCollabRepo`）。打开项目、克隆组织时挑协作仓、`collab.project.join` 都按这一条认。

一个人可以有几台电脑、几个 home，各有各的码，都写进自己那一项的 `codes`。码不是秘密：它进 git，挡不住组里的人冒用别人的码；联网的命令另外核对令牌的账号就是身份（见下面「Gitea 令牌」）。

谁是负责人也不存：每个仓的负责人就是 Gitea 上这个仓的协作者，`site/people.json` 不记（见 [Gitea 权限怎么配](/gitea/permissions)）。项目负责人（协作仓的协作者）在三处起作用，都现读 Gitea：

| 在哪用 | 谁读 | 怎么读 |
| --- | --- | --- |
| 推给网站的数据里的 `projectLeads`：网站头像上的星标、网站上删别人的任务与模块 | `collab-repo/leads.ts` 的 `CollabRepoLeads`（接缝 8） | 完整刷新与收到协作仓的 `leads changed` 时重读，变了才交给通知；这次加载后还没读到为 `null` |
| `collab.task.delete`、`collab.module.delete` 删别人的任务与模块 | `collab-repo/leads.ts` 的 `projectLeadsOf`（接缝 9） | 每次现读，当参数传给写入规则 |
| 提交审核推送前查只有负责人能改的内容 | `collab-repo/submit/` 自己 | 推送前经 Gitea 读协作仓的协作者，算出自己是不是项目负责人，交给合并检查包的 `leadOnlyProblems` |

{/* ref file="../plugins/collab/src/collab-repo/leads.ts" lines="6-36" hash="e19542aa5b3d" blob="b012e082430d" */}
{/* ref file="../plugins/collab/src/collab-repo/submit/submit.ts" lines="138-148" hash="2d8cbc63f6b4" blob="92a88843de16" */}

别的仓的负责人是那个仓的协作者，`other-repos/review.ts` 每次重读那个仓时现读，只用来判断等我审阅的、轮到负责人回的该不该列给我，不交出去（见 [协作仓和别的仓](/gwb-collab/other-repos)）。

推送前这一查和执行器用的是合并检查包的同一个函数，版本却各有来源：插件用的是它发版时打包进去的那一版，执行器按协作仓 main 上工作流文件里 `MERGE_CHECK_RANGE` 写的版本安装。规则改了以后、成员升级插件之前，本机这一查和执行器可能不一样，以执行器的结论为准。

## Gitea 令牌

要联网的操作——取回、推送与等执行器的结论、克隆、读 Gitea——都用 gwb-gitea 设置里的地址与令牌，本插件不另存，每次现读：人在设置里换了令牌，下一条命令就用新的。

- 读法：局部注入 gwb-gitea 的服务 `gwbGitea`，调它的 `connection()` 读地址、推送地址与令牌。gwb-gitea 没装或停用时报「gwb-gitea 没装或没启用」；令牌是空字符串就报「还没填 Gitea 令牌」。令牌不进入命令回执
- 令牌对应的账号：经服务的 `http` 调 Gitea 的 `/user` 查一次，同一个令牌不再问

{/* ref file="../plugins/collab/src/gitea-api/access.ts" lines="31-70" hash="3e1916c5f7e5" blob="773c410e340f" */}

- 交给 git 的方式：令牌拼成 `Authorization` 请求头，配置键写成只对这个 Gitea 生效（`http.<base-url>/.extraHeader`），同时把 `credential.helper` 清空。两项都经环境变量 `GIT_CONFIG_COUNT` 只传给这一次 git 调用，不写进任何配置文件，也不出现在进程的命令行里，所以插件的 git 不经 Windows 凭据管理器
- 核对：协作仓的 `origin` 要在 gwb-gitea 配的那台 Gitea 上；令牌的账号要和身份（身份码认出的那一项的 `id`）一样。提交审核是 AGit 推送，Gitea 把合并请求记在推送用的账号名下，执行器拿这个发起人比对协作仓的协作者；两边不一样，记录的作者和合并请求的提交人就对不上，所以一开始就拒绝，写明两边各是什么、换令牌还是改身份码
- 项目文件夹：协作仓的上一级要是以 `origin` 的主人（组织）命名的项目文件夹，不是就拒绝，写明用 `collab.project.clone` 把组织整个克隆一遍。`origin` 在这一步只读一次，主人与仓名记在打开的项目里，之后取回别的仓、读合并请求、克隆新仓都直接用这个项目文件夹

{/* ref file="../plugins/collab/src/project/account.ts" lines="26-64" hash="fc5078bfe574" blob="62ff1b38908b" */}
{/* ref file="../plugins/collab/src/project/project.ts" lines="21-30" hash="762a42555d5f" blob="5507995a33f1" */}

只读本机的命令（`collab.inbox`、建改任务与模块、站点、`collab.projects`）不需要令牌；删任务与模块要读协作仓的协作者，`collab.project.join` 要读令牌的账号，都要令牌。一个 home 只有一个 Gitea 账号、一个身份码：同一台电脑上要扮演几个人（比如测试账号），各开一个隔离 home。

令牌只管插件自己运行的 git 与 Gitea 接口。人和 AI 在终端或 VS Code 里运行的 git 用 Windows 凭据管理器里存的登录：按 Gitea 地址存一份，第一次联网时登录一次，项目里所有仓共用；登录的账号要和令牌的账号相同。插件克隆出来的仓不改任何凭据配置。
插件的 git 用令牌，是因为能核对令牌的账号就是身份，后台的刷新也不会在凭据失效时弹出登录窗口；代价是令牌存在 gwb 的设置文件里，能调设置插件命令的程序（包括经 MCP 连上的 AI）都读得到，而 Windows 凭据管理器是用系统加密存的。

## 加入项目

项目列表是本插件的设置 `projects`，一行一个协作仓根，读写在 `project/list.ts`，加减项目、开始与停止监视在 `organization/events/`。还没克隆的，人把组织地址和放在哪个目录下告诉 AI，AI 调 `collab.project.clone {url, parent}`：

1. 在选的目录下新建项目文件夹 `<组织>/`（已存在就拒绝），经 gwb-gitea 列出组织里的仓（接缝 24），用令牌逐个克隆进去，文件夹名就是仓名，每个仓的配置里开 `core.longpaths`
2. 带 `collab/` 与 `site/people.json` 的仓正好一个，它就是协作仓；一个都没有或不止一个，照实报错、写明是哪些仓
3. 令牌的账号不在 `site/people.json` 里就到这里为止，回执 `listed` 为 `false`：请项目负责人加上 `{ "id": "<账号>", "name": "<显示名>", "gitea": "<账号>" }` 并合进 main，在协作仓里 `git pull` 拿到之后再调 `collab.project.join` 与 `collab.project.add`
4. 在里面就照 `collab.project.join` 把本 home 的身份码加进自己那一项，照 `collab.project.add` 加进项目列表，在协作仓的 `site/` 里 `pnpm install`，装完交给 gwb-docsite 托管。身份码那一行改动在工作区里，要 `collab.submit` 提交审核

中途一个仓克隆失败就停下，报出已经克隆了哪些、git 的原话，已克隆的留在项目文件夹里；要重来先删掉这个文件夹。加进列表或装依赖失败，报错写明前面做到了哪一步，前面的不回退。

{/* ref file="../plugins/collab/src/organization/setup/commands.ts" lines="51-90" hash="554508425fee" blob="ec7da9d915b4" */}
{/* ref file="../plugins/collab/src/organization/setup/clone-organization.ts" lines="33-65" hash="c181613481f6" blob="5ade7b0b6876" */}

`collab.project.join {repo}` 把本 home 的身份码加进协作仓 `site/people.json` 里令牌账号那一项：经 gwb-gitea 读令牌的账号，在工作区的人员列表里找 `id` 是这个账号的那一项，交给 `gwbDocsite.join` 把码加进它的 `codes`（接缝 28）；码已经在里面就不改文件，回执 `changed` 为 `false`。账号不在列表里就拒绝：加人只有项目负责人能做。只写工作区，改了要 `collab.submit` 提交审核；合并检查允许每个人只改自己那一项（`gitea` 是自己）的 `codes`，所以不是负责人也合得进去（见 [合并检查包](/collab-merge-check)）。换了电脑、换了身份码、自己克隆的仓都用它。

项目文件夹里只放仓，不放工作区文件：在 VS Code 里直接打开整个项目文件夹就是整个项目。

已经克隆好的协作仓，调 `collab.project.add` 加进列表。加进去之前先按协作仓的要求打开一次（本 home 的身份码要已经在人员列表里），再核对两条：协作仓 `origin` 的主人是 Gitea 上的组织（经 gwb-gitea 查 `/orgs/<主人>`），协作仓放在以这个组织命名的项目文件夹里；哪一样不满足就拒绝，写明原因：实时推送靠组织级的 webhook，项目里别的仓都按这个文件夹找。加进去后两边开始监视本机的仓、把站点交给 gwb-docsite 托管（见 [站点](/gwb-collab/site)）、约 2 秒后完整刷新一次，刷新完把它的组织加进实时推送的订阅。

`collab.project.remove` 移出列表：两边都不再监视它，忘掉为它读到、记下的（自动同步结果、负责人、合并请求与 issue、规矩的问题、组织 webhook 的问题、各步的出错），让 gwb-docsite 停掉它的站点，再核对一次订阅；它在本 home 的 QQ 命令一起删掉，QQ 任务组撤掉（见 [通知、QQ 私聊与交给 AI](/gwb-collab/notices)）。仓本身不动。

## 协作窗格

协作窗格是外壳里的「协作站」窗格，界面在 `pane/browser/`，只经命令总线调命令。窗格看得见时每 15 秒调一次 `collab.projects`；它只读本机，不取回远端（查令牌的账号除外），只给窗格用，要处理的事都是通知、经 `collab.ai.handoff` 交给 AI：

{/* ref file="../plugins/collab/src/pane/commands.ts" lines="28-43" hash="1c31f6bd0f0b" blob="61a621e0db6e" */}

回执 `{ watchError, gitea, push, projects }`：

| 键 | 是什么 |
| --- | --- |
| `watchError` | 设置 `projects` 写错了的原因，这时 `projects` 是空的，刷新、站点、实时推送都没开始；每次现读，改好了就是 `null` |
| `gitea` | `{ login, baseUrl, error }`：gwb-gitea 配的账号与地址，没装、没填令牌或令牌无效时 `login` 为 `null`、原因在 `error` |
| `push` | 实时推送 `{ state, url, topics, error }`，全部项目共用一条，见 [组织事件](/gwb-collab/checks) |
| `projects` | 每个项目一项 `{ repo, summary, error, site, qqTaskGroup }`；打不开的项目 `summary` 为 `null`、原因在 `error`，一个项目出错不影响整张列表 |

`summary` 是 `{ repo, title, person, name, counts, giteaUrl }`：`title` 是项目名（站名，即 `site/content/meta.json` 的 `title`，没写就用协作仓的目录名），`name` 是身份在 `site/people.json` 里的显示名，`counts` 是通知三组各几条，`giteaUrl` 是 Gitea 上协作仓所在组织的网页。`site` 是 `{ url, running, error }`：在运行时是实际地址，没运行时是 gwb-docsite 从 `site/package.json` 的 `dev` 脚本读出的预期地址（读不到为 `null`），`error` 是没交给 gwb-docsite 托管的原因或 gwb-docsite 报的原因（接缝 21，见 [站点](/gwb-collab/site)）。`qqTaskGroup` 是 `{ command, registered, error }`：本 home 给这个项目起的 QQ 命令（没起为 `null`）、此刻有没有注册成 QQ 任务组、没注册上的原因（见 [通知、QQ 私聊与交给 AI](/gwb-collab/notices)）；窗格不显示它。

{/* ref file="../plugins/collab/src/pane/commands.ts" lines="7-26" hash="cf4f9800830a" blob="61a621e0db6e" */}
{/* ref file="../plugins/collab/src/pane/summary.ts" lines="7-27" hash="45804a8c831d" blob="7f633c564fda" */}

**窗格的计数和网站一样**，因为数的是同一份通知：`summaryOf` 拿 `ProjectNotifications.currentOf` 现算的通知，用数据模型包的 `notificationCountsOf` 数三组（接缝 22），网站提示栏收起时也用这个函数。所以别的仓的合并请求、轮到负责人回的 issue 只算进那个仓负责人的那一行，找我的按本机身份算。本机状态用两边监视着的那份（文件一变就跟着变），合并请求、issue、各步的出错、没能自动同步是最近一次读到的结果。

窗格里每个项目一行，从左到右：

1. 项目名、我的显示名
2. 通知标签：写成「协作仓 N 条 · 别的仓 K 条 · 找我的 M 条」，没有的那一组不写；协作仓组有通知标红，只有后两组有标黄，都没有是绿的「没有通知」。站点在运行时点它打开协作站，每一条是什么在网站顶部的提示栏里，窗格不列通知。项目打不开时标签是「打不开」，站点没能启动时是「站点没能启动」，都标红，原因写在这一行下面
3. 「交给 AI 处理」按钮：有通知时才出现，点了调 `collab.ai.handoff`，交的时候按钮写「正在交给 AI…」；成功后这一行下面写「已把 N 件事交给 ZCode，会话 …」或「已把 N 件事交给新开窗口里的 Claude Code，提示词在 …」，失败写「没能交给 AI：」加命令回的原话（见 [通知](/gwb-collab/notices)）
4. 右边三个入口：站点端口（运行中绿点，没运行灰点，没能启动红点；点它调 `collab.site.start`，没在运行会先启动）、Gitea 上协作仓所在组织的网页、用 VS Code 打开整个项目文件夹（`collab.project.open`）

{/* ref file="../plugins/collab/src/pane/browser/projects.ts" lines="26-61" hash="dfe1262d239e" blob="e64a309a01c7" */}

站点不用新窗口链接打开：窗格里的新窗口链接会被内核交给系统默认浏览器，开不了 Chrome 的应用窗口。窗格顶上显示 gwb-gitea 配的账号，下面一行是实时推送的状态标签：连上了是绿的，有项目没订上、连不上 NAS 等重连是黄的，没能开始是红的，鼠标停在上面看原因或订的是哪几个 topic。推送订阅断了只在这个标签上显示，不成为通知。

{/* ref file="../plugins/collab/src/pane/browser/projects.ts" lines="75-94" hash="426cc8e58583" blob="e64a309a01c7" */}

窗格里能点的只有打开站点、Gitea、VS Code 和「交给 AI 处理」，别的操作让 AI 做：「怎么用」展开一段说明，写这个窗格怎么看、「交给 AI 处理」交给谁、别的操作可以怎么对 AI 说、第一次用之前要做什么。绿色是本插件在 `pane/browser/tokens.css` 里声明的，外壳的主题令牌里没有。
