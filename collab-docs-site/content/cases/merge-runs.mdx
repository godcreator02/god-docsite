下面五种是 2026-09-30 在 MMC 协作仓上实测的，那时检查只有三条（没有冲突、合并后只改了 `collab/`、没有新的格式问题），前一条不过后面的就不查；合并请求编号、用时与留言是那次的原样。
按 [合并检查包](/collab-merge-check) 的规则，执行器只查两条：没有冲突、没改只有负责人能改的内容。拿这五种对照：#25 那种格式不对的记录，成员的插件提交前在本机就拦下、推不上来，执行器不查格式；#26 另外改的是仓根的 `README.md`，谁都能改，不拦；新加记录、两人改同一行、删记录三种结论相同，冲突留言的末尾写「改好冲突的文件」。没合并的都被打回：留言末尾写合并请求已关闭、改动已退回提交人的工作区，再关掉合并请求。
