功能包分两侧：服务端函数（`src/server/`，在站点的服务端运行，由布局数据 `./site-server` 与 `src/routes/` 里路由模块的 loader、action 调）和界面（`src/ui/`，在浏览器里运行）。
两侧没有 import 关系，只靠根上的 `site-data.ts` 对上：布局交给界面的 `CollabSiteData`、写任务的地址与 action（接缝图上的 7 到 10，见 [功能包](/collab-site)）。

## 数据怎么到页面上

基础包骨架里整站布局的 loader 每次都调功能包 `./site-server` 的 `layoutData`，读一份协作数据：从 `collab/records/` 算出任务与模块，加上人员列表、本机身份、gwb-collab 推来的通知与项目负责人、有日志的日子，
以及骨架交进来的站里每一页（任务链接页面时从里面选）。`./site` 的 `Provider` 用 `CollabDataProvider` 包住整个布局，把它交给下面所有页面，任务页、日历、通知栏、`RecordLink` 都经 `useCollabData` 取同一份：

{/* ref file="../packages/collab-site/src/feature/site-server.ts" lines="4-7" hash="df4a9f5b8b56" blob="01369d4f3b2b" */}

{/* ref file="../packages/collab-site/src/server/index.ts" lines="26-42" hash="9f76ec3c5a99" blob="dedd98507f38" */}

gwb-collab 不往站点发请求，它把通知与项目负责人推进基础包推送通道的频道 `collab`（推送通道怎么工作见基础包自述站的「开发服务插件」页）。
浏览器里推来新的一份，`CollabDataProvider` 先用上它的通知与负责人，再让布局的 loader 重新读一遍。gwb-collab 每次检查完协作仓就推一次，
所以 AI 直接改的、自动同步进来的任务与模块，也在这时出现在页面上：

{/* ref file="../packages/collab-site/src/ui/collab-data.tsx" lines="10-22" hash="f27a56d9d902" blob="1f1f384c53dc" */}

还没推来时通知与负责人为 `null`：通知栏不出现，谁的头像都不标负责人，删任务与模块的请求按「没有负责人」处理。不是 gwb-docsite 启动的站一直是这样。

## 写任务与模块

网页上新建、修改、删除任务与模块，都发 `POST /api/collab`，请求体是 `{ action, record }`。功能包的路由模块 `src/routes/collab.ts` 原样交给 `collabRecordResponse`，
它带上本机身份交给数据模型包的写入规则，通过了才写 `collab/records/` 里的文件，不运行 git：

{/* ref file="../packages/collab-site/src/server/index.ts" lines="64-91" hash="2a8b55bdad0a" blob="dedd98507f38" */}

| 回什么 | 什么时候 |
| --- | --- |
| 200 | 写好了；新建回新记录的 id，删除回删掉的文件 |
| 400 | 请求体不是 JSON、`action` 认不出、多了字段 |
| 403 | 只读：站点不是 gwb-docsite 启动的，或本机身份码不在 `people.json` 里；正文是基础包给的原因 |
| 405 | 不是 POST |
| 422 | 写入规则拒绝，正文是它的原话（比如改了别人任务里不许改的字段、模块下还有任务时删模块） |

{/* ref file="../packages/collab-site/test/server.test.ts" lines="68-86" hash="8d1edcf8c447" blob="76b5b01be85d" */}

界面这边由 `useCollabWriter` 发请求：被拒时把原话抛给表单显示，写好了等布局的 loader 重新读完才返回，所以接着跳到新建的那一页时它已经在了。
页面上显示的永远是 loader 读出的文件，不是网页自己记的改动。

## 任务页与任务那一页

`/tasks` 从上到下三块：人员卡片（`people.json` 里的人，agent 不列）写每人没做完、过期的任务数和负责的模块；甘特图只画模块，每个模块一行，只在截止日画一个记号；
看板放具体的小任务。点人员卡片看板只显示他负责的任务，点甘特图上的模块只显示它的任务，两个筛选同时生效。能写时新建任务、模块在弹窗里只填最少的几项，建好就打开它那一页。

每条任务、每个模块另有自己那一页 `/tasks/<记录 id>`。能改哪些字段和写入规则一致：作者都能改，别人只能改 `fieldsAnyoneMayChange` 里列的；删除按钮只有作者和项目负责人看得到：

## 日历与日志

日历 `/calendar` 是月历（`?month=YYYY-MM` 看别的月），一周从周一开始；有日志的日子画一个点，模块截止的那天画和甘特图同一套的记号，点任何一天进 `/calendar/<日期>`。

某一天的日志是站点目录里的 `journal/<日期>.mdx`，全项目一天一篇，由 AI 写进文件、提交审核，网页上不能写，不记是谁写的。
功能包模板复制进站点的 `journal` 集合把它编译成页面，路由模块 `src/routes/journal.tsx` 显示它，顶上一条 `JournalDayBar`：回到那一月的日历、前后有日志的日子、当天截止的模块。那一天没有日志时显示「这一天还没有日志」，今天以后的日子写「还没到这一天」。
日志页和别的 MDX 页一样能写 fumadocs 的组件与 `RecordLink`，但不进侧栏的页面树。

`journal/` 里只能放 `<真实日期>.mdx`，不合规矩的文件站点检查报错，布局的 loader 读有日志的日子时也直接报错：

### RecordLink 与日志里的进展

MDX 页面（内容页、日志页、评论正文）不用 `import` 就能写 `<RecordLink id="记录 id" />` 引用一条任务或一个模块：显示记录当前的标题，任务带状态、模块带截止日的记号，点了进它那一页。
指向的记录后来删了写「已删除的记录」，不报错，以前的日志照样打得开：

{/* ref file="../packages/collab-site/src/ui/record-link.tsx" lines="20-96" hash="69cb8a24544d" blob="edf0b6e2a1a2" */}

每条任务、每个模块那一页的最下面是「日志里的进展」，就是日志引用它的反向链接。记录页的 loader 读全部日志页的原文，`journalMentionsOf` 按空行分段，
找出写了这条记录的 `RecordLink` 的段，段里的引用换成记录当前的标题、去掉别的标记，新的日子在前。只算日志页，内容页里的 `RecordLink` 不算：

## 页面上的评论

任务页、任务与模块各自那一页、日志页能和内容页一样写评论：路由表里这几条标了 `comments: true`，基础包的评论接口与启动检查就认这些地址。
路由的 loader 用 `routeCommentData` 取评论数据，页面用 `RouteComments` 包住正文。只认地址的样子，删了任务，批它那一页的评论照样留着。

## repo: 链接

正文里写 `repo:<仓>/<路径>` 链接项目文件夹（协作仓的上一级）里别的仓的文件，文本文件可以带 `#L<行号>`，PDF 可以带 `#page=<页>`。
卡片显示出来时问 `POST /api/repo-links` 能不能打开，点了按回答打开：PDF、图片、网页、视频经 `/api/project-file/` 在浏览器的新标签页里看，
文本文件在开着项目文件夹的 VS Code 窗口里打开并跳到那一行，别的用系统默认程序打开。
本机没克隆那个仓画成灰色，文件不在、路径写错画成红色，原因写在鼠标停上去的提示里。只读的站点（没有本机身份）不碰项目文件夹，链接一律是灰色：

## 通知栏

顶部正中的通知栏列出 gwb-collab 推来的通知，每条的短句、原文、点了去哪都由数据模型包的 [通知模型](/collab-model) 按 `kind` 算，网站自己不拼句子。
按组分三段：协作仓、别的仓、找我的，各一种颜色；别的仓一个仓一行。收起时只写各组几条，没有通知（或还没推来）时整个不显示：

{/* ref file="../packages/collab-site/src/ui/notification-bar.tsx" lines="161-168" hash="71b7dae09823" blob="1ed0c7fdd4cc" */}

插件按此刻的状态算，处理好了就不再推，通知栏里随即消失，没有「已读」。点短句按通知的去处走：任务通知去那条任务那一页；@我与回复我的去评论所在的那一页并打开那串评论
（地址带 `?comment=<评论串>`，不属于任何页面的去全部评论页）；合并请求与 issue 开 Gitea 的网页；没有去处的只显示。理由见 [提示栏取代通知](/trajectory/2026-10-03-notice-bar-replaces-notifications)。

{/* ref file="../packages/collab-site/src/ui/notification-bar.tsx" lines="83-101" hash="8701b3f535c6" blob="1ed0c7fdd4cc" */}

网页上没有提交、同步、交给 AI 的按钮：要交给 AI，就在 gwb 的协作窗格里点那个项目一行上的「交给 AI 处理」，通知栏展开后顶上写着这一句。

## 不做的事

- **不运行 git、不算通知**：通知与项目负责人都是插件推来的，网站只显示
- **不向插件发请求**：交给 AI 在协作窗格里，网页只收推来的数据
- **不检查绕过写入接口的改动**：AI 或别的程序直接改的文件照样读出来显示，读不出的列进问题，校验留给提交审核
- **页面、评论不归这里**：内容页怎么写、评论怎么存照基础包，见 [页面怎么写](/collab-site/pages)
