# 命令行

这一章回答：三条命令各打印什么、退什么码，problems 长什么样，记录簿那个 json 里到底存了什么。

命令行的 cwd 就是项目根——`livedoc.config.mjs` 在哪儿，就在哪儿跑。三条命令逐篇处理文档目录下
被格式包认领的每一篇。

## 输出的词汇表

一行一处引用：状态符号、文档、`文件:起-止`、一句话说明。

{/* ref file="../packages/cli/src/run.ts" lines="17-32" */}

`REASON` 前三条是「缺失」的细分——说清楚是哪一种指向空气，而不是含糊地报一句「代码没了」；
第四条 `unlocated` 是「有变动」的细分：hash 记忆找不到这段了，位置不明。`MEMORY` 是 `confirm` 用的：
哪一处拿到的是 hash 记忆（文件不在 git 里），那一行标出来。

## check：只读，报状态

{/* ref file="../packages/cli/src/run.ts" lines="75-90" */}

```text
🟢 content/docs/formats/wiring.mdx  livedoc.config.mjs:11-21  新鲜
⚪ content/docs/start/requirements.mdx  ../packages/core/src/types.ts:11-16  未确认，等作者确认
🟡 docs/a.md  src/greet.ts:2-3  有变动，等作者复核
🟡 docs/a.md  vendor/lib.ts:2-3  有变动，等作者复核（hash 记忆找不到这段了，位置不明——重读源码、重钉）
🔴 docs/a.md  src/greet.ts:4-5  缺失，引用指向空气（整段已被删光）
```

红有三个来源，都算数：**缺失**的引用、**孤儿记录**（记录簿里有、文档里已经没有了）、
**名册外组件**（`livedoc.config.mjs` 里没给它压平规则）。

```text
🔴 docs/a.md  src/greet.ts:4-5  孤儿记录：文档里已经没有这处引用
🔴 docs/b.mdx  第 7 行 <Callout>  名册外组件，livedoc.config.mjs 里没给它压平规则
```

## confirm：出记录、清孤儿、换记号

{/* ref file="../packages/cli/src/run.ts" lines="92-108" */}

顺利的时候一处一行 `✅`，清掉的孤儿一行 `🧹`。文档本身删了、挪了的，它的记录逐篇那圈看不到，`check` 按文档清单一览算红，`confirm` 末尾整个忘掉，也是一行 `🧹`：

```text
✅ docs/a.md  src/greet.ts:2-3  已确认，草稿记号已换成正式记号
✅ docs/a.md  vendor/lib.ts:2-3  已确认，草稿记号已换成正式记号（hash 记忆：不在 git 里）
🧹 docs/a.md  src/greet.ts:4-5  孤儿记录已清
🧹 docs/old.md  文档已不存在，记录已清
```

后面那句会说清楚这一趟到底动没动文档：草稿记号换掉了、文档写回了、还是什么都没改。
末尾的括号说清楚拿到的是哪种记忆：被 `.gitignore` 忽略的、不在任何仓里的文件走 hash 记忆——没有旧内容、
变了就找不着，写手得知道这是弱记忆。分派规则见 [状态与比较器](/docs/principles/comparator)。

有一处钉不住就整篇拒，problems 逐条打出来，末尾补一句「这篇整篇没确认」：

```text
🔴 docs/a.md 第 3 行：src/greet.ts:2-3 未提交——钉住只对已提交的内容做，先 commit
·  docs/a.md  这篇整篇没确认——上面几处先处理掉
```

## render：问格式包要产物

{/* ref file="../packages/cli/src/run.ts" lines="110-119" */}

格式包没有对应的渲染函数就说一声、退 0，不当错：

```text
→  docs/a.md  渲染成 ai：out/a.md.ai.md
·  docs/a.html  html 的产物就是文档本身，人和 AI 都读它
```

fumadocs 那份的 `renderAi` 是借它自己的 loader 出的 md，见 [fumadocs 格式包](/docs/formats/fumadocs)。
人看的那份就是站本身，所以 `--target human` 在这几个格式包上都没有实现。

## 退出码

| 码 | 什么时候 |
| --- | --- |
| 0 | 全绿、全黄、全白都算过——**黄和白不是错**，黄是等作者复核，白是等作者确认 |
| 1 | 有红：缺失、孤儿记录、名册外组件；`confirm` 里有 problems 也是 1 |
| 2 | 命令名不认识 |

所以门禁里可以直接 `pnpm livedoc check`：它只在「引用指向空气」这一类真错上拦人。

## 记录簿：一个 json，两层键

文档 → `文件:起-止` → 记录。这是**记忆本身**，要进 git。

```json
{
  "docs/a.md": {
    "src/greet.ts:2-3": {
      "kind": "git",
      "blob": "51e8ec8849b61cbf6589846f637126cae78e4a0e",
      "commit": "4107961e9d27c8a9d2d0d8f9260495a61406d323",
      "lines": [2, 3],
      "hash": "c60d683fa80ca87e474727647e96b0d2d9354e32c6420587e04c8fc476d3ee0f"
    }
  }
}
```

除了 `kind`，别的字段归那个比较器自己定；一本记录簿里 `git` 和 `hash` 两种并存。git 版记这四样：
