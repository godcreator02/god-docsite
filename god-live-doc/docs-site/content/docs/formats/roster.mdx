# 名册

这一章回答：站上用了 `Tabs`、`Note` 这类组件的地方，给 AI 读的那份 md 里该出现什么，谁说了算。

## 为什么要压平

mdx 里的组件是 JSX 节点。序列化成 md 时，它要么原样漏成一个裸标签（AI 读到一个 `Tabs` 标签一头雾水），
要么被整个丢掉（内容也没了）。两条都不行——所以要一张表说清楚：**每个组件在 md 里变成什么**。

这张表叫名册。机制在格式包里，内容在项目自己的 `livedoc.config.mjs` 里——组件是项目的，
规则当然也该是项目的。

## 规则三种写法

{/* ref file="../packages/format-fumadocs/src/roster.ts" lines="34-35" */}

- `"children"`：只留子内容，去掉外壳。
- `"drop"`：整个不进 AI 那份。
- **函数**：`(node, helpers) => 一个或一组普通 markdown 节点`。

嵌套的组件不用规则操心——子节点还在树上，各自有各自的标。**名册外的组件硬失败**，报到行；
命令行 `check` 也查这一条，不用等构建才发现。

格式包自带的默认表 `defaultRoster` 只有一条 `Note`，按语义定、不知道它在哪个站上长什么样：块级的
变成一个引用块（前面缀 `[note]`），写在句子里的变一段行内文字——别把句子拆断。项目一般把它展开，
再加上自己的组件。

## helpers 契约：节点对规则是黑盒

函数规则只能通过 helpers 读节点（`attr` / `textOf`）、造节点（`text` / `heading` / `paragraph` /
`quote` / `children`），**不碰 `node.type`、`node.children` 这些字段**：

{/* ref file="../packages/format-fumadocs/src/roster.ts" lines="21-32" */}

<Note>
  守住这一条，同一张表换个宿主照样能用：宿主各自提供一套 helpers，造的是自己的节点。
  规则里一旦直接摸 mdast 的字段，这张表就跟 mdast 绑死了。
</Note>

`inline` 告诉规则「这处是不是写在句子里」——行内的位置只能交回行内节点。这一条现在**没有机制守**，
靠规则作者自觉，记在[待定](/docs/maintain/roadmap)里。

## 打标不动树

{/* ref file="../packages/format-fumadocs/src/roster.ts" lines="124-137" */}

同一棵树接着还要出页面，所以 `stamp` 只在组件节点上挂标，不替换、不删除：`data.livedocAi` 是一组替换
节点（序列化时交给 fumadocs 的状态机接着走，嵌套组件顺着走），空的就挂 fumadocs 自家的
`data._stringify = { text: "" }` 表示整个不要。
