# 状态与比较器

一处引用只有四种状态，颜色跟着状态走：

<Tabs>
  <Tab title="🟢 新鲜">
    段哈希跟记忆里那份一样。代码挪了位置但内容没变，也是绿的——git 版靠 hunk 表跟，hash 版靠滑窗跟。
  </Tab>
  <Tab title="🟡 有变动">
    内容变了，等作者复核，不退出码。git 记忆把改过的行渲成 diff（旧行新行在同一块里）；
    hash 记忆找不到这段了，只留一句「位置不明」。
  </Tab>
  <Tab title="⚪ 未确认">
    还没确认过（新写的引用，或者记录是别家比较器记的）。空心黄，跟「改过了」是两回事。
  </Tab>
  <Tab title="🔴 缺失">
    引用指向空气：整段被删光、文件没了、或者记忆里的 blob 不在对象库。显示的是文档写下时那段。
  </Tab>
</Tabs>

**两个方法就是全部**：`snapshot` 在确认时出记录，或者说清楚为什么钉不住；`judge` 在核对时判状态，
顺便交回这段今天在哪。三个实现：`git`、`hash`，和默认的 `auto`——它自己不记，按文件位置挑前两个。

## 记忆按文件位置分派

被引文件不限于项目自己的仓：另一个单元的仓、上游 clone、被 `.gitignore` 忽略的 `node_modules`、
不在任何仓里的目录，都能钉。规则一条：

| 文件在哪 | 记忆 |
| --- | --- |
| 任何 git 仓里、已跟踪、干净 | **git**，本仓外仓一视同仁 |
| 任何 git 仓里、已跟踪但有改动，或未跟踪且没被忽略 | 拒，「先 commit」——**不退成 hash** |
| 仓里但被 `.gitignore` 忽略（`git check-ignore` 说的） | **hash** |
| 不在任何仓里 | **hash** |
| 仓还没有一次提交 | 拒，「这个仓还没提交过」 |

{/* ref file="../packages/project/src/auto-comparator.ts" lines="22-27" */}

「该进 git 的东西」不能悄悄退成一份弱记忆，所以未跟踪、脏的一律拒，只有明确被忽略的才走 hash。
文件在哪个仓按它的**真实路径**定（pnpm 的软链按指向的地方算），细节见 [git 原理](/docs/principles/git)。

核对时不看文件在哪，按**记录的 kind** 转发——记录是当时哪种记忆记的，就让哪个比较器判：

一个项目里 git 记录和 hash 记录并存。哪一处拿到的是 hash 记忆，`confirm` 那一行会标出来
（见 [命令行](/docs/cli/cli)）——写手得知道自己拿到的是弱记忆。

记忆就是那个仓 HEAD 里的 blob，哪儿都不存第二份内容。判定拿 `git diff -U0 旧内容 当前内容` 出 hunk 表，

<Note>
  **绿只认段哈希**：hunk 说没碰到也再比一次。行映射跟内容对不上时（记录被手改过之类），
  宁可报黄让人复核，也不把红判成绿。

确认那头守几道门：在某个仓里、那个仓提交过、文件在 HEAD 里（未跟踪、大小写不符都拒）、工作区干净。
**钉住只对已提交的内容做**——先 commit，再 confirm，别人的仓也一样。细节见 [git 原理](/docs/principles/git)。

## hash 版怎么判

只记段哈希和旧行号，不问 git，也没有旧内容。行段靠**滑窗**跟：先看旧位置，不对就按段长在整个文件里
逐行滑一遍找同哈希的窗口：

{/* ref file="../packages/core/src/hash-comparator.ts" lines="53-68" */}

- **内容没变、只是挪了**：找得到，绿、带新行号，跟 git 版一样。
- **撞车**（同样的段出现不止一处，一两行的 `}` 之类常见）：取离旧位置最近的一处；两处一样近就不猜，当找不到。
- **找不到**：内容改了。没有旧内容，给不出 diff，也定位不了——报「有变动、位置不明」（reason `unlocated`），
  行号停在旧位置，站上那一块不摆代码、只留一句提示，等人重读源码重钉。旧位置已经超出文件的，当整段没了（`vanished`）。

这就是 hash 记忆比 git 记忆弱的地方：升一次依赖版本，挪和改往往一起发生，git 记忆一屏黄灯各带 diff，
hash 记忆一屏「位置不明」。所以能进 git 的都走 git，hash 只给进不了的。

## 记录带 kind：认不认是比较器自己的事

记录的第一个字段是 `kind`，记它的那个比较器的名字。核心不看它——取记录时原样递给比较器，
比较器看到别家的 kind 就交回「未确认」：

{/* ref file="../packages/core/src/hash-comparator.ts" lines="53-56" */}

所以配置里把 `comparator` 强制成 `hash`，原来的 git 记录一律退回「未确认」等人重新确认。
不把 git 的记录翻译成 hash 的记录——翻译就是猜。auto 版按 kind 转发，两种记录各归各的比较器判。
