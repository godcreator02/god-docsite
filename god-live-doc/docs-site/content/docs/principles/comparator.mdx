# 状态与比较器

一处引用只有四种状态，颜色跟着状态走：

<Tabs>
  <Tab title="🟢 新鲜">
    段哈希跟记忆里那份一样。代码挪了位置但内容没变，也是绿的。
  </Tab>
  <Tab title="🟡 有变动">
    内容变了，等作者复核。这一块把改过的行渲成 diff（旧行新行在同一块里），不退出码。
  </Tab>
  <Tab title="⚪ 未确认">
    还没确认过（新写的引用，或者换过比较器）。空心黄，跟「改过了」是两回事。
  </Tab>
  <Tab title="🔴 缺失">
    引用指向空气：整段被删光、文件没了、或者记忆里的 blob 不在对象库。显示的是文档写下时那段。
  </Tab>
</Tabs>

**两个方法就是全部**：`snapshot` 在确认时出记录，或者说清楚为什么钉不住；`judge` 在核对时判状态，
顺便交回这段今天在哪。两个实现：`git`（产品用）和 `hash`。

## git 版怎么判

记忆就是 HEAD 里那个 blob，仓里不存第二份内容。判定拿 `git diff -U0 旧blob 当前内容` 出 hunk 表，
把旧行段映到今天：

<Note>
  **绿只认段哈希**：hunk 说没碰到也再比一次。行映射跟内容对不上时（记录被手改过之类），
  宁可报黄让人复核，也不把红判成绿。
</Note>

确认那头守两道门：文件得在 HEAD 里（被 `.gitignore` 忽略、没跟踪、路径大小写跟 git 记的不一样，都拒），
工作区得干净。**钉住只对已提交的内容做**——先 commit，再 confirm。细节见 [git 原理](/docs/principles/git)。

## hash 版怎么判

只记段哈希，别的什么都不记。它**不跟行段**——记号上写的是哪几行，就一直看那几行：

{/* ref file="../packages/core/src/hash-comparator.ts" lines="31-38" */}

代价写在脸上：代码整体往下挪了两行，它只会说「有变动」，说不出挪到哪儿了，也拿不回旧内容
（记忆里没存第二份），所以站上那一块退成一块普通的当前段，标题里缀一句「· 有变动」。
它的用处是两个：没有 git 的目录能用；在测试里当第二实现，证明这个接口真能换。

## 记录带 kind：换了比较器不猜

记录的第一个字段是 `kind`，记它的那个比较器的名字。取记录时对不上，就当没有：

{/* ref file="../packages/core/src/service.ts" lines="53-57" */}

所以配置里把 `comparator` 从 `git` 改成 `hash`，全站引用一律退回「未确认」等人重新确认。
不把 git 的记录翻译成 hash 的记录——翻译就是猜。

## 归一化：站展示什么就哈希什么

换行统一成 LF、去每行行尾空白、去掉末尾空行。缩进保留，注释保留——JSDoc 是契约的一部分，改了就该黄。
展示前做的归一化就是哈希前做的归一化，两处共用同一个函数，两个比较器也共用。
