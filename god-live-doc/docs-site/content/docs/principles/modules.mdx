# 模块拆分

这一章回答：为什么是六个包不是一个，谁能依赖谁，以及核心凭什么敢说自己「不认识 git、不认识 fumadocs」。

## 六个包，四层

```text
core             零依赖（只用 node:crypto）。接口正本、编排服务、归一化与哈希、行段映射与 LCS diff、hash 比较器（滑窗）
project          装配：读 livedoc.config、造读取器 / json 记录簿 / 比较器；git 那条线和按文件位置分派的 auto 比较器也住这儿
cli              check / confirm / render
format-md        注释记号 + 围栏展示区 + 尾注释
format-fumadocs  mdx 与 fumadocs 是一个整体：remark 插件、序列化回调、meta 白名单、pre 组件 + 样式
format-html      元素既是记号又是展示区，文件即终态（final），不渲染
```

依赖方向只有两条线：`cli → project → core`，`格式包 → core`。多一条例外：`format-fumadocs` 还依赖
`project`，因为它在站的 remark 链上要自己装配一次项目。

## 核心零依赖，靠的是把三样东西倒过来拿

## 两个入口，同一条管线

算状态的只有一处——核心的编排服务。它被两个调用方使唤：

1. **命令行**：`cli` 调 `loadProject(cwd)` 拿到服务，逐篇 `resolve` 或 `confirm`。
2. **站构建**：`format-fumadocs` 的 remark 插件在 fumadocs 的链尾巴上，把已经认好的引用交给
   `resolveRefs`——树都解析好了，不必再 parse 一遍。

两边装配的是同一份 `livedoc.config.mjs`，所以站上看到的状态和 `pnpm livedoc check` 报的状态必然一致。

## 换一样东西要动几个包

| 想换的东西 | 动哪儿 |
| --- | --- |
| 换一种文档格式（asciidoc、typst……） | 新写一个格式包，核心一行不动 |
| 换记忆的记法（不用 git） | 实现 `Comparator` 两个方法，配置里换个名字 |
| 换记录簿的存法（换成数据库） | 实现 `Ledger` 五个方法 |
| 换站的宿主（不用 fumadocs） | 只动 `format-fumadocs` 一个包 |
