# 记号：草稿与正式

作者不用记各格式的记号长什么样。想引一段代码，**在文档里写一行草稿记号**就行：

```md
@@livedoc ref src/greet.ts:2-3 @@
```

`check` 会认它、报「未确认」；`confirm` 把它换成这种格式的正式记号并投影内容，之后草稿不再出现。

## 草稿记号：核心定，四种格式一个写法

整行匹配，头尾的 `@@` 是哨兵——少一头就是普通文字，不报错；写在句子里的不算；写在围栏里、
`<script>` 里的也不算。载荷交给 `toTarget` 校验，行号不合理就报到行。

{/* ref file="../packages/core/src/types.ts" lines="152-158" */}

动作词现在只有 `ref`。`exists`、`tree` 是给下一步留的位子（见 [待定与路线图](/docs/maintain/roadmap)）。

### 四种不认

「认得出」只是一半，「什么时候不认」才是这套写法敢往正文里塞的理由。四种情况一条测试守着，
三个格式包一起过：

{/* ref file="../tests/marker.test.ts" lines="29-40" */}

| 不认的情况 | 为什么 |
| --- | --- |
| `@@livedoc ref a.ts:1-2`（少一头哨兵） | 哨兵不齐就是普通文字，**不报错**——文档里聊到这个写法不该炸 |
| 写在句子里：`这句话里有 … 不算` | 草稿记号必须独立成段（html 那头是独立成行） |
| 围栏里的同样文字 | md / mdx 走语法树：围栏里是 `code` 节点，压根不是段落 |
| `<script>` / `<style>` 里的，或转义写成 `&lt;pre` 的 | html 逐行扫时跳过这两种块；转义过的文本天然不匹配 |

## 正式记号：格式包定，各长各的

`marker(target)` 出一行，`parse(marker(t))` 必须认回 `t`——「怎么写」和「怎么认」住同一个包。

<Tabs>
  <Tab title="md">
    `<!-- ref file="…" lines="a-b" -->` + 一段围栏 + `<!-- /ref -->`。围栏是展示区：确认时投影进去，
    它是派生缓存不是记忆，手改它不影响状态。
  </Tab>
  <Tab title="mdx">
    `{/* ref file="…" lines="a-b" */}`。没有展示区——内容在 build 时现拿，页面里不存副本。
  </Tab>
  <Tab title="html">
    `<pre data-file="…" data-lines="a-b"></pre>`。元素既是记号又是展示区，闭合就是边界；
    容器是作者的（外面的 `figure`、`figcaption` 随便写），元素里面的内容归格式包，每次确认整个重写。
  </Tab>
</Tabs>

<Note>
  三种格式认记号都走语法树或逐行扫，不是全文正则：围栏里、行内、转义过的同样文字一律认不出来。
  这就是「为什么不用一条正则搞定」的答案。
</Note>

## 记号会自己挪

`confirm` 记的是**今天**这段在哪：代码往下挪了几行，下一次确认时记号上的行号会跟着改写，
记录簿里的旧键当孤儿清掉。所以记号上的数字不需要人去维护。整个过程见
[一条引用的一生](/docs/start/lifecycle)第五幕；各格式包怎么写回，见 [格式包](/docs/formats/formats)。
