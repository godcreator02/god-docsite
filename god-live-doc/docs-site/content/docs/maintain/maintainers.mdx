# 维护者手册

这一章回答：要改这个仓的代码，东西都放在哪儿、提交前得跑绿哪几条、提交怎么写、发布是什么状况。

## 仓布局

```text
单元根                          = git 仓
  AGENTS.md  CLAUDE.md  unit.json
  god-live-doc/                 pnpm 包工作区
    packages/                   core、project、cli、format-md、format-fumadocs、format-html
    docs-site/                  这个站：用这套机制写自己的文档，也是工作区成员
    tests/                      工作区级测试（八个文件）
  examples/                     邻居示例，外部引用这套包的消费方
    fumadocs-site/              外部 fumadocs 站
    plain/                      手写 html + 纯 md，比较器换成 hash
```

示例各自 link 依赖 `../../god-live-doc/packages/*`，各自 `pnpm install`、各自跑测试——它们扮演的就是
「装了这几个包的别人家项目」。

## 提交规矩

按步骤拆，一个提交一件事。文档章节和它带来的记录簿改动放在同一个提交里——记录簿就是那一章的记忆，
分开提交等于让中间那个提交自相矛盾。提交信息中文，末尾带会话里给的 `Co-Authored-By` 与 `Claude-Session` 两行。

## 发布：能发，没发

六个包都没写 `private`，也没配发布流程。真要发之前得先想清楚版本策略（六个包同版本还是各走各的），
见 [待定与路线图](/docs/maintain/roadmap)。现在消费方都是 `workspace:*` 或 `link:` 引的。
