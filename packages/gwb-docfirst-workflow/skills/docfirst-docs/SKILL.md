# 地图不是镜像

文档的职责是**路由注意力**——告诉读者东西在哪、先读什么、可以跳过什么；把代码翻译成散文
是镜像，写时浪费、随即漂移、读完还是不知道该看哪。

**一等读者是干活的 agent**，人是看呈现面的监督者。agent 直接读 mdx，不养机读副本；唯一
的生成物是 outputs（见末尾）。两条随手用的判据：

* **段落自检**：删掉这句读者会迷路吗？会——留；只是复读代码里也写着的事实——钉码指过去，或删。
* **每页头一句「本页回答：…」**。答不出问题的页删。

# 六区

```
docs-site/content/
├── docs/        # 1 现状：此刻是什么、为什么存在、边界在哪；散文、**钉码只在这一区**；入口页、边界页、system-map、模块页、start、glossary
├── trajectory/  # 2 轨迹：卡只增不改；evidence 卡指向仓根 probes/<时间戳>_<目的>/
├── spec/        # 3 交接：在途 spec 与实施方案，随做随提交，做完拆解归梁后删页
├── future/      # 4 未来：只放还没发生的事——roadmap（在等什么前提、到期再选的决定）；现状区一字不写未来
├── outputs/     # 5 生成正本：agents.mdx、readme.mdx、skills/<名>.mdx → render 到仓根与包内
└── feedback/    # 6 反馈：hatch（本仓重复操作候选）+ inbox（别的仓投来的，处理完删）
```

六种生命周期：现状长生、轨迹只增、交接必删、未来常改、生成随源、反馈周转。**目录即状态**：
`spec/` 有页就是有活在路上。

## 钉码只在现状区

**钉一处码，是在说「这句话跟着这段代码走，它变了就来找我」。** 只有现状区的论断是这种性质——
它讲当前代码长什么样，代码一改它就该跟着改。别的区不是：

* **轨迹**记的是当时的了断，**代码后来怎么变都不该动它**。钉了码，代码一改这张卡就变黄、要人复核，
  于是它从「历史」退化成了一份要维护的现状文档。这是条**硬红线**，`check` 会把卡里的记号当病报出来。
* **交接**（spec）随做随改，钉码的价值在于钉住稳定的论断，而在途的东西本来就不稳定。
* **未来**讲还没做的事，压根没有对应的代码可钉。
* **反馈**是别人写的意见，不是关于代码的论断。

`docfirst check` 因此只扫 **docs 与 outputs** 两区。outputs 进门禁不是因为要钉码，是要守
**生成物跟 mdx 源一致**；那些页里可以有钉码（比如 AGENTS 正本引一段配置），但那是顺带，
不是它进门禁的理由。

其余四区的记号与卡天然不进门禁——**在那儿写钉码，没有任何东西会守它，等于写了个不会响的闹钟。**

# 五梁一横

页面类型是职责，不是目录名；各站照体量自由摆页，但每页必须认梁，认不进的并页或删。

| 梁  | 回答的问题                 | 住哪区                              |
| -- | --------------------- | -------------------------------- |
| 愿景 | 为什么存在、只做什么、不做什么       | docs（入口页 `index`、边界页 `boundary`） |
| 用法 | 当前代码现状下怎么用            | docs/start                       |
| 设计 | 怎么拆的、怎么隔离开发测试、为什么这么切  | docs（system-map + 每模块一页）         |
| 未来 | 还没发生的事：在等什么前提、到期再选的决定 | future（roadmap）                  |
| 轨迹 | 怎么走到今天、每次取舍的理由        | trajectory（卡）                    |

判据：**此刻是什么归现状，怎么走到今天归轨迹，还没发生的才归未来。** 为什么存在、刻意不做什么
都是此刻的边界，住现状区；边界页每条「不做」只写一句此刻的边界，理由链到轨迹卡。入口页是现状区
的根（`docs/index.mdx`），循序渐进：是什么与为什么存在 → 主线走一遍（按本仓自己的主流程）→
按来意怎么读 → 模块索引；system-map 可以并进来。

横切两页：**glossary**（术语，住 docs）与 **hatch**（重复操作候选，住 feedback；短期内碰到
三次或人点名即升为 skill，升格后条目划掉指向新 skill，过期条目直接删）。

原理型内容（整体怎么转、一次调用从头走到尾、依赖方向为什么这样）归设计梁，厚薄由
「错了难改」判据定：错了难改的讲透，错了好改的一句话。

# 现状区怎么写

**只写现状、禁历史**：「原来怎样现在怎样」的对比一律不出现，历史归卡。正文散文；全站只有
四类固定结构块允许列表化：模块页固定块、契约钉码块、spec 页头的验收清单、glossary 表。

## 模块页固定块

每模块一页，七段顺序固定：**管什么 / 不知道什么 / 数据结构 / 提供的接口 / 依赖的接口 /
怎么单独测 / 代码地图**。「不知道什么」比「知道什么」更能钉边界；数据结构只钉形状，不列
字段；依赖的接口写成表（接口 / 用来做什么 / 生产实现 / 测试实现）；怎么单独测写「喂什么
假实现、证明哪几件事」。代码地图四件：**在哪**（物理位置）、**先读**（入口一两个）、
**读序**（依赖方向，谁吃谁）、**可跳过**（生成物、vendor、脚手架）。总索引一张放 system-map。

依赖必须单向、隔离靠接口不靠自觉、每块写清「不知道什么」——写不出来往往说明代码切错了，
先去改代码，别在文档里把环描述圆。目录树用 `tree` 引用钉，不手画。

## design 停止线

只写「错了难改」的：边界约束、依赖方向、接口契约（钉码）、状态机、取舍。像素、文案、字段
清单、内部算法是实现的自由度，写进 design 是过早承诺且立刻开始漂。判据一句话：**实现者
剩下的自由度里做任何选择都不违背 design，就够了**——再写一行都是过度设计。

## 写作规则

* **论断可验证**：要么钉码，要么给确切路径。命令、配置项、数字这类事实以代码为唯一真相。
* **复述代码行为的段落是坏味道**，改钉码；投影块是论据不是正文，一段引用配一句「这段说明什么」。
* **AGENTS.md 与 skill 精简**：前者是每会话固定开销，后者触发即读，每行都要挣位置——只留
  硬约束与「怎么干」，为什么住站里。站页可以厚，它是按需付的成本。
* **引卡背书，不当铁律**：引一张卡的意思是「有先例」，不是「不许动」。环境变了就写新卡推翻。
* **现状页少做站内链接**；对决策的说明一律下沉到轨迹卡再连。
* 手画目录树、手抄配置样例、给跑出来的数字写散文，都是腐化源；别钉生成物与 `.ledger.json`。

## 五类引用各钉哪种话

| 引用                          | 该用在这种话                        |
| --------------------------- | ----------------------------- |
| 行段 `ref f:a-b`              | 「某某是这样写的」——论断某段实现、或钉住注释里的设计理由 |
| 整文件 `ref f`                 | 「整个文件就是……」——小而完整的模块 / 配置      |
| 目录树 `tree d`                | 「这里有哪些东西」——结构陈述               |
| 存在 `exists` / 断言不在 `absent` | 「有 / 不该有 XX」——边界与红线           |
| 名字 `has f "…"`              | 「里面写着 XX」——契约条目、导出名           |

草稿记号 `@@docfirst ref 路径:起-止 @@` 独立一行，路径相对项目根。状态点：绿新鲜、实心黄
代码变了待复核、空心黄未确认、红指向空气。记忆怎么分派、四态语义见 docfirst 站的原理章。

# 保鲜：两速

* **内圈快**：`pnpm check`（类型 + lint + 测试）不带文档检查。
* **提交边界慢**：`docfirst check` 与代码门禁并列，**红了这个提交不许推**。漂移处置二选一：
  `docfirst confirm` 认新行，或改论断。
* **confirm 点名你改的页**：`docfirst confirm <文档路径…>` 只动那几篇；不带路径是整仓一趟，同仓别人
  没复核的黄灯会被一起签掉。拿不准用法跑 `docfirst --help`（只打用法、什么都不动）。
* git 比较器只钉已提交内容：动了被引用的源码，**confirm 之前先 commit**。
* 挂 outputs 的页改了源，`docfirst render` 重摆，生成物与源**同一个提交**。

# 开发循环

```
一句话需求 → A 盘问（spec-grill）→ B 实验 + 选型（gwb-decide）→ C 实施方案（spec 页）
→ D TDD → E 全绿 → F 更新现状、spec 拆解归梁删页、落卡、outputs 重摆
```

A 阻断直接干活：`spec-grill` skill 在对话里把想法盘到能说清「回答什么 / 不做什么 / 成功
判据」，人点头前不动代码。它盘需求边界，`gwb-decide` 盘选型，不重叠。一个提交：代码 +
文档变化 + 卡，一起落。

**这一处的三份纪律随本插件一起发，各有触发条件**：`spec-grill`（A 那一步怎么盘）、
`parallel-by-module`（活大到要派 subagent 时怎么切、什么必须串行）、`docs-governance`
（文档与注释治理——代码自解释扫描、术语统一、历史出清、所有权重分家）。这一页不复述它们的正文。

| 代码动作             | 文档面                         |
| ---------------- | --------------------------- |
| 动接口 / 状态机 / 依赖方向 | 模块页契约，先改或同提交                |
| 撞墙、做了选型、实验有结论    | 轨迹卡，当场落（`trajectory` skill） |
| 命令 / 配置变了        | 用法页 + outputs 重摆            |
| 定了新术语            | glossary                    |
| 做 / 不做的边界动了      | 边界页，理由落卡                    |
| 同一操作短期内第三次出现     | feedback/hatch 记条目          |

真没有文档面可动，说明改动连「错了难改」的边都没碰。

## spec：升格件，住站在途

升格判据：**跨会话、跨模块、有未定选型**，三条占一条才写 spec；装得进一个会话的直接进
模块页开工。升格那一刻起就是 `content/spec/` 里的页，**随做随提交**：中途每次提交都是可
交接的快照。页头列验收清单，做完一项勾一项，「做到哪了」写在自己身上。spec 是脚手架：
**做完拆解归梁**——设计归模块页、决策归卡、剩余删，然后**删页**；git 历史是它的档案。

## 只剩一条留在这儿的通用纪律

TDD、命名、拆函数、注释三分法的正本在 `docs-governance`（手术一：代码自解释扫描），这一页不复述。留在这儿的
只有 outputs 那条，因为它讲的是本区的写法：每仓 `outputs/agents.mdx` 只写仓专属（跑法、
端口、check 命令、红线、代码地图入口）加一行指回这份 skill，render 出的 AGENTS.md 压在
60 行内。

# 重写规则：现状漂了

在那个站目录跑 `docfirst check` 报红（要机读清单就 `docfirst check --json`，自己读 `docs[].items[]`
里 `status` 是 `changed` / `missing` 的那些）之后：

1. 逐页逐钉看漂移：被钉的代码变了什么、正文哪句因此不再成立。
2. **只改漂移段落**——不重排全页、不顺手润色别处、固定块的段序与标题原样保留、沿用本页
   已有的口吻与钉法。
3. 论断仍成立的钉 `docfirst confirm` 认新行；不成立的改论断再 confirm。
4. 人审 diff 后提交，代码与文档同提交。

# 术语表

站上配一张术语表，全站命中处自动标注、悬停显示定义。收三类：仓自己造的词、通用词在这里
有特定含义的、外来框架词（最该收，正是读者最容易卡住的地方）。不收通用编程词与单字词。

正本是一份数据文件（`src/glossary.ts` 一类），每条 `term / aliases / def / href`。**定义只
写概念，不写服务名、类型名、路径**——数据文件钉不住，写进去就腐化，具体名字留给 `href` 指
的那一页。自动标注发生在站构建的 remark 阶段，源文件干净；手写 `<Term>` 要在
`docfirst.config.mjs` 的名册里有一条（`Term: 'children'`）。机制见 docfirst 站 fumadocs 章。

# outputs

README、AGENTS.md、包内 SKILL.md 都是生成物，正本住 `content/outputs/`，`docfirst.config.mjs`
的 `outputs` 映射到落点，`docfirst render` 重摆。SKILL.md 的 `name` / `description`
从 mdx frontmatter 随行带过去；AGENTS / README 不带 frontmatter。改正本不改生成物。

# 起站与交接

起一个新站是**两步，顺序不能反、中间别改文件**，两步都是工作台里的命令（那个 npm 包的命令行
里没有这两条——铺一次模板只在 agent 手上发生，不在仓的门禁里发生）：先用站点插件的
`docs-site.create {"dir":"<仓>/docs-site"}` 铺一个标准 fumadocs 骨架（装了 fumadocs 的人才该有
那个能力），再用 docfirst 插件的 `docfirst.attach {"dir":"<仓>/docs-site"}` 把六区装上——六个集合、
六条路由、侧栏六个根节、`docfirst.config.mjs`、mdx 接线、名册脚本、各区的骨架页，`package.json`
里补上依赖与 doc 脚本。只写文件不跑 install，端口用骨架挑好的那个。

**装配只在刚铺好的骨架上跑**：站里已经有 `docfirst.config.mjs`、或 `content/` 下已经有骨架之外的
内容，它报一句「这个站已有内容，请人工接线」退非零，一个字不改写——给跑了半年的站加 docfirst
走人工那条路，比自作聪明地 AST 改写安全。

模板假设站住仓根 `docs-site/`、被钉代码在仓根（引用写 `../src/…`），换形状就改
`docfirst.config.mjs` 里的相对路径。细节见 docfirst 站的「装配六区」那一页。

交接面四样：**入口页 → 边界 → 模块页 → glossary**，读序就这一条线；轨迹按需查。
交接面上的钉码在、check 绿，交接面就没有说谎。

docfirst 自己那个仓的 `docs-site/` 是最全的示例站，写不准时去那儿找同类页照着抄结构。
