文档站重写设计

文档站基础包 @godcreator/docsite-kit、插件 gwb-docsite 与 docfirst 的整体重写。先从现有代码推出需求，再按需求划分模块、接口与前后端，最后重写。协作站下一轮再做。

做法

  • 一、读懂 fumadocs 最新版的源码：每层怎么实现、留了哪些扩展点、官方扩展包怎么组织
  • 二、照 fumadocs 的扩展点设计我们的扩展机制：每个包接在哪、导出什么、站点代码怎么写
  • 三、需求只用来核对机制有没有漏
  • 四、风险大的地方先做小实验，然后重写

fumadocs 原理

  1. 一张图走完全流程 待你看 从 react-router dev 启动到第一次打开、接管、站内跳转、改文件，再到 build + start 有什么不同，全在一张图里逐步播放；每一步标出是谁的机制，旁边同步显示正在执行的站点代码。打开「加上我们的功能」，能看到评论和钉码各接在哪。先看这一页
  2. 编译一个 .mdx：从文本到 JS 模块 待你看 全流程里「编译 .mdx」那一格放大：17 道工序按源码顺序排开，语法树一步步怎么变、最后导出了什么；钉码的 remark 插件排在哪、设置怎么送进来；最后两个要点：必须用 applyMdxPreset 包一层，以及怎么登记依赖

我们的设计

  1. 设计原则与总体划分 待你看 九条原则（站点生成一次归站点、固定版本旧站能运行、照 fumadocs 的扩展点、库不反过来读站点、前后端照框架模式分、插件与站点的约定向后兼容、只看身份、docfirst 核心不知道站点、错了就报错），各部分管什么、依赖方向、站点怎么引用库
  2. docsite 开发方案 待你看 直接写正式代码（探针只判上游未知行为）；fumadocs 原生能力底座（集合、双端生成物、评论即 MDX 集合、action 组合）；包格局与清理清单、七步推进；范围只有 docsite 自己，docfirst 与协作站以后另立方案
  3. 扩展机制：我们的包接在 fumadocs 的哪些扩展点上 未写 基础包、评论、TSX/HTML 页面、docfirst 各自导出什么、挂在哪个扩展点、站点每个文件怎么写；前端后端怎么分
