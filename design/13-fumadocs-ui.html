DocsLayout 的结构

layouts/docs/index.tsx:39-65、client.tsx:75-150：

<TreeContextProvider tree={tree}>
  <LayoutContext value={{ props, slots, navItems, menuItems }}>
    <slots.sidebar.provider>
      <slots.container>                       // CSS Grid 容器
        <slots.header />                      // 移动端头部
        <slots.sidebar.root />                // 侧栏
        {tabMode === 'top' && <LayoutTabs />}
        {children}                            // DocsPage
        {aiChat?.panel && <AIChatPanel className="[grid-area:toc] …" />}
props用在哪
tree侧栏页面树；没给 tabs 时从树里的 root 文件夹生成侧栏切换
navtitle、url 给站名；children 放侧栏顶部和移动端头部；transparentMode
links / githubUrl普通链接放页面树上方；type: 'icon' 的放侧栏底部一行
sidebarbanner（搜索框和切换下拉之下）、footer、defaultOpenLevel、collapsible、components{ Item, Folder, Separator }（换页面树每一项的渲染）
tabs / tabModeauto：侧栏里下拉；top：正文上方一排
aiChat{ open, onOpenChange, panel }：在目录那一列放一个面板，打开时目录自动隐藏，xl 以下变浮层
containerProps、themeSwitch、searchToggle、i18n容器属性与几个共享部件

lib/layout.shared.tsx 里的 baseOptions() 只是站点的约定写法：返回共享的 props，DocsLayout 和 HomeLayout 都展开它。

可替换部件 slots

旧的 component 属性全部废弃，统一改成 slots：传一个组件就替换，传 false 就隐藏。

所属部件
共享（shared/client.tsx:70-85）navTitle、themeSwitch、searchTrigger{ sm, full }、languageSelect{ root, text }
DocsLayout（client.tsx:31-40）header、container、sidebar{ provider, root, trigger, useSidebar }
DocsPage（page/index.tsx:78-87）toc{ provider, main, popover }、container、footer、breadcrumb

每个部件的默认实现都单独导出（layouts/docs/slots/*、layouts/shared/slots/*），可以在自己的部件里包一层默认实现再加东西。

可以读写的 context

context怎么读能不能改
页面树、当前路径useTreeContext()、useTreePath()只读；按 tree.$id 缓存，换一个 $id 相同的新树不会更新
布局useDocsLayout()只读
侧栏useSidebar()能：setOpen、setCollapsed；Ctrl+B 折叠
页面useDocsPage()只读
目录useTOCItems、useActiveAnchor(s)只读
搜索useSearchContext()能：setOpenSearch(true) 打开搜索
语言、主题useI18n()、useTheme()能

DocsPage 与宽度

  • 结构：toc.provider 里先放目录浮层，再放 container（面包屑、正文、页脚），最后放 toc.main（page/index.tsx:103-146）。
  • 正文 <article id="nd-page"> 默认最宽 900px，full 时 1168px，并且不渲染目录（page/slots/container.tsx:11-22）。
  • 没有目录条目时会放一个占位，宽屏下仍占 268px，让同一站点各页正文宽度一致。
  • 目录三种样式 normal / clerk / block；窄屏变成顶部 40px 的浮层，带阅读进度。
  • 页脚的上一页、下一页按页面树和当前路径算；面包屑用 core 的 getBreadcrumbItemsFromPath。

样式机制：部件自己把尺寸写回布局

布局是 CSS Grid，模板写在容器的内联 style 里（layouts/docs/slots/container.tsx:16-26）：

"sidebar sidebar header      toc toc"
"sidebar sidebar toc-popover toc toc"
"sidebar sidebar main        toc toc" 1fr
/ minmax(min-content,1fr) var(--fd-sidebar-col)
  minmax(0, calc(var(--fd-layout-width,97rem) - var(--fd-sidebar-width) - var(--fd-toc-width)))
  var(--fd-toc-width) minmax(min-content,1fr)

关键机制：容器上的宽度变量默认都是 0；每个部件渲染时带一个 layout:[--fd-x:…] 类，CSS 借 :has() 把变量写到容器上（css/lib/base.css:168-177）。侧栏写 md:layout:[--fd-sidebar-width:268px]，目录写 xl:layout:[--fd-toc-width:268px]。部件不渲染，变量回到 0，那一列就消失。

@variant layout {
  #nd-docs-layout:has(&), #nd-notebook-layout:has(&), … { @slot; }
}
  • 公开的：颜色变量 --color-fd-*、--fd-layout-width、--fd-banner-height、文档列出的几个行列变量、prose 类、主题 CSS。
  • 内部的：#nd-docs-layout、#nd-page、#nd-toc 等 id，data-* 属性，268px、900px 这些写死的数。我们现在覆盖的正是这些。
  • Tailwind：css/preset.css 带上构建时扫描布局源码生成的 @source inline("类名…")，站点不用扫描 node_modules；@fumadocs/tailwind 只提供 typography（prose）插件。暗色模式用 .dark 类。

RootProvider 与界面文字

  • 嵌套：方向 → 语言 → 主题（next-themes）→ 搜索 → 页面（provider/base.tsx:88-123）。
  • search：SearchDialog（换对话框）、options、links、快捷键。
  • i18n：translations 是 Record<string, string>，键的格式是「英文原文(备注)」，例如 'Search(search trigger)'。推荐 i18nProvider(translations, lang)。中文直接用官方 @fumadocs/language 的 zhCN() 预设：translations().extend(uiTranslations()).preset('cn', zhCN())。

MDX 组件

defaultMdxComponents 只有：代码块（含标签页）、Card、Callout、a（core 的 Link）、img、h1–h6（带锚点）、table（横向滚动）（mdx.tsx:56-81）。Tabs、Steps、Accordion、Files、TypeTable、Banner、InlineTOC、ImageZoom 都要站点自己导入加进映射。几个实现细节：Accordion 在 URL hash 命中时自动展开，浏览器页内查找也能找到收起的内容；Banner 带 id 时把关闭状态存进 localStorage，首屏用内联脚本避免闪烁。

搜索

  • 引擎已经从 Orama 换成 ZBSearch，文件名还叫 orama-*。
  • 索引内容来自每页的 structuredData（remarkStructure 产出）。advanced 模式每页拆成多条：标题一条、描述一条、每个小标题一条、每段正文一条，url 带 #小标题（search/server/build-doc.ts:15-76）。
  • createFromSource(source, options)：按 loader 实例缓存索引；options.search 原样传给引擎（如 tolerance）；默认分词 multilingual，中文按字还是按词切没有核实。
  • 实时查询走 GET /api/search?query=…；静态导出走 staticGET + 浏览器端 useStaticSearch。
  • 换对话框：RootProvider search={{ SearchDialog: MySearch }}，用 SearchDialog、SearchDialogInput、SearchDialogList 等部件自己拼。Base UI 版要把 props 里的 dialogHandle 传下去，否则搜索按钮打不开。
  • 自定义组件想进索引：在 remark 阶段给节点设 data.structuredData。

CLI：把布局复制进站点

这是官方对深度定制的回答。npx @fumadocs/cli customise 先选布局（docs、notebook、flux、glass、home、spacious），再选范围：

  • 整个布局：复制 layouts/docs 下的源码进站点，并自动把路由文件里的 fumadocs-ui/layouts/docs 改成 @/layouts/docs。
  • 从极简版重写：复制一个最小的 docs-min 布局。
  • 只换一个部件：复制 layouts/docs/slots/sidebar 这类单个部件，打印一段 slots={{ … }} 示例，接回原包的布局上。

复制出来的代码归站点，不会自动更新。没复制的模块（context、provider）仍从包里导入，所以复制的布局和包里的 RootProvider 共用同一份 context。cli/src/commands/customise.ts:36-371

  • 组件注册表：每个包有 registry/index.ts，官网构建成 https://fumadocs.dev/registry；--dir 可以指向自己的注册表。
  • add：复制单个组件（进 ./components）；会复用站点已有的 shadcn 组件。
  • 定制梯度：props 配置 → slots 换部件 → CLI 复制单个部件 → 复制整个布局 → 从极简版重写。

常见定制需求的官方做法

想做的官方做法
右侧盖住目录列的面板（评论栏）aiChat={{ open, onOpenChange, panel }}，panel 放任意内容；要多个面板就替换 slots.toc.main，自己用 xl:layout:[--fd-toc-width:…] 占住这一列
正文上方提示条全站：<Banner> 放在 DocsLayout 外面，会自动推开固定定位的元素；单页：放在 DocsPage 的 children 里，或替换 slots.breadcrumb
侧栏里一排入口sidebar.banner、sidebar.footer、links（type: 'icon' 进底部图标行）、nav.children
搜索按钮换位置、换样式slots.searchTrigger
改宽屏宽度只有 --fd-layout-width 是公开的；单页加宽用 full；侧栏、目录宽度要替换部件或用 CLI 复制布局
改页面树每一项的样子sidebar.components{ Item, Folder, Separator }
侧栏打开非页面树页面时停在上一组没有官方机制；只能复制侧栏部件自己实现
